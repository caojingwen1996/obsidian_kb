## 风险观察对象

**风险观察对象表 `risk`，一条记录代表“针对特定市场或主体，持续观察的一个具体风险”。** 它负责确定观察对象，连接风险定义、事件和历次评估。

例如：“A股融资盘去杠杆风险”是一条观察对象；每周对它作出的判断，分别进入 `risk_snapshot`。

| 字段                       | 中文名称    | 类型                 | 表单含义                          | 是否需要 LLM | 生成方式                     |
| ------------------------ | ------- | ------------------ | ----------------------------- | -------- | ------------------------ |

| `title`                  | 风险名称    | VARCHAR(200)       | **正在观察什么宏观风险？**               | 是        | 根据具体风险问题生成，不包含临时等级       |
| `slug`                   | 页面标识    | VARCHAR(200)，唯一，可选 | 详情页链接中的标识，用户无需填写              | 否        | 系统生成；直接使用 `risk_id` 时可省略 |

```
【观察对象的定义】

观察对象，是一项具体风险判断所针对的、具有明确身份和范围边界的
经济或金融对象。

它回答：
“我们正在判断谁、哪个市场或哪套经济金融系统的风险状况？”

对风险大小、影响程度、持续性及是否缓和的判断，
都必须针对这个对象成立。

观察对象不限定为企业或机构，也可以是经济体、行业、资产、市场
或金融系统。

【第一版范围】

本系统第一版只建立宏观层面的风险观察对象，允许的类型为：
- 经济体
- 宏观主体，例如中央政府、中央银行
- 市场
- 金融系统

行业、企业和单项资产可以作为宏观风险的证据或传导环节，
本阶段不单独建立为观察对象。

【识别方法】

1. 明确风险问题
先用一句话说明：正在担忧什么不利变化，以及可能造成什么损害。

2. 确定判断针对谁
识别直接承受该项损害、需要被评估风险状况的对象。
区分风险发起者、应对者、信息发布者和风险作用对象；
它们不一定是同一个对象。

例如，央行收紧货币政策：
央行可能是风险驱动方，但观察对象可能是受影响的融资市场，
不能仅因为材料提到央行，就把央行设为观察对象。

3. 明确对象边界
说明其地域、主体或市场范围，以及必要的包含和排除项。
选择足以回答风险问题的范围，不把局部证据直接扩大到全球或整体经济。

4. 检查能否形成一致判断
如果一个名称包含多个风险表现明显不同、无法共用同一判断的对象，
应拆分，或者选择与当前问题最直接相关的主要对象。

5. 匹配已有对象
优先匹配已有对象的身份和边界，不仅匹配名称。
已有同一对象时复用；确实不存在时提出新增对象。
不能为了生成新记录而改写同一对象的名称。

【命名要求】

- 优先使用明确、通行的经济体、主体或市场名称。
- 对金融系统等集合对象，必须给出可理解的范围定义。
- 名称不包含“高风险”“正在恶化”等当前状态。
- 名称不包含本次事件、日期或临时观察窗口。
- 不把风险来源、传导过程和受影响对象拼成含义不清的新名称。

【需要区分的内容】

- 风险名称：正在观察什么不利问题。
- 观察对象：该风险判断针对谁或什么系统。
- 关键变量与指标：凭什么判断风险变化。
- 事件：什么变化触发、加剧或缓和风险。
- 本次观察边界：本轮具体研究对象的哪些方面。

利率、汇率、库存等数值通常属于指标，不直接作为观察对象。
新闻、会议、公告通常属于事件，不直接作为观察对象。

【输出】

- 对象名称
- 对象类型
- 对象定义与基本边界
- 本次风险观察边界
- 识别依据：材料中的哪些事实支持选择这个对象
- 与已有对象的匹配结果：复用 / 建议新增 / 暂无法确定

证据不足时，说明缺少什么，不强行创建对象。

```

观察边界与范围 `scope_boundary` 的定义:

```
观察范围（scope_boundary）：
说明针对当前观察对象，这项风险具体研究哪些方面，以及判断覆盖到哪里。

AI识别要求：
1. 根据风险名称、观察对象和传导机制，确定直接相关的研究环节。
2. 包含影响风险形成、持续和缓和的主要环节。
3. 必要时说明哪些相邻问题不单独评估。
4. 不写当前风险等级，不罗列指标，不把缺少数据的环节直接排除。
5. 用1—3句话表达；无法确定的边界标注“待明确”。

第一版仅判断宏观风险，行业和企业变化可作为证据。

**示例：**

> 美国主权债务再融资风险：观察联邦债务的到期续接、融资成本、市场承接及财政缓冲，不单独评估企业和地方政府债务风险。

```

```

    ↓ 提出

    ↓ 按观察对象与范围筛选
本项风险需要跟踪的变量
    ↓ 通过指标和事件获取证据
本次风险判断

```

## 风险源与关键变量


`risk_source_variable_relation`
**中文名称：风险—风险源—关键变量关联表**  
**表性质：业务关联表**

一条记录表示：

> **针对某项具体风险，在某个一级风险源下，选择哪个关键变量进行观察，以及该变量为什么重要、怎样影响风险。**

该表保存AI 根据具体风险的观察对象与范围，分析风险来源和传导机制后，筛选出的关键变量及其作用依据。**不保存完整中间分析过程，也不保存变量当前值和当前风险判断。**

**`risk.scope_boundary` 定研究边界，关联表把这个边界落实为具体要观察的变量。** 两者是“范围说明”和“观察清单”的关系。

| 字段                        | 中文名称     | 类型             | 表单含义                        | 是否需要 LLM | 生成方式                                 |
| ------------------------- | -------- | -------------- | --------------------------- | -------- | ------------------------------------ |
| `relation_id`             | 关联记录 ID  | UUID，主键        | 唯一标识这条关联，供后续评估引用            | 否        | 系统生成                                 |
| `risk_id`                 | 风险观察 ID  | UUID，外键        | **为哪项风险选择变量？**              | 否        | 系统传入已有 `risk.risk_id`                |
| `source_id`               | 一级风险源 ID | FK，类型与来源配置主键一致 | **这个变量从哪个风险源的分析中提取？**       | 辅助选择     | LLM 从 `risk_source` 中选择，系统校验         |
| `variable_id`             | 关键变量 ID  | FK，类型与变量配置主键一致 | **需要观察哪个变量？**               | 辅助匹配     | 优先匹配 `variable_config`；确需新增时由系统生成 ID |
| ``variable_role``         | 变量主要作用   | ENUM           | **它主要推动、传递、缓冲风险，还是验证损害？**   | 是        | 根据变量在当前风险中的作用判断                      |
| `variable_impact_on_risk` | 如何影响风险   | TEXT           | **变量通过什么方式、在什么条件下加大或减小风险？** | 是        | 保存简明因果解释、适用条件及必要限制                   |
| `created_at`              | 创建时间     | TIMESTAMP，带时区  | 何时建立关联                      | 否        | 系统生成                                 |
| `updated_at`              | 更新时间     | TIMESTAMP，带时区  | 关联内容最近何时修改                  | 否        | 系统更新                                 |

`variable_role`取值:

| 取值                    | 中文名称       | 回答的问题            | 示例     |
| --------------------- | ---------- | ---------------- | ------ |
| `risk_driver`         | **风险驱动变量** | 什么在产生或加大风险压力？    | 到期偿付需求 |
| `risk_transmission`   | **风险传导变量** | 什么决定压力能否传递、传递多大？ | 融资可得性  |

## 业务处理模型

| 层级            | 业务定位                 | 输入                              | 核心处理                                             | 输出                                                                  |
| ------------- | -------------------- | ------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------- |
| **L0：观测源接入**  | 提供可追溯的原始材料与数据        | 新闻、文章、公告、指标数据；观测任务及补充资料需求       | 获取材料 → 检查完整性 → 清理格式 → 保留来源与时间 → 标识重复或修订          | 原始材料、标准化数据记录、来源与时间信息、接入异常                                           |
| **L1：风险观察建模** | 建立或匹配可持续跟踪的风险观察模型    | L0 材料；已有风险模型；配置字典；适用方法论；模型重审请求  | 提取事实并区分观点、预测 → 匹配已有风险 → 决定复用、新建或调整 → 分析机制 → 提取变量 | 风险观察模型、可追溯事实、匹配结果和待补充事项；主要对应 `risk`、`risk_source_variable_relation` |
| **L2：变量状态评估** | 将本轮证据转化为变量状态及风险作用判断  | 风险模型；本轮事实与指标；历史变量评估；信息截止时点和比较口径 | 关联证据 → 检查时间、口径与有效性 → 处理冲突 → 判断状态与变化 → 检验机制条件     | 变量状态、变化说明、当前风险作用、证据依据和不确定性；主要对应 `risk_snapshot_variable_evidence`   |
| **L3：整体风险判断** | 综合变量评估，形成当前整体风险状态    | 本轮变量评估集合；风险模型；等级规则；比较快照；信息截止时点  | 检查关键变量覆盖 → 综合压力、传导、缓冲和损害 → 应用等级规则 → 对比基准 → 形成快照  | 整体风险状态、判断依据、不确定性和下一步观察事项；主要对应 `risk_snapshot`                       |
| **L4：风险演化分析** | 基于历史快照，解释风险发展过程及关键节点 | 历史风险快照；对应变量证据；比较依据；适用演化方法       | 组织历史序列 → 检查可比性 → 分析阶段变化 → 回溯驱动与缓冲变化 → 判断关键节点     | 演化方向、阶段说明、节点判断、支持与反向证据、后续验证需求                                       |

### AI分析模型

输入数据 → 分析任务 → Prompt → 输出 Schema → 校验规则 → 数据持久化
AI-01 风险识别与匹配（L1）

输入：最新资料、已有风险定义库、风险源与变量配置。

输出：匹配的风险 ID、相关性、风险源、变量关联、是否需要新建候选风险。

AI-02 变量证据与状态分析（L2）

输入：风险变量定义、最新证据、观测指标、历史变量状态。

输出：变量当前状态、变化方向、影响强度、分析依据、证据引用。

AI-03 整体风险研判（L3）

输入：风险定义、各变量评估结果、历史快照。

输出：整体风险等级、风险方向、损害表现、核心驱动因素、持续条件。

AI-04 风险演化分析（L4）

输入：当前快照、历史快照、变量变化记录。

输出：加剧或缓解的原因、关键变化事件、风险传导路径、转折信号。

AI-05 风险报告生成（L5）

输入：当前风险状态、演化结论及相关证据。

输出：风险摘要、监测报告、预警解释、时间线描述。

AI-06 分析结果校验（横向能力）

输入：各阶段 AI 分析结果、原始证据、结构化约束。

输出：事实一致性检查、矛盾标记、证据充分性评价、是否需要重新分析。

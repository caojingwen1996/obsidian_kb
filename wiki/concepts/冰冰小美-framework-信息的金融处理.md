# 冰冰小美-framework-信息归纳框架

## 一句话定义

归纳，是从海量信息中筛选出能够改变市场行为的信息，并通过持续跟踪这些信息，判断风险正在增加还是减弱，从而决定哪些方向应该回避、哪些方向可以逐渐参与。

## 概念来源

- 来源间接支持：
- 整理者归纳：
- 待验证：

## 概念要解决的问题


这是我假设的应用场景，
1.将每日晨报作为信息源 2. 提前设置好金融因子和一级非金融信息观测源，每日扫描，进行信息归纳，3.给出一个标的，自动扫描该标的的相关信息进行归纳

### 归纳什么？

> “归纳内容的核心要点是在于这种信息会引发市场行为变化，特别是其相关风险评估。”



分类维度:  
按来源：市场数据（股价、汇率）、机构数据（财报、监管报告）、用户数据（交易记录、信用评分）。  
按功能：风险类（波动率、违约率）、交易类（订单流、流动性）、分析类（行业趋势、政策解读）  
  

关注：引发市场行为变化的信息 + 风险变化。

|建档级别|信息源类型|建档条件与用途|
|---|---|---|
|**核心源：长期建档**|央行、财政及统计部门、重要政策发布机构、监管机构与交易所|持续提供货币、财政、制度和经济运行的一手材料，是长期判断的依据|
|**专题源：按研究需要建档**|公司公告与投资者关系栏目、行业协会、产业统计机构、相关主管部门|与正在跟踪的产业、企业或风险直接相关，能提供连续数据或执行证据|
|**观察源：试用建档**|研究机构、专业媒体、专家和分析者|能持续提供独特线索，引用可追溯，观点可以事后验证；需要记录立场、利益关系和纠错情况|
|**线索源：通常不独立建档**|聚合平台、转载号、匿名爆料、偶然看到的文章|仅记录具体线索及原始出处；持续提供独特且可验证的信息后，再升级为观察源|

## 方法论
### 信息处理系统



#### step1.信息获取


目的：将外部信息变成系统可处理的信息单位

根据输入模式选择信息范围
- 晨报模式:输入晨报，输出晨报中的原始信息
- 扫描模式：根据预设观测对象 获取这些预设观测对象当天新增的信息
- 标的模式：输入具体标的，获取具体标的的相关信息

#### Step2 信息结构化

目的：把静态信息变成动态观察。这些 Event 应该放在哪个时间窗口、时间轴、观察对象下？

2.1 定时间窗口
这些 Event 应该放在哪一段时间语境里理解？


一个完整时间窗口=核心问题+关键事件+事件前预期+事件后重新定价

| Event结构项     | 含义                    | 示例                        |
| ------------ | --------------------- | ------------------------- |
| **核心问题**     | 这一轮时间窗口真正关注的问题        | 美联储会不会继续降息？               |
| **关键事件**     | 可能推动预期重新定价的核心事件       | FOMC 会议                   |
| **事件前：预期形成** | 市场在关键事件落地前形成的预期       | 市场提前交易降息预期                |
| **事件落地**     | 关键事件正式发生              | FOMC 公布利率决议               |
| **事件后：重新定价** | 市场根据实际结果重新调整预期和价格     | 利率、美债、美元、股票重新定价           |
| **完整时间窗口**   | 从预期形成到事件落地，再到重新定价的全过程 | 会前预期形成 → FOMC 落地 → 会后重新定价 |


2.2 建事件时间轴：观察信息有没有连续性。


Event
+
金融因子？
+
市场反应？
        ↓
按时间连续排列

输出：

> **Structured Event Timeline**

#### step3 信息归纳



3.1 找事件密集区：识别同一核心问题下 短期集中出现的相关 Event
事件密集区定义：在一个较短时间窗口内，多个与同一核心问题高度相关的重要事件连续出现，导致市场预期频繁更新。

|维度|问题|
|---|---|
|时间集中度|是否在相对短的窗口内连续发生？|
|问题相关度|是否围绕同一个核心问题？|
|信息增量|新 Event 是否不断修改市场已有认识？|

3.2 提取共同现象：这些事件共同影响什么？
判断方法

可以问三个问题：

1. 这些 Event 有没有相同方向的变化？
2. 有没有重复出现的行为或状态？
3. 能不能用一句接近事实的话描述这种共同变化？

 输出

> ommon Pattern / Common Phenomenon

3.3  提炼共同变量：把一组围绕同一问题反复出现的具体事件，进一步压缩成少数能够解释这些事件共同变化方向的观察变量。

大量事件最后往往会收敛到少数变量。

| 步骤           | 要回答的问题              | 结果       |
| ------------ | ------------------- | -------- |
| **1. 找共同对象** | 这些变化都作用在哪？          | 找到共同作用对象 |
| **2. 找共同机制** | 背后有什么共同传导机制？        | 找到共同传导机制 |
| **3. 向上抽象**  | 能否用一个更高层变量统一描述？     | 候选核心变量   |
| **4. 检查解释力** | 这个变量能不能解释大部分 Event？ | 确认核心变量   |

### 信息处理skill的开发

SKILL.md: 能力说明

```
定位：
`information-processing` 是一个通用的信息处理 Skill。

它负责围绕指定观察目标获取相关信息，将原始材料提取为 Event，并进一步完成事件结构化、时间组织和信息归纳。

能力边界：
该 Skill 不执行具体领域判断。

它的职责是把外部信息加工成：
可追溯
+
结构化
+
可归纳
+
可供下游 Skill 继续分析的机器可读信息结果。

## 核心能力 
1. **信息获取** 围绕指定观察目标获取相关信息。 
2. **信息组织** 将分散信息组织为具有时间、观察对象和来源关系的结构化信息集合。
3. **信息归纳** 从相关信息中提取共同现象和核心变量，形成可追溯的结构化归纳结果。


标准输出对象统一定义为：InformationProcessingResult
```

Skill 入口：
```
Skill 支持三种主要入口模式：
feed：
适用于已经存在一份或多份待处理材料的场景。
该模式主要回答：从已有材料中，可以提取哪些与当前观察目标相关的 Event？

monitor：
适用于已经建立固定观察体系，需要周期性扫描预设信息源的场景。
该模式主要回答：预设观察对象在当前扫描周期内出现了哪些新的 Event？

target：
适用于给定一个具体对象，围绕该对象动态获取相关信息的场景。
该模式主要回答：与指定 Target 相关的新增 Event 有哪些？


```

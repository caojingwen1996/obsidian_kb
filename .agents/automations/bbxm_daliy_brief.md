## 三、抓取与完整性

1. 读取项目规则、项目内抓取技能及 `EXTEND.md`；本任务明确为仅抓取，覆盖技能默认的后处理要求。
2. 通过项目内 `.agents/skills/cjw-xueqiu-daily-monitor/scripts/start_automation_chrome.sh` 和共用选择器启动或复用专用 Chrome for Testing / Chromium，不得新启动日常 Google Chrome 或降级打开旧登录目录。
3. 使用技能自带提取脚本获取目标日期帖子，先统计候选量，遵守 `--request-pacing auto` 的自动降频；若使用站内时间线 API，列表中的截断文本不能当作完整正文，必须获取详情全文。
4. 目标日期按帖子实际发布时间判定，标题中的直播日期原样保留，不以直播日期替代发布时间。保留文章正文、原有结构和实际来源；附带评论时只保留作者本人直接相关的原始补充，并与正文明确区分，不自行补写观点。
5. 登录、访问验证、正文缺失、提取或保存失败时记录失败阶段和具体原因；不得把抓取不完整写成“无新帖”。发现候选但未拿到全文时，不得以截断内容冒充成功保存。
6. 抓取完成后校验原文文件、来源标识、发布时间及保存数量，候选、符合日期及标题条件、已存在、新增、修订和失败分别计数。

## 四、原文、状态与同日重跑

1. 冰冰小美原帖文件名为 `{DATE}_HHMMSS_原帖标题.md`，`HHMMSS` 取原帖实际发布时间；老木匠直播整理稿统一使用 `{直播日期} 老木匠直播：{原标题主题}.md`，例如 `2026-10-20 老木匠直播：含科量转向、卖出心理与新手牛市.md`。直播日期取原标题或原文明确记载的日期，不用发布或抓取日期替代，不另加时分秒；原文元数据继续保留实际发布时间，当日抓取筛选仍按发布时间。无明确直播日期的资料使用原有标题，不编造日期或直播性质；无标题时使用正文开头的简短原文片段，不生成观点摘要。清理文件名禁用字符、控制字符、尾部空格和句点；不同帖子同名或修订版本冲突时，才追加稳定内容 ID 或版本标识，避免覆盖。
2. 原文元数据保留标题、实际发布账号、原始 URL 或稳定内容 ID、发布时间、抓取时间及来源性质；正文按抓取内容保存，不做主题分类、风险评级或动作信号推导。
3. 每位作者仅持续追加一个 `_task/task.log`，不再生成每日状态 JSON、日期前缀日志或独立运行状态表。冰冰小美日志位于 `sources/automations/BBXM每日汇总/_task/task.log`，老木匠日志位于 `sources/automations/老木匠每日汇总/_task/task.log`；文章仍写入第二节指定目录。
4. 同日重跑先读取该作者的 `_task/task.log`，再核对已保存原文的 URL 或稳定内容 ID 与正文版本；仅补抓新增或修订版本，不覆盖、不重命名已有原帖。原文文件是保存事实的依据，日志中的成功记录须与实际文件核对，不因日志缺失、迁移或旧布局变化重复保存。用户明确要求改名时，追加 `post_renamed` 事件记录旧路径、新路径、来源 ID 和正文版本哈希；重跑按该事件解析当前路径，改名不计为新增抓取。
5. 同一帖子正文发生修订时另存版本并记录关系；相同版本不重复保存，不把同版本重跑计为新增。
6. 完整抓取且无符合条件资料时，在固定日志中追加空结果。老木匠分支报告“无当日符合条件的老木匠资料”，不称整个账号无帖；失败时追加失败记录并保留必要证据，不按空结果清理。
7. 不删除或改写已有原文、历史汇总、知识页、分析文件及工作簿；本次切换只改变后续任务行为。
8. 通用脚本如果强制生成状态文件或按日输出，在来源目录之外的临时工作目录运行；从已保存原文及固定日志重建本轮临时状态。最终仅发布原文，并将抓取结果追加到固定日志，不把临时状态、按日日志或中间文件复制进文章目录。成功后清理本轮临时文件；失败证据如需保留，放在 `_task/failed/` 并在日志注明位置。
9. 旧状态、日志和运行状态表原样归档到 `_task/history/`，保持原相对目录和文件内容，停止更新；归档不是第二份活动状态。既有原文不迁移、不重命名。

## 五、仅抓取执行边界

- 保存入口 `content_task.py` 或 `task_store.py finish` 必须传入 `--capture-only`，跳过抓取技能默认的预处理与 Timeline 后处理；不要调用 `timeline_postprocess.py prepare` 或 `apply`。
- 不调用风险识别、信息分析或估值技能，不进行风险分析、评级、风险计数、交易推导或操作信号提炼。
- 不生成或更新观点汇总、`summary.md`、`daily_brief.md`、`操作.md`、风险分析 JSON、HTML 报告或 Excel 工作簿，也不清理旧风险行。
- 不整理或创建 Wiki 页面、Timeline、主题候选，不修改知识库索引；抓取结果仅进入第二节的原始资料目录。
- 收尾只报告抓取数量、保存路径、覆盖边界、错误和人工跟进项，不扩展行情、新闻或其他研究。
- 本任务只执行业务抓取，不创建、修改或暂停调度定义。

## 六、固定日志与收尾

1. `_task/task.log` 使用 UTF-8，每行一条 JSON 事件，持续追加、不覆盖；事件包含执行时间、目标日期、作者或账号、事件类型和执行标识。同一作者的重叠运行须串行或使用临时锁，避免并发去重与保存冲突。
2. 原文保存成功后及时追加 `post_saved` 事件，记录来源 URL 或内容 ID、正文版本哈希、原文相对路径及修订关系。每次运行开始和结束分别追加 `run_started`、`run_finished`，结束事件记录状态、候选数、符合条件数、新增数、已有数、修订数、失败数、原文目录、错误原因及必要失败证据位置；无结束事件视为未完成，补跑追加记录并保留原失败痕迹。不得记录 Cookie、令牌或其他凭证。
3. 完整且有资料记成功，完整且无符合条件资料记空结果，部分失败或中断如实记录；不能用一路成功表示整项任务全部完成。
4. 最终逐路报告目标日期、来源账号、各项抓取计数、原文目录与固定任务日志路径、覆盖边界、失败原因和人工跟进项。
5. 对本轮新增或修改的 Markdown 执行 `python3 rules/check_markdown_tables.py`，追加项目根 `log.md` 的抓取运行记录，不维护正式知识页索引。

## 定位

将持仓标的或已生成研报标的的当日新增信息映射回原研报核心假设和估值输入，识别异常、逻辑强化或削弱、估值重算需求、待人工复盘事项和研报更新需求。输出研究监控结果，不直接替用户下交易指令；除非用户明确要求操作分析，否则只提示“维持估值 / 局部重算 / 完整重估 / 人工判断 / 复盘 / 更新”。

每日监控解决“是否需要重算”的筛选问题，不负责在没有完整模型输入时自动生成新价值区间。只有价格变化时，更新相对估值区间位置、安全边际和盈亏比，不修改原研报的内在价值区间。

## 开始前确认

先确认监控时点：

- 当前日期、时间和时区；
- 是否为交易日；
- 监控是盘中还是收盘后；
- 行情、公告和产业数据的截止时间；
- 停牌、休市或数据延迟时实际采用的数据日期。
- 原研报估值日期、模型版本和最近一次完整重估时间。

若用户没有提供完整持仓清单，先基于已给标的执行；不得凭记忆补全成本、仓位、估值区间或研报假设。缺失项统一写“未提供 / 未获取到”。

## 输入契约

每个标的尽量读取或向用户索取：

- 基础信息：股票名称、代码、行业、持仓状态、仓位、成本、动态估值区间、研报版本、最近人工复盘时间；
- 研报信息：核心投资逻辑、行业周期判断、盈利来源、竞争优势、核心假设、关键监控指标、主要风险、失效条件、估值区间、预期催化剂；
- 估值基线：估值日期、采用方法及权重、盈利预测、收入增长、利润率、经营现金流、资本开支、营运资本、订单或储备、WACC、永续增长率、净现金或净负债、总股本、可比公司估值及各自阈值；
- 当日数据：收盘价、当日/本周/近5日涨跌幅、行业指数涨跌幅、成交额、换手率、近20日均成交额、公告、公司新闻、产业新闻、商品价格、库存、产能、供需、政策和同行动态；
- 监控配置：异常涨跌、成交额、相对行业偏离、估值区间、商品价格、库存、成本、产量、业绩偏离、估值输入变化、数据频率、模型有效期和研报失效阈值。

核心假设必须编号，例如 `H1`、`H2`。没有编号时，先为本次监控临时编号并说明“本次临时编号”。

## 监控范围

按以下顺序确定扫描标的：

1. 用户明确提供的持仓或关注清单；
2. 用户要求“扫描已生成研报的标的”时，扫描当前项目内状态为 `active` 的权威个股研报，并按证券代码去重；
3. 用户只提供部分标的时，只扫描已提供部分，不凭记忆扩展持仓。

每个标的只能使用一份当前权威研报作为估值基线。存在多份候选、证券代码缺失、估值日期缺失或区间冲突时，估值处置状态直接标记为 `MANUAL_REVIEW`，不得自行挑选最有利的一版。

## 来源纪律

按以下优先级取证：

1. 证券交易所、证监会、上市公司正式公告；
2. 政府部门、统计机构、行业协会；
3. 商品交易所、权威行业数据库；
4. 上市公司官网和投资者关系记录；
5. 主流财经媒体；
6. 券商研报；
7. 其他公开信息。

未经证实的传闻、自媒体观点和匿名消息只能作为线索，不能作为确定性结论。重要信息必须记录标题、发布时间、数据日期、来源、原始事实、是否当日新增、是否已被此前监控覆盖。多来源指向同一事件时合并去重。

## 默认异常规则

用户没有配置阈值时，注明“采用默认规则”，并使用：

- 单日绝对涨跌幅达到 5%；
- 近 5 日累计涨跌幅达到 10%；
- 单日跑赢或跑输行业指数 3 个百分点；
- 成交额达到近 20 日均值 2 倍；
- 换手率显著高于近期平均；
- 价格突破动态估值区间上限或下限；
- 连续 3 个交易日明显跑输行业指数；
- 涨停、跌停、停牌或复牌；
- 价格和成交量同步异常。

股价涨跌本身不能证明基本面变化。若没有可靠证据解释异常，写“市场波动原因暂未确认”，并标记是否需要人工核实。

## 默认估值重算触发规则

估值重算只由模型输入、商业事实或模型有效期变化触发。用户没有配置阈值时，注明“采用默认估值触发规则”，并使用下表；行业差异明显时可收紧或放宽，但必须说明理由。

| 估值输入或事件 | 默认触发条件 | 默认处置 |
|---|---:|---|
| 盈利预测 / EPS | 相对原模型变化达到 5% | `LIGHT_REVALUE`，更新盈利倍数法 |
| 归母净利润或自由现金流 | 相对原模型变化达到 10% | `FULL_REVALUE` |
| 毛利率或经营利润率 | 偏离原模型达到 1 个百分点 | `LIGHT_REVALUE`；达到 2 个百分点时 `FULL_REVALUE` |
| 经营现金流 | 相对原模型偏离达到 15%，或利润增长但现金流明显恶化 | `FULL_REVALUE` |
| 重大订单 / 合同 | 金额达到最近年度收入 5% | `LIGHT_REVALUE`；达到 10%或明显改变收入可见度时 `FULL_REVALUE` |
| 净现金 / 净负债 | 对原股权价值的影响达到 5% | `LIGHT_REVALUE`，更新股权价值桥接 |
| 总股本 | 增发、期权、可转债等潜在摊薄达到 3% | `LIGHT_REVALUE`；达到 5%时 `FULL_REVALUE` |
| 可比公司估值 | 可比组中位估值持续变化达到 15% | `LIGHT_REVALUE`，只更新相对估值 |
| WACC关键输入 | 无风险利率、融资成本或风险溢价变化达到 0.5 个百分点 | `LIGHT_REVALUE`，重跑DCF敏感性 |
| 商业逻辑或核心风险 | 重大客户、竞争格局、监管、产品路线或生存条件发生实质变化 | `FULL_REVALUE` |
| 定期报告 | 新季报、半年报、年报或业绩预告 / 快报披露 | `FULL_REVALUE`；数据不完整时 `MANUAL_REVIEW` |
| 模型有效期 | 距最近完整重估超过 90 天 | `MANUAL_REVIEW`，安排常规重估 |
| 价格 | 突破估值区间上下沿 | `NO_REVALUE`；只更新安全边际并列入人工复盘，不单独触发估值重算 |

阈值判断必须比较“原研报模型基线”和“最新可审计数据”。没有原模型值、最新值、单位、口径或数据日期时，不得计算伪精确变化率，标记 `MANUAL_REVIEW`。

估值处置状态只能使用以下四类之一，并与后文的六类投资逻辑判断分别输出：

- `NO_REVALUE`：只有股价、量价或资金状态变化，或估值输入变化未达到阈值；维持原价值区间，只更新安全边际。
- `LIGHT_REVALUE`：单项估值输入达到阈值，能够明确对应某一种估值方法；只重算受影响方法，不自动改写综合区间。
- `FULL_REVALUE`：财报、盈利与现金流显著变化、商业逻辑变化或多项输入共振；重新执行相对估值、DCF和行业特定估值。
- `MANUAL_REVIEW`：来源冲突、缺少模型基线、事件影响无法量化、报告过期或多份权威研报冲突；先人工核验，不自动重算。

快速判例：

- 股价上涨 8%，但盈利、现金流和估值输入均未变：`NO_REVALUE`。
- 盈利预测上调 7%，其他假设未变：`LIGHT_REVALUE`，只更新盈利倍数法。
- 半年报使净利润预测上调 12%，同时现金流和利润率偏离原模型：`FULL_REVALUE`。
- 发现重大订单但原研报没有收入基线或订单口径冲突：`MANUAL_REVIEW`，不得先行抬高估值。

## 执行流程

### 0. 建立标的清单与估值基线

读取每个标的的当前权威研报，记录：研报路径、版本、估值日期、综合区间、下沿 / 中枢 / 上沿含义、三类估值结果、关键模型输入、输入阈值和最近完整重估时间。

将输入分为三类：

- 每日可更新：价格、估值倍数、可比公司估值、利率、量价和资金；
- 事件驱动：公告、订单、指引、融资、股本、重大客户和风险事件；
- 定期更新：收入、利润率、现金流、资本开支、营运资本、净债务和财务预测。

没有新数据时沿用原研报基线并标明日期，不把“今日无新值”写成零，也不要求财务指标每日刷新。

### 1. 收盘表现

逐标的计算并展示：最新收盘价、当日涨跌幅、本周涨跌幅、近5日涨跌幅、相对行业表现、成交额变化、换手率变化、当前估值区间位置。

估值位置：

```text
估值位置 = (当前价格 - 估值区间下限) / (估值区间上限 - 估值区间下限)
```

估值状态使用：低于区间下限、合理偏低、合理、合理偏高、高于区间上限。估值区间缺失时写“未提供估值区间，无法计算”。

### 2. 异常波动

说明触发规则、异常程度、可验证原因、原因类型（公司 / 行业 / 市场 / 未知）、是否需要人工核实。不要强行解释无证据的价格变化。

### 3. 公司公告

重点检查定期报告、业绩预告/快报、产销数据、重大合同、项目投产或延期、资产交易、股债融资、回购、增减持、管理层变动、监管问询、处罚、诉讼、安全事故、停复产、分红和关联交易。

对重要公告提取：核心事实、相对原预期的变化、影响的核心假设、对收入/利润/现金流/资产负债/竞争力的可能影响、影响持续时间、是否需要修改盈利预测。公告标题不能替代分析结论。

### 4. 产业新闻

重点检查供给、需求、库存、产品价格、原材料价格、产能投放或退出、开工率、政策、环保、进出口、技术路线、竞争格局、海外供需、竞争对手和上下游议价变化。

产业新闻必须回答：是否直接相关，影响收入端/成本端/资产端/估值端，影响短期/周期性/结构性，是否影响原研报行业假设，是否已反映在市场预期中。与核心假设无明确关系的普通新闻只简要记录，不升级为异常。

### 5. 关键指标

每个标的只跟踪 3 至 8 项直接对应核心假设的指标。每项输出最新值、上期值、环比、同比、趋势、是否超阈值、数据日期、来源、对核心假设的影响。数据不足时写“数据暂缺”，不得补造数字。

### 6. 估值输入变化与重算判断

逐项比较原模型值、最新值、变化幅度、触发阈值和受影响方法。至少检查盈利预测、利润率、经营现金流、订单、净债务、股本、可比估值、WACC关键输入、商业逻辑事件和模型有效期；不适用项写“不适用”，缺失项写“未获取到”。

每个标的只输出一个估值处置状态，并说明：

- 触发项与证据；
- 价格变化是否只是改变安全边际；
- 受影响的估值方法；
- 是否需要更新综合区间；
- 重算前仍然有效的旧区间及其估值日期；
- 完成重算所缺数据和人工复核事项。

多个可量化触发项并存时，在 `NO_REVALUE / LIGHT_REVALUE / FULL_REVALUE` 中采用最高等级；若基线、口径或证据不足以安全判级，最终状态改为 `MANUAL_REVIEW`，并记录潜在重估等级。`MANUAL_REVIEW` 表示证据条件不足，不等于风险高于 `FULL_REVALUE`。未真正执行重算前不得给出新的估值区间。

### 7. 核心假设关联

所有重要变化都尝试关联到具体假设，输出：假设编号、假设内容、新增证据、证据方向、影响程度、影响路径、判断置信度。

影响路径必须写成因果链，不能只写“利好 / 利空”。

### 8. 系统初判

每个标的只使用以下六类判断之一：

- 强化：新增信息支持核心假设；
- 无实质影响：变化仍在原研报预期范围内；
- 轻微削弱：不利变化出现，但核心假设仍成立；
- 明显削弱：核心假设出现较大偏离；
- 逻辑失效：预设失效条件触发，或关键假设被事实证伪；
- 信息不足：现有信息不足以可靠判断。

同时输出受影响假设、支持证据、反向证据、影响路径、影响程度、置信度（高 / 中 / 低）、是否人工复盘。

六类投资逻辑判断描述“原投资逻辑被强化还是削弱”；四类估值处置状态描述“估值模型是否需要重算”。两者可以组合，例如“逻辑强化 + NO_REVALUE”或“无实质影响 + LIGHT_REVALUE”，不得互相替代。

### 9. 人工复盘和研报更新

出现以下情况时标记“待人工复盘”：轻微削弱、明显削弱、逻辑失效；重大量价异常且原因不明；业绩预告、定期报告或重大资产事项；关键指标破阈值；触发研报失效条件；盈利预测可能明显变化；价格突破估值区间；来源冲突；置信度低；常规复盘到期。

提出研报更新建议，但未经用户确认不得覆盖原研报结论。说明建议修改章节、修改原因、需补充数据、原结论与建议结论差异。`LIGHT_REVALUE`、`FULL_REVALUE` 或 `MANUAL_REVIEW` 必须进入估值重算队列；只有真正完成估值模型更新并通过复核后，才能改写权威研报的综合估值区间。

## 输出契约

最终回复必须严格使用同目录 [template.md](template.md)。若用户明确要求简版，也保留“监控概览、重点变化、估值重算判断、待人工复盘、研报更新建议”五块。

每次运行必须生成逐标的报告和当日汇总报告，并全部同时保存 Markdown 母稿与 HTML 阅读版：

- 对扫描清单中的每个标的各生成一份完整报告，严格使用 [template.md](template.md)，命名固定为 `tools/a-share-market-dashboard/data/<六位代码>-<名称>-每日监控-YYYY-MM-DD.md` 与同名 `.html`；例如 `601208-东材科技-每日监控-2026-08-06.html`。
- 全部逐标的报告完成后，使用 [summary-template.md](summary-template.md) 生成一份组合汇总，命名固定为 `tools/a-share-market-dashboard/data/持仓今日监控汇总-YYYY-MM-DD.md` 与同名 `.html`。
- 汇总报告必须覆盖全部扫描标的，每行链接到对应逐标的 HTML；不得用汇总报告替代任何逐标的报告，也不得只为异常标的生成报告。
- 汇总报告第三章“逐标的监控索引”负责全量覆盖；第六章“研报更新建议”只列 `是否建议更新=是` 的标的，未建议更新的标的不重复列出。第六章只保留更新行动所需的优先级、建议修改章节、修改原因、所需数据和下一步，不重复估值处置状态。
- 证券代码无法确认时，文件名前缀使用 `待核实`，正文明确记录代码缺口；不得猜测代码。
- HTML 必须由本技能的 `scripts/render_report_html.py` 从对应 Markdown 母稿生成，不得另写一份可能与母稿漂移的摘要版；
- HTML 输出必须保留标题层级、表格、来源与数据缺口，并把四类估值处置状态显示为中文标签；
- 生成完成后必须确认 HTML 存在且包含“监控概览”“重点变化摘要”“估值重算队列”“来源与数据缺口”。
- 汇总 HTML 还必须包含“逐标的监控索引”，且索引中的本地链接均指向本次生成的逐标的 HTML。
- 所有 HTML 校验通过后，从 `tools/a-share-market-dashboard/` 运行 `node scripts/build.mjs`：顶部“每日监控”按钮只允许链接最新汇总 HTML，列表“每日估值监控”读取并链接各自最新逐标的 HTML。Node 不可用或构建失败时不得删除报告，应在“来源与数据缺口”及最终回复中说明“看板待重新构建”。


为便于看板稳定提取，每个标的第 6 节必须各自保留以下两行，不得改名或合并到其他段落：

```text
- 估值处置状态：NO_REVALUE / LIGHT_REVALUE / FULL_REVALUE / MANUAL_REVIEW
- 触发理由：说明导致该状态的核心证据或数据缺口
```

第二章“重点变化摘要”必须直接给出“是否需要继续阅读后续章节”的快速结论：

- 全部标的均为 `NO_REVALUE`，且不存在待人工复盘、逻辑削弱、逻辑失效或关键信息不足时，写“无需继续阅读后续章节”，并用一句话概括维持结论和下一验证点；
- 任一标的为 `LIGHT_REVALUE`、`FULL_REVALUE` 或 `MANUAL_REVIEW`，或者虽为 `NO_REVALUE` 但存在待人工复盘、逻辑削弱、逻辑失效或关键信息不足时，写“需要继续阅读后续章节”，并列出需要阅读的标的、章节和原因；
- 多标的扫描时，在第二章摘要表中为每个标的单列“是否需继续阅读”，不得只给组合层面的笼统判断。

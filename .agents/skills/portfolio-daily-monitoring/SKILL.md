# 持仓每日监控

## 定位

将持仓标的的当日新增信息映射回原研报核心假设，识别异常、逻辑强化或削弱、待人工复盘事项和研报更新需求。输出研究监控结果，不直接替用户下交易指令；除非用户明确要求操作分析，否则只提示“需要重新评估 / 复盘 / 更新”。

## 开始前确认

先确认监控时点：

- 当前日期、时间和时区；
- 是否为交易日；
- 监控是盘中还是收盘后；
- 行情、公告和产业数据的截止时间；
- 停牌、休市或数据延迟时实际采用的数据日期。

若用户没有提供完整持仓清单，先基于已给标的执行；不得凭记忆补全成本、仓位、估值区间或研报假设。缺失项统一写“未提供 / 未获取到”。

## 输入契约

每个标的尽量读取或向用户索取：

- 基础信息：股票名称、代码、行业、持仓状态、仓位、成本、动态估值区间、研报版本、最近人工复盘时间；
- 研报信息：核心投资逻辑、行业周期判断、盈利来源、竞争优势、核心假设、关键监控指标、主要风险、失效条件、估值区间、预期催化剂；
- 当日数据：收盘价、当日/本周/近5日涨跌幅、行业指数涨跌幅、成交额、换手率、近20日均成交额、公告、公司新闻、产业新闻、商品价格、库存、产能、供需、政策和同行动态；
- 监控配置：异常涨跌、成交额、相对行业偏离、估值区间、商品价格、库存、成本、产量、业绩偏离、数据频率和研报失效阈值。

核心假设必须编号，例如 `H1`、`H2`。没有编号时，先为本次监控临时编号并说明“本次临时编号”。

## 来源纪律

按以下优先级取证：

1. 证券交易所、证监会、上市公司正式公告；
2. 政府部门、统计机构、行业协会；
3. 商品交易所、权威行业数据库；
4. 上市公司官网和投资者关系记录；
5. 主流财经媒体；
6. 券商研报；
7. 其他公开信息。

未经证实的传闻、自媒体观点和匿名消息只能作为线索，不能作为确定性结论。重要信息必须记录标题、发布时间、数据日期、来源、原始事实、是否当日新增、是否已被此前监控覆盖。多来源指向同一事件时合并去重。

## 默认异常规则

用户没有配置阈值时，注明“采用默认规则”，并使用：

- 单日绝对涨跌幅达到 5%；
- 近 5 日累计涨跌幅达到 10%；
- 单日跑赢或跑输行业指数 3 个百分点；
- 成交额达到近 20 日均值 2 倍；
- 换手率显著高于近期平均；
- 价格突破动态估值区间上限或下限；
- 连续 3 个交易日明显跑输行业指数；
- 涨停、跌停、停牌或复牌；
- 价格和成交量同步异常。

股价涨跌本身不能证明基本面变化。若没有可靠证据解释异常，写“市场波动原因暂未确认”，并标记是否需要人工核实。

## 执行流程

### 1. 收盘表现

逐标的计算并展示：最新收盘价、当日涨跌幅、本周涨跌幅、近5日涨跌幅、相对行业表现、成交额变化、换手率变化、当前估值区间位置。

估值位置：

```text
估值位置 = (当前价格 - 估值区间下限) / (估值区间上限 - 估值区间下限)
```

估值状态使用：低于区间下限、合理偏低、合理、合理偏高、高于区间上限。估值区间缺失时写“未提供估值区间，无法计算”。

### 2. 异常波动

说明触发规则、异常程度、可验证原因、原因类型（公司 / 行业 / 市场 / 未知）、是否需要人工核实。不要强行解释无证据的价格变化。

### 3. 公司公告

重点检查定期报告、业绩预告/快报、产销数据、重大合同、项目投产或延期、资产交易、股债融资、回购、增减持、管理层变动、监管问询、处罚、诉讼、安全事故、停复产、分红和关联交易。

对重要公告提取：核心事实、相对原预期的变化、影响的核心假设、对收入/利润/现金流/资产负债/竞争力的可能影响、影响持续时间、是否需要修改盈利预测。公告标题不能替代分析结论。

### 4. 产业新闻

重点检查供给、需求、库存、产品价格、原材料价格、产能投放或退出、开工率、政策、环保、进出口、技术路线、竞争格局、海外供需、竞争对手和上下游议价变化。

产业新闻必须回答：是否直接相关，影响收入端/成本端/资产端/估值端，影响短期/周期性/结构性，是否影响原研报行业假设，是否已反映在市场预期中。与核心假设无明确关系的普通新闻只简要记录，不升级为异常。

### 5. 关键指标

每个标的只跟踪 3 至 8 项直接对应核心假设的指标。每项输出最新值、上期值、环比、同比、趋势、是否超阈值、数据日期、来源、对核心假设的影响。数据不足时写“数据暂缺”，不得补造数字。

### 6. 核心假设关联

所有重要变化都尝试关联到具体假设，输出：假设编号、假设内容、新增证据、证据方向、影响程度、影响路径、判断置信度。

影响路径必须写成因果链，不能只写“利好 / 利空”。

### 7. 系统初判

每个标的只使用以下六类判断之一：

- 强化：新增信息支持核心假设；
- 无实质影响：变化仍在原研报预期范围内；
- 轻微削弱：不利变化出现，但核心假设仍成立；
- 明显削弱：核心假设出现较大偏离；
- 逻辑失效：预设失效条件触发，或关键假设被事实证伪；
- 信息不足：现有信息不足以可靠判断。

同时输出受影响假设、支持证据、反向证据、影响路径、影响程度、置信度（高 / 中 / 低）、是否人工复盘。

### 8. 人工复盘和研报更新

出现以下情况时标记“待人工复盘”：轻微削弱、明显削弱、逻辑失效；重大量价异常且原因不明；业绩预告、定期报告或重大资产事项；关键指标破阈值；触发研报失效条件；盈利预测可能明显变化；价格突破估值区间；来源冲突；置信度低；常规复盘到期。

提出研报更新建议，但未经用户确认不得覆盖原研报结论。说明建议修改章节、修改原因、需补充数据、原结论与建议结论差异。

## 输出契约

最终回复必须严格使用同目录 [template.md](template.md)。若用户明确要求简版，也保留“监控概览、重点变化、待人工复盘、研报更新建议”四块。

## 完成前检查

- [ ] 监控日期、数据截止时间、盘中/收盘状态明确；
- [ ] 每项关键结论有来源、数据日期或明确缺口；
- [ ] 事实、推断、传闻和用户观点已区分；
- [ ] 异常均写明触发规则；
- [ ] 重要变化均尝试关联核心假设编号；
- [ ] 无证据时没有强行解释股价；
- [ ] 没有编造持仓成本、仓位、估值区间、指标值或公告；
- [ ] 系统初判只使用六类限定判断；
- [ ] 待人工复盘事项可执行；
- [ ] 没有自动覆盖原研报或给出未经请求的买卖指令。

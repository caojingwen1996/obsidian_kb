# 风险演绎观察工作流

## 执行准备

读取项目 AGENTS.md、schema.md、page-types.md、index.md，以及最新 [风险观察与演绎](../../../wiki/concepts/冰冰小美-framework-风险观察与演绎.md) 第二层和 [共享交接契约](../bbxm-risk-identification/references/handoff-contract.md)。定位已有模型、T0 与上一轮记录，核对观察对象、模型版本和任务状态。

复用适用的本轮信息处理结果；缺失、过期或缺少关键事实时由信息处理补充。缺模型先识别；类型、来源、关键变量或机制仍不充分时保留候选模型并等待证据，不对未建立的风险强给方向。已有模型且只需初始化时可复用建模用的上游结果，不额外扫描。

## Step 1. 建立风险观察基准

以具体版本 Risk Model 的类型、来源、关键变量、传导关系和风险表现建立 T0。已有基准时读取并保留，不每轮重建。记录模型快照时点与各变量真实观测时点，不能把过期数据冒作当前值。

确定本轮与比较窗口。继承上游信息窗口，并在风险层选择可比较的观测区间；这不重新定义上游事件。比较同一对象、指标口径、单位和频率。只有本轮数据、没有历史可比证据时输出 T0、方向证据不足、任务状态已建基准；有明确的历史证据时可引用并说明如何建立比较，不能倒推当时预期。

## Step 2. 观察风险演绎力量

读取上游事件、归纳和证据，筛选影响风险来源、风险应对、关键变量及表现的事件。为相关或排除项记录理由；不重做原始事件提取、分类或共同变量提炼。对已经处理且无事实增量的事件不重复计为风险冲击；数据修订保留获知时间与旧判断。

依次观察：

1. **风险来源**：推动形成或扩大的力量有何变化，哪些证据支持、哪些反驳。
2. **风险应对**：缓解力量是否出现，区分宣布、执行与传导见效，不把表态当成风险消失。
3. **关键变量与表现**：比较 T0、上一轮、本轮值或定性状态，评估两股力量哪方占优势；不同变量冲突时逐项解释，不编造加权总分。
4. **风险方向**：相对上一轮与相对 T0 分别判断，避免将“比最坏时改善”写成“当前持续改善”。

| 方向 | 判定要求 |
|---|---|
| 增加 | 来源强化或关键变量恶化，应对不足以抵消；写出支持、反证和机制 |
| 维持 | 有可比观测支持风险状态无实质变化；明确维持在什么基准状态，不能只因无新闻或力量数量相等而判定 |
| 减弱 | 来源衰减或应对见效，并有关键变量或风险表现改善支持；区分短暂波动与实际缓解 |
| 证据不足 | 缺基准、口径不可比、数据失败/过时或关键证据冲突未解；列具体缺口 |

“重新增强”需此前减弱与当前增加两个阶段的证据，方向仍记增加。反复事件在较长可比窗口内观察，不能用单日反弹抹去中期恶化。

按 [输出模板](template.md) 记录本轮增量风险时间轴；引用上游 Event 并增加风险影响解释，不复制整个上游信息时间轴。保留 T0 和历史记录，晚到事件注明发生与本轮获知时间；无相关新增事件可以没有新增行，不伪造连续变化。

## Step 3. 判断风险持续性

分别分析风险来源是否持续、应对力量能否持续兑现、关键变量是否形成趋势。输出短期 / 中期 / 长期或待验证，说明对应的日期窗口或事件周期及依据；不机械套用统一天数。短期减弱不等于长期风险消失。

按证据给出增加、维持、减弱的条件路径、反证和下一检查节点；没有足够依据的路径标为待验证，不强填未来事件、概率或阈值。条件演绎与已发生事实分开。

## Step 4. 动态检验 Risk Model

| 情况 | 动作 |
|---|---|
| 原风险继续且模型有效 | 沿用身份和版本，追加状态，任务状态继续观察 |
| 信息不足而无法判断模型有效性 | 模型有效性待验证，任务状态等待证据；不把缺数据当作机制失效 |
| 风险减弱 | 检查结束条件；未满足则继续观察，保留残余风险 |
| 风险消失或满足明确结束条件 | 记录依据、时点、残余风险和重新开启条件，标已结束，保留历史 |
| 风险性质或传导机制改变 | 标原模型失效、任务状态需要重识别；将新旧证据和原因交给风险识别 |

结束条件遵守 Agent 编排的操作补充：一次减弱不自动结束。重识别按共享契约限制同次循环；成功得到新模型后建立新版本基准，不直接把新旧模型状态串成同口径趋势。不能仅因数值变坏或方向反转就认定风险性质改变。

## 交付与检查

用 [输出模板](template.md) 分别交付方向、持续性、模型有效性和任务状态。核对模型版本、T0、上一轮引用、证据可知时间和比较口径；没有充分证据不判维持、结束或重新增强。

按共享契约默认在 Risk 目录先保存完整逐轮记录再更新定位表，用户明确仅对话时不落盘；只更新分析记录，不替上游推进失败来源游标。报告本轮真正完成的内容，不把一次运行声称为持续监控已启动。

- 先保存完整 Markdown 母稿，再读取并执行 [通用 HTML 输出工作流](../bbxm-html-report/workflow.md) 和样式规范，生成同名 HTML；逐项核对模板章节、数值、状态、来源与缺口一致，并完成语法和实际渲染检查。按共享契约登记两种格式，最终优先交付 HTML，附 Markdown。HTML 生成或验收未完成时保留母稿并报告缺项，不声称双格式交付完成。

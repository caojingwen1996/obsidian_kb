# 资金面分析

## 定位

这是市场、指数、板块和个股资金面分析的独立项目级入口。它回答：谁在买、谁在卖，钱从哪里来、流向哪里、能否持续、价格是否确认、撤退时谁来承接，以及当前资金结构允许什么动作。

本技能参考华泰证券 2021 年《A股择时之资金面指标测试》的资金来源分类，并吸收 F3/F5/F7 日频监测思路。两者只提供研究起点：本技能不是华泰模型复刻，F3/F5/F7 也不是论文原生“三因子”。同时吸收 LSEG `equity-research` 技能的研究骨架，把共识预期、基本面证据、价格表现、估值和宏观背景转化为“基本面与价格预期校验”，只用于校验资金持续性和预期差，不替代资金流证据。

## 路由边界

- 用户主动作是资金面、资金来源、交易方画像、谁在买卖、资金共振或资金驱动的仓位判断：使用本技能。
- 用户要求竞争格局、流动性和情绪位置组成的完整三要素分析：使用 `bbxm-three-factor-analysis`；本技能结果可以作为其流动性输入。
- 用户只要求风险增强、持平、减弱或重新增强：使用 `bbxm-risk-identification`。
- 用户主动作是信息处理、事件结构化与归纳，或调用信息的金融处理框架：使用 `information-processing`（信息处理）；资金状态和参与者判断仍由本技能负责。
- 用户要求十年财务或完整财报研究：使用 `financial-report-research`；用户要求DCF、公允价值、目标价或交易溢价：使用 `个股估值计算`，资金面只作为交易溢价的一个输入。
- 用户提供交割单或买卖记录要求复盘：使用 `bbxm-trade-ticket-review`。

## 唯一输出契约

最终回复必须读取并严格使用同目录 [template.md](template.md)。

1. 保留模板全部一级、二级标题及其顺序。
2. 不得自行压缩为聊天版、简版或自由格式，除非用户明确要求简版；即便简版，也不得删除数据缺口、代理边界、行动条件和失效条件。
3. 缺少信息时填写“待核验”“证据不足”或“不适用”，不得删除字段。
4. 先给资金状态与行动，再展开证据；新增资金和已有持仓必须分开。
5. 分析完成后必须生成 HTML 阅读版；除非用户明确要求“只在聊天里回答 / 不生成文件”，否则不能只给 Markdown 或聊天版结论。

## HTML 版本契约

资金面分析属于动态自动化工件。分析结束后生成一个独立 HTML 快照，并在最终回复中给出保存路径。

### 保存位置

- 若分析对象已经有明确产业或主题分类，保存到 `sources/automations/<分类>/` 下对应目录。
- 若分类尚未确定，保存到 `sources/automations/temp/`，并在最终回复说明“分类待确认”。
- 不保存到 `workbench/targets/`，不保存到正式 `wiki/` 页面目录。
- 不因新增 HTML 快照更新 `index.md`；它不是正式知识页。
- 需要记录维护动作时，追加 `log.md`。

### 命名与覆盖

- 默认文件名：`YYYY-MM-DD-<分析对象>资金面分析.html`。
- 如果同一天同一对象需要多次快照，使用 `YYYY-MM-DD-HHmm-<分析对象>资金面分析.html`。
- 不覆盖旧版 HTML，除非用户明确要求“覆盖旧版”或“原地更新”。
- 如果更新现有 HTML，先说明将覆盖哪个文件，并保留关键数据截止时间。

### HTML 内容要求

- HTML 必须完整承载 `template.md` 的 11 个一级章节及其顺序。
- HTML 首屏必须显示分析对象、代码或对象层级、分析截止时间、比较窗口、资金状态、新增资金动作和已有持仓动作。
- 第 2 章必须先用“指标 / 数值 / 解读”三列表呈现资金面与筹码结构；核心数值右对齐，结论性数值可加粗，不把读者首先暴露在宽而密的审计表中。
- 第 5 章必须先用“价位 / 性质 / 意义或确认标准”表呈现关键价位。价位来自可复算数据，性质使用克制的标签，不得把技术位写成必然支撑或阻力。
- 关键价位表后固定展示“成交量与趋势确认”三列表，列出均量、放缩量倍数、成交额、换手、上涨与回调量能，以及突破 / 跌破 / 回踩的验证状态；不能只用“放量 / 缩量”一句话替代。计算口径按下文“成交量与趋势确认规则”，缺口保留在表中。
- 资金结构存在反向证据时，在核心表后增加“结构矛盾”提示框，写清谁在流入、谁在流出、是否独立以及为何影响趋势判断。
- 表格、证据、缺口、行动条件、失效条件、来源与使用边界都要进入 HTML，不得只生成摘要卡片。
- HTML 中必须保留“交易方画像与数据层独立性”章节，明确金额方向与账户身份边界。
- 对 `未获取到 / 待核验 / 不适用` 的项目照样展示，不得为了版面整洁删除。
- 样式可以复用已有资金面 HTML 的视觉风格；不要为每次分析引入与任务无关的大型前端依赖。

### HTML 视觉规范

- 读取并复用 [assets/report-style.css](assets/report-style.css)；交付单文件 HTML 时把样式内联，避免依赖外部网络或库外绝对路径。
- 视觉基调采用白底、浅灰表头、细分隔线、适度圆角和充足留白；避免深色渐变大标题、过多阴影、粗重网格线和装饰性仪表盘。
- 首屏只保留标题、简短副标题、元信息和三张以内的决策卡；正文按阅读顺序展开，不把所有指标都做成卡片。
- 核心表优先使用三列结构。数值列使用等宽数字并右对齐；单位与日期写在数值或指标中，不单独制造窄列。
- 性质与状态使用语义标签：中性/观察为灰蓝，确认/有利为绿色，警戒/压力为琥珀色，失守/流出为红色。颜色只辅助阅读，文字必须独立表达结论。
- “结构矛盾、风险升级、数据缺口”使用淡红或淡琥珀提示框；普通说明使用浅蓝提示框。提示框控制在一段话内，先写结论，再写证据边界。
- 来源和口径使用正文末尾的小字号脚注。不得把“非一手来源、需核实原文”等限定藏进悬浮提示或颜色中。

### HTML 验证

提交前至少检查：

- HTML 文件存在；
- 包含 11 个 `h2` 章节，且章节标题与模板一致；
- 包含资金状态、新增资金动作、已有持仓动作、分析截止时间；
- 包含“交易方画像与数据层独立性”和“来源与使用边界”；
- 包含“资金面与筹码结构”“关键价位与确认标准”两张核心表及至少一类语义标签；存在反向证据时包含“结构矛盾”提示框；
- 包含“成交量与趋势确认”表及其比较窗口、计算口径和数据缺口；成交量、成交额与资金净流入没有混用；
- 数值列有明确对齐样式，移动端表格可以横向滚动且不会压缩成不可读窄列；
- 不含 Unicode 替换字符（U+FFFD）和明显中文乱码；
- 本地相对链接能解释其指向，无法确认时在来源边界中标注。

## 时间窗口

默认比较三个窗口：

1. 当日或最新交易日：识别边际变化与异常值；
2. 近 5 个交易日：识别短期方向、持续性和反复；
3. 近 20 个交易日：识别中期趋势、历史位置和拥挤程度。

数据频率不支持时，使用最接近的可比窗口，并说明替代方式。单日信号不能单独升级为趋势判断或 `buy`。

## 数据与证据纪律

### 来源优先级

优先使用本地 `tushare-data` MCP 中已经暴露且当前账号可用的工具获取基础事实、价格、估值、资金分档 / 大小单、融资融券、财报、分红和指数成分；其次使用交易所、登记结算、监管与基金公告等一手数据；再次使用 AKShare 等口径透明的公开数据封装、专业数据平台和券商研究；最后才使用媒体、自媒体或用户转述。每个关键数据记录来源、时点、单位、覆盖范围和计算方式。

### Tushare MCP 优先使用规则

当前 `tushare-data` MCP 只把 2000 积分账号可用或已验证可用的工具作为优先层。执行资金面分析时，先检查当前会话是否已热加载 `tushare-data` MCP；若未热加载，可通过本地 stdio server `tools/tushare-data/scripts/mcp_server.py` 调用。MCP 调用失败、接口无权限、无数据、字段缺失或对象不适用时，不得把失败解释为“没有该事实”，应回退到 AKShare / 交易所 / 公开页面，并在来源说明中写明回退原因。

#### A 股个股融资融券强制规则

分析 A 股个股时，融资融券 / F3 必须优先使用本地 `tushare-data` MCP 暴露的 `get_margin_detail`。不要因为当前会话的可见工具列表没有直接出现 `get_margin_detail` 就跳过；若未热加载，必须先尝试通过 `tools/tushare-data/scripts/mcp_server.py` 的 stdio JSON-RPC 调用。

推荐调用参数：

```json
{
  "name": "get_margin_detail",
  "arguments": {
    "ts_code": "<证券代码，如 002270.SZ>",
    "start_date": "<YYYYMMDD，覆盖至少近20个交易日>",
    "end_date": "<YYYYMMDD，分析截止日>",
    "limit": 40,
    "use_cache": true
  }
}
```

报告必须在数据审计中记录 `get_margin_detail` 的返回状态、`row_count`、最新 `trade_date`、覆盖窗口，以及核心字段：`rzye`（融资余额）、`rzmre`（融资买入额）、`rzche`（融资偿还额）、`rqye`（融券余额）、`rzrqye`（融资融券余额）。F3 计算优先使用 `融资净买入 = rzmre - rzche`，并分别汇总最新交易日、近 5 个可得交易日和近 20 个可得交易日；同时记录融资余额在窗口首尾的变化。

只有在 `get_margin_detail` 调用失败、接口无权限、返回空行、字段缺失或对象不适用时，才回退 AKShare / 交易所 / 东方财富 / CFI 等公开融资融券来源。回退时必须写明失败原因和已尝试的本地 MCP 路径；不得直接写“当前会话未暴露工具入口”作为最终缺口。

### 三类证据标签

- 已验证事实：可以回溯到明确数据和口径。
- 统计代理：指标与资金主体相关，但不能确认账户身份。
- 经验推断：由产品特征、交易行为或历史模式推测，必须单列且降低权重。

### 基本面与价格预期校验

资金面结论必须回答“资金在交易什么预期、价格是否已经反映这组预期，以及预期是否有基础证据支撑”。按 `equity-research-integration.md` 检查：

- 共识预期或市场叙事：盈利、分红、订单、政策、主题或周期预期；没有一致预期数据时写“未获取到 / 待核验”，不得虚构 FY1 / FY2。
- 基本面证据：收入、利润、现金流、负债、资本开支和分红是否支持资金叙事；优先使用 `get_financial_statements` 和 `get_dividend_history`。
- 价格表现：当日、近 5 日、近 20 日及必要时 YTD / 1Y / 52 周位置；优先使用 `get_stock_daily`。
- 估值位置：PE、PB、PS、股息率、市值和历史或同业背景；优先使用 `get_stock_valuation`。
- 宏观背景：利率、信用、汇率、通胀、政策和行业景气是否为资金顺风或逆风；MCP 未覆盖时使用公开来源或标记缺口。

这些字段只能用于解释资金持续性、承接理由、价格是否透支预期和下一验证点，不能把“基本面好 / 估值低 / 分红高”直接写成“长期资金已买入”，也不能输出完整基本面评级、目标价、DCF、公允价值或脱离资金面的买卖建议。

### 交易方结论等级

交易方方向只能使用以下证据等级，不用星级或任意评分制造精确感：

- 直接测量：数据直接对应已识别账户、持有人或法定披露主体；
- 可靠推断：至少两项相互独立证据方向一致，其中至少一项提供身份锚点；
- 弱推断：只有单一身份代理，或证据之间存在覆盖重叠；
- 不可知：没有直接身份数据、关键数据未获取到或冲突无法解释。

金额方向与账户身份必须分开写。可以确认“大额订单净卖”，不等于确认“机构净卖”；可以确认“小单净买”，不等于确认“全部由散户接盘”。

### 禁止事项

- 不把特大单直接写成“机构真实买入”或“主力建仓”。
- 不把 ETF 申购直接写成“国家队买入”。
- 不把小单直接写成全部散户行为。
- 不把 F3、F5、F7 或不同平台的资金指标机械相加为全市场净流入。
- 不用任意权重生成“共振得分”；如使用评分，必须给出可追溯回测与参数依据。
- 不把资金流数据脱离价格、广度、筹码供给和连续性单独用于下单。
- 不把同一成交在资金分档、龙虎榜、融资交易和 ETF 成分股交易中的重复呈现当成多源共振。
- 不用“未获取到”推导“没有”，也不用风险接口返回空值推导无质押、无解禁或无减持。

## 分析流程

### 1. 先采集并暂存数据审计

逐项检查数据时点、频率、覆盖对象、单位和统计口径。先列出哪些字段来自 `tushare-data` MCP，尤其是 `get_stock_moneyflow` 的订单规模代理、`get_margin_detail` 的融资融券代理、`get_financial_statements` 的财报数据、`get_stock_valuation` 的估值交易指标和 `get_dividend_history` 的分红数据；哪些字段来自 AKShare / 交易所 / 公开页面；哪些字段未获取到。特别检查 ETF 样本是否覆盖目标对象、融资与订单流是否可能重叠、不同日期是否使用了不同版本或估算方法。若没有共识预期、宏观或行业景气数据，单列为缺口，不得用资金流反推共识。

数据审计是分析前置工作，但输出时按 `template.md` 放在后段“数据审计”章节，不作为第 2 章展开。正文先给资金来源、F3/F5/F7 与交易方画像，让读者先看到资金结构，再回看数据质量。

第 10 章“数据审计”只使用一张“数据采集清单”，不要再拆出“详细审计表”或单独的“基本面与价格预期校验”表。采集清单按 L0-L7 开头，之后只追加与资金流向、承接、抛压或资金持续性直接相关的品类，例如质押和筹码供给；证券身份、日线行情、估值、财报、分红、市场预期和宏观背景不进入本清单，除非它们直接构成资金流向证据。每一行都同时记录状态、最新时点、观察窗口、来源、口径与覆盖范围、数据性质和缺口影响。

### 2. 建立资金来源全景

按 reference 检查适用于对象的资金类型：外资与跨境、杠杆、公募与 ETF、产业资本、保险与长期资金、私募与信托、券商资管、个人资金，以及 IPO、增发、减持、解禁等筹码供给。

输出第 2 章时只列已经取得数据、对象天然适用、或对结论有实质影响的资金来源。不要把所有资金池机械铺成一张“未获取到”大表；大面积未获取到、不可穿透或不适用的资金池，放到第 10 章“数据审计”和第 4 章“不可用 / 不适用层”中说明。未取得不等于没有，必须说明影响，但不要让缺口表喧宾夺主。

### 3. 建立交易方画像与数据层独立性

在资金来源全景和 F3/F5/F7 面板之后，回答谁在主买、谁在主卖、谁在承接，并说明这些判断与流入机制之间的关系。

个股默认检查以下交易方；市场、指数或板块不适用的主体保留并标记“不适用”：

- G 国家队或政策性资金；
- I 内资机构；
- N 北向或跨境资金；
- Q QFII 等境外机构；
- H 游资、量化和短线交易资金；
- M 融资等杠杆资金；
- R 个人或小额订单代理；
- C 产业资本、上市公司、控股股东和内部人。

交易方画像章节必须采用 `template.md` 中的展开格式：标的类型声明、一句话交易方画像、画像表、核心结论、交易方结构特征、证据详情、不可用 / 不适用层、数据层独立性、交叉验证总结、信号冲突与不可知。每类交易方分别记录方向、强度、证据、证据等级、反证和不可知项。若无法穿透账户身份，交易方名称后加“代理”，不得省略代理边界。

再按数据渠道建立数据层表，至少检查适用的资金分档、跨境、融资融券、大宗交易、龙虎榜、回购、增减持、股东户数、ETF、质押、解禁和筹码。逐对判断：

- 独立：来源主体、统计链路和样本不重叠；
- 部分独立：身份或余额独立，但成交金额可能进入另一订单流；
- 非独立：同一成交的子集、重分类或派生值；
- 无法判断：口径不足，不能用于提高证据强度。

龙虎榜成交属于全市场成交和资金分档的子集，不能与特大单重复计票；融资买入会进入订单流，融资余额的账户属性较独立，但买入金额与 F5 部分重叠；ETF 申赎最终可能转为成分股交易；筹码成本由价格成交推导，与量价半独立。完整规则见 `indicator-boundaries.md`。

数据冲突时不做多数投票。先解释覆盖范围、身份锚点、时间窗口和重叠关系，再判断是“局部买、全局卖”“价格先修复、结构未修复”还是证据不足。

### 4. 判断流入机制

把观察到的资金支持归入且可并列：

- 场外真实增量：新资金进入市场或对象；
- 存量迁移：资金从其他资产、行业或个股切换而来；
- 减量报团：总体资金下降，剩余资金集中少数方向。

若无法区分，标记“机制待验证”。不要把局部相对强势自动解释为全市场新增资金。

### 5. 分析 F3/F5/F7 日频面板

分别评价方向、强度、持续性、稳定性、价格响应和数据质量：

- F3：融资净买入，观察杠杆资金边际变化；
- F5：特大单净买入，观察大额主动交易代理；
- F7：ETF 估算净申赎，观察 ETF 份额变化形成的申赎代理。

`tushare-data` MCP 当前可通过 `get_margin_detail` 优先获取 F3 融资融券代理，通过 `get_stock_moneyflow` 优先获取 F5 大额订单 / 资金分档代理；F7 ETF 估算净申赎仍需使用 AKShare、交易所、基金公告或其他公开来源。A 股个股的 F3 不允许直接跳过 `get_margin_detail`；即使当前会话未热加载该工具，也要先通过 `tools/tushare-data/scripts/mcp_server.py` 本地 stdio server 尝试调用。若 MCP 调用失败、接口无数据或字段缺失，保留“未获取到 / 待核验”并回退公开来源，不得用成交额、换手率或市值变化代替资金流。

指标不可用或不适用于对象时保留该行并写明原因。不得因为三项中两项为正就自动称为“共振流入”。

### 6. 检查供给与退出路径

检查股票融资供给、减持、解禁、套牢盘、高位筹码、赎回、杠杆平仓和资金集中度。回答：当前流入需要承接多少筹码，资金停止后谁会接盘，最可能怎样退出。

### 7. 做交叉验证

至少检查：

- 价格响应：净流入后价格是否上涨、企稳或仍冲高回落；
- 成交与换手：放量推进、放量滞涨、缩量反弹还是恐慌换手；
- 上涨广度：多数成分参与还是少数权重维持；
- 相对强弱：相对市场、行业或基准是否改善；
- 连续性：当日信号能否延续到 5 日和 20 日；
- 筹码供给：新增买盘是否足以覆盖新增供给和潜在抛压。
- 基本面与价格预期：资金方向是否被财报、分红、估值、价格位置、宏观背景或行业景气支持；市场共识可能错在过度乐观、过度悲观，还是证据不足。

资金与价格冲突时，不猜“吸筹”或“洗盘”；先写冲突事实，再降低置信度并列下一验证点。

#### 成交量与趋势确认规则

在第 5 章关键价位表之后、综合交叉验证表之前，固定输出成交量与趋势确认表。先展示数值，再用白话说明“交易是否更活跃、价格是否有效推进、回调时卖压是否收敛”；量能只用于验证，不单独证明资金身份、净流入或趋势反转。

- **数据与单位**：A 股优先从 `get_stock_daily` 取得 `vol`、`amount`，从 `get_stock_valuation` 取得 `turnover_rate`。Tushare `daily` 的 `vol` 为手、`amount` 为千元；展示时显式换算为万手、亿元，保留原字段和来源。换手率保留总流通股本或自由流通股本口径，不混用；市场、指数、板块需注明成交统计范围与去重方式，不将 ETF 自身成交量冒充板块成交量。
- **固定基线**：以最近完整交易日为 t，展示当日成交量、此前 5 日均量、此前 20 日均量，以及“当日量 / 此前 5 日均量”和“当日量 / 此前 20 日均量”。此前 N 日指 t-1 至 t-N，不含 t；这是日成交量相对均量倍数，不等同软件的盘中“量比”。成交额、换手率同样展示当日值及此前 5 / 20 日均值。记录实际起止日期和样本数，不用成交额倍数替代成交量倍数。
- **量能趋势**：比较近 5 日（含 t）与再前 5 日两个不重叠窗口的日均成交量，并列各自价格涨跌幅；涨跌幅从窗口首日前一交易日收盘计算至末日收盘。需要前 20 日基线时至少采集 21 个完整交易日，价格比较另保留所需前收盘；跨除权除息需统一可比价格口径，成交量不机械乘价格复权因子。
- **上涨与回调**：在同一近 20 日窗口（含 t），以可比的收盘日涨跌分组，列上涨日 / 下跌日的天数、日均成交量及两者比值；平盘日单列且不混入两组。另对最近一段已识别的上涨与随后回调列明日期、涨跌幅和日均量，检查回调量 / 上涨量；没有可识别完整段落就写“待形成”，不强行凑波段。两组日均量比较只是描述，不能用它反推真实买卖盘金额。
- **关键位事件**：对突破、跌破及回踩分别写“已发生 / 未发生 / 待确认”，对应具体价位、事件日量 / 事件日前 20 日均量、收盘位置、后续持续或回踩表现，以及同窗口资金方向。未来交易日尚未发生时不得提前确认。结合价位位置区分放量推进、放量滞涨、缩量反弹、缩量回调和放量下跌；缩量回调不自动等于洗盘，放量下跌不自动等于出清完成。
- **阈值与失效**：若使用倍数或持续天数作为行动条件，注明来自用户规则、历史分布还是本次观察约定；未回测的阈值不写成通用有效标准。收盘失守关键位应及时记录风险，不因“尚未放量”忽略破位；量能与资金只影响确认强度，不替代用户既定风控。
- **异常与缺口**：盘中数据不能直接与完整日量判定放缩量，只与历史同一时刻累计量比较，缺少同时间样本时等待收盘。停牌零量、缺失记录和上市不足导致样本不全时披露处理与实际样本数，不以补零凑满窗口；均量为零或上涨 / 下跌组为空时，比值写“不可计算”。涨跌停、复牌、股本变化等影响可比性的事件单列说明，不静默删除异常日。

### 8. 给出资金状态

最终状态只能选择一个：

- `共振流入`：多个相互独立的资金来源持续流入，至少包含一种可识别的场外增量或长期配置力量，且价格、广度和相对强弱确认。
- `结构性流入`：资金集中进入部分对象，整体或其他资金来源未同步，仍有明确承接但不是全面增量。
- `多空分歧`：主要资金来源方向相反，或资金流与价格、广度明显冲突，尚无一方取得稳定主导。
- `结构性流出`：部分主要资金持续撤离，但仍有局部承接、迁移或托底。
- `共振流出`：多个独立资金来源持续撤离，价格、广度与筹码压力共同确认，承接显著收缩。
- `证据不足`：缺少关键当前数据、窗口不可比、口径冲突或证据无法解释。

### 9. 映射行动与仓位

行动只使用：`buy / sell / reduce / wait / observe / review`。

#### 新增资金

- `buy`：资金至少达到结构性流入，且持续性、价格响应、广度或相对强弱及风险预算得到确认。首笔通常只用计划仓位的一部分；不能仅凭单日 F 信号买入。
- `wait`：方向有改善但确认条件未完成，明确等待什么数据。
- `observe`：证据不足、分歧严重、对象不适用或风险预算缺失，不投入新增资金。
- `review`：已有研究或计划需要重审，但资金面本身不足以决定投入。

#### 已有持仓

- `sell`：原资金假设或持仓逻辑的失效条件已确认，承接持续恶化且退出仍可执行。
- `reduce`：资金状态恶化、价格确认转弱或仓位超过承受能力，但尚未达到全部退出条件。
- `wait`：持仓逻辑仍成立、仓位可承受，资金信号未确认方向；不等于放弃风控。
- `review`：缺少成本、仓位、原计划或当前数据，先复核再行动。
- `observe`：仅用于没有明确操作需求的跟踪仓或观察仓。

#### 仓位表达

优先使用用户已有的风险预算和计划仓位。若没有风险预算，不编造“最佳仓位”，只给条件化区间：

- `observe`：新增资金 0%；
- 试探性 `buy`：计划仓位的 10%—30%，并写明升级条件；
- 已确认但仍有分歧：不超过计划仓位的 50%；
- `reduce`：说明降低现有仓位的 1/4—1/2，或降到用户预设风险线；
- `sell`：仅在失效条件确认时退出剩余风险仓位。

这些是缺少用户专属风控时的表达上限，不是普适最优比例。不得因为“共振流入”自动建议满仓或加杠杆。

## 最终检查

提交前逐项确认：

- 已使用模板全部章节；
- 已写分析截止时间和三个比较窗口；
- 已优先检查 `tushare-data` MCP 可覆盖的数据项，包括 `get_stock_moneyflow` 和 `get_margin_detail`；A 股个股融资融券必须记录 `get_margin_detail` 是否通过本地 stdio server 调用、返回 `row_count`、最新 `trade_date`、近 5 日 / 近 20 日融资净买入和融资余额变化，并为 MCP 未覆盖或失败的数据写明回退来源和原因；
- 已区分事实、代理和推断；
- 已检查资金来源而不只看 F3/F5/F7；
- 已形成交易方画像，并将金额方向与账户身份分开；
- 已检查数据层独立性，未把龙虎榜、资金分档、融资交易和 ETF 成分股交易重复计票；
- 已解释方向冲突并保留国家队、北向、QFII 等不可知项；
- 已披露重叠统计和身份代理边界；
- 已做价格、广度、相对强弱、筹码与连续性交叉验证；
- 已输出成交量与趋势确认表：当日与此前 5 / 20 日基线、两个不重叠 5 日窗口、上涨 / 下跌及上涨 / 回调量能、关键位事件；已核对单位、样本数、除权及盘中可比性，未把成交活跃等同资金净流入；
- 已用“基本面与价格预期校验”检查共识预期、基本面证据、估值、价格表现和宏观背景对资金持续性的影响；未获取到的项目已列为缺口；
- 资金状态只使用限定词汇；
- 新增资金与已有持仓分别给出行动、仓位条件和失效条件；
- 关键数据缺失时没有给无条件 `buy`。

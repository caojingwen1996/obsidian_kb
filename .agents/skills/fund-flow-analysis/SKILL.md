# 资金面分析

## 定位

这是市场、指数、板块和个股资金面分析的独立项目级入口。它回答：谁在买、谁在卖，钱从哪里来、流向哪里、能否持续、价格是否确认、撤退时谁来承接，以及当前资金结构允许什么动作。

本技能参考华泰证券 2021 年《A股择时之资金面指标测试》的资金来源分类，并吸收 F3/F5/F7 日频监测思路。两者只提供研究起点：本技能不是华泰模型复刻，F3/F5/F7 也不是论文原生“三因子”。同时吸收 LSEG `equity-research` 技能的研究骨架，把共识预期、基本面证据、价格表现、估值和宏观背景转化为“基本面与价格预期校验”，只用于校验资金持续性和预期差，不替代资金流证据。

## 路由边界

- 用户主动作是资金面、资金来源、交易方画像、谁在买卖、资金共振或资金驱动的仓位判断：使用本技能。
- 用户要求竞争格局、流动性和情绪位置组成的完整三要素分析：使用 `bbxm-three-factor-analysis`；本技能结果可以作为其流动性输入。
- 用户只要求风险增强、持平、减弱或重新增强：使用 `bbxm-risk-identification`。
- 用户要求过滤一条新闻、政策、公告或研报：使用 `bbxm-information-filter-flow`。
- 用户要求完整公司研究、十年财务、DCF、公允价值或目标价：使用 `bbxm-equity-research`；资金面只作为其中一个输入。
- 用户提供交割单或买卖记录要求复盘：使用 `bbxm-trade-ticket-review`。

## 唯一输出契约

最终回复必须读取并严格使用同目录 [template.md](template.md)。

1. 保留模板全部一级、二级标题及其顺序。
2. 不得自行压缩为聊天版、简版或自由格式，除非用户明确要求简版；即便简版，也不得删除数据缺口、代理边界、行动条件和失效条件。
3. 缺少信息时填写“待核验”“证据不足”或“不适用”，不得删除字段。
4. 先给资金状态与行动，再展开证据；新增资金和已有持仓必须分开。
5. 分析完成后必须生成 HTML 阅读版；除非用户明确要求“只在聊天里回答 / 不生成文件”，否则不能只给 Markdown 或聊天版结论。

## HTML 版本契约

资金面分析属于动态自动化工件。分析结束后生成一个独立 HTML 快照，并在最终回复中给出保存路径。

### 保存位置

- 若分析对象已经有明确产业或主题分类，保存到 `sources/automations/<分类>/` 下对应目录。
- 若分类尚未确定，保存到 `sources/automations/temp/`，并在最终回复说明“分类待确认”。
- 不保存到 `workbench/targets/`，不保存到正式 `wiki/` 页面目录。
- 不因新增 HTML 快照更新 `index.md`；它不是正式知识页。
- 需要记录维护动作时，追加 `log.md`。

### 命名与覆盖

- 默认文件名：`YYYY-MM-DD-<分析对象>资金面分析.html`。
- 如果同一天同一对象需要多次快照，使用 `YYYY-MM-DD-HHmm-<分析对象>资金面分析.html`。
- 不覆盖旧版 HTML，除非用户明确要求“覆盖旧版”或“原地更新”。
- 如果更新现有 HTML，先说明将覆盖哪个文件，并保留关键数据截止时间。

### HTML 内容要求

- HTML 必须完整承载 `template.md` 的 11 个一级章节及其顺序。
- HTML 首屏必须显示分析对象、代码或对象层级、分析截止时间、比较窗口、资金状态、新增资金动作和已有持仓动作。
- 表格、证据、缺口、行动条件、失效条件、来源与使用边界都要进入 HTML，不得只生成摘要卡片。
- HTML 中必须保留“交易方画像与数据层独立性”章节，明确金额方向与账户身份边界。
- 对 `未获取到 / 待核验 / 不适用` 的项目照样展示，不得为了版面整洁删除。
- 样式可以复用已有资金面 HTML 的视觉风格；不要为每次分析引入与任务无关的大型前端依赖。

### HTML 验证

提交前至少检查：

- HTML 文件存在；
- 包含 11 个 `h2` 章节，且章节标题与模板一致；
- 包含资金状态、新增资金动作、已有持仓动作、分析截止时间；
- 包含“交易方画像与数据层独立性”和“来源与使用边界”；
- 不含 Unicode 替换字符（U+FFFD）和明显中文乱码；
- 本地相对链接能解释其指向，无法确认时在来源边界中标注。

## 时间窗口

默认比较三个窗口：

1. 当日或最新交易日：识别边际变化与异常值；
2. 近 5 个交易日：识别短期方向、持续性和反复；
3. 近 20 个交易日：识别中期趋势、历史位置和拥挤程度。

数据频率不支持时，使用最接近的可比窗口，并说明替代方式。单日信号不能单独升级为趋势判断或 `buy`。

## 数据与证据纪律

### 来源优先级

优先使用本地 `tushare-data` MCP 中已经暴露且当前账号可用的工具获取基础事实、价格、估值、资金分档 / 大小单、融资融券、财报、分红和指数成分；其次使用交易所、登记结算、监管与基金公告等一手数据；再次使用 AKShare 等口径透明的公开数据封装、专业数据平台和券商研究；最后才使用媒体、自媒体或用户转述。每个关键数据记录来源、时点、单位、覆盖范围和计算方式。

### Tushare MCP 优先使用规则

当前 `tushare-data` MCP 只把 2000 积分账号可用或已验证可用的工具作为优先层。执行资金面分析时，先检查当前会话是否已热加载 `tushare-data` MCP；若未热加载，可通过本地 stdio server `tools/tushare-data/scripts/mcp_server.py` 调用。MCP 调用失败、接口无权限、无数据、字段缺失或对象不适用时，不得把失败解释为“没有该事实”，应回退到 AKShare / 交易所 / 公开页面，并在来源说明中写明回退原因。

| 数据需求 | 优先 MCP 工具 | 适用对象 | 回退方向 | 边界 |
|---|---|---|---|---|
| 证券身份、简称、行业、上市状态 | `get_stock_basic` | A 股个股 | AKShare / 交易所公开资料 | 只用于身份校验和基础画像，不代表资金方向 |
| 日线行情、价格响应、量价验证 | `get_stock_daily` | A 股个股 | AKShare / 东方财富 / 交易所行情 | Tushare `daily` 为不复权价格；复权口径需另行说明 |
| 估值、市值、股息率、换手等交易活跃度 | `get_stock_valuation` | A 股个股 | AKShare / 东方财富 / Wind 类公开替代 | `dv_ttm` 是个股股息率字段，不等同指数股息率 |
| 资金分档、大小单、主力净流入代理 | `get_stock_moneyflow` | A 股个股 | AKShare / 东方财富资金流向 | 只能确认订单规模方向，不能确认机构、散户或国家队账户身份 |
| 融资融券、杠杆资金 F3 | `get_margin_detail` | A 股个股 | AKShare / 交易所 / 东方财富融资融券 | 融资买入会进入订单流，不能与资金分档机械相加 |

| 历史分红方案与实施 | `get_dividend_history` | A 股个股 | 公司公告 / 交易所公告 / AKShare | 分红是长期资金吸引力旁证，不是当日流入证据 |
| 指数成分股及权重 | `get_index_constituents` | A 股指数 | 中证指数官网 / AKShare | 可用于判断 ETF 或指数资金覆盖样本；不能确认申购者身份 |

以下资金面关键项当前仍不由 `tushare-data` MCP 覆盖，必须继续走其他来源并保留代理边界：ETF 份额与估算申赎 F7、龙虎榜、北向 / 陆股通持仓、回购、增减持、股东户数、质押、解禁、大宗交易、实时盘口与订单分档。不要为了“优先 MCP”而用行情、估值或财报字段替代这些资金流指标。

### 三类证据标签

- 已验证事实：可以回溯到明确数据和口径。
- 统计代理：指标与资金主体相关，但不能确认账户身份。
- 经验推断：由产品特征、交易行为或历史模式推测，必须单列且降低权重。

### 基本面与价格预期校验

资金面结论必须回答“资金在交易什么预期、价格是否已经反映这组预期，以及预期是否有基础证据支撑”。按 `equity-research-integration.md` 检查：

- 共识预期或市场叙事：盈利、分红、订单、政策、主题或周期预期；没有一致预期数据时写“未获取到 / 待核验”，不得虚构 FY1 / FY2。
- 基本面证据：收入、利润、现金流、负债、资本开支和分红是否支持资金叙事；优先使用 `get_financial_statements` 和 `get_dividend_history`。
- 价格表现：当日、近 5 日、近 20 日及必要时 YTD / 1Y / 52 周位置；优先使用 `get_stock_daily`。
- 估值位置：PE、PB、PS、股息率、市值和历史或同业背景；优先使用 `get_stock_valuation`。
- 宏观背景：利率、信用、汇率、通胀、政策和行业景气是否为资金顺风或逆风；MCP 未覆盖时使用公开来源或标记缺口。

这些字段只能用于解释资金持续性、承接理由、价格是否透支预期和下一验证点，不能把“基本面好 / 估值低 / 分红高”直接写成“长期资金已买入”，也不能输出完整基本面评级、目标价、DCF、公允价值或脱离资金面的买卖建议。

### 交易方结论等级

交易方方向只能使用以下证据等级，不用星级或任意评分制造精确感：

- 直接测量：数据直接对应已识别账户、持有人或法定披露主体；
- 可靠推断：至少两项相互独立证据方向一致，其中至少一项提供身份锚点；
- 弱推断：只有单一身份代理，或证据之间存在覆盖重叠；
- 不可知：没有直接身份数据、关键数据未获取到或冲突无法解释。

金额方向与账户身份必须分开写。可以确认“大额订单净卖”，不等于确认“机构净卖”；可以确认“小单净买”，不等于确认“全部由散户接盘”。

### 禁止事项

- 不把特大单直接写成“机构真实买入”或“主力建仓”。
- 不把 ETF 申购直接写成“国家队买入”。
- 不把小单直接写成全部散户行为。
- 不把 F3、F5、F7 或不同平台的资金指标机械相加为全市场净流入。
- 不用任意权重生成“共振得分”；如使用评分，必须给出可追溯回测与参数依据。
- 不把资金流数据脱离价格、广度、筹码供给和连续性单独用于下单。
- 不把同一成交在资金分档、龙虎榜、融资交易和 ETF 成分股交易中的重复呈现当成多源共振。
- 不用“未获取到”推导“没有”，也不用风险接口返回空值推导无质押、无解禁或无减持。

## 分析流程

### 1. 审计数据完整性

逐项检查数据时点、频率、覆盖对象、单位和统计口径。先列出哪些字段来自 `tushare-data` MCP，尤其是 `get_stock_moneyflow` 的订单规模代理、`get_margin_detail` 的融资融券代理、`get_financial_statements` 的财报数据、`get_stock_valuation` 的估值交易指标和 `get_dividend_history` 的分红数据；哪些字段来自 AKShare / 交易所 / 公开页面；哪些字段未获取到。特别检查 ETF 样本是否覆盖目标对象、融资与订单流是否可能重叠、不同日期是否使用了不同版本或估算方法。若没有共识预期、宏观或行业景气数据，单列为缺口，不得用资金流反推共识。

### 2. 建立资金来源全景

按 reference 检查适用于对象的资金类型：外资与跨境、杠杆、公募与 ETF、产业资本、保险与长期资金、私募与信托、券商资管、个人资金，以及 IPO、增发、减持、解禁等筹码供给。

不是每个对象都能取得全部数据。未取得不等于没有，填“未获取到”并说明影响。

### 3. 建立交易方画像与数据层独立性

在资金来源全景之后，先回答谁在主买、谁在主卖、谁在承接，再进入流入机制和 F3/F5/F7 判断。

个股默认检查以下交易方；市场、指数或板块不适用的主体保留并标记“不适用”：

- G 国家队或政策性资金；
- I 内资机构；
- N 北向或跨境资金；
- Q QFII 等境外机构；
- H 游资、量化和短线交易资金；
- M 融资等杠杆资金；
- R 个人或小额订单代理；
- C 产业资本、上市公司、控股股东和内部人。

每类交易方分别记录方向、强度、证据、证据等级、反证和不可知项。若无法穿透账户身份，交易方名称后加“代理”，不得省略代理边界。

再按数据渠道建立数据层表，至少检查适用的资金分档、跨境、融资融券、大宗交易、龙虎榜、回购、增减持、股东户数、ETF、质押、解禁和筹码。逐对判断：

- 独立：来源主体、统计链路和样本不重叠；
- 部分独立：身份或余额独立，但成交金额可能进入另一订单流；
- 非独立：同一成交的子集、重分类或派生值；
- 无法判断：口径不足，不能用于提高证据强度。

龙虎榜成交属于全市场成交和资金分档的子集，不能与特大单重复计票；融资买入会进入订单流，融资余额的账户属性较独立，但买入金额与 F5 部分重叠；ETF 申赎最终可能转为成分股交易；筹码成本由价格成交推导，与量价半独立。完整规则见 `indicator-boundaries.md`。

数据冲突时不做多数投票。先解释覆盖范围、身份锚点、时间窗口和重叠关系，再判断是“局部买、全局卖”“价格先修复、结构未修复”还是证据不足。

### 4. 判断流入机制

把观察到的资金支持归入且可并列：

- 场外真实增量：新资金进入市场或对象；
- 存量迁移：资金从其他资产、行业或个股切换而来；
- 减量报团：总体资金下降，剩余资金集中少数方向。

若无法区分，标记“机制待验证”。不要把局部相对强势自动解释为全市场新增资金。

### 5. 分析 F3/F5/F7 日频面板

分别评价方向、强度、持续性、稳定性、价格响应和数据质量：

- F3：融资净买入，观察杠杆资金边际变化；
- F5：特大单净买入，观察大额主动交易代理；
- F7：ETF 估算净申赎，观察 ETF 份额变化形成的申赎代理。

`tushare-data` MCP 当前可通过 `get_margin_detail` 优先获取 F3 融资融券代理，通过 `get_stock_moneyflow` 优先获取 F5 大额订单 / 资金分档代理；F7 ETF 估算净申赎仍需使用 AKShare、交易所、基金公告或其他公开来源。若 MCP 调用失败、接口无数据或字段缺失，保留“未获取到 / 待核验”并回退公开来源，不得用成交额、换手率或市值变化代替资金流。

指标不可用或不适用于对象时保留该行并写明原因。不得因为三项中两项为正就自动称为“共振流入”。

### 6. 检查供给与退出路径

检查股票融资供给、减持、解禁、套牢盘、高位筹码、赎回、杠杆平仓和资金集中度。回答：当前流入需要承接多少筹码，资金停止后谁会接盘，最可能怎样退出。

### 7. 做交叉验证

至少检查：

- 价格响应：净流入后价格是否上涨、企稳或仍冲高回落；
- 成交与换手：放量推进、放量滞涨、缩量反弹还是恐慌换手；
- 上涨广度：多数成分参与还是少数权重维持；
- 相对强弱：相对市场、行业或基准是否改善；
- 连续性：当日信号能否延续到 5 日和 20 日；
- 筹码供给：新增买盘是否足以覆盖新增供给和潜在抛压。
- 基本面与价格预期：资金方向是否被财报、分红、估值、价格位置、宏观背景或行业景气支持；市场共识可能错在过度乐观、过度悲观，还是证据不足。

资金与价格冲突时，不猜“吸筹”或“洗盘”；先写冲突事实，再降低置信度并列下一验证点。

### 8. 给出资金状态

最终状态只能选择一个：

- `共振流入`：多个相互独立的资金来源持续流入，至少包含一种可识别的场外增量或长期配置力量，且价格、广度和相对强弱确认。
- `结构性流入`：资金集中进入部分对象，整体或其他资金来源未同步，仍有明确承接但不是全面增量。
- `多空分歧`：主要资金来源方向相反，或资金流与价格、广度明显冲突，尚无一方取得稳定主导。
- `结构性流出`：部分主要资金持续撤离，但仍有局部承接、迁移或托底。
- `共振流出`：多个独立资金来源持续撤离，价格、广度与筹码压力共同确认，承接显著收缩。
- `证据不足`：缺少关键当前数据、窗口不可比、口径冲突或证据无法解释。

### 9. 映射行动与仓位

行动只使用：`buy / sell / reduce / wait / observe / review`。

#### 新增资金

- `buy`：资金至少达到结构性流入，且持续性、价格响应、广度或相对强弱及风险预算得到确认。首笔通常只用计划仓位的一部分；不能仅凭单日 F 信号买入。
- `wait`：方向有改善但确认条件未完成，明确等待什么数据。
- `observe`：证据不足、分歧严重、对象不适用或风险预算缺失，不投入新增资金。
- `review`：已有研究或计划需要重审，但资金面本身不足以决定投入。

#### 已有持仓

- `sell`：原资金假设或持仓逻辑的失效条件已确认，承接持续恶化且退出仍可执行。
- `reduce`：资金状态恶化、价格确认转弱或仓位超过承受能力，但尚未达到全部退出条件。
- `wait`：持仓逻辑仍成立、仓位可承受，资金信号未确认方向；不等于放弃风控。
- `review`：缺少成本、仓位、原计划或当前数据，先复核再行动。
- `observe`：仅用于没有明确操作需求的跟踪仓或观察仓。

#### 仓位表达

优先使用用户已有的风险预算和计划仓位。若没有风险预算，不编造“最佳仓位”，只给条件化区间：

- `observe`：新增资金 0%；
- 试探性 `buy`：计划仓位的 10%—30%，并写明升级条件；
- 已确认但仍有分歧：不超过计划仓位的 50%；
- `reduce`：说明降低现有仓位的 1/4—1/2，或降到用户预设风险线；
- `sell`：仅在失效条件确认时退出剩余风险仓位。

这些是缺少用户专属风控时的表达上限，不是普适最优比例。不得因为“共振流入”自动建议满仓或加杠杆。

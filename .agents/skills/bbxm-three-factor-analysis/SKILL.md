## 定位

这是三要素分析的唯一项目级入口。独立分析竞争格局、流动性辩证分析和情绪位置变化，再映射为综合状态与行动语言。

本技能不负责风险增强或减弱判断；`bbxm-risk-identification` 独立处理风险方向。两者平行工作，互不调用。

## 路由边界

- 用户直接要求三要素分析、三要素共振或三要素行动映射：使用本技能。
- 用户要求风险增强、风险持平、风险减弱或风险重新增强：使用 `bbxm-risk-identification`。
- 用户要求过滤单条信息并判断其金融意义：使用 `bbxm-information-filter-flow`。
- 用户提供交割单或交易记录：使用 `bbxm-trade-ticket-review`；它可以消费本技能的分析结果。
- 用户要求完整公司研究、估值或 DCF：使用 `bbxm-equity-research`；它可以消费本技能的分析结果。

### 概念页驱动的自主检索

竞争格局概念页不是背景阅读材料，而是本要素的动态取证契约。每次分析都必须重新读取其当前版本，并从中提取：

1. 三层适用范围；
2. 每层的比较对象；
3. 每层规定的比较维度；
4. 每个维度的重点观察项；
5. 五问所需的趋势、反证和失效条件。

不得把技能中曾经使用过的维度当成固定清单覆盖概念页。概念页新增、删除或调整比较维度后，当前分析必须同步变化。

按提取结果建立“层级 → 比较维度 → 重点观察 → 目标证据 → 来源 → 时点 → 结论/缺口”的内部检索清单，并自主完成检索：

- 第一优先级：当前 Wiki 中与对象、产业、政策、事件和推导有关的页面；
- 第二优先级：当前知识库 `sources/` 中的原始资料、法定公告、财报、规划、政策原文和数据快照；
- 第三优先级：截至分析时点的权威原始发布渠道。政策优先原始发布机关，行业优先主管部门、交易所、协会和可审计数据，企业优先法定披露、产品/认证材料和同口径可比数据；
- 库外原始资料必须先按项目规则复制或归档到 `sources/`，再作为正式报告来源。

国家层最低检索必须覆盖概念页当前列出的适用项目，并逐项标记“已检查 / 不适用 / 无法取得”：

- 国策高度：政治局会议、中央经济工作会议、政府工作报告、五年规划纲要、国民经济和社会发展计划、预算、法律和决议等顶层文件；
- 政策定调与落地：实施方案、实施细则、管理办法、申报指南、补贴办法、技术标准和考核办法；
- 资源配置：财政、信贷、产业资本和政府采购的实际投向。

概念页未来增补其他国家层、产业层或企业层观察项时，同样纳入最低检索，不需要等待技能再次修订。

论证时严格区分四个命题：

1. `国策方向`：顶层文件是否明确把对象所属方向列为国家发展重点；
2. `政策落地`：是否已有实施方案、规则、标准、项目或考核机制；
3. `资源配置`：财政、信贷、产业资本或政府采购是否已经实际流入；
4. `企业受益`：资源是否传导到对象所在环节，并由该企业获得收入、利润、份额或控制力。

上位方向成立不能自动推出细分环节受益，细分环节受益也不能自动推出企业比较优势。必须逐层给出传导证据。

在完成适用的最低检索前，不得仅因现有数据快照缺少政策或竞争数据就直接写“证据不足”。若检索后仍缺证据，必须列出已检查的会议、文件、来源、关键词或数据口径，以及缺口如何影响状态与置信度。

## 分析步骤

### 1. 竞争格局的比较优势

内部分析必须完整执行知识页中的“3 层 × 5 问模型”，不得只写企业自身经营优势：

- 三层：国家层、产业 / 行业层、企业层；非个股对象按实际层级说明不适用项。
- 五问：跟谁比、比什么、优势是什么、优势怎么变、什么情况下优势消失。

同时检查安全与发展方向、利润流向、议价权、国内与全球位置、供给扩张或出清、优势持续性。明确比较对象和参照系，分别列出证据、反证、数据缺口与失效条件；缺少同口径竞争者数据时，不得把企业经营改善直接写成高置信度比较优势。

区分分析层与展示层：

- 分析层用于防止漏项，必须逐层回答五问并保留证据审计；这一步可以在工作底稿中完成，不等于最终正文要逐问展示。
- 成品报告第 3 章默认不展示三张完整“五问”表。按国家层、产业 / 行业层、企业层分别输出：`结论 / 核心证据 / 核心反证 / 数据缺口 / 下一验证点 / 失效条件`，让读者直接看到判断依据。
- 第 3 章的判断正文与研究审计信息必须在视觉层级上分开：`结论 / 核心证据 / 核心反证`以及国家层的`国策方向 / 政策落地 / 资源配置`属于正文，因为证据与反证直接决定判断是否成立；`已检索范围 / 数据缺口 / 下一验证点 / 失效条件`属于研究审计提示，统一写入模板规定的 `> [!note] 研究提示` Callout，不作为普通正文项目符号平铺。
- 用户明确要求“3 层 × 5 问审计底稿”“逐问展开”或“方法复核”时，才在附录或正文中展示完整五问表；不得用完整审计表替代决策结论。
- 个股报告的国家层只回答国家未来是否把政策与资源配置到标的所属方向，以及这种配置能否传导至相关产业。除非国际竞争直接决定方向资格，不默认扩展为宽泛的国家、制度或全球产业体系比较。
- 产业 / 行业层回答利润流向哪个产业链环节、该环节的位置是否升级，以及产业资本、份额、定价权、标准或关键控制力如何变化。
- 企业层再选择具体可比公司，判断谁能获得利润，重点比较技术壁垒、准入门槛、客户关系、成本、定价权、经营质量和商业空间。
- 第 2 章“核心证据”必须优先写能够证明相对位置的证据。收入、利润或订单增长只能证明经营改善时，应明确标注为支持线索，不能把它直接写成比较优势。
- 每层论证必须逐项覆盖概念页规定的比较维度和重点观察；无法取得的项目写明已检索范围与影响，不得跳过后用其他维度代替。
- 国家层结论必须说明国策方向、政策落地和资源配置分别处于什么证据状态；不得只引用公司公告或行业景气数据判断是否属于国策产业。

### 2. 流动性辩证分析

核心边界：成交量只是结果，不能仅凭放量或缩量判断流动性有利或不利。必须同时解释钱从哪里来、能否持续、流向哪里、需要承接多少筹码，以及撤退时谁来承接。

本要素必须形成两个互不替代的结论：

1. `方向评价`：流动性对分析对象当前是`有利 / 中性 / 不利 / 证据不足`；
2. `阶段状态`：当前处于`扩张 / 平衡 / 转弱 / 收缩 / 修复 / 证据不足`。

阶段状态使用最新版 `wiki/concepts/冰冰小美-concept-体系三要素之流动性辩证分析.md` 中“五种状态”的定义。若概念页调整名称或边界，以概念页当前版本为准；输出统一使用`平衡`和`转弱`，把材料中的“均衡”“弱化”分别视为同义表述，不并列创造新状态。

按三层分别检查，不得只写微观成交和资金流：

- 宏观流动性：检查全球利率、美元、商品和外部风险偏好是否改变风险资产估值上限。
- 中观流动性：检查央行操作、政策利率、M2/M1、信用扩张及货币向实体和市场的传导，区分“货币存量充足”和“资金实际流通”。
- 微观流动性：检查成交与换手、上涨广度、ETF、机构、杠杆资金、做空回补、主线承接、报团溢价和资金分化，判断资金是扩散、切换、掩护退出还是整体撤退。

资金来源必须至少分为三类，并说明渠道、持续性与退出条件：

1. 场外真实增量：新资金进入市场或对象；
2. 存量迁移：卖出其他方向后转入对象；
3. 减量报团：市场总体资金下降，但剩余资金集中到少数方向。

不得混用两类“融资”：

- 杠杆资金：融资余额、融资买入、保证金或其他杠杆接力；
- 股票融资供给：IPO、增发、配股、可转债等新增股票或潜在筹码供给。

最低数据检查必须覆盖适用于该对象的项目，并给出数据时点、观察窗口和来源；无法取得或不适用时逐项说明：

- 宏观：全球利率、美元或汇率、商品与外部风险偏好；
- 中观：央行公开市场操作、政策利率、M2/M1、社融或信用传导；
- 微观：成交额与换手率、上涨/下跌广度、ETF 份额或净申购、机构或主力承接、融资余额、做空回补迹象；
- 供给与抛压：IPO/再融资、减持、解禁、套牢盘和高位筹码松动；
- 时间窗口：至少比较当日、短周期和中周期；不能取得三档窗口时说明缺口及其对结论的影响。

检查潜在退出路径，分别列出支持证据、反向证据、下一验证点和失效条件；资金流向数据不得脱离价格、广度、筹码供给与连续性单独使用。

完成上述分层分析、供给与抛压检查、反证和退出路径分析后，最后按以下边界判断阶段状态：

- `扩张`：存在可识别、可持续的增量渠道，且资金已转化为承接、上涨广度和挣钱效应扩散；只有局部抱团或单日放量时，不判为整体扩张。
- `平衡`：托底、买入与卖出力量大致相抵，总量没有明显恶化但缺少强增量；指数稳定而个股分化仍可属于平衡。
- `转弱`：原有支撑边际下降，资金从扩散转向集中，高波动或成长方向先承压，但尚未形成全面卖压和自我强化下跌。
- `收缩`：资金供给、承接、风险偏好和价格形成持续下行共振，卖压、恐惧与亏钱效应互相强化。
- `修复`：政策、ETF、核心权重或其他承接渠道先阻断收缩，市场止跌或反弹，但持续性和扩散范围尚不足以确认新一轮扩张。

状态判定必须同时给出：`当前状态 / 上一可辨识状态或基准状态 / 转换方向 / 宏观—中观—微观依据 / 相邻状态排除理由 / 置信度`。无法确认上一状态时写`证据不足`，不得倒推补造。宏观、中观、微观不一致时，以能解释资金实际进入对象、承接筹码和持续时间的证据为主，并把分歧写入反证，不得机械投票。

阶段状态与方向评价不能机械一一映射。例如，修复可以仍是中性，转弱也可能暂时未达到不利；必须根据对象所处位置、资金传导和筹码压力分别判断。

### 3. 情绪位置变化

判断处于冰点、试错、扩散、拥挤、退潮或修复阶段；检查广度、接力、赚钱与亏钱效应、消息反应、情绪标与套利行为。分别列出证据和反证，并给出失效条件。

### 4. 形成状态判断

- 每个要素的方向评价只能使用：`有利 / 中性 / 不利 / 证据不足`。
- 流动性的阶段状态单独使用：`扩张 / 平衡 / 转弱 / 收缩 / 修复 / 证据不足`；不得用阶段状态替代方向评价。
- 综合状态只能使用：`同步有利 / 部分有利 / 尚未形成有利共振 / 同步不利 / 证据不足`。
- 不得用一个强要素机械抵消两个不利要素。必须指出主导要素、拖累要素、下一验证点和失效条件。
- 不得因单条利好、单日行情或单一叙事给出确定性结论。

### 5. 映射行动

行动词只使用：`buy / sell / reduce / wait / observe / review`。

- 新增现金和已有持仓必须分开判断，并为每个行动写明触发条件。
- 证据不足时，新资金优先 `observe`，已有持仓优先 `review`；若持仓事实也不足，可用 `observe`。
- 行动结论必须能由三要素状态、主导矛盾和失效条件反推，不能只凭故事或单一信号。

### 6. 形成报告并落盘

严格使用同目录 `template.md`，先生成完整 Markdown 母稿，再由母稿生成 HTML。HTML 不维护第二套正文。

默认文件名：`YYYY-MM-DD-HHmm-<分析对象>-三要素分析.md`。

在 llmwiki 中：

1. Markdown 保存到 `workbench/targets/`，frontmatter 使用 `artifact_type: three_factor_analysis`；目录保持扁平，不创建证券代码、指数、板块或单对象子目录。
2. 生成前按证券代码、对象名称和标题检索 `workbench/targets/`。已有同一对象的权威三要素分析时，读取原 Markdown 并原地更新，不得仅因时间、行情、模板或结论变化创建第二份权威报告。
3. 只有用户明确要求历史快照或对比稿时才另存，并在文件名中标注 `历史快照`、`对比稿` 或事件名称。
4. HTML 不进入 `workbench/`，写入对象已归属的 `sources/automations/<分类>/`；分类未确定时写入 `sources/automations/temp/`。HTML 与 Markdown 使用相同文件名主体。
5. 更新 `workbench/index.md` 和根 `log.md`；不更新根 `index.md`，也不得把专项分析保存到 `wiki/queries/`。
6. 库外原始材料必须先复制到当前库 `sources/`，正式报告优先引用库内 source 副本。

在其他项目中，优先使用用户指定目录；用户未指定时，将 Markdown 与 HTML 保存到当前项目合理的研究输出目录，并保持同名。

### 7. 生成并验证 HTML

Markdown 通过完整性检查后，默认生成同源 HTML；只有用户明确要求仅在对话中回答或仅交付 Markdown 时才可跳过落盘或 HTML。

使用命令：

```text
node .agents/skills/bbxm-three-factor-analysis/scripts/render-three-factor-html.cjs --input <报告.md> --output <报告.html> --vault-root <知识库根目录>
```

若系统 PATH 中没有 `node`，先定位工作区 Node.js 运行时，再用绝对路径执行。禁止通过 PowerShell 管道或内联脚本传递中文 HTML。

HTML 输出规则：

1. 固定使用技能内 `assets/report.css`，包含渐变封面、三要素摘要卡、左侧目录、右侧正文、移动端和打印样式。
2. 封面从报告标题与元数据提取对象层级、市场、分析截止时间和报告生成时间；缺失字段显示“未获取”，不得猜测。
3. 摘要卡从第 1—2 章提取综合状态、竞争格局、流动性、情绪位置和总体置信度，不改变 Markdown 结论。
4. 必须生成 9 个可跳转目录锚点，并转换 Obsidian 双链。
5. 生成后检查 UTF-8 中文、9 个章节锚点、摘要状态、双链转换和 Markdown / HTML 结论一致性。
6. HTML 生成或验证失败时，报告仍视为未完成。
7. 第 3 章的 `> [!note] 研究提示` 必须转换为 `.research-note` 提示卡，且 HTML 中不得残留 `[!note]` 原始标记；提示卡应弱于结论正文，不使用状态色或高强调警示色。

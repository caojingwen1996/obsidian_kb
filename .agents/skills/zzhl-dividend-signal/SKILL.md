# 中证红利股息率信号

当用户要求检查、运行、定时触发或记录“中证红利买入信号 / 中证红利股息率信号”时，使用此 skill。

## 执行方式

在 llmwiki 项目根目录运行内置脚本：

```powershell
python .agents\skills\zzhl-dividend-signal\scripts\check_signal.py
```

脚本会执行以下动作：

1. 获取中证红利 `000922` 指数估值数据，并得到用于规则判断的股息率口径。
   - 当前使用 AKShare `stock_zh_index_value_csindex` 的 `股息率2`。
2. 获取中证红利日收盘价，计算本年度首个交易日至指数估值日期的全年收益率和年内最大回撤，并生成指数成立以来的逐年历史。
3. 通过腾讯行情接口获取中证红利 `sh000922` 的当天涨跌幅；该涨跌幅日期默认等于记录日期。
4. 通过 AKShare `bond_zh_us_rate` 获取 10 年期中国国债收益率。
5. 仅使用绝对股息率和股债倍数评分；不获取理杏仁或指数估算分位。
6. 优先读取已应用的每日策略配置，尚无配置时读取本技能 `strategy-v2.json`，按V2双指标连续加权评分计算综合分、子分数、权重贡献和等级。原问题页仅保留旧研究背景，不作为当前参数源。
7. 将每日结果写入 `sources/automations/中证红利信号/中证红利每日信号.xlsx`。
8. 将最近一次结果写入 `sources/automations/中证红利信号/最新信号.md`。
9. 将原始输入、实际数据日期、策略版本、得分贡献和连续确认状态写入 `sources/automations/中证红利信号/评分记录.json`。
10. 将指数成立以来每一年的收益率和年内最大回撤写入 `sources/automations/中证红利信号/中证红利年度表现.json`。

## 数据源优先级

本 skill 的主数据源优先级为：

1. AKShare 免费数据源。
2. 腾讯行情。

脚本会在来源说明中写明实际使用的数据源。不要把公开接口未返回字段理解为“没有股息率”；这只表示当前接口、权限或字段口径未取得，需要回退或人工核验。

| 数据 | 优先接口 | 回退接口 | 脚本用途 |
|---|---|---|---|
| 中证红利指数估值数据 | AKShare `stock_zh_index_value_csindex(symbol="000922")` | 无自动回退 | 使用 AKShare `股息率2` 作为绝对股息率和股债利差口径 |
| 中证红利指数日收盘价 | 中证指数官网 `index-perf(000922)` | AKShare `stock_zh_index_daily_tx(symbol="sh000922")`，再回退 `stock_zh_index_daily` | 官网日线从发布日期 `2008-05-26` 起计算逐年收益率和最大回撤；AKShare 只在官网失败时回退 |
| 中证红利当天行情 | 腾讯行情 `http://qt.gtimg.cn/q=sh000922` | 无自动回退 | 获取当天涨跌幅；日期默认等于记录日期，只记录，不修正股息率 |
| 中国10年国债收益率 | AKShare `bond_zh_us_rate(...)` | 无自动回退 | 获取中国10年国债收益率，用于计算股债利差 |

股息率口径约定：

- 使用 `股息率2` 作为本 skill 的默认数据源口径。
- 不使用 `股息率1` 作为默认口径。`股息率1` 与 `股息率2` 可能在同一天出现明显差异，例如 2026-06-02 中证红利 `股息率1 = 5.04%`，`股息率2 = 4.83%`。
- 未来更换数据源时，应优先寻找与 `股息率2` 对应或更接近指数实际权重的估值口径。
- 每天下午运行时，指数估值日期通常仍是上一个交易日；脚本会保留该估值日期和 `股息率2`，并额外记录当天涨跌幅（腾讯行情）。当天涨跌幅的日期默认等于同一行的记录日期，不单独写入行情日期列；不用当天涨跌幅修正股息率。
- 当前 AKShare 指数估值接口可能只返回最近一段数据，不一定足以直接计算真正的“近10年股息率分位”。若要严格执行历史分位点规则，应接入完整历史股息率数据源后再计算分位。
- 历史分位已从当前模型和界面移除。旧原始档案保留；兼容解析函数及旧CLI参数不用于新任务评分或触发分位采集。

## V2 双指标评分

当前默认参数源为 [strategy-v2.json](strategy-v2.json)，基础版本 `dividend-two-factor-v2`。每日运行读取看板已应用配置。旧 [strategy-v1.json](strategy-v1.json) 冻结保留用于档案追溯；旧配置在读取评分时仅迁移两项有效权重，不再计算历史分位。

综合分 = 绝对股息率得分 × 92% + 股债倍数得分 × 8%。股债倍数 = 股息率2 ÷ 中国10年国债收益率。

| 子分数 | 绝对股息率（%） | 股债倍数（倍） |
|---|---|---|
| 0 | 3 | 1 |
| 40 | 4 | 1.5 |
| 60 | 5 | 2 |
| 80 | 5.5 | 2.5 |
| 100 | 6 | 5 |

按相邻锚点线性插值，范围外截断为0或100；默认C40、B48、A65分。评级使用未舍入分数。综合分、输入、日期和贡献仅包含两项；原始档案中的旧分位列不删除，不参与评分与分组。

买入规则：仅综合评级A可买入；B为观察区间、C为等待区间、D不买入，B/C/D均不发出买入提示。单项指标的A/B/C/D仅表示指标得分高低，不能替代综合评级。Excel仅高亮综合A级；走势图仅标记综合A级买点。各等级的假设买入收益仍用于回测对照，不表示其均可买入。此规则不改变权重、锚点、等级分界或已保存历史分数。

### 数据质量与缺失

- 缺项不填零、不重新分配权重。下界为已知贡献之和，上界为下界加缺失项权重，不输出完整综合等级。
- 非有限数、负股息率、非正国债收益率作为无效输入。无法取得关键源数据时保留原产物并明确报告失败，不制造数据。
- 官方指数推算等替代历史口径标为“参考评分”；数据质量单独显示，不混入估值分数扣分。
- 指数、国债日期不一致或日期缺失时标为“日期未对齐”，不参与连续确认。页面分别显示真实日期。
- 来源切换或评分算法版本切换重新建立连续确认基准。两项分数使用同一指数估值日期。

### 连续确认

默认3个交易日，只影响策略调整提示，不改变当日分数或等级。使用既有指数日线实际交易日期作为证据日历，按指数估值日期去重，同日或休市日重跑不增加次数。

按配置的确认交易日数（当前1天）累计有效交易日为同一等级时建立基准；之后同一新等级满足配置天数才提示调整。缺失或无效交易日中断连续序列，周末和节假日不计入交易日；来源/版本切换重建基准。缺少日历或记录时标为“证据不足”。旧历史数据试算和首次参考快照不作为正式确认记录。

### 结构化输出与兼容

`评分记录.json` 包含 `schemaVersion`、本次任务的 `strategy`、`latest`、`records` 和 `tradingDates`。每条记录保存 `input`、`dates`、`sourceKey`、`reference`、`kind`、`strategyVersion`、`components`、`score/lower/upper`、`grade/label`、`nextGrade/nextDistance`、`quality`、`eligible` 和原始字段 `raw`；最新条目附 `confirmation`。每条新增结果附 `strategySnapshot`，保留当次参数。历史记录按“估值日期＋策略版本”去重；同日新版本保留旧版本结果。Excel同记录日期的新策略版本亦保留旧行，同版本重跑才替换本版本行。

每日Markdown同步追加评分说明；Excel在原列之后追加策略版本、综合分/等级、上下界、两项得分/贡献、质量和连续确认状态，保留中文表头可见。旧文件缺少这些字段仍可读取。

首次离线重算使用以下命令，生成 `评分记录.json` 与 `V1参考快照.md`，不联网，不覆盖旧 `最新信号.md` 和工作簿，也不把重算时间当作行情日期：

```bash
.work/zzhl-dividend-signal/.venv/bin/python .agents/skills/zzhl-dividend-signal/scripts/check_signal.py --snapshot-from-local
```

正常每日运行命令和现有数据来源保持原流程，读取最新已应用的每日参数；单次任务开始时锁定参数快照，任务中途发布的新参数留待下次运行。参数或算法变更须更新版本，不能无声改变历史成绩。

### 看板参数设置

“策略详情”可编辑两项权重、五个输入锚点与内部得分、等级分界。页面已移除连续确认交易日数及确认状态，按当天综合A级判断买入；旧配置字段和历史记录保留兼容，不作为买入等待条件。分数端点固定0/100。输入即校验，可保存到当前浏览器当前站点；可撤销未保存修改或恢复双指标默认值。更换浏览器或服务端口不共享参数；存储不可用时明确提示仅保留本次会话。

权重各项大于0且合计100%；输入锚点与分数严格递增；分位0～100%、股息率锚点非负、倍数锚点正数；分界满足 `0<C<B<A<100`，确认天数1～20整数。无效值标注字段并禁用保存，不自动纠正。

看板展示“每日记录结果”和“策略详情”参数表单；本地实时测算卡片已移除，编辑参数不再生成当日试算分数、分差或等级变化。每日结果的连续确认按有效评分记录与交易日历判断，不按页面访问次数计数。

“保存本地参数”仅保留浏览器参数。“保存并应用到每日测算”调用本地服务 `POST /api/dividend-strategy`（`strategy` 与 `expectedRevision`），保存后下一次每日任务生效，同时同步浏览器本地参数。当前每日结果及旧历史不立即重算。`GET /api/dividend-strategy` 返回当前配置；修改前读取版本，冲突返回409并保留编辑参数。直接打开HTML或旧服务不支持应用时，提示使用/重启启动面板。

每日配置文件包含 `schemaVersion`、`revision`、`strategy`、`updatedAt`、`history`。首次变更发布 `dividend-two-factor-v2-r1`，后续每次参数变化递增revision；相同参数重复应用不生成新版本。配置历史保留各版完整参数和北京时间。写入使用进程/文件锁与原子替换，非法参数或保存失败不覆盖原配置；配置损坏明确报错，不静默退回默认。保存配置不改调度时间、不主动运行每日任务。恢复双指标默认值先只改变编辑参数，需再次点击应用按钮才发布到每日任务。

版本改变后连续确认重新建立基准；已记录旧版本的分数、贡献和结论仍可回溯。

### 验证边界

权重92/8是在当前区间、既定锚点和等级分界下的候选；多组邻近权重筛选相同A级，不代表唯一最优或样本外验证。股债倍数包含股息率，二者并不独立。评分不代表上涨概率，不规定投入金额、频率或仓位比例。

数学与行为验证使用 [V2共享样例](tests/scoring-cases-v2.json)、Python `tests/test_scoring.py` 和看板相关测试。旧 [V1样例](tests/scoring-cases.json) 作为档案保留。

# 主题归纳参考（Theme Synthesis）

## 1. 目的

定义如何将**当前 feed 运行**中的多个 Cluster 归纳为更高层次的 Theme。

**Theme** 是由本次运行中多个相关 Cluster 支持的、更高层次的核心问题或解释结构。

主题归纳是无状态的，不跨轮次检索、更新、合并或跟踪 Theme。

正式对象结构定义见：

`schemas/theme.schema.json`

---

## 2. 核心模型

```text
当前 feed 中的 Cluster
        ↓
寻找共同变量
        ↓
寻找共同驱动因素
        ↓
寻找共同传导结构
        ↓
识别共同核心问题
        ↓
评估解释性压缩
        ↓
   ┌────┴────┐
   ↓         ↓
Theme    保持各Cluster独立
```

核心问题：

> 当前 feed 中这些 Cluster 共同描述了什么更高层次的问题？

---

## 3. 无状态边界

主题归纳只能比较本次运行创建的 Cluster。

不得要求使用：

```text
历史 Theme
历史 Cluster
跨轮次 Theme 匹配
跨轮次 Theme 更新 / 合并
Theme 生命周期状态
历史持续性跟踪
```

如果当前 feed 已明确包含历史上下文，可以将其保留为证据；工作流不从记忆中检索这些上下文。

---

## 4. Theme 的定义

Theme 超越单一事件过程。

概念上：

```text
Event
= 单一事实

Signal
= 变量变化

Cluster
= 当前 feed 内的相关变化结构

Theme
= 跨Cluster的更高层次问题 / 解释结构
```

只有当前 feed 中的多个 Cluster 能支持有用的更高层次抽象时，才形成 Theme。

---

## 5. 主题形成的判断维度

从以下维度评估当前 feed 中的多个 Cluster 是否具有共同的更高层次结构。

### 5.1 共同问题

询问：

> 这些 Cluster 是否在回答同一个更高层次问题的不同部分？

这是最重要的 Theme 判断标准。

示例：

```text
高融资成本与AI驱动的扩张如何相互作用？
```

---

### 5.2 共同变量

询问：

> 这些 Cluster 是否涉及相互重叠的核心变量？

示例：

```text
能源
通胀
长期利率
成长资产估值
```

---

### 5.3 共同驱动因素

询问：

> 这些 Cluster 是否具有由本次运行证据支持的共同底层驱动因素？

示例：

```text
能源冲击
货币政策
AI资本开支周期
信用收紧
```

---

### 5.4 共同传导结构

询问：

> 这些 Cluster 能否通过一条连贯的传导结构连接起来？

示例：

```text
能源
→ 通胀
→ 利率
→ 估值
```

各环节的联系必须有证据支持，或明确标记为推断。

---

### 5.5 方向关系

在当前 feed 中，Cluster 之间可能存在：

```text
reinforce
offset
conflict
reframe
```

即相互强化、抵消、冲突，或重新界定问题。

方向关系描述当前证据集合中，支撑 Theme 的 Cluster 如何相互作用。

---

### 5.6 解释性压缩

询问：

> 能否用一个更高层次的问题，更清楚地解释多个原本独立的 Cluster？

有用的 Theme 应降低复杂度，同时不掩盖重要差异。

---

## 6. 主题形成逻辑

```text
INPUT current_feed_clusters

candidate_groups = DetectHigherLevelRelationships(current_feed_clusters)

FOR group IN candidate_groups:

    IF 多个 Cluster 具有明确的共同核心问题
       AND 关系有证据支持
       AND 归纳有助于解释性压缩:

        创建 Theme

    ELSE:
        保持各Cluster独立
```

不要仅因为多个 Cluster 出现在同一份 feed 中，就创建 Theme。

不要为 Theme 创建跨时间持续状态或生命周期状态。

---

## 7. 主题命名

Theme 名称应描述当前 feed 中可见的更高层次问题或解释结构。

推荐：

```text
高融资成本对AI扩张的压力
AI基础设施扩张与融资需求
能源驱动的通胀压力
信用收紧与需求放缓
```

避免：

```text
看多
看空
利好
利空
市场风险
```

Theme 命名应保持描述性。

---

## 8. 核心问题

每个 Theme 应包含一个明确的 `core_question`。

示例：

```text
高融资成本正在如何影响成长资产估值？

AI需求能否支撑当前资本开支扩张速度？

能源压力是否已足够广泛，能够改变利率预期？
```

核心问题为本次主题归纳提供稳定的组织中心。

---

## 9. 支撑主题的 Cluster

Theme 应引用支撑它的 Cluster。

示例：

```text
Cluster A：
AI资本开支扩张

Cluster B：
大型科技公司的债务融资

Cluster C：
数据中心电力需求

↓
Theme：
AI基础设施扩张及其融资与资源需求
```

Theme 通常需要多个独立 Cluster。

单个孤立 Cluster 应继续保留为 Cluster。

---

## 10. 传导结构

存在相关联系时，Theme 可以概括连接各 Cluster 的更高层次传导结构。

示例：

```text
AI基础设施扩张
→ 融资需求
→ 电力需求
→ 资源需求
```

该结构应能够追溯到支撑它的 Cluster。

---

## 11. 证据状态

Theme 的证据状态可以概括本次运行的支持情况：

```text
支撑Cluster的数量
来源多样性
当前feed内的跨市场确认
方向一致性
相互矛盾的证据
推断深度
```

Theme 的置信度不能只依据 Cluster 数量判断。

不要把历史持续性作为必需条件。

---

## 12. 不确定性与待回答问题

Theme 应保留尚未解决的问题。

示例：

```text
融资增长反映的是暂时性的发行时点安排，还是更广泛的资金需求？

AI资本开支增长是否足够快地转化为收入？

能源约束是否已足以影响部署速度？
```

使用：

```text
uncertainties[]
open_questions[]
```

这些字段保留当前证据的限制。

---

## 13. 本次运行内的 Theme 边界

同一次运行中，如果两个候选 Theme 结构重叠，只有满足以下条件时才合并：

- 具有相同核心问题；
- 具有相同核心变量；
- 是同一传导结构中相邻的部分；
- 合并后能够使解释更清楚。

以下情况应保持独立：

- 驱动因素存在实质差异；
- 作用范围存在实质差异；
- 共同问题变得过于宽泛；
- 关系较弱或依赖推测。

这只是本次运行内的归纳决策，不合并已存储的 Theme。

---

## 14. Theme 的职责边界

Theme 可以描述：

```text
更高层次的核心问题
更高层次的解释结构
共同变量
共同驱动因素
共同传导结构
支撑Cluster之间的关系
不确定性
```

Theme 不应决定：

```text
组合配置
交易执行
资产推荐
风险评分
估值结论
没有所提供证据支持的历史持续性
```

这些属于下游专家分析或未来的时间演化分析能力。

---

## 15. 质量检查

接受一个 Theme 前，检查：

- 是否有多个来自当前 feed 的 Cluster 支撑？
- 是否具有明确的核心问题？
- 共同变量是否可识别？
- 共同驱动因素是否有证据支持？
- 传导结构是否连贯？
- Theme 是否有意义地压缩了信息？
- 是否保留了矛盾？
- 待回答问题是否明确？
- 每项主张能否追溯到本次运行的 Cluster？
- Theme 是否避免依赖历史存储？

---

## 16. 输出原则

好的 Theme 回答：

> 当前 feed 中这些 Cluster 共同描述了什么更高层次的问题或解释结构？

概念流程：

```text
Cluster
    ↓
共同结构
    ↓
核心问题
    ↓
解释性压缩
    ↓
Theme
```

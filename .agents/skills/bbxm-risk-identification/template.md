本模板为执行约定。每条独立风险使用一份；未知填“待验证”，首次关联引用可空。不适用项说明原因，不保留占位内容。正文优先解释风险，证据引用紧随判断，完整登记放在附录；Markdown 与 HTML 使用相同顺序。

正文与图示使用自然语言名称；Event/Signal/变量内部编号、模型数量、上游快照和运行交接说明只放在附录或运行记录。正文引用使用来源名称链接，必要日期与证据限制合并为简短注释，不重复声明流程边界。

## 识别结论

用一段简洁文字交代风险判断、核心变量和首要验证条件，将“候选 / 尚未确认损害”等必要状态自然融入结论，不逐项列出内部字段。

来源与日期注释：注明主要来源、数据时点及影响理解的证据限制。完整截止时间和身份登记见附录。

### 2. 风险表现：现在实际观察到了什么？

先按工作流列出各项待核表现，通过信息处理 theme 模式逐项搜集事件、数据和反证，或复用覆盖相同问题与窗口的theme结果，再写本节。不只复述输入，不以“建议调用theme”或待办清单代替实际核验。

按重要性为各项表现设置简短小标题，每项先给当前能确认的一句话，再写：

- **实际观察：** 对象、指标或行为、数值/变化、数据期与比较口径，紧随原始来源链接。
- **反证与缺口：** 不支持该表现的证据、适用范围，以及未查到、访问失败或口径不匹配等具体情况。
- **判断边界：** 已观察到 / 仅有线索 / 待验证；区分背景变化、已经发生的不利表现和尚未发生的可能后果。

图表围绕该项表现最重要的比较展开，证据覆盖图与逐项结果一致；不得把没有观察到的后果画成现实损害。内部theme编号、事件/信号计数和检索过程放入附录，正文保留关键反证与来源。只有风险线索时保留候选状态；没有充分证据时可不建模型，说明范围与缺口。

### 3. 风险来源：发生了什么变化？

先引用知识库对风险来源的定义，再按当前知识页分类展示；名称、层次和定义/核心问题直接取自知识库，案例解释单独填写。只列本材料相关来源，不把分类归属写成已确认的损害。

| 层次 | 知识库风险来源 | 知识库定义 / 核心问题 | 本材料中的具体变化 | 证据状态 |
|---|---|---|---|---|

链接对应知识页；无对应分类时明确说明。每项用直白语言回答“谁、发生什么变化、何时”。传导机制、受影响主体与反证分别进入对应章节，不另起一套来源标签。

### 4. 风险关键变量：什么变化最能改变判断？

优先说明最关键的变量及选择理由，再列必要的辅助变量，不按信息出现频次罗列指标。无法确定主导变量时说明竞争解释及区分它们所需的证据。

| 关键变量 / 主次 | 为什么决定风险 / 作用环节 | 当前已知状态 / 证据引用 | 什么变化支持机制 / 什么变化削弱或否定机制 |
|---|---|---|---|

这里描述条件关系，不判定本轮风险已经增加、维持或减弱。完整指标口径与快照见附录。

### 5. 风险传导关系：如何逐步造成损害？

本节以一张传导主链图和简短解释为主体，表达“风险来源 → 风险关键变量 → 市场 / 主体行为变化 → 风险表现”，不放逐环节长表。

- 节点写具体变化，并标明已有观察、局部线索或待验证后果。
- 箭头写明成立条件；已有因果证据使用实线，条件推断使用虚线，并提供图例。两端节点均有观察不等于中间因果已验证。
- 放大因素用侧向分支接入相关环节；缓冲或阻断条件在对应箭头旁标注，不画成已经发生的应对。
- Markdown 保留 Mermaid 或等价关系图；HTML 使用实际渲染的 SVG / HTML+CSS，窄屏优先纵向主链，不仅输出图源码。

图后只解释最关键的传导条件、未证实环节与有力反证，来源就近链接。完整逐环节核对资料放入附录，避免在正文重复整张图。

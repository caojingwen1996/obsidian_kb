# 风险识别工作流

## 执行准备

1. 读取项目 AGENTS.md、schema.md、page-types.md、index.md，以及最新 [风险观察与演绎](../../../wiki/concepts/冰冰小美-framework-风险观察与演绎.md) 第一层。页面路径失效时检索真实路径；区分整理者框架与作者原话，必要时核对页面所链来源。
2. 取得适用的 feed `InformationProcessingResult` 或 theme `ThemeProcessingResult` 与运行说明，核验对象、截止时间、证据引用及已有模型。原始材料先用信息处理 feed 整理；已有明确风险问题而缺信息时，直接按 Step 1 调用 theme，不要求先生成一个空 feed 结果。theme 补证的接入与回填按本工作流执行；模型的历史保存和后续交接另遵守 [共享交接契约](references/handoff-contract.md)。
3. 先记录上游信息窗口与本次分析截止时间。历史回看仅采用当时可得资料；未指定截止时间的当前识别，可补查截至本次执行时已公开的数据，逐项注明实际观测期，不能把旧材料标成实时状态。原上游窗口保持不变，新增证据的覆盖范围另记。簇或共同变量为空不等于输入无效，按证据判断。

## Step 1. 识别风险表现

从上游事件、共同现象及当前风险问题中列出各项待核表现，通过下述 theme 搜集与核验后，再描述已经发生的异常或不利表现。待核清单不是已观察结果；本步骤不预先认定来源，预测、传闻和未发生的损害不得写成现实结果。

### 主动补证

本步骤对应报告“风险表现：现在实际观察到了什么”。默认实际调用 [信息处理入口](../bbxm-information-processing/SKILL.md) 的 theme 模式，按 [theme 工作流](../bbxm-information-processing/workflows/theme-workflow.md) 逐项搜索相关信息、事件和数据，同时找反证；不以待办清单代替执行。用户限定给定材料或禁止联网时，仅检索允许的材料或本地来源，并登记限制；工具不可用或技能执行失败须如实记录，不伪造搜索日志或已完成的 theme 结果。

1. **列出各项待核表现。** 每项写清对象、可观察指标或行为、验证问题、时间窗口、可比口径及反向证据方向。表现名称可作主题标题，但核心问题须保持开放，例如“融资可得性是否下降，还是仅发行增加？”。不预设风险必然存在，不机械穷举所有风险。
2. **逐项构造 theme 请求。** 传入 `theme_context.theme_name`、`core_question`、`core_variables`；在请求中另附观察对象、明确的 `observation_window`、分析截止日、来源限制与所需比较期。可用 `open_questions` 列出各表现的问题。字段遵守 [theme 结果 Schema](../bbxm-information-processing/schemas/theme-processing-result.schema.json)，不添加自定义顶层字段。窗口由风险任务显式传入，不被 theme 默认最近30天覆盖。核心变量是搜集线索，不自动成为风险关键变量。
3. **执行或复用 theme 搜集。** 每项表现都须有独立查询与证据覆盖，支持和反证同时查；共享对象、窗口和来源的表现可合并一次 theme 调用，问题与变量仍逐项对应，不能只搜一个笼统风险主题。已有结果满足同一对象、问题、窗口与口径时复用并登记覆盖，不重复查询；只补缺口或需更新部分。信息处理完成回源、时点/单位核验、去重、Event / Signal 提取与证据整理；历史时点不得采用截止日之后公开的信息。按 theme 停止条件结束，关键来源持续不可得或预算耗尽时保留缺口。
4. **保存并校验完整结果。** 来源摘录或数据副本进入本库 `sources/`，复用已有副本。默认将本轮 theme JSON 保存到项目根下 `tools/a-share-market-dashboard/data/Risk/inputs/<result_id>.json`，配套 `<result_id>-run.md` 记录各待核表现与问题、变量、证据/缺口的对应，以及来源时间、口径、采用范围和失败原因。保留原上游结果与窗口，新增结果使用独立标识；跨结果引用同时写明 `result_id + 对象ID`，不能只用可能重名的E1/S1。调用信息处理的 `scripts/validate_result.py <结果路径>` 并确认通过后才作为结构化输入；失败先修正，无法修正则说明未完成，不将结果改标feed。用户仅对话时遵从其落盘要求并保留等价引用。
5. **逐项回填风险表现。** 按表现读取 `events / signals / evidence / findings / gaps / search_log`，每项都对应证据或明确缺口，不能遗漏未找到结果的表现。风险识别再判断证据是否显示异常或不利变化，区分“已观察到”“仅有线索”“待验证”，并保留反证或不支持该表现的证据；局部样本标明范围。只有背景变化时明确其背景性质，不自动视为风险表现。没有查到、访问失败与口径不匹配分别说明。theme Finding 的置信度和support映射不等于风险确认，也不要求theme提供feed的移交字段。

例如融资主题可以分别核实“融资成本是否上升”“发行是否受阻”“企业现金是否承压”；发债规模是相关背景，不能仅凭规模上升确认上述三项。这是问题拆分示例，不是预设风险清单。

执行 theme 是同一分析任务内调用信息处理流程，不要求另建任务；中间交付以完整 JSON 与运行说明为主，不为每项表现重复生成独立 HTML。最终由风险模型统一展示本节内容及图表，检索细节和跨结果映射放入附录。

后续步骤发现新的关键变量或传导缺口时，可按同一规则返回补证。补证导致已有模型实质判断改变时遵守版本与重识别规则，新判断不能覆盖旧快照；只补记录也应注明对结论有无影响。

## Step 2. 确定风险类型

按 [风险类型](../../../wiki/concepts/冰冰小美-indacator-风险类型.md) 判断这是什么风险、影响谁、造成何种不利后果；知识库没有合适类别时明确“本次候选归纳”，不强制穷举类别。多条风险分别建模，同一根因的多个表现不重复计数。

## Step 3. 识别风险来源

读取最新[风险来源与传导路径](../../../wiki/topics/冰冰小美-风险来源与传导路径.md)，按照该页“风险来源”的定义，回答“发生了什么？什么变化可能带来损害？”。先匹配宏观、中观或微观层次，再使用该层已有的风险来源名称及定义/核心问题，不以机制解释代替来源分类。

输出“层次 → 知识库风险来源 → 知识库定义/核心问题 → 本材料中的具体变化 → 证据状态”，并链接定义所在知识页。名称和定义从本次读取的知识库取用，不在技能中另存固定分类表；只展示有关的来源，不凑齐所有类别。无法匹配时明确“知识库尚无对应分类”，不要把自拟类别伪装成已有定义。知识库的整理口径不自动归为作者原话。

每项变化用直白的一句话说明对象、变化及已知时间，未知则注明。分类匹配不等于风险已确认，也不把同一条传导链涉及的来源重复计为独立风险。触发与放大关系放在传导章节，暴露主体放在风险类型章节，反证和替代解释放在验证章节；这些内容仍需保留，但不替代来源名称与定义。上游金融因子只是信息依据，不能直接视为已经证实的机制。

## Step 4. 确定风险关键变量

从来源与传导机制出发，选择最能改变风险状态判断的可观察变量。逐项说明与上游共同变量的对应或差异，不把“信息集中讨论某变量”等同于“该变量决定风险”。

先确定最关键的变量并说明其作用环节，再列必要的辅助变量；无法确定主导变量时说明竞争解释。逐项说明什么变化支持机制、什么变化削弱或否定机制，这属于后续验证条件，不是本轮方向结论。

变量应与来源存在直接关系、反映风险程度、可以持续观察，并能改变后续判断。记录指标口径、单位、已知值或定性状态、观测时点、来源、建议频率和验证条件。影响判断的缺失事实按主动补证规则检索，仍不可得或不匹配的内容再列为后续补充需求；值或阈值未知时保留待验证，不自行填造。候选变量或机制尚未成立时保留候选状态。

## Step 5. 建立风险传导关系

组织“风险来源 → 风险关键变量 → 市场 / 主体行为变化 → 风险表现”。每个箭头标明证据或推断，以及可推翻它的条件。检查是否存在更合理的替代解释，不能用下跌或反弹补齐因果链。

正文生成主链图，辅以少量解释；逐环节证据表仅放附录。节点的观察状态与箭头的因果证据分别标注，已观察节点之间也可能只能画虚线。箭头标明成立条件，必要的放大分支及阻断条件贴近对应环节；提供图例并在窄屏保持主链可读。HTML 必须实际渲染图形，不能只展示 Mermaid 源码。

用 [输出模板](template.md) 交付模型。首次分配稳定 risk_id 和 model_version；重识别遵守共享契约的版本和关联规则。模型基准取识别时点可知的信息快照，不等于已经判断风险方向。用户要求持续观察时将模型及上游引用交接给演绎观察，否则完成到此。

## 交付与检查

- 五项模型内容分别表达；缺失内容明确标注，不把候选模型包装成已确认风险。
- 风险来源的层次、名称及定义/核心问题与本次读取的知识页逐项核对；本案例的解释与知识库原定义分列，避免把风险类型、传导机制或暴露主体写成来源分类。
- 检查首屏、正文、图示及导航：内部编号、运行统计和交接说明进入附录；正文保留来源名称链接、关键不确定性和简短时点注释，不因简化呈现而删除证据边界。
- 按模板先结论、后五项模型、再验证重点与附录；核对影响对象与损害、驱动力与放大因素、关键变量主次、每段传导条件是否清楚。读者无需先读身份字段和数据登记即可理解核心判断，正文证据引用仍保留。
- 确认引用可解析到原上游结果，或通过theme的result_id与对象ID回溯到Event / Signal / Evidence及原始来源；补证不冒充上游已有对象。核对分析截止时间与新增覆盖范围，不采用截止时间之后才可知的材料。
- 核对待核表现清单：每项都有theme查询/证据、复用依据或实际未执行原因；有结果者通过结构化校验，无结果者对应缺口，不能只补查最易找到的一项。核对运行说明、来源副本、反证、失败原因及正文/图表状态一致，不能把“未查到”写成“风险不存在”，也不能把主题检索命中当作风险成立。
- 区分没有发现风险、材料不足和来源失败；空输入不证明风险不存在。
- 按共享契约在默认 Risk 目录保存完整模板产物、上游结果及运行说明，并更新定位表；用户明确仅对话时完整交付模板。不重建上游事件时间轴，不在本步骤输出方向、持续性或买卖判断。

- 先保存完整 Markdown 母稿，再读取并执行 [通用 HTML 输出工作流](../bbxm-html-report/workflow.md) 和样式规范，生成同名 HTML；逐项核对模板章节、数值、状态、来源与缺口一致，并完成语法和实际渲染检查。按共享契约登记两种格式，最终优先交付 HTML，附 Markdown。HTML 生成或验收未完成时保留母稿并报告缺项，不声称双格式交付完成。

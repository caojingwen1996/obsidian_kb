# 风险技能共享交接契约

本文件由风险识别与风险演绎观察共同引用，是模型身份、证据引用和记录定位的唯一执行约定。它补充项目方法论，不冒称原作者提出的固定字段或评分模型。风险模型和观察记录采用各技能的 Markdown 模板；当前不另建未经约定的 JSON Schema。

## 上游接入

读取 [信息处理入口](../../information-processing/SKILL.md) 与 [输出约定](../../information-processing/references/output-contract.md)。接收完整 InformationProcessingResult，包括 schema_version、result_id、context、events、timeline、induction，并结合运行说明和 raw_ref 证据记录。保存的上游 JSON 可用其 [校验脚本](../../information-processing/scripts/validate_result.py) 检查结构；通过不等于证据真实、及时或覆盖完整。

1. 先核对对象、核心问题、事件窗口、时区、信息截止时间和来源范围；generated_at 只是生成时间，不能代替信息截止时间或事件时间。
2. 有适用结果则复用。仅有材料用 feed；配置了对象、来源和扫描基准的新增扫描用 monitor；围绕对象动态选择来源用 target。读取上游技能后执行，返回本风险任务，不能让上游再次触发同一风险任务。
3. 缺少原始事实时，提出具体补充需求：对象、待验证问题或指标、口径、所需时间范围及已有证据缺口。由信息处理获取和组织证据；风险技能负责解释这些证据对模型的含义。
4. 同次请求对同一未解决缺口最多补取一轮；来源继续失败时输出缺口与候选/证据不足，等待新材料，不循环调用。新的独立用户请求可以继续补充。
5. 上游可以没有归纳簇或共同变量；不要为满足风险输入要求强造聚类。反之，有共同变量也不能直接视为风险关键变量。
6. 纯 JSON 缺少覆盖与失败诊断时，标注覆盖未知，必要时请求上游运行说明。events 为空只说明结果中没有事件，不足以判定没有风险或风险维持。风险技能不自行修改来源扫描游标。

## 证据引用

- 跨轮次引用用 `result_id + event_id` 并附可定位的结果文件或对话段落；现象和共同变量同样带 result_id，避免不同结果的局部 ID 碰撞。
- 事件事实及分类不在风险层重新提取或改写；同一事件跨轮次已被纳入且无新事实时，不重复当成新增风险冲击。上游修订数据时记录新旧结果引用、修订时点和本轮影响，不静默覆盖历史。
- 风险机制属于分析推断；标明事实、来源观点、推断、候选及反证。历史回看只使用当时可知证据，区分事件发生、发布和本轮获知时间。

## Risk Model

五项业务内容固定为风险类型、风险表现、风险来源、风险关键变量、风险传导关系。执行交接还包括：

| 字段 | 约定 |
|---|---|
| risk_id、model_version、观察对象 | 同一风险跨轮次沿用身份，首次版本1；名称相似不代表同一风险 |
| identification_status | 已支持 / 候选 / 证据不足；不是风险方向 |
| model_as_of、信息截止时间、信息窗口 | 模型快照时点、可知证据截止点与上游窗口分别记录 |
| 上游结果与证据引用 | result_id、结果位置、所用事件/现象/变量及原始证据 |
| 关键变量基准 | 指标、口径、单位、值或状态、观测时点、来源、建议频率；未知写待验证 |
| 风险应对基线 | 当时已知措施及宣布/执行/见效阶段；未知不填成“无” |
| 反证、替代解释、缺口 | 限定模型解释力；机制不足时不能标记已支持 |
| 模型失效、结束和重新开启条件 | 可验证条件；数值阈值无依据时不编造 |
| previous_model_ref、变更原因 | 首次可空；重识别关联旧模型，保留版本历史 |

没有受证据支持的风险允许输出零份模型。旧基准卡或用户等价材料可按此契约映射，未知字段保留缺失；不能因为旧文件格式不同重新编造模型。

## 观察状态与模型版本

- 演绎观察初始化建立 T0，引用具体 risk_id/model_version 的模型基准；记录真实变量观测时点，不把旧数值写成 T0 当日数据。T0 是观察基准，不是“维持”。已有模型但无历史可比观测时，仅初始化并标注方向证据不足。
- 每轮以 observation_id 标识，记录 current_window、comparison_window、信息截止时间和 previous_observation_ref。分别给相对上一轮和相对 T0 的变化；不可比的一项标证据不足。
- 方向：增加 / 维持 / 减弱 / 证据不足；持续性：短期 / 中期 / 长期 / 待验证，并说明实际期限；模型有效性：有效 / 待验证 / 失效；观察任务状态：已建基准 / 继续观察 / 等待证据 / 需要重识别 / 已结束。这些维度分列，不能互相替代。
- 普通状态或数值更新写观察记录，不覆盖原模型或 T0，不提升模型版本。机制假设实质改变时由风险识别升版本；变成不同风险对象或不同性质的独立风险时建立关联 risk_id，说明与旧风险的关系。
- 同次请求重识别最多一轮；模型仍不充分时停止于候选/等待证据，不在两个技能间循环。新模型需建立自己的基准，旧 T0 不能直接冒作新模型 T0；可比历史只能明确引用为辅助证据。
- 风险减弱不自动结束；结束需风险消失或满足明确结束条件。已结束记录不因普通增量请求自动重新开启，先核对重新开启条件，再决定重新基准或重识别。此为 Agent 编排对方法论结束分支的操作补充。

## 保存与下次定位

用户已指定两个风险技能的默认输出根目录为 `<项目根>/tools/a-share-market-dashboard/data/Risk/`（保留 `Risk` 大小写）。当前项目绝对位置为 `E:/caojingwen/obsidian/llmwiki/tools/a-share-market-dashboard/data/Risk/`。用户输入的 `..\tools\a-share-market-dashboard\data\Risk` 按项目内已存在的看板目录落实；执行时从含根 AGENTS.md 的项目根定位，不相对当前终端或技能目录直接拼接 `..`。

风险识别、风险演绎观察保留完整 Markdown 母稿，默认调用 [通用 HTML 报告输出](../../bbxm-html-report/SKILL.md) 生成同目录、同文件名主体的 HTML 阅读版；对话以 HTML 链接为主，附 Markdown 链接和摘要。模型交接与历史追踪继续读取 Markdown，JSON 上游保持原格式；不需要每轮重复询问是否保存。用户明确仅对话、指定其他格式或本轮另行指定目录时优先遵从。本目录承载市场、行业和具体标的的风险工件，不进入正式 Wiki，也不自动迁移或覆盖 Workbench 的旧研究。先读目标工作域规则；此路径约定不代表已经接入看板显示或启动定时任务。

在输出根目录中沿用以下记录结构：

- `risk-records.md`：定位表，列观察对象、risk_id、当前模型版本、模型/T0/最新观察的 Markdown 与 HTML 链接、任务状态、最新分析截止时间与上游运行记录位置；历史记录尚无 HTML 时注明未生成，不伪造链接。
- `inputs/<result_id>.json` 与 `inputs/<result_id>-run.md`：本轮上游结构化结果及来源覆盖、时间口径、失败与缺口；已有可定位文件可引用复用。原始资料按项目规则归档到 `sources/`，在运行说明中链接。
- `models/<risk_id>-v<version>.md` 与同名 `.html`：Markdown 为不可静默覆盖的完整模型快照，HTML 为同源完整阅读版；不能只保存结论摘要。
- `observations/<risk_id>/<observation_id>.md` 与同名 `.html`：逐轮完整记录及阅读版，包含上一轮引用和本轮增量时间轴；沿 Markdown 引用链还原历史，T0 保留。

文件名使用可安全用于路径的稳定标识，不能直接拼接未经核对的用户路径。同一轮重试先查已存在结果，已保存成功则复用；更正需留更正说明，不覆盖原时点判断。先保存 Markdown 和上游工件，再生成并检查同源 HTML，验证实际存在的链接后更新定位表。HTML 失败时保留 Markdown，定位表注明该阅读版未完成，不使用旧版 HTML 冒充本轮结果；最终明确缺项。未生成模型时不为输出格式强造模型，可保存范围与缺口说明及其同源阅读版。

下次按用户指定记录 → 当前对话可定位记录 → 默认 Risk 根目录的 risk-records.md（本轮指定其他输出目录时使用该目录）/既有索引 → 在该工作域按对象和 risk_id 检索的顺序查找。核对实际模型版本和上一轮状态，不仅按文件修改时间选“最新”。多个匹配且无法唯一确定时询问最小必要问题；找不到记录时明确缺失，不能假定已跨会话保存。

来源成功扫描截止点与失败状态沿用上游运行记录；最新分析截止时间不等于所有来源都成功覆盖到该时点。保存动态产物遵守工作域日志要求；可复用知识回流 Wiki 另走正式规则。

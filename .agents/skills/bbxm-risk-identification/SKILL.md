# 风险识别

回答：**现在是什么风险？为什么产生？** 最终交付可供后续观察承接的“风险类型、风险来源、核心变量”，不把识别与风险方向判断混为一体。

## 方法论与准备

1. 每次运行先读项目 `AGENTS.md`、`schema.md`、`page-types.md`、`index.md`。
2. 动态读取 `wiki/concepts/冰冰小美-concept-风险观察与演绎.md`，以第一层信息整理、第二层风险识别为主；按需读取其中链接的时间窗口、风险类型及来源页。路径失效时先在 `wiki/` 检索真实路径，不凭旧记忆重建分类。
3. 区分概念页中的整理者框架与原作者观点；必要时核对 `sources/articles/2025-09-20-冰冰小美：风险变化如何观察.md`。历史案例不能充当当下事实。
4. 本文的基准字段与证据规则是执行约定，不冒称原文已有的固定评分模型。不要发明统一风险分数或强制穷举所有风险类别。

## 输入与证据

- 确定观察对象、核心问题、事件窗口、信息截止时间、用户提供的材料及已有信息归纳结果。
- 优先复用已有材料。缺少对象或关键事件且无法从上下文确定时，先问最小必要问题；可以完成的材料整理继续进行。
- “现在、今日、最新”的分析需要检索和核验当前原始公告、政策、交易所或可靠数据源；记录事件时间、发布时间、获取时间、来源和口径。历史研究只使用截止时点已知信息，避免事后信息倒灌。
- 区分事实、作者观点、分析推断、传闻与待验证。数据失败时记录具体缺口和失败原因，不用历史值、猜测或价格表现替代缺失机制证据。

## 执行步骤

### Step 1. 整理信息与时间窗口

筛选可能改变市场行为的信息，按“宏观 / 中观 / 微观”和“政策 / 市场 / 产业 / 企业 / 机构 / 资金”两层分类。一条信息可有多个属性，但保留同一事件身份，避免重复计数。

将新闻翻译为金融因子：影响钱的数量、价格、流向、信用、现金流、盈利预期或风险偏好的哪一项，依据是什么。没有金融联系的材料留在信息池，不强行纳入风险链。

明确“核心问题 + 关键事件 + 事前预期形成 + 事后重新定价”的时间窗口。建立风险识别时间轴：

| 时间 | 事件及来源 | 层级/类别 | 金融因子 | 事前预期 | 实际结果 | 预期差 | 市场反应 |
|---|---|---|---|---|---|---|---|

事前预期必须有当时证据；缺失写待验证，不能从结果倒推。尚未落地的事件标注计划时间。短期多个事件只有共同指向同一问题并反复改变预期，才构成相关事件密集区，不能只按新闻数量判断风险。

### Step 2. 收敛风险主线

解释事件之间的关联或传导关系、共同现象和共同变量，形成：

**事件 → 金融因子 → 市场行为 → 风险表现**。

为每个箭头列证据或标注推断，检查其他解释与反证。相关性不等于因果；下跌、反弹和波动只是市场表现，不能单独证明风险来源。

### Step 3. 识别风险模型

- **风险类型**：这是什么风险，影响谁、通过什么方式造成损害；分类依据来自当前 Wiki 或明确标注为本次归纳。
- **风险来源**：什么触发事件或驱动变量产生风险，哪些因素只是放大器或结果。
- **核心变量**：哪个变量最能决定风险继续演化还是结束，为什么；将抽象变量落实为可观察指标、口径、来源、频率与验证条件。
- 多条独立风险分别建卡；说明主次，不把同一根因的多种表现重复计为独立风险。
- 同时给出反证、替代解释、关键缺口和原模型失效条件。机制未确认时输出“候选风险 / 证据不足”，不强行定性。

### Step 4. 建立交接基准

每项风险建立稳定风险标识和 T0 基准；后续更新沿用标识，不用每次日期生成一个新风险。需要连续观察时交给 [风险演绎观察](../bbxm-risk-evolution-monitoring/SKILL.md)。仅要求识别时完成到此，不自动扩大为持续监控或交易建议。

## 输出结构

1. **识别结论**：对象、截止时间、风险类型、来源、核心变量，以及已支持 / 候选 / 证据不足。
2. **风险识别时间轴**：使用上表，保留预期与实际落地区分。
3. **风险主线与解释**：因果链、证据、反证和替代解释。
4. **风险基准卡**：每条独立风险一张，按下列字段交接。

| 字段 | 内容要求 |
|---|---|
| 风险标识、版本、对象 | 可跨轮次引用的身份；首次版本为 1 |
| T0、截止时间、事件窗口 | 明确日期范围与时区 |
| 风险类型、风险来源、核心变量 | 三者分开，附理由 |
| 核心变量基准 | 值或有来源的定性状态、观测时点、口径、来源、频率；缺失写待验证 |
| 传导链与当前市场表现 | 机制和表现分开记录 |
| 风险治理力量 | 已观察到的政策或治理措施，区分宣布与兑现 |
| 支持证据、反证、缺口 | 可追溯链接及证据性质 |
| 后续验证与模型失效条件 | 可检验条件；未知阈值不编造 |
| 观察记录引用 | 首次可为空；保存后续观察时记录上一轮文件或会话记录位置 |

## 保存与边界

默认在对话交付。用户要求保存或已有工作流指定保存时，先检查目标规则与已有文件：具体标的研究进入 `workbench/`，读其 `AGENTS.md`，保留基准历史；市场或行业动态观察使用获准的工作域位置，不能伪装为正式 Wiki 知识。正式知识回流另按项目准入规则、模板、来源副本、双链、索引和日志执行。

本技能不输出风险增加 / 维持 / 减弱，不代替三要素、估值或买卖决策；观察风险不等于寻找支持原有立场的证据。

## 技能维护

变更说明、模板或随附文件后，向 [log.md](log.md) 追加日期、版本变化（不升级时写版本号不变）、原因、涉及文件、具体变更和实际验证结果，并更新项目根日志。保留已有记录，不补写未经核实的历史；运行报告不属于技能变更。

# 风险识别

## 定位

依据 [风险观察与演绎](../../../wiki/concepts/冰冰小美-framework-风险观察与演绎.md) 第一层，将已处理的信息转成可解释、可追溯、可供后续观察的 Risk Model。

## 核心能力

1. 将各项待核风险表现交给信息处理的 theme 模式搜集事件、数据与反证，再识别已观察到的表现，确定风险类型与影响对象。
2. 区分风险来源、放大因素和结果，选择决定风险演化的关键变量。
3. 建立风险传导关系，交付模型、证据、反证与失效条件。

## 输入

- 标准上游：feed 的 `InformationProcessingResult` 或 theme 的 `ThemeProcessingResult`，包括观察对象、核心问题、窗口、事件、信号及可用归纳结果；按各自契约读取，不互相改标模式。
- 配套证据：上游运行说明、可定位的原始证据、来源覆盖与失败情况。JSON 未提供的诊断不能假定为正常。
- 补充证据：风险表现核验中调用 theme 模式取得的结构化结果，保留各表现的证据映射、反证、缺口、来源、时点及检索记录。
- 重识别时：旧风险模型、版本和使其失效的新证据。

已有且适用的上游结果直接复用；只有原始材料需要结构化时，衔接 [信息处理](../bbxm-information-processing/SKILL.md) 的 feed 入口。进入风险表现步骤后，逐项建立验证问题，实际执行信息处理的 [theme 工作流](../bbxm-information-processing/workflows/theme-workflow.md) 搜集相关信息和事件；不能仅建议以后调用，也不以本技能自行检索后罗列链接代替 theme 结果。规则见 [工作流中的主动补证](workflow.md#主动补证)。已有 theme 结果覆盖相同对象、问题、窗口和口径时复用，仅补查未覆盖或需更新的表现。

## 输出

每条独立风险输出一份 Risk Model，包含 **风险类型、风险表现、风险来源、风险关键变量、风险传导关系**，附稳定身份、版本、模型基准及证据。采用 [输出模板](template.md)。

正文先给一句话识别结论，再解释五项模型要素，重点回答“谁可能受损、由什么机制驱动、哪个变量最能改变判断、传导成立需要什么条件”。区分已观察表现与可能后果，给变量排主次，明确最关键的验证与反证。身份、完整口径和交接信息放在附录；正文判断仍须就近引用证据。HTML 保留这一阅读顺序。

正文及图示用来源名称和变量名称表达，不展示内部事件/信号/变量编号、模型数量或运行交接说明；这些信息保留在附录或运行记录。首屏用简短结论与来源日期注释，避免将内部字段逐项展示给读者。

风险表现逐项展示“核实了什么、实际观察到什么、反证或缺口、当前能说到哪一步”，按重要性排列；引用 theme 结果中的原始来源。检索前的表现清单是待核假设，不能直接写成已发生风险；仅有背景变化时说明其性质。

风险传导关系以“主链图＋简短解释”展示，不以逐环节表格作为正文主体。节点区分已有观察与待验证后果；箭头注明成立条件，只有因果联系有证据支持时才用实线，条件推断用虚线。放大支线和阻断条件放在对应环节旁，详细证据核对表移入附录；窄屏优先纵向排布，避免阅读主链时横向滚动。

“风险来源”直接采用知识库[风险来源与传导路径](../../../wiki/topics/冰冰小美-风险来源与传导路径.md)中当前的层次、分类名称及定义/核心问题，说明材料中发生了什么变化及证据状态。不得用“结构性驱动、触发事件、潜在放大因素、暴露主体”自行拼成另一套来源分类；传导机制和受影响主体分别放入对应章节。

区分“已支持”“候选”“证据不足”。未发现受证据支持的风险时可以不生成模型，说明范围与缺口；不能为填模板强造风险。仅识别不输出增加、维持、减弱或持续性结论。

保留按模板生成的完整 Markdown 作为模型交接与历史追踪母稿；默认调用 [通用 HTML 报告输出](../bbxm-html-report/SKILL.md) 生成同目录、同文件名主体的 `.html` 阅读版。最终回复优先给 HTML 链接，并附 Markdown 链接；直接调用本技能也执行此要求，不依赖专家总入口。用户明确仅对话或指定其他格式时遵从。

## 工作流入口

执行时读取 [workflow.md](workflow.md)，按五步建立模型。输入接入、模型交接、保存和跨轮次定位统一遵守 [共享交接契约](references/handoff-contract.md)。

## 能力边界

- 原材料的信息获取、事件提取、信号归纳和证据整理通过信息处理执行；本技能负责提出各风险表现的验证问题、调用 theme 并解释证据对风险的意义。后续关键变量或传导缺口仍返回此入口补证，不扩展为无关的全市场扫描。
- 保留原上游结果与历史模型快照；新增证据单独登记并明确采用的分析截止时间。补证不等于机制已确认，也不自动产生风险方向、持续性或交易判断。
- 风险关键变量需要机制和可观察性依据，不能直接复制上游共同变量。
- 不用价格变化单独证明风险来源，不将相关性冒充因果，不编造评分、阈值和观测值。
- 仅在用户要求观察或上游任务明确包含观察时，交给 [风险演绎观察](../bbxm-risk-evolution-monitoring/SKILL.md)；仅识别则到模型交付为止。
- 默认将完整模型及证据引用保存到项目根目录下 `tools/a-share-market-dashboard/data/Risk/`，组织与定位遵守共享交接契约；对话返回摘要、HTML 主链接及 Markdown 链接。用户明确仅对话或另行指定路径时从其要求；不自动生成交易建议或定时任务。

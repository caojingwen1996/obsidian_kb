# 机构级个股研究

## 0. 当前版本

当前版本：`3.0.5`

---

## 定位

本技能用于把公开信息转化为可审计、可证伪、可直接支持真实决策的个股研报。完整公司研究由本技能主导；资金状态、风险状态和动作约束应压缩进入决策摘要、事实章节、最终结论与监控指标，不设置独立的“冰冰小美框架判断”章节。

## 路由边界

以下请求使用本技能：

- 研究一家上市公司或产出机构级研报；
- 估算公允价值、目标价、DCF 或安全边际；
- 比较多种估值方法并判断低估、合理或高估；
- 回答“如果今天这是一笔现金，我会不会买”。

以下请求使用相邻技能：

- 单条新闻、公告、政策、传闻是否有用：`bbxm-information-filter-flow`；
- 交割单、成交记录、仓位行为复盘：`bbxm-trade-ticket-review`；
- 只判断风险增强、持平、减弱或重新增强：`bbxm-risk-identification`；
- 只分析竞争格局、流动性、情绪位置和三要素共振：`bbxm-three-factor-analysis`。

用户明确要求完整三要素或专项风险分析时，可另用相邻技能生成独立分析；`bbxm-three-factor-analysis` 与 `bbxm-risk-identification` 两个技能互不调用，个股研报只引用其必要结论，不得在本技能中复制其检查清单。

## 开始前必须确认

1. 公司全称、证券代码、交易所和币种；
2. 研究截止时间，以及“实时”数据的实际抓取时间；
3. 报告准则和法定披露体系；
4. 用户是否指定数据源、持仓成本、预期持有期或风险预算；
5. 当前项目的落盘规则。若处于 llmwiki，先读取根 `AGENTS.md`、`SCHEMA.md`、`page-types.md`、`index.md`，再读取 `workbench/AGENTS.md` 和 `workbench/index.md`。

标的身份存在歧义时，停止估值，先核对身份。不得把同名证券、母子公司或不同上市地数据混用。

## 证据纪律

### 来源优先级

1. 监管机构、交易所和公司法定文件；
2. 公司投资者关系材料、业绩会记录和正式公告；
3. A 股研究中，本地 `tushare-data` MCP 已暴露工具用于优先获取可结构化事实；
4. 用户指定的行情、估值或评级平台；
5. 券商研报和权威媒体；
6. 聚合器、搜索摘要和社交信息仅用于定位线索。

财务历史必须按市场选择法定来源：

- 美国 SEC 申报公司：SEC 10-K、10-Q、8-K；
- A 股：上交所、深交所、北交所或巨潮资讯法定披露；
- 港股：港交所披露易及公司法定报告；
- 其他市场：当地监管机构或交易所正式披露。

用户要求 SEC 但目标不是 SEC 申报公司时，明确写“SEC 文件不适用”，再使用当地法定披露；不得伪造 SEC 口径。

### A 股 Tushare MCP 优先调用规则

当研究对象是沪深北 A 股时，优先检查当前会话是否已热加载 `tushare-data` MCP；若未热加载，可通过本地 stdio server `tools/tushare-data/scripts/mcp_server.py` 调用。MCP 调用失败、接口无权限、无数据、字段缺失或对象不适用时，不得把失败解释为“没有该事实”，应回退 AKShare / 交易所 / 巨潮资讯 / 公司公告 / 公开页面，并在第 2 章来源矩阵写明回退原因。

| 研究数据需求 | 优先 MCP 工具 | 用途 | 必要边界 |
|---|---|---|---|
| 证券身份、简称、行业、上市状态 | `get_stock_basic` | Step 1 / 第 2 章身份校验 | 只用于身份和行业基础画像，不能替代公司公告中的业务分部 |
| 日线价格、成交额、52 周区间、YTD、量价窗口 | `get_stock_daily` | Step 2 / 第 3 章行情与第 1 章资金面组 | Tushare `daily` 为不复权价格；复权和盘中价格需另行说明 |
| PE、PB、PS、股息率、市值、换手率 | `get_stock_valuation` | 第 3 章行情与估值快照，第 10 章公允价值区间计算输入 | `dv_ttm` 为个股股息率字段；估值输入需说明日期和单位 |
| 资金分档、大单 / 小单、主力净流入代理 | `get_stock_moneyflow` | 第 1 章资金面组、第 3 章行情和第 9 章多空论据 | 只确认订单规模方向，不能确认机构、散户或长期资金账户身份 |
| 融资融券余额、融资买入、偿还、融券变化 | `get_margin_detail` | 第 1 章资金面组与第 9 章交易风险论据 | 融资买入会进入订单流，不能与资金分档机械相加 |
| 利润表、资产负债表、现金流核心科目 | `get_financial_statements` | 第 6—7 章财务历史和最新季度的结构化初稿 | A 股财务结论仍需交易所 / 巨潮 / 公司法定报告复核；不得只凭 MCP 自动字段完成五年历史 |
| 历史分红方案与实施 | `get_dividend_history` | 分红、股息率和股东回报旁证 | 分红是股东回报证据，不等于资金流入证据 |
| 指数成分股及权重 | `get_index_constituents` | 指数 / ETF 覆盖和中观配置背景 | 不能确认 ETF 申购者或国家队身份 |

当前 `tushare-data` MCP 不覆盖或不直接支持的项目继续走其他来源，并在来源矩阵中保留缺口：卖方一致预期、目标价分布、第三方公允价值 / 护城河 / 星级、公司公告全文、业绩会纪要、订单明细、分部收入、可比公司估值、DCF 假设、ETF 份额与估算申赎、北向 / 陆股通持仓、龙虎榜、回购、增减持、股东户数、质押、解禁和大宗交易。

MCP 是结构化数据入口，不改变法定披露优先原则。行情、估值、资金和财务字段可以提高采集效率，但关键财务、分部、指引、风险事件和估值假设必须回到法定公告、交易所文件、公司材料或可审计来源确认。

### 写作约束

- 每个关键数据标注来源、发布日期或抓取时间和口径。
- 事实与判断分开。推断必须以 **“我的判断”** 开头，并紧接依据。
- 来源冲突时列出各自数字、口径和时间，再说明采信理由。
- 无法取得的数据统一写 **“未获取到”**，并写已检查的来源；不得使用记忆补全。
- 数据源失败不等于数据不存在，不得据此写“没有”。
- 多空论据必须并陈，并分别写出验证指标和失效条件。
- 搜索摘要不能成为关键财务数字或结论的唯一来源。
- 实时市场判断必须当日重新核验，不复用旧价格、旧估值或旧新闻结论。

## 执行流程

### Step 1：建立来源矩阵

为下列项目逐项记录“目标来源、实际来源、数据时间、状态”：

- A 股标的的 `tushare-data` MCP 调用清单、返回状态、数据时间、缺失字段和回退原因；
- 实时价格、52 周高低、今年以来表现；
- 第三方公允价值、护城河评级、星级；
- 最新季报、分部收入、管理层指引；
- 卖方评级、目标价分布；
- 近三个月新闻与催化剂；
- 五年营收、毛利率、自由现金流和 ROIC。
- 决策所需的连续量价、换手率、相对强弱、融资、ETF / 机构代理和资金数据。
- 企业全部已识别产业位置的业务暴露与景气证据，包括需求、供给、价格 / 价差、库存 / 订单、产能 / 资本开支和政策信号中适用的字段。
- 所有公司的通胀适用性筛查，以及中高暴露公司所需的价格来源、需求、成本、定价权、金融条件和分部传导证据；不得仅凭 CPI 高低判断影响。
- 前沿科技分部的技术、认证、客户、量产、单位经济性、现金消耗、融资和股权稀释证据。

状态只能为：`已获取`、`未获取到`、`不适用`、`口径冲突待解释`。

### Step 2：采集行情与外部预期

按用户指定来源获取实时价格、52 周高低和年初至今表现；未指定且目标为 A 股时，先用 `tushare-data` MCP 的 `get_stock_daily` 和 `get_stock_valuation` 获取收盘价格、成交、换手、估值、市值和股息率，再用交易所、行情平台或本地行情代理补盘中价格。记录是否复权、盘中或收盘、当地时区。非 A 股仍优先使用交易所或可靠行情平台。

同步收集可取得的连续交易证据：至少两个可比窗口的价格、成交额、换手率、相对行业强弱，以及融资、ETF / 机构代理或大单资金。A 股优先用 `get_stock_moneyflow` 获取大单 / 资金分档代理，用 `get_margin_detail` 获取融资融券代理；MCP 未覆盖的 ETF、北向、龙虎榜、机构持仓等继续回退公开来源。无法取得的字段登记到来源矩阵并说明缺口，不得在形成决策时无记录地另起一套数据口径。

第三方公允价值、护城河和星级只能在实际取得页面字段后填入。付费墙或登录限制下写“未获取到”，不得从搜索摘要猜测。

卖方观点至少记录：机构、评级、目标价、发布日期、预测期和关键假设。目标价分布缺少样本明细时必须降低可信度。

### Step 3：提取法定财务历史

至少整理最近五个完整财年：

- 营业收入；
- 毛利率；
- 经营现金流；
- 资本性支出；
- 自由现金流；
- ROIC 或明确标注的 ROIC 代理值。

默认计算口径：

```text
自由现金流 = 经营现金流 - 购建长期资产支付的现金
NOPAT = 经营利润 × (1 - 标准化税率)
ROIC 代理值 = NOPAT ÷ 平均投入资本
```

若公司披露口径不同，可并列展示，但不得混为同一序列。一次性损益、会计政策变化、重大重组和币种变化必须说明。

A 股标的可先用 `get_financial_statements` 形成利润表、资产负债表和现金流核心科目的结构化初稿，再用交易所 / 巨潮资讯 / 公司年报复核五年财务历史、分部口径、一次性项目和管理层解释。MCP 没有返回的财务字段写“未获取到”，不得用相邻年份、搜索摘要或估算值补齐。

### Step 4：拆解最新经营变化

提取最新季度或半年度的收入、利润率、净利润、调整后利润、经营现金流、订单/储备及资产负债表异常项。结合分部收入和利润率判断增长来自数量、价格、并购、会计重分类还是真实需求。

管理层指引必须区分：正式量化指引、定性展望、卖方预测和“我的判断”。

同时完成商业模式事实底稿：收入来源、客户与定价权、成本结构、资本强度、主要竞争者、替代方案和监管约束，并在第 4 章形成独立、可引用的基本面结论。

产业位置不得默认只有一个，也不得套用预设分类。根据公司的实际业务、资源禀赋、供需关系、客户用途、政策环境和技术变化，识别所有与收入、利润、资产价值或估值逻辑有实质关联的产业位置，并分别写明识别依据。某种属性、主题或需求驱动只有能写出“外部变化 → 公司产品量价或成本 → 分部利润 / 现金流”的传导链时才可列入；仅有概念关联时标为“弱关联 / 待验证”，不得当作已兑现产业位置。

第 4 章必须按以下规则形成“多产业位置景气度排序”：

1. 每个位置分别写明位置名称、识别依据、公司业务 / 资产暴露、当前景气度、景气趋势、核心证据、财务传导、验证指标和失效条件；不得把多个位置合并成一句标签，也不得为了套用分类而拆分或合并实际位置。
2. 当前景气度只允许写 `高 / 较高 / 中 / 较低 / 低 / 证据不足`。至少核对需求、供给、价格或利润指标三类证据；按行业特性补充库存、订单、产能、资本开支或政策信号。
3. 排序首先按当前景气度从高到低，其次按趋势 `上行 / 持平 / 下行`，再次按公司可验证的利润或资产暴露强弱。`证据不足` 单列在已评级位置之后，不得伪装成低景气。
4. 同一利润来源被多个产业位置或叙事覆盖时明确交叉关系，不重复计算收入、利润或估值贡献。
5. 排名靠前不等于公司必然受益。结论必须同时说明受益弹性、兑现时滞、约束条件，以及景气能否进入公司利润和现金流。

### Step 4.3：筛查通胀暴露并建立经营传导

所有公司先完成通胀适用性筛查，结果只写 `高暴露 / 中等暴露 / 低暴露 / 证据不足`。筛查同时覆盖经营成本、客户需求和利率 / 信用 / 汇率三类渠道；低暴露公司简要说明为何不足以改变利润、现金流或估值锚，中高暴露公司必须继续判断通胀类型并按主要分部建立传导链。

在 llmwiki 中先读取 `wiki/concepts/冰冰小美-macro-通胀与资产.md`；其他项目读取 `references/inflation-transmission.md`。按参考规则区分通缩或低通胀修复、温和再通胀、输入性 / 供给冲击型通胀、滞胀或恶性通胀、混合状态、证据不足，并输出：

```text
价格与政策冲击 → 分部需求 / 销量 → 产品价格 → 成本与转嫁 → 利润率 → 营运资金 / 现金流 → 估值锚
```

不得把上游涨价机械外推为整家公司利好或利空。分别识别直接影响、客户资本开支等二阶影响、海外与汇率缓冲、传导时滞和失效条件；通胀结论若足以改变基本面状态或估值假设，必须进入第 1、9、10、12、13 章。

### Step 4.4：判断企业价值类型与主估值锚

估值前先判断企业主要依靠什么创造股东价值。在 llmwiki 中以 `wiki/concepts/冰冰小美-framework-估值判断.md` 的“### 一、怎么计算公允价值”为分类依据；其他项目直接执行下表。企业类型判断使用商业模式、利润来源、资产结构、资本强度和现金流特征，不使用投资大师命名分类。

| 企业价值类型 | 核心判断 | 主估值锚 |
|---|---|---|
| 稳定盈利 | 需求、盈利和资本开支可预测，价值来自持续利润、现金流与分红 | 正常化 EPS × 合理 PE；自由现金流与股息率交叉验证 |
| 周期资源 | 利润主要受供需、价格、库存、产能利用率和成本周期驱动 | 周期中枢利润 × 中枢 PE；PB、供需与周期位置交叉验证 |
| 重资产 | 厂房、设备、库存、土地、矿权或运输资产的质量与回报决定价值 | 调整后 NAV × 合理 PB；ROIC、重置成本与可变现价值交叉验证 |
| 成长企业 | 已有经营基础，未来收入能否转化为利润、自由现金流和再投资回报决定价值 | 未来利润 × 届时合理 PE 后折现；悲观 / 基准 / 乐观概率加权 |
| 前沿科技 | 尚无可靠利润，技术、认证、客户、量产或商业化仍存在重大不确定性 | 已验证基本盘＋里程碑概率加权未来业务价值，扣除投入、稀释和失败风险 |

整家公司只写一个主类型；确有两种以上价值来源时，不新增“混合型”类别，而是说明各分部属于上述哪一种类型，分别估值后加总。企业类型决定主估值锚，但不能替代下一步的分部成熟度判断。

### Step 4.5：建立分部级估值成熟度路由

估值前按业务分部而不是整家公司贴标签。每个实质影响收入、利润、资产或估值区间的分部，只能归入以下一种状态：

| 成熟度 | 判断标准 | 主要估值锚 |
|---|---|---|
| 已验证基本盘 | 已形成可追踪收入、利润、订单或现金流 | DCF、PE、EV/EBITDA、正常化现金流 |
| 商业化成长业务 | 关键技术、监管和交付节点已通过，已出现可重复收入，但规模、利润率或资本效率仍在形成 | 分阶段 DCF、收入 / 毛利倍数、可比公司 |
| 前沿期权业务 | 技术、认证、客户、量产或盈利仍缺决定性验证；仅有试点、意向订单或首批付费订单不自动升级 | 里程碑概率加权、融资 / 交易定价、分部加总 |
| 失败或退出业务 | 已失去商业化路径或只能回收剩余资产 | 清算、残值或零值 |

当任何前沿期权业务可能实质影响估值中枢或上沿时，必须读取并执行 `references/frontier-tech-valuation.md`。混合企业分别估值后再汇总，不能用成熟主业的利润率、折现率或估值倍数直接覆盖未验证业务，也不能因合并报表亏损把已验证基本盘计为零。



### Step 5：整理新闻、催化剂与风险


新闻窗口默认最近三个月，按发生日而非搜索结果发布日期排序。每条催化剂写：

```text
事件 → 影响变量 → 财务传导 → 当前价格是否已反映 → 验证节点 → 失效条件
```

同时列出负面催化剂、公司治理风险、融资/减持/解禁、订单兑现、政策变化和估值锚失效风险。

### Step 6：按企业类型与分部成熟度计算公允价值区间

先执行企业类型的主估值锚，再用分部成熟度决定证据权重和区间位置：已验证基本盘可以进入下沿与中枢；商业化成长业务按经营证据和资本效率进入中枢或上沿；前沿期权业务只能按里程碑概率进入上沿；失败或退出业务只计残值或零值。

五类企业的主计算不得互相替代：

| 企业价值类型 | 主计算 | 必做交叉验证 | 禁止项 |
|---|---|---|---|
| 稳定盈利 | 正常化 EPS × 合理 PE | 自由现金流、可持续分红、历史与同业估值 | 把一次性利润当成持续利润 |
| 周期资源 | 周期中枢利润 × 中枢 PE | PB、3—5年中枢价格、正常产能利用率与供需位置 | 在景气顶部把低 PE 当成便宜 |
| 重资产 | 调整后 NAV × 合理 PB | 资产可变现价格、ROIC、减值与处置成本 | 直接按账面净资产计算劣质资产和库存 |
| 成长企业 | 未来利润 × 届时合理 PE 后折现 | 增长质量、资本开支、营运资金、自由现金流与情景概率 | 只看营收增速和市场空间 |
| 前沿科技 | 基本盘＋概率加权未来业务价值 | 里程碑、融资定价、现金跑道、稀释与失败情景 | 把尚未兑现的故事按成功计价 |

#### 标准路线

没有实质性前沿期权业务时，以 Step 4.4 确定的企业类型主估值锚作为第一方法，再选择至少两项真正独立的交叉验证；不得为了凑齐方法而机械套用不适用的 DCF，也不得用三个相近倍数冒充三种方法：

1. **主估值锚**：稳定盈利企业使用正常化利润、自由现金流或分红能力；周期资源企业使用周期中枢利润、PB 和供需位置；重资产企业使用调整后 NAV 与合理 PB；成长企业使用概率加权的未来利润并折现；
2. **经营与资产交叉验证**：按企业类型选择自由现金流、股息率、ROIC、资产可变现价值、3—5 年中枢价格、正常产能利用率、资本开支和营运资金等独立证据；
3. **相对或行业估值**：选择可比公司或行业特定指标，解释业务、成长、利润率、资本结构、会计口径及周期位置的可比性；
4. **反向估值**：计算现价隐含的增长、利润率、资产回报、周期位置或成功概率，作为必做约束，不把市场价格反过来当成公允价值证据。

只有在自由现金流能够形成可审计预测时才使用 DCF。采用 DCF 时，必须明确预测期、收入增长、利润率、税率、折旧摊销、资本开支、营运资本、WACC、永续增长率和净债务，并提供悲观 / 基准 / 乐观三种情景、二维敏感性分析、股权价值到每股价值的桥接、反向 DCF，以及长期负自由现金流或终值占比过高的风险提示；低权重或不适用时必须说明理由。

#### 前沿科技路线

存在实质性前沿期权业务时，以分部价值桥为主，至少使用三个独立视角交叉验证；不得为了凑齐方法而伪造不可用的 PE、PS 或完整公司 DCF：

1. **已验证基本盘价值**：对已跑通业务单独使用 DCF、正常化利润、资产价值或可比公司估值；
2. **里程碑概率加权 SOTP**：按技术、认证、客户、量产、单位经济性和融资生存节点，为失败、延期、有限商业化、基准成功和突破成功情景赋值；
3. **融资 / 交易定价**：使用独立第三方融资、战略投资、技术授权、并购或可比项目价格，并调整交易时间、优先权、控制权和流动性差异；实际未获取到时明确缺口；
4. **反向估值**：计算现价隐含了哪些项目成功、成功概率、收入和利润率，作为必做约束，不把当前市值反过来当成未来业务价值的证据。

前沿科技的当前股东价值桥使用统一口径：

```text
当前股东价值
= 已验证基本盘价值
+ Σ（各未来业务各情景价值 × 情景概率 × 时间折现 × 当前股东保留比例）
+ 净现金
- 公司自行承担且尚未计入分部价值的未来投入
```

公司使用现有现金投入时扣除未来现金消耗；外部股权融资通过当前股东保留比例或稀释后股本反映；新增债务进入净债务。不得把同一笔资金同时作为未来投入和融资稀释重复扣除。若情景概率已经反映技术或商业失败风险，不再用异常高折现率重复惩罚同一风险。

完整公司 DCF 在自由现金流预计五年后才转正、终值占企业价值超过 70%，或稳态利润率缺乏可验证依据时，降为低权重约束；无法形成可审计预测时可写“不适用”，但必须保留基本盘估值和反向估值。五年和 70% 是初始治理阈值，不是金融定律，后续应根据案例回测调整。

无论采用哪条路线，各方法都不得机械平均。最终区间必须解释：下沿只计保守基本盘与可回收价值；中枢计入已有里程碑支持的概率加权价值；上沿计入下一阶段验证成功；高于上沿需要新增订单、收入、利润率、融资或技术证据。

Step 4.3 判断为中高通胀暴露时，悲观 / 基准 / 乐观情景必须与通胀类型及传导链一致，至少检查收入、利润率、营运资金、融资成本和估值锚中的适用项。已经进入收入、利润率、WACC 或估值倍数的同一冲击不得重复扣减；低暴露公司只保留有证据的金融条件影响。

### Step 7：计算市场价格偏离并判断估值泡沫

在形成最终结论前，先逐项核对分部价值是否重复、概率与折现是否重复惩罚、未来投入与融资稀释是否重复扣除，再用反向估值检查现价隐含假设。完成公允价值区间后，必须增加市场价格分解：

本步骤的完整输出必须写入独立的第 11 章“市场价格分解与估值泡沫判断”，不得继续作为第 10 章“公允价值区间计算”的子章节。第 10 章只保留估值方法、价值桥、交叉验证以及企业类型与估值锚匹配。

```text
市场价格
= 公允价值
+ 可解释的估值溢价
+ 交易定价偏离
```

- **公允价值**：已验证基本盘价值，加尚未形成可靠收入利润但已按里程碑、失败概率、时间折现和当前股东保留比例处理的未来业务价值；
- **可解释的估值溢价**：市场为已被经营证据验证的竞争优势、增长质量、定价权、资本效率或稀缺性支付的额外价格；
- **交易定价偏离**：不能由公允价值和可解释溢价充分说明、主要由流动性、风险偏好、杠杆、拥挤和情绪一致性形成的剩余价格偏离。

若相对估值、DCF 或分部价值已经在增长、利润率、折现率或倍数中计入质量溢价，不得再次把同一因素作为“可解释的估值溢价”相加。市场价格分解是解释框架，不得为了凑平现价而倒推出虚假的精确值。

至少计算并展示：

```text
相对中枢偏离率 = 当前价格 ÷ 公允价值中枢 - 1
相对上沿偏离率 = 当前价格 ÷ 公允价值上沿 - 1
上沿外价格 = max（0，当前价格 - 公允价值上沿）
```

偏离率只用于确认脱锚程度，不能单独证明泡沫。继续完成以下七问审计：

1. 当前价格比公允价值中枢和上沿高多少？
2. 高出的部分隐含了多少年增长，以及怎样的收入、利润率、资本回报或项目成功概率？
3. 这些预期是否已有订单、收入、利润和自由现金流交叉验证？
4. 是否完整扣除了后续投入、融资稀释、现金消耗、时间折现和失败概率？
5. 流动性、风险偏好和估值倍数恢复到正常状态后，企业价值还能否支撑现价？
6. 增长、利润率、商品价格或项目成功率回到正常水平后，现价还能否成立？
7. 市场是否仍在认真定价竞争、融资、政策、技术失败和经营不及预期等失败情景？

按企业类型选择反向估值变量：稳定盈利企业看正常化 EPS、自由现金流与隐含 PE；周期企业看中枢利润、商品价格与周期位置；重资产企业看调整后 NAV、PB 与 ROIC；成长企业看隐含增长年限、稳态利润率和再投资回报；前沿科技企业看项目成功概率、商业化时间、现金跑道、融资稀释和当前股东保留比例。

#### 三表逐项扫描

完成七问审计后，必须按照“基本面触发、流动性触发、预期触发”三张表逐项扫描，再判断市场价格的估值状态。在 llmwiki 中，完整读取 `wiki/concepts/冰冰小美-framework-估值判断.md` 的“泡沫破裂的触发器”当前版本；在其他项目中，完整读取 `references/valuation-bubble-trigger-scan.md`。不得凭记忆改写观察项，也不得只扫描有数据或支持既有结论的项目。

三张表固定覆盖：

1. **基本面触发表（9项）**：现金流断点5项，盈利不匹配4项；
2. **流动性触发表（14项）**：宏观货币条件4项，中观政策与主线资金4项，微观杠杆和承接6项；
3. **预期触发表（9项）**：叙事耗尽4项，财报与真实经营接管定价5项。

通胀必须拆成两条证据链：经营层影响写入 Step 4.3，并在基本面表的原材料成本、定价权和利润 / 现金流转化中验证；流动性表的“通胀”只判断利率、信用、美元与估值的金融传导。不得因 CPI 较低就把原材料上涨和成本无法转嫁判为整体有利，也不得把资金流变化外推为经营改善或恶化。

对每一个观察项填写：`当前证据与时间`、`扫描状态`、`对估值状态的影响`。扫描状态只能使用：

- `有利`：当前证据更接近表内有利状态；只表示该触发器尚未形成，不代表股票便宜；
- `逆转`：当前证据已达到表内逆转信号；必须说明它是否击中主估值锚；
- `证据不足`：已检查来源但无法判断，不能按有利处理；
- `不适用`：业务或市场结构确实不适用，并写明理由。

每张表完成后汇总有利、逆转、证据不足和不适用项，并写出：关键逆转、主要反证、缺失证据、与其他表的传导关系。三张表的标题或行名存在不能证明扫描完成；32项必须逐行出现，案例文章只能解释识别方法，不能替代当前标的证据。

扫描结果不是机械评分，不允许按逆转项数量机械打分。逆转项数量只用于完整性核对；估值状态取决于现价是否脱离公允价值、逆转是否击中主估值锚，以及基本面、流动性、预期之间是否形成可验证的传导链。

泡沫判断使用三项核心门槛和三项放大器，不设跨行业统一 PE 或固定涨幅阈值：

| 类型 | 判断问题 | 成立条件 |
|---|---|---|
| 核心门槛：估值脱锚 | 现价是否超过乐观公允价值上沿，且反向估值要求超出可审计的合理乐观情景？ | 两项同时成立 |
| 核心门槛：经营验证缺口 | 远期增长是否缺少订单、利润、自由现金流、资本回报或关键里程碑验证？ | 至少一项关键价值驱动缺少验证 |
| 核心门槛：正常化压力失败 | 流动性、增长、利润率、商品价格或成功率正常化后，现价是否无法成立？ | 至少一项关键压力测试失败 |
| 放大器：融资依赖 | 估值是否依赖持续外部融资、现金消耗或显著股权稀释？ | 依赖显著且未充分计价 |
| 放大器：杠杆与承接 | 上涨是否依赖融资杠杆、集中持仓、逼空或单一增量承接？ | 承接逆转可能触发去杠杆 |
| 放大器：叙事一致性 | 市场是否线性外推远期成功并忽视失败情景？ | 失败情景明显退出主流定价 |

最终只允许使用以下互斥结论：

- `公允价值内`：现价处于公允价值区间内，且基本面扫描没有推翻当前估值锚；一旦估值锚被推翻，先返回 Step 6 重算区间；
- `可解释估值溢价`：现价高于中枢，但溢价主要由已验证的企业质量与增长解释；基本面关键项有利、正常化压力仍可成立，流动性或叙事不是维持现价的主要条件；
- `普通高估`：现价高于公允价值上沿或安全边际不足，但严格估值脱锚或跨表泡沫传导链尚未成立；孤立逆转信号不能自动升级为泡沫；
- `估值泡沫`：估值脱锚成立；基本面或预期表出现击中主估值锚的关键逆转；同时流动性或预期表至少出现一个显著放大器；
- `严重估值泡沫`：三项核心门槛全部成立，并至少一个放大器显著；基本面、流动性、预期三表均出现能够相互传导的关键逆转；
- `证据不足`：公允价值、反向估值或三表关键观察项缺少足够证据，无法区分相邻状态。

“严重估值泡沫”是证据门槛，不是机械打分。报告必须逐项列出成立、不成立和未获取到的证据，并给出置信度；不能只给标签。泡沫程度与泡沫是否正在出清必须分开：三表没有关键逆转时写“未见出清触发”；单表出现关键逆转，或多表只有早期信号但尚未形成价格、融资或业绩传导时写“出清观察”；至少两表出现相互传导的关键逆转，并由价格、融资收缩、盈利不匹配或承接恶化确认时，才写“出清中”；无法判断时写“证据不足”。

若标的出现大幅下跌、恐慌或被迫卖出，或结论准备升级为买入，再增加逆向投资闸门，区分价格下跌、基本面永久受损、价值陷阱与足够安全边际；不得仅因跌幅大或泡沫开始出清而给出买入。




### Step 8：形成决策并落盘

使用同目录 `template.md`。结论必须回答：

1. 当前属于低估、合理还是高估；
2. 动作为买入、观望还是规避；
3. 公允价值区间与相对现价空间；
4. 市场价格属于公允价值内、可解释估值溢价、普通高估、估值泡沫、严重估值泡沫还是证据不足，并列出三表逐项扫描摘要、关键逆转、反证、跨表传导与置信度；
5. **如果今天这是一笔现金，我会买它吗**；
6. 关键经营变化，至少覆盖经营指标的转折、管理层态度的变化，以及公司基本面与市场预期之间的偏差；
7. 哪些事实会改变结论；
8. 后续 3–5 个监控指标。
9. 当 Step 7 的逆向投资闸门触发时，必须写明满足/缺失条件、是否存在价值陷阱风险，以及该判断如何影响买入、观望或规避动作。
10. 企业价值主类型、分部类型映射、主估值锚、价值创造链、市场预期偏差、证伪条件及估值锚失效后的退出条件。
11. 通胀适用性、当前宏观价格环境、对基本面与估值的净影响及下一验证点；低暴露时说明为何不构成主要变量。

默认文件名：`YYYY-MM-DD-HHmm-<标的>-机构级决策研报.md`。但在 llmwiki 中，文件名只用于首次新建；每次生成前必须先按证券代码、公司简称和标题检索 `workbench/targets/` 是否已有同一标的的 `机构级决策研报.md`。如果已有权威研报，必须读取原 Markdown，在原文件基础上更新内容，并用同一路径重新渲染 HTML；不得为了记录新时间、套用新模板、刷新样式、补充行情或修正结论而创建第二份同标的权威研报。只有用户明确要求“保留历史快照 / 新建一版对比稿”时，才允许另存，并在文件名中标明 `历史快照`、`对比稿` 或事件类型。

第 1 章基本面组的 `公允价值区间` 不能只填一个数字区间。必须在同一字段内压缩写出区间含义，至少覆盖：

- 下沿：代表保守情景或只看已验证主业时的价值；
- 中枢：代表当前最可能的主业质量、成长与合理溢价；
- 上沿：代表已经计入的成长溢价、新业务期权或乐观假设；
- 高于上沿：说明需要哪些新增事实支撑，例如订单、收入、利润率修复、盈利预测上修或资金重新定价。

前沿科技路线还必须在同一字段标明“基本盘价值”和“已计入的未来业务期权”，避免读者把整个区间误解为已兑现盈利价值。

推荐格式：

```text
30-37 元；30 元附近=保守主业价值，34-35 元=主业合理溢价，37 元附近=已含部分液冷/机器人期权，38 元以上需新业务订单、收入或盈利上修支撑。
```

在 llmwiki 中，库外原始材料必须先保存到 `sources/`。正式研报首次新建时保存为 `workbench/targets/YYYY-MM-DD-HHmm-<标的>-机构级决策研报.md`，frontmatter 使用 `artifact_type: equity_research`；已有同标的研报时必须原地更新既有文件。`workbench/targets/` 保持扁平，不创建证券代码子目录或单标的索引。更新 `workbench/index.md` 与根 `log.md`，不更新根 `index.md`，也不得把研报保存到 `wiki/queries/`。其他项目保存到用户指定位置；未指定时使用当前项目合理的研究输出目录。

### Step 9：生成并验证 HTML

Markdown 通过完整性检查后，默认必须再生成一份同源 HTML；只有用户明确要求仅交付 Markdown 时才可跳过。HTML 不维护独立研究正文，必须由最终 Markdown 通过技能内统一渲染器生成。

使用命令：

```text
node .agents/skills/bbxm-equity-research/scripts/render-report-html.cjs --input <研报.md> --output <研报.html> --vault-root <知识库根目录>
```

若系统 PATH 中没有 `node`，先调用工作区依赖定位能力取得 Node.js 可执行文件，再用其绝对路径执行同一命令。禁止通过 PowerShell 管道或内联脚本传递中文 HTML 文本。

输出规则：

1. 在 llmwiki 中，HTML 不进入 `workbench/`；写回原自动化分类 `sources/automations/<分类>/`，尚未分类时写入 `sources/automations/temp/`，文件名与 Markdown 主文件名一致；已有同标的 HTML 时，必须优先覆盖与当前权威 Markdown 同名的 HTML，旧版重复 HTML 应归档或删除，不得让同一标的在同一分类目录下并列多份“机构级决策研报”；
2. 在其他项目中，用户指定 HTML 目录时写入该目录；未指定时与 Markdown 同目录、同名，仅扩展名改为 `.html`；
3. 页面固定使用技能内 `assets/report.css` 的版式：渐变封面、判断徽章、四张关键指标卡、左侧目录、右侧正文和打印样式；
4. 封面字段从“决策摘要”和报告元数据自动提取；缺失字段显示“未获取”，不得猜测；
5. 生成后必须检查 15 个目录锚点、UTF-8 中文、关键指标、Obsidian 双链转换和 Markdown / HTML 结论一致性；
6. HTML 生成或验证失败时，整份研报仍视为未完成。

### Step 10：生成每日跟踪面板

HTML 必须在16章正文之前生成一个可重复更新的“每日跟踪面板”，用于把静态研报转成持续决策入口。面板不是第二套研究正文，只消费第1章决策摘要和已有资金证据。

第1章决策摘要必须拆分为“基本面组”和“资金面组”两个小表，避免单表信息过密。“基本面组”填写：`估值状态`、`公允价值区间`、`相对现价空间`、`估值泡沫判断`、`基本面状态`、`宏观价格环境`、`关键经营变化`、`结论置信度`；其中`公允价值区间`必须同时包含数值区间和区间含义，详细计算过程在第 10 章“公允价值区间计算”展开；`估值泡沫判断`填写 Step 7 的互斥结论、关键证据和置信度，不得只写“有 / 无泡沫”；`宏观价格环境`填写通胀暴露、通胀类型、净影响、证据时间和下一验证点，低暴露也必须说明依据；`关键经营变化`需压缩覆盖经营指标转折、管理层态度变化、基本面与市场预期偏差，详细证据在第 7 章展开。“资金面组”填写：`操作建议`、`冰冰小美动作`、`当前价格及时间`、`资金状态`、`风险状态`、`每日跟踪时间`、`资金面分析链接`。

`基本面状态`和`风险状态`不是只有标签的状态字段，而是每日面板直接使用的两条决策结论。统一使用“**状态短句。核心依据。**”格式：

- `基本面状态`先写“改善 / 持平 / 恶化 / 证据不足”之一，再用1—2句归纳盈利、收入、利润率、现金转化及适用的通胀净影响。例如：`持平。盈利、收入和毛利率改善，但现金转化明显恶化。`
- `风险状态`先写“风险新增 / 风险增强 / 风险持平 / 风险减弱 / 风险重新增强 / 证据不足”及是否形成放大链，再用1—2句归纳最重要的经营、通胀、估值、资金与杠杆证据。例如：`风险新增，尚未形成放大链。经营现金净流出扩大、应收账款与合同资产增长；同时通胀暴露高，但毛利率尚未受到全面挤压。股价、融资和估值暂未形成同向恶化。`
- 状态结论只做压缩归纳，不删减研究过程。详细证据、数据时间、下一验证点和失效条件继续保留在第4—13章，不塞回每日面板。

`风险状态`不能只填写“风险增强 / 风险持平 / 风险减弱 / 风险重新增强 / 证据不足”总标签。总方向无法告诉读者风险来源，也会掩盖不同风险同时向相反方向变化。按以下规则形成结论：

1. 先识别对当前决策最重要的具体风险类型，包括但不限于估值兑现、主营盈利质量、经营现金流、融资与稀释、杠杆、资金承接、政策、技术或项目落地风险；只写有当前证据且会影响动作的1—3项。
2. 每项使用“**具体风险类型＋方向＋关键证据**”表达，方向仍只使用增强、持平、减弱、重新增强或证据不足；证据必须含时间与可复核指标，不能用涨跌感受替代。
3. 不同风险方向不一致时必须拆开写，不能用一个总标签覆盖。例如：`估值兑现风险和反弹承接风险重新增强；杠杆风险减弱：现价仍高于公允价值上沿，近10日资金承接转弱；同期60日融资余额下降。`
4. 紧接主要反证或缓释项，说明它削弱的是哪一类风险。不得把“融资余额下降”同时写成杠杆风险减弱和全部风险减弱，也不得把“资金流出”直接外推为基本面恶化。
5. 泡沫出清状态继续使用“未见出清触发 / 出清观察 / 出清中 / 证据不足”，并与风险状态中的方向判断分开。风险重新增强不自动等于出清观察，杠杆风险减弱也不自动等于基本面风险解除。

每日面板执行规则：

1. 面板使用 `<!-- DAILY_TRACKING_START -->` 和 `<!-- DAILY_TRACKING_END -->` 作为唯一稳定边界；重新渲染后必须各出现一次。
2. 面板只生成两张卡片，顺序固定为`基本面状态`、`风险状态`；不展示公允价值、交易定价偏离、盘中行情、盈亏比、动作、置信度、资金链接、下一验证点或失效条件。
3. 两张卡片只读取第1章同名结论，不从行情、估值或其他字段二次拼接说明，也不在HTML端自行推导新结论。
4. 旧报告只有`风险方向`时，渲染器可将其作为`风险状态`的兼容回退；新报告必须使用`风险状态`。
5. 头部不再重复显示静态 verdict/KPI；完整估值、价格、动作、置信度与研究过程仍在16章正文中呈现。

### Step 11：检查产业研报并建立 HTML 反向链接

在 llmwiki 中生成个股 HTML 后，检查该 HTML 所在的 `sources/automations/<分类>/` 目录是否已有产业研报。个股研报与产业研报位于同一分类目录时，产业研报应提供通往个股 HTML 的入口，使产业链阅读能够继续下钻到公司研究。

使用命令：

```text
node .agents/skills/bbxm-equity-research/scripts/link-report-to-industry.cjs --equity-html <个股研报.html>
```

执行规则：

1. 脚本自动查找同目录名称包含“产业完整分析报告”“产业分析报告”或“产业研报”的 HTML；找到唯一文件时，在其“个股研报链接”区追加当前个股 HTML；
2. 链接使用同目录相对路径；重复执行必须保持幂等，不得生成重复条目；
3. 产业研报不存在时，保留个股 HTML，并在完成说明中明确记录“产业研报不存在，未建立反向链接”，不得凭空创建产业研报；
4. 同目录存在多个产业研报候选时停止自动写入，核对主产业研报后通过 `--industry-report <产业研报.html>` 明确指定；
5. 写入后检查产业研报已包含个股 HTML 链接，且链接目标文件真实存在；
6. 非 llmwiki 项目或 HTML 不在产业分类目录时，此步骤标记为“不适用”。

- [ ] 产业位置均来自公司的实际业务与证据，未套用预设分类，也未重复计算同一收入、利润或估值贡献；
- [ ] 所有公司已完成通胀适用性筛查；低暴露有依据，中高暴露已区分通胀类型并按主要分部建立需求、成本、定价权、时滞、利润和现金流传导；
- [ ] 通胀判断没有只看 CPI，也没有把上游涨价机械外推为整家公司利好或利空；经营层通胀与金融层通胀已分开验证；

- [ ] 多头与空头论据均有证据和失效条件；
- [ ] 已按稳定盈利、周期资源、重资产、成长企业、前沿科技五类判断企业价值主类型及主估值锚，并说明价值创造链；多价值来源企业已按分部映射，没有另造“混合型”类别；
- [ ] 已用 EPS、现金流、库存、应收、负债、资本开支和一次性项目检查价值创造质量；
- [ ] 估值方法与企业价值类型匹配，正常化利润、周期中枢利润、资产净值、未来利润折现、概率加权价值或困境生存条件均未被机械套用；

- [ ] 标准路线已完成企业类型主估值锚、至少两项独立交叉验证和反向估值；DCF 低权重或不适用时已说明理由；前沿科技路线的基本盘、概率加权 SOTP、融资 / 交易定价和反向估值已按可得证据完成；
- [ ] DCF 适用性、自由现金流转正年份和终值占比已说明；低权重或不适用时理由明确；
- [ ] 前沿业务概率来自可追踪里程碑，没有把 TAM、产业叙事或公司目标直接当作价值；
- [ ] 公司自有资金投入、外部股权融资稀释和新增债务分别处理，没有重复扣除；

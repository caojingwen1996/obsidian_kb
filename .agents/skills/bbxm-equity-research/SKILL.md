## 定位

本技能用于把公开信息转化为可审计、可证伪、可直接支持真实决策的个股研报。完整公司研究由本技能主导；三要素结论使用 `bbxm-three-factor-analysis`，风险方向使用 `bbxm-risk-identification`，但“方向正确”不能直接推出“可以买”。

## 路由边界

以下请求使用本技能：

- 研究一家上市公司或产出机构级研报；
- 估算公允价值、目标价、DCF 或安全边际；
- 比较多种估值方法并判断低估、合理或高估；
- 回答“如果今天这是一笔现金，我会不会买”。

以下请求使用相邻技能：

- 单条新闻、公告、政策、传闻是否有用：`bbxm-information-filter-flow`；
- 交割单、成交记录、仓位行为复盘：`bbxm-trade-ticket-review`；
- 只判断风险增强、持平、减弱或重新增强：`bbxm-risk-identification`；
- 只分析竞争格局、流动性、情绪位置和三要素共振：`bbxm-three-factor-analysis`。

如果完整研报同时要求三要素和风险方向，以本技能为主，分别调用两个平行技能并导入各自结论；两个技能互不调用，也不互相充当前置门槛。

## 开始前必须确认

1. 公司全称、证券代码、交易所和币种；
2. 研究截止时间，以及“实时”数据的实际抓取时间；
3. 报告准则和法定披露体系；
4. 用户是否指定数据源、持仓成本、预期持有期或风险预算；
5. 当前项目的落盘规则。若处于 llmwiki，先读取根 `AGENTS.md`、`SCHEMA.md`、`page-types.md`、`index.md`，再读取 `workbench/AGENTS.md` 和 `workbench/index.md`。

标的身份存在歧义时，停止估值，先核对身份。不得把同名证券、母子公司或不同上市地数据混用。

## 证据纪律

### 来源优先级

1. 监管机构、交易所和公司法定文件；
2. 公司投资者关系材料、业绩会记录和正式公告；
3. A 股研究中，本地 `tushare-data` MCP 已暴露工具用于优先获取可结构化事实；
4. 用户指定的行情、估值或评级平台；
5. 券商研报和权威媒体；
6. 聚合器、搜索摘要和社交信息仅用于定位线索。

财务历史必须按市场选择法定来源：

- 美国 SEC 申报公司：SEC 10-K、10-Q、8-K；
- A 股：上交所、深交所、北交所或巨潮资讯法定披露；
- 港股：港交所披露易及公司法定报告；
- 其他市场：当地监管机构或交易所正式披露。

用户要求 SEC 但目标不是 SEC 申报公司时，明确写“SEC 文件不适用”，再使用当地法定披露；不得伪造 SEC 口径。

### A 股 Tushare MCP 优先调用规则

当研究对象是沪深北 A 股时，优先检查当前会话是否已热加载 `tushare-data` MCP；若未热加载，可通过本地 stdio server `tools/tushare-data/scripts/mcp_server.py` 调用。MCP 调用失败、接口无权限、无数据、字段缺失或对象不适用时，不得把失败解释为“没有该事实”，应回退 AKShare / 交易所 / 巨潮资讯 / 公司公告 / 公开页面，并在第 2 章来源矩阵写明回退原因。

| 研究数据需求 | 优先 MCP 工具 | 用途 | 必要边界 |
|---|---|---|---|
| 证券身份、简称、行业、上市状态 | `get_stock_basic` | Step 1 / 第 2 章身份校验 | 只用于身份和行业基础画像，不能替代公司公告中的业务分部 |
| 日线价格、成交额、52 周区间、YTD、量价窗口 | `get_stock_daily` | Step 2 / 第 3 章行情，第 11 章情绪与流动性 | Tushare `daily` 为不复权价格；复权和盘中价格需另行说明 |
| PE、PB、PS、股息率、市值、换手率 | `get_stock_valuation` | 第 3 章行情与估值快照，第 10 章估值输入 | `dv_ttm` 为个股股息率字段；估值输入需说明日期和单位 |
| 资金分档、大单 / 小单、主力净流入代理 | `get_stock_moneyflow` | 第 11 章流动性辩证分析和资金面组 | 只确认订单规模方向，不能确认机构、散户或长期资金账户身份 |
| 融资融券余额、融资买入、偿还、融券变化 | `get_margin_detail` | 第 11 章微观流动性和杠杆资金 | 融资买入会进入订单流，不能与资金分档机械相加 |
| 利润表、资产负债表、现金流核心科目 | `get_financial_statements` | 第 6—7 章财务历史和最新季度的结构化初稿 | A 股财务结论仍需交易所 / 巨潮 / 公司法定报告复核；不得只凭 MCP 自动字段完成五年历史 |
| 历史分红方案与实施 | `get_dividend_history` | 分红、股息率和股东回报旁证 | 分红是股东回报证据，不等于资金流入证据 |
| 指数成分股及权重 | `get_index_constituents` | 指数 / ETF 覆盖和中观配置背景 | 不能确认 ETF 申购者或国家队身份 |

当前 `tushare-data` MCP 不覆盖或不直接支持的项目继续走其他来源，并在来源矩阵中保留缺口：卖方一致预期、目标价分布、第三方公允价值 / 护城河 / 星级、公司公告全文、业绩会纪要、订单明细、分部收入、可比公司估值、DCF 假设、ETF 份额与估算申赎、北向 / 陆股通持仓、龙虎榜、回购、增减持、股东户数、质押、解禁和大宗交易。

MCP 是结构化数据入口，不改变法定披露优先原则。行情、估值、资金和财务字段可以提高采集效率，但关键财务、分部、指引、风险事件和估值假设必须回到法定公告、交易所文件、公司材料或可审计来源确认。

### 写作约束

- 每个关键数据标注来源、发布日期或抓取时间和口径。
- 事实与判断分开。推断必须以 **“我的判断”** 开头，并紧接依据。
- 来源冲突时列出各自数字、口径和时间，再说明采信理由。
- 无法取得的数据统一写 **“未获取到”**，并写已检查的来源；不得使用记忆补全。
- 数据源失败不等于数据不存在，不得据此写“没有”。
- 多空论据必须并陈，并分别写出验证指标和失效条件。
- 搜索摘要不能成为关键财务数字或结论的唯一来源。
- 实时市场判断必须当日重新核验，不复用旧价格、旧估值或旧新闻结论。

## 执行流程

### Step 1：建立来源矩阵

为下列项目逐项记录“目标来源、实际来源、数据时间、状态”：

- A 股标的的 `tushare-data` MCP 调用清单、返回状态、数据时间、缺失字段和回退原因；
- 实时价格、52 周高低、今年以来表现；
- 第三方公允价值、护城河评级、星级；
- 最新季报、分部收入、管理层指引；
- 卖方评级、目标价分布；
- 近三个月新闻与催化剂；
- 五年营收、毛利率、自由现金流和 ROIC。
- 三要素所需的连续量价、换手率、相对强弱、融资、ETF / 机构代理和资金数据。
- 企业全部已识别产业位置的业务暴露与景气证据，包括需求、供给、价格 / 价差、库存 / 订单、产能 / 资本开支和政策信号中适用的字段。

状态只能为：`已获取`、`未获取到`、`不适用`、`口径冲突待解释`。

### Step 2：采集行情与外部预期

按用户指定来源获取实时价格、52 周高低和年初至今表现；未指定且目标为 A 股时，先用 `tushare-data` MCP 的 `get_stock_daily` 和 `get_stock_valuation` 获取收盘价格、成交、换手、估值、市值和股息率，再用交易所、行情平台或本地行情代理补盘中价格。记录是否复权、盘中或收盘、当地时区。非 A 股仍优先使用交易所或可靠行情平台。

为后续三要素映射同步收集可取得的连续交易证据：至少两个可比窗口的价格、成交额、换手率、相对行业强弱，以及融资、ETF / 机构代理或大单资金。A 股优先用 `get_stock_moneyflow` 获取大单 / 资金分档代理，用 `get_margin_detail` 获取融资融券代理；MCP 未覆盖的 ETF、北向、龙虎榜、机构持仓等继续回退公开来源。无法取得的字段登记到来源矩阵并说明缺口，不得等到 Step 7 才无记录地另起一套数据口径。

第三方公允价值、护城河和星级只能在实际取得页面字段后填入。付费墙或登录限制下写“未获取到”，不得从搜索摘要猜测。

卖方观点至少记录：机构、评级、目标价、发布日期、预测期和关键假设。目标价分布缺少样本明细时必须降低可信度。

### Step 3：提取法定财务历史

至少整理最近五个完整财年：

- 营业收入；
- 毛利率；
- 经营现金流；
- 资本性支出；
- 自由现金流；
- ROIC 或明确标注的 ROIC 代理值。

默认计算口径：

```text
自由现金流 = 经营现金流 - 购建长期资产支付的现金
NOPAT = 经营利润 × (1 - 标准化税率)
ROIC 代理值 = NOPAT ÷ 平均投入资本
```

若公司披露口径不同，可并列展示，但不得混为同一序列。一次性损益、会计政策变化、重大重组和币种变化必须说明。

A 股标的可先用 `get_financial_statements` 形成利润表、资产负债表和现金流核心科目的结构化初稿，再用交易所 / 巨潮资讯 / 公司年报复核五年财务历史、分部口径、一次性项目和管理层解释。MCP 没有返回的财务字段写“未获取到”，不得用相邻年份、搜索摘要或估算值补齐。

### Step 4：拆解最新经营变化

提取最新季度或半年度的收入、利润率、净利润、调整后利润、经营现金流、订单/储备及资产负债表异常项。结合分部收入和利润率判断增长来自数量、价格、并购、会计重分类还是真实需求。

管理层指引必须区分：正式量化指引、定性展望、卖方预测和“我的判断”。

同时完成商业模式事实底稿：收入来源、客户与定价权、成本结构、资本强度、主要竞争者、替代方案和监管约束，并在第 4 章形成独立、可引用的基本面结论。

产业位置不得默认只有一个，也不得套用预设分类。根据公司的实际业务、资源禀赋、供需关系、客户用途、政策环境和技术变化，识别所有与收入、利润、资产价值或估值逻辑有实质关联的产业位置，并分别写明识别依据。某种属性、主题或需求驱动只有能写出“外部变化 → 公司产品量价或成本 → 分部利润 / 现金流”的传导链时才可列入；仅有概念关联时标为“弱关联 / 待验证”，不得当作已兑现产业位置。

第 4 章必须按以下规则形成“多产业位置景气度排序”：

1. 每个位置分别写明位置名称、识别依据、公司业务 / 资产暴露、当前景气度、景气趋势、核心证据、财务传导、验证指标和失效条件；不得把多个位置合并成一句标签，也不得为了套用分类而拆分或合并实际位置。
2. 当前景气度只允许写 `高 / 较高 / 中 / 较低 / 低 / 证据不足`。至少核对需求、供给、价格或利润指标三类证据；按行业特性补充库存、订单、产能、资本开支或政策信号。
3. 排序首先按当前景气度从高到低，其次按趋势 `上行 / 持平 / 下行`，再次按公司可验证的利润或资产暴露强弱。`证据不足` 单列在已评级位置之后，不得伪装成低景气。
4. 同一利润来源被多个产业位置或叙事覆盖时明确交叉关系，不重复计算收入、利润或估值贡献。
5. 排名靠前不等于公司必然受益。结论必须同时说明受益弹性、兑现时滞、约束条件，以及景气能否进入公司利润和现金流。

### Step 4.5：彼得·林奇公司分类与投资故事

完整个股研究必须读取 `references/peter-lynch-equity-research-framework.md`，用它建立公司类型、投资故事、增长质量和类型化估值约束；不要在本技能中复制其完整检查清单。该框架补充 Step 4 的商业模式和 Step 6 的估值，不替代法定披露、DCF、三要素或风险识别。

先回答三个问题：为什么关注这家公司、未来几年利润增长来自哪里、当前价格隐含的预期是否合理；再用 2—5 句话形成可证伪的投资故事。无法简单说明公司如何赚钱、为何能赚更多、增长可持续多久和何时失效时，不得进入高仓位决策。

执行要求：

1. 在缓慢增长型、稳健增长型、快速增长型、周期型、困境反转型、资产隐蔽型中确定一个主分类；存在混合属性时可设一个次分类，但必须按当前主要利润来源和估值锚解释，不能为了完整而多选。
2. 写出可量化的利润增长等式，例如“销量 × 价格 × 利润率”“门店数 × 单店收入 × 净利率”，并核对营收、EPS、现金流、库存、应收、负债、回购和一次性项目，区分主营增长与财务杠杆、周期涨价或非经常性收益。
3. 按类型选择估值重点：成长型只在盈利增长相对稳定时使用 PEG；周期型使用正常化利润；困境反转型先检验生存、债务和现金流；资产隐蔽型使用扣除负债、税费和变现折价后的资产价值。类型化估值是 Step 6 第三种方法的约束或交叉验证，不能替代三类估值。
4. 同时列出市场可能低估和高估的因素、林奇式积极信号、危险信号、投资逻辑证伪条件以及与公司类型匹配的卖出条件。不得因“业务简单”“行业冷门”或低 PEG 单独给出买入结论。
5. 将结论写入 `template.md` 的第 1、4、6、10、12、13 章；后续财报复核时检查投资故事是否仍成立，卖出判断优先依据逻辑破坏、成长见顶、估值透支或出现更高赔率机会，而不是股价单独上涨。

### Step 5：整理新闻、催化剂与风险

新闻窗口默认最近三个月，按发生日而非搜索结果发布日期排序。每条催化剂写：

```text
事件 → 影响变量 → 财务传导 → 当前价格是否已反映 → 验证节点 → 失效条件
```

同时列出负面催化剂、公司治理风险、融资/减持/解禁、订单兑现、政策变化和估值锚失效风险。

### Step 6：执行三类估值

至少使用以下三种方法，不得用三个相近倍数冒充三种方法：

1. **相对估值**：选择可比公司，解释业务、成长、利润率、资本结构和会计口径的可比性；
2. **DCF**：明确预测期、收入增长、利润率、税率、折旧摊销、资本开支、营运资本、WACC、永续增长率和净债务；
3. **行业特定估值**：按行业选择 P/B-ROE、EV/产能、EV/用户、订单/储备价值、NAV 或分部加总，并解释适用性。

DCF 必须包含：

- 基准、悲观、乐观三种情景；
- WACC × 永续增长率或 WACC × 终值利润率的二维**敏感性分析**；
- 股权价值到每股价值的桥接；
- 反向 DCF 或反向估值，说明现价隐含的增长与利润率；
- 对长期负自由现金流公司的终值风险提示。

三种方法不得机械平均。按数据质量和商业模式适用性赋权，给出最终估值区间及相对现价的上行/下行空间。

### Step 7：映射冰冰小美框架

Step 7 是估值之后的独立决策流程，不是重新搜索并生成另一份独立三要素报告，也不是对前文风险的四句摘要。它以 Step 1—6 已收集、已登记来源的证据和数据为主要输入，按照冰冰小美体系三要素重新组织，辅助最终决策判断：

1. 读取并执行 `bbxm-three-factor-analysis/SKILL.md` 的分析方法，把 Step 1—6 的证据映射为竞争格局、流动性辩证分析、情绪位置变化三类。第 11 章引用前文章节与第 2 章来源矩阵，不重复抄写商业模式、财务、新闻和估值正文。
2. 报告需要风险方向时，读取并完整执行 `bbxm-risk-identification/SKILL.md`，只导入“风险增强 / 风险持平 / 风险减弱 / 风险重新增强 / 证据不足”之一，以及传导链、验证指标、失效条件和置信度。
3. 三要素结论与风险方向并列展示，互不替代。完整研报的估值、现金决策和最终动作仍由本技能综合财务、估值、三要素、风险方向与用户约束后形成。
4. 对每个要素先执行证据充分性闸门，再判断状态。证据不足时，状态必须写“证据不足”，不得判断为“有利”“中性”或“不利”；同时列出缺失字段、已检查来源、对决策的影响和下一验证点，不得用产业叙事、单日涨跌或主观感觉补空。
5. Step 7 默认不补采，也不为完成表格而另起搜索。若用户明确要求补齐最新数据或重跑完整研报，只补采已识别的关键缺口；补采结果必须先回填第 2 章来源矩阵和对应事实章节，再进入第 11 章，不能只在第 11 章出现孤立数据。

映射口径：

- 竞争格局：主要引用第 4—7 章的商业模式、多产业位置景气度排序、分部盈利、资本回报、订单和最新经营证据；
- 流动性辩证分析：主要引用 Step 2 形成的量价、换手、相对强弱、融资、ETF / 机构代理和资金数据，并结合第 8—9 章的供给与事件影响；
- 情绪位置变化：主要引用行情相对强弱、催化兑现后的价格反馈、卖方预期、多空论据和交易扩散证据；
- Step 6 的估值结果不强行归入任一要素，作为三要素行动映射的价格约束，防止把“跌得多”直接等同于“低估”或买点。

`template.md` 第 11.1—11.7 节是三要素导入的硬契约：不得删节、合并成一张摘要表，也不得因数据不足而省略小节。状态总表只能作为索引，不能替代逐项证据分析。第 11.1 节必须显示“前六步证据映射”，使每个要素可以追溯到前文章节和第 2 章来源矩阵。数据不足时仍保留对应小节，并明确写出“未获取到”、已检查来源和对结论的影响。

验收必须核对两个子技能的实际证据与结论；章节存在、状态总表存在或出现 `wait`、`observe` 等关键词，不能证明 Step 7 已执行。

### Step 7.5：霍华德·马克斯逆向投资条件判断

当标的出现大幅下跌、行业被普遍厌恶、用户询问“是否恐慌”“是否底部”“是否逆向买入”“是否别人恐惧我贪婪”，或研报结论准备从 `observe` 转向 `buy` 时，必须增加本步骤。本步骤是最终动作前的独立闸门，用来判断下跌是否已经形成可承担的逆向机会；它不能替代 Step 6 估值，也不能替代 Step 7 三要素。

核心原则：

```text
霍华德·马克斯式逆向机会 = 极端悲观 + 恐慌/被迫卖出 + 价格远低于价值 + 基本面未永久毁灭 + 风险补偿足够厚 + 投资者有时间和流动性承受波动
```

执行时按六个条件逐项判断，状态只能写 `满足 / 部分满足 / 不满足 / 证据不足`，并为每项写明证据、反证、验证指标和失效条件：

| 条件 | 判断问题 | 主要证据 | 常见反证 |
|---|---|---|---|
| 市场共识是否极端悲观 | 市场是否只讨论风险、坏消息被放大、好消息被忽略 | 价格相对历史区间、卖方评级下修、媒体标题、社交情绪、成交放大下跌、行业估值分位 | 只是普通回调；仍有拥挤看多；估值仍高 |
| 是否存在恐慌或被迫卖家 | 卖家是否因赎回、杠杆、风控、指数调整、产业链出清而不计价格卖出 | 融资余额快速下降、放量急跌、大单/特大单净流出、基金赎回、解禁/减持、信用或流动性压力 | 下跌主要来自理性盈利下修；卖压温和；长期资金仍在主动买入 |
| 价格是否明显低于保守价值 | 价格跌幅是否大于内在价值受损幅度 | Step 6 估值区间、反向 DCF、PB/PE/EV 指标、净现金/资产价值、股息率或清算价值 | 估值方法失效；账面资产需减值；现价仍隐含乐观假设 |
| 基本面是否未永久毁灭 | 公司是否能活下去，行业是否有正常化路径 | 现金余额、债务期限、经营现金流、订单/需求底、成本曲线位置、产能退出、政策或行业供给约束 | 资产持续减值、产品被替代、债务压垮股权、行业不可逆萎缩 |
| 风险补偿是否足够厚 | 悲观情景亏损是否可控，正常化情景收益是否明显 | 上下行情景空间、盈亏比、股息/资产保护、信用利差或权益风险溢价、估值分位 | 下行空间仍大；上行依赖远期期权；赔率只来自情绪反弹 |
| 自身资金是否能等待 | 用户或策略是否有足够期限和无杠杆承受继续下跌 | 持有期、仓位、现金流、补仓计划、止损条件、组合相关性 | 短钱、杠杆、单一重仓、无法承受继续下跌 |

输出结论必须使用以下四档之一：

| 逆向等级 | 含义 | 动作约束 |
|---|---|---|
| `A：高质量逆向机会` | 六项多数满足，价格显著低于保守价值，基本面未永久毁灭，卖压具有非理性或被迫属性 | 可进入 `buy / 分批买入` 候选，但仍必须受 Step 6 估值区间和仓位规则约束 |
| `B：逆向观察区` | 悲观和卖压成立，但估值安全边际、基本面止血或资金承接仍有缺口 | 默认 `observe / 小仓观察`，等待关键验证信号 |
| `C：普通下跌或周期底部候选` | 下跌较深，但主要由真实盈利下修或周期恶化驱动，尚不能证明价格低于价值 | 不得因跌幅给出买入；保留跟踪指标 |
| `D：价值陷阱风险` | 价值可能随价格一起下修，基本面存在永久受损、债务压垮或资产减值风险 | 默认 `avoid / 规避`，除非出现明确反证 |

写作要求：

- 不能把“跌得多”直接等同于“便宜”，必须先回答“价格崩了，还是价值崩了”。
- 不能把行业政策、反内卷、救助预期或市场传闻直接计为基本面修复，除非能写出 `外部变化 → 公司量价/成本 → 利润/现金流` 的传导链。
- 若 PE 因亏损失效，优先使用 PB、EV/产能、现金成本曲线、净债务、现金流和行业出清证据，不得用历史高利润期 PE 机械估值。
- 若判断为 `A` 或从 `observe` 升级为 `buy`，必须列出至少 3 个“市场错在哪里”的证据和至少 2 个“如果市场是对的我会输在哪里”的反证。
- 若判断为 `B/C/D`，最终结论要明确缺哪几个条件，下一次复核需要看哪些数据。

### Step 8：形成决策并落盘

使用同目录 `template.md`。结论必须回答：

1. 当前属于低估、合理还是高估；
2. 动作为买入、观望还是规避；
3. 估值区间与相对现价空间；
4. **如果今天这是一笔现金，我会买它吗**；
5. 关键经营变化，至少覆盖经营指标的转折、管理层态度的变化，以及公司基本面与市场预期之间的偏差；
6. 哪些事实会改变结论；
7. 后续 3–5 个监控指标。
8. 当 Step 7.5 触发时，必须写明霍华德·马克斯逆向等级、满足/缺失条件、是否存在价值陷阱风险，以及该判断如何影响买入、观望或规避动作。
9. 彼得·林奇主分类、一句话投资故事、利润增长等式、市场预期偏差、证伪条件及类型化卖出条件。

默认文件名：`YYYY-MM-DD-HHmm-<标的>-机构级决策研报.md`。但在 llmwiki 中，文件名只用于首次新建；每次生成前必须先按证券代码、公司简称和标题检索 `workbench/targets/` 是否已有同一标的的 `机构级决策研报.md`。如果已有权威研报，必须读取原 Markdown，在原文件基础上更新内容，并用同一路径重新渲染 HTML；不得为了记录新时间、套用新模板、刷新样式、补充行情或修正结论而创建第二份同标的权威研报。只有用户明确要求“保留历史快照 / 新建一版对比稿”时，才允许另存，并在文件名中标明 `历史快照`、`对比稿` 或事件类型。

第 1 章基本面组的 `综合估值区间` 不能只填一个数字区间。必须在同一字段内压缩写出区间含义，至少覆盖：

- 下沿：代表保守情景或只看已验证主业时的价值；
- 中枢：代表当前最可能的主业质量、成长与合理溢价；
- 上沿：代表已经计入的成长溢价、新业务期权或乐观假设；
- 高于上沿：说明需要哪些新增事实支撑，例如订单、收入、利润率修复、盈利预测上修或资金重新定价。

推荐格式：

```text
30-37 元；30 元附近=保守主业价值，34-35 元=主业合理溢价，37 元附近=已含部分液冷/机器人期权，38 元以上需新业务订单、收入或盈利上修支撑。
```

在 llmwiki 中，库外原始材料必须先保存到 `sources/`。正式研报首次新建时保存为 `workbench/targets/YYYY-MM-DD-HHmm-<标的>-机构级决策研报.md`，frontmatter 使用 `artifact_type: equity_research`；已有同标的研报时必须原地更新既有文件。`workbench/targets/` 保持扁平，不创建证券代码子目录或单标的索引。更新 `workbench/index.md` 与根 `log.md`，不更新根 `index.md`，也不得把研报保存到 `wiki/queries/`。其他项目保存到用户指定位置；未指定时使用当前项目合理的研究输出目录。

### Step 9：生成并验证 HTML

Markdown 通过完整性检查后，默认必须再生成一份同源 HTML；只有用户明确要求仅交付 Markdown 时才可跳过。HTML 不维护独立研究正文，必须由最终 Markdown 通过技能内统一渲染器生成。

使用命令：

```text
node .agents/skills/bbxm-equity-research/scripts/render-report-html.cjs --input <研报.md> --output <研报.html> --vault-root <知识库根目录>
```

若系统 PATH 中没有 `node`，先调用工作区依赖定位能力取得 Node.js 可执行文件，再用其绝对路径执行同一命令。禁止通过 PowerShell 管道或内联脚本传递中文 HTML 文本。

输出规则：

1. 在 llmwiki 中，HTML 不进入 `workbench/`；写回原自动化分类 `sources/automations/<分类>/`，尚未分类时写入 `sources/automations/temp/`，文件名与 Markdown 主文件名一致；已有同标的 HTML 时，必须优先覆盖与当前权威 Markdown 同名的 HTML，旧版重复 HTML 应归档或删除，不得让同一标的在同一分类目录下并列多份“机构级决策研报”；
2. 在其他项目中，用户指定 HTML 目录时写入该目录；未指定时与 Markdown 同目录、同名，仅扩展名改为 `.html`；
3. 页面固定使用技能内 `assets/report.css` 的版式：渐变封面、判断徽章、四张关键指标卡、左侧目录、右侧正文和打印样式；
4. 封面字段从“决策摘要”和报告元数据自动提取；缺失字段显示“未获取”，不得猜测；
5. 生成后必须检查 16 个目录锚点、UTF-8 中文、关键指标、Obsidian 双链转换和 Markdown / HTML 结论一致性；
6. HTML 生成或验证失败时，整份研报仍视为未完成。

### Step 10：生成每日跟踪面板

HTML 必须在16章正文之前生成一个可重复更新的“每日跟踪面板”，用于把静态研报转成持续决策入口。面板不是第二套研究正文，只消费第1章决策摘要和已有资金证据。

第1章决策摘要必须拆分为“基本面组”和“资金面组”两个小表，避免单表信息过密。“基本面组”填写：`估值状态`、`综合估值区间`、`相对现价空间`、`基本面状态`、`关键经营变化`、`结论置信度`；其中`综合估值区间`必须同时包含数值区间和区间含义，详细计算过程在第 10 章展开；`关键经营变化`需压缩覆盖经营指标转折、管理层态度变化、基本面与市场预期偏差，详细证据在第 7 章展开。“资金面组”填写：`操作建议`、`冰冰小美动作`、`当前价格及时间`、`资金状态`、`风险方向`、`每日跟踪时间`、`资金面分析链接`。统一渲染器据此生成六张卡片：基本面状态、动态价值区间、盈亏比、每日同步价、盘中实时、动作与置信度。

执行规则：

1. 面板使用 `<!-- DAILY_TRACKING_START -->` 和 `<!-- DAILY_TRACKING_END -->` 作为唯一稳定边界；重新渲染后必须各出现一次。
2. 每日同步价来自报告的正式行情快照；直接打开 `file://` 时仍可读取，不能依赖联网脚本。
3. 盘中实时默认支持沪深 A 股：渲染器必须根据证券代码自动生成本地行情代理使用的 `secid`，直接打开 `file://` 或本地服务未连接时显示降级状态“每日同步 · 实时未连接”，不得把可识别的沪深 A 股默认显示为“未配置实时行情”。只有无法识别市场、证券代码缺失或非沪深 A 股暂未接入时，才显示“未配置”。
4. 实时价格只能更新盘中卡和盈亏比，不能自动改写动态价值区间、基本面状态或动作。
5. 资金面分析链接只允许同目录 HTML 文件名；显式填写且文件存在时优先使用该文件。文件不存在、未生成或希望自动匹配时写“未获取到”，统一渲染器会在输出 HTML 同目录扫描文件名包含“资金面分析”的 HTML，并按文件名日期选择最新一份自动挂入每日跟踪面板；不得填写绝对路径、Obsidian 双链或不存在的伪造链接。
6. 头部不再重复显示静态 verdict/KPI；估值、价格、动作和置信度统一进入每日面板。

### Step 11：检查产业研报并建立 HTML 反向链接

在 llmwiki 中生成个股 HTML 后，检查该 HTML 所在的 `sources/automations/<分类>/` 目录是否已有产业研报。个股研报与产业研报位于同一分类目录时，产业研报应提供通往个股 HTML 的入口，使产业链阅读能够继续下钻到公司研究。

使用命令：

```text
node .agents/skills/bbxm-equity-research/scripts/link-report-to-industry.cjs --equity-html <个股研报.html>
```

执行规则：

1. 脚本自动查找同目录名称包含“产业完整分析报告”“产业分析报告”或“产业研报”的 HTML；找到唯一文件时，在其“个股研报链接”区追加当前个股 HTML；
2. 链接使用同目录相对路径；重复执行必须保持幂等，不得生成重复条目；
3. 产业研报不存在时，保留个股 HTML，并在完成说明中明确记录“产业研报不存在，未建立反向链接”，不得凭空创建产业研报；
4. 同目录存在多个产业研报候选时停止自动写入，核对主产业研报后通过 `--industry-report <产业研报.html>` 明确指定；
5. 写入后检查产业研报已包含个股 HTML 链接，且链接目标文件真实存在；
6. 非 llmwiki 项目或 HTML 不在产业分类目录时，此步骤标记为“不适用”。

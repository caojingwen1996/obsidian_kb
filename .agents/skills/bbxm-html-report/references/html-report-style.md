# HTML 报告样式规范

来源为用户指定的 wb-finance-skill 1.5.0 [HTML研报输出规范副本](../../../../sources/manual/2026-09-22-wb-finance-1.5.0-html-report-style.md)。原文件实际目录为 `cb_teams_marketplace/finance-data/1.5.0`，副本保留原字节。本文件是项目适配规范，不依赖外部插件缓存继续存在。

## 1. 整体风格与内容

- 浅底深字的研报风：白色/浅灰背景、深色正文、细分隔线，避免暗色仪表盘、巨大渐变封面和装饰卡片堆叠。
- 首屏结论先行：标题、对象、数据截止时间及适用的比较窗口，随后一句核心回答和少量重要发现/数字；导航放在结论之后。未知时间明确写未知；生成日期不能替代数据截止日期。内部编号、对象计数、验证过程放在附录。
- 正文每节围绕一个核心问题，先回答，再展示关键证据、来源与必要限制；标题尽量表达问题或有证据支持的发现。遵守领域模板的必需主章节及顺序，章内可分关键证据与明细；没有固定章节要求时按问题组织，避免把处理流水账作为正文。
- 完整证据保留在正文和可展开附录中。影响结论的候选状态、证据不足、反证、来源失败摘要必须在正文直接可见；逐笔明细、完整口径、检索与校验记录可折叠。每个折叠区使用说明性标题（如“发行明细与口径”），优先原生 `details / summary`，支持键盘操作；打印时展开内容。
- 正文中的关键断言直接引用来源，不能仅在文末提供来源合集。正文与附录须和母稿/结构化数据一致；折叠不改变结论、不删掉必要证据。避免结论、图注、后文总结整段重复。
- A股价格/涨跌幅按红涨绿跌；风险状态用“增加、维持、减弱、证据不足”等文字和独立语义标签，避免用涨跌颜色替代风险含义。其他市场注明颜色口径。
- 手机端内容不溢出：宽表在独立容器横向滚动，图表宽度自适应。打印时展开数据表，隐藏操作按钮和无关导航。

## 2. 图表分工

| 信息 | 呈现 |
|---|---|
| 趋势、对比、占比、分布等有数值轴的数据 | 优先ECharts，必须有精确数据表或图/表切换 |
| 产业链、风险传导、股权结构等关系 | SVG或HTML+CSS；箭头标明已支持或推断，不捏造权重 |
| 查阅、多维对照、来源与口径审计 | 表格 |
| 仅一两个数值或没有可靠序列 | 简洁文字/表格；不强画趋势图、评分雷达图 |

每张图回答一个主要问题，图题表达具体比较或发现，旁边用简短文字解释读图结论与适用范围。不要为了增加图表数量把不相关指标放在一起；复杂关系保留必要分支和条件，不以简化布局删掉它们。

数字密集的趋势模块默认显示图，提供可操作的“图/表”切换或“查看精确数值”展开入口，两种视图使用同一份数据。表格保留精确值和缺失状态；图表不可用时表格必须可读且入口不依赖绘图库。图表、正文和明细无需默认重复铺开整组数据。

## 3. 数据与绘图规则

- 时间轴、单位、币种、数据期和来源明确；半年与全年不能当作同口径年度变化。
- 对照基准须匹配所解释的对象、期限和窗口；不匹配的均值只作明确标注的背景说明，不画成标准线或阈值。
- 同比/环比缺基期时由原分析流程补一个所需完整周期，不能补零或猜值。取得基础值但仍需计算时按原分析口径复算，标明计算方法。
- 完全没有可绘制值的前段不硬占图位，可裁剪图轴或展示已有绝对值；精确表仍保留缺失说明。序列中间缺值使用null和断点，不连接成真实连续值。
- 量级差明显时用分别标注单位的双轴或分图；不要让小序列压在坐标底部。占比图先确认分母及合计关系；雷达图没有明确评分依据时不用。
- 浏览器运行的ECharts容器使用唯一id及明确高度（建议360px）；窗口变化调用resize，隐藏标签页显示后再resize。离线SVG使用viewBox和响应式尺寸，窄屏保持标签可读，必要时生成同数据的窄屏版本；不能仅缩小整张图导致文字难读。

## 4. ECharts与JS

允许网络依赖且无更严格领域契约时，可按原规范引入：

```html
<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>
```

默认正文和精确表不能依赖此CDN。需离线时改用经过验证的本地库；不自动下载或引入更多前端框架。

优先使用平坦、可复用的option结构，数据由同一对象提供，不从零手敲大量嵌套。下面仅是结构示意，变量必须来自已核验数据，不是演示数据授权：

```javascript
const option = {
  tooltip: { trigger: 'axis' },
  legend: { data: [seriesName] },
  xAxis: { type: 'category', data: labels },
  yAxis: { type: 'value', name: unit },
  series: [{ name: seriesName, type: 'line', data: values, connectNulls: false }]
};
const chart = echarts.init(document.getElementById('chart-main'));
chart.setOption(option);
window.addEventListener('resize', () => chart.resize());
```

饼图使用 `{name, value}`；K线数据顺序为 `[open, close, low, high]`，成交量需独立轴/分图；雷达指标必须有可解释的量纲及上限。legend.data只存名称数组，不混入其他字面量。

所有内联可执行script在交付前用Node语法校验，不能以人工数括号冒充自动校验。该检查不验证外部库可用性、变量是否存在、DOM挂载及实际渲染，仍需浏览器验收。数据块（如application/json）不能当作JS语法检查；按JSON解析。

## 5. 项目适配说明

沿用原规范的浅色、首屏结论、红涨绿跌、图表分工、图表切换、补足比较周期与JS自检。额外明确完整业务模板、静态表降级、离线契约优先、文本转义、原始数据保留及视觉验收边界。样式统一不改变分析判断、原产物路径或机器接口。

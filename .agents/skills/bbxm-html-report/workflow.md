# HTML 报告工作流

## Step 1. 核对分析与交付契约

读取当前分析技能的 SKILL.md、workflow 和输出模板，确认核心方法论已经落实到内容。逐项核对章节、表格、状态、来源与缺口；缺项返回本轮分析补齐，不能用美化页面代替分析。

报告输出默认采用 HTML。保留领域技能需要的母稿与JSON；明确纯JSON、仅聊天和简短问答不强制生成HTML。图表中的趋势数据只消费经过核对的现有数据；需要更多历史数据时交给原分析流程补取，取不到保留缺口。

## Step 2. 生成同源 HTML

读取 [样式规范](references/html-report-style.md)，可复用并内联 [report.css](assets/report.css)。先保留领域模板的正文顺序，再加标题、元信息、摘要及导航；摘要不替代正文。若领域技能规定图表替换某张表，在原章节保留图表及精确数据查询入口。

输出位置按“用户本轮指定 → 业务技能已有路径 → 母稿同目录同文件名主体.html”确定。没有母稿与业务路径时使用项目内 `workbench/targets/YYYY-MM-DD-<对象>-<任务>.html`，先读该工作域规则。路径从项目根解析，不从当前终端或技能目录猜测。

风险模型与观察记录分别生成同名HTML，放在 Risk 下原模型或观察记录旁；引用仍指向原模型版本及原始上游文件。定位表可增加HTML入口，不改历史状态、身份或截止时间。旧研究不自动迁移；已有文件按业务技能的覆盖规则处理，没有授权覆盖规则时使用新快照名。

HTML 使用 `<!doctype html>`、`lang="zh-CN"`、UTF-8、viewport、非空title和一个h1。转写外部文本、标签、来源链接前做HTML转义，嵌入JSON时转义可能终止script的字符（如将 `<` 编码为 `\u003c`）；原材料不得变成可执行HTML或JS。Obsidian双链转换为可用的相对文件链接和显示名，不原样残留在阅读版。

## Step 3. 验证

1. 对照母稿检查章节与精确值、单位、日期、来源、反证和缺口一致；使用领域专属检查器时仍需运行。
2. 运行 `python scripts/validate_html.py <报告.html> --node <node可执行文件>`（脚本相对本技能）。全部内联可执行JS分别语法检查，包括module；JSON数据块单独校验。有JS却找不到Node时报告检查未完成，不声称通过。无JS时记录不适用。
3. 实际打开交付文件，检查桌面与窄屏、表格横向滚动、目录跳转、图/表切换和图表尺寸。存在图表时确认每个容器真正渲染且没有运行错误；语法通过不等于图表通过。浏览器或页面无法访问时如实记录视觉/交互未验收，不绕过访问限制。
4. CDN失败时显示同一数据表及明确提示，页面正文仍可读；若图表是交付必要项，修复依赖后再称完成。离线要求或领域技能禁止外部依赖时使用已验证的本地ECharts并打包/内联，不擅自改成联网依赖。

## Step 4. 交付

给出HTML的绝对路径链接和简短结论；需要时附母稿/JSON，不只贴HTML源码。说明实际验证情况，有缺项明确标注。沿业务规则更新产物定位与根日志；动态报告不新增正式Wiki页面或修改其页面计数。本次生成不等于已接入看板展示或自动更新。

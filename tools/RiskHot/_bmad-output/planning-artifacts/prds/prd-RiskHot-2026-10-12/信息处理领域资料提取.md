- **建议而非已确认**：EventTarget 在决策表中是“本文补充建议”；M 五维及权重是候选；逻辑存储结构、通知名称、实施顺序是建议。下文忠实保留正文中的能力与不变量，不代表这些建议已经获批。〔7.1，L801；3.6，L454–468；4.5，L522；6.1，L759；7.3，L816–824〕

## 产品目标、用户与范围

- 将可信宏观资讯转化为可追溯、可归组、可更新、可评级、可供后续风险分析的 Event；一份 Information 可有多个 Event，同一 Event 可积累多份资料。交付稳定事件/对象/变量标识及原文引用链。〔1.1，L11–17〕
- 明确消费者是下游风险识别、风险变量分析、风险快照与演化分析；原稿未定义具体人类角色、角色权限、使用人数、商业目标或客户端形态，仅提及人工校正、审核、研究/展示排序和检索。〔1.2–1.5，L23–30、L54–68；1.6，L74〕
- V1 只处理宏观领域：经济体、宏观政策主体、金融系统、主要金融市场、宏观经济部门；采信第一手官方信息、官方公开数据及权威机构公开研究报告。事件允许已发生、推进中、已宣布、计划/预期。〔1.4，L45–56；3.3，L410–416〕
- 不建设逐条事实可信度 C/事实核验流水线，不强制拆事实与预测，不建设独立优先级 P，不形成风险等级/方向/传导结论或投资交易建议，不创建微观企业/行业/资产 Target，不将 Variable 固定归属 Target，不引入通用 Entity 模型。〔1.6，L70–78〕

## 独特业务能力与流程

1. **信源管理与准入**：维护白名单、准入档位、启停、采集范围、来源身份和可选信用 S；每次分析引用既有长期信用，不重复计算。记录转载和原始发文主体，能识别原出处时优先原文。〔1.2，L23；2.2.1，L160；3.1，L384–390〕
2. **信息采集与预处理**：采集正文、附件、来源元数据、原始出处、发布时间/采集时间，清洗正文与规范链接；识别同来源同版本、新资料/新来源及原文修订，保留版本和采集引用；不同来源同内容仍保留来源关系。未知发布时间为空，不以抓取时间代替。〔2.2.1，L123–148、L160；3.1，L388–390；4.5.2，L552〕
3. **事件抽取与归组**：抽取主体、行为、状态、时间与原文位置；比较主体、行为、作用对象、时间范围及政策/行动标识，以新事件/同事件/待判定分支处理。一篇材料中的独立事件分别处理，某事件待复核不阻断其他事件。相同机构、标题或关键词不构成合并依据；同一行动生命周期追加更新，独立决定另建 Event。〔2.2.2，L166–189、L203–207；3.2，L392–402〕
4. **作用对象与变量引用**：Target 身份由名称/代码、辖区、类型、范围共同确定，跨事件复用；Event 的主体只在同时是作用对象时进入 EventTarget。先匹配现有变量，无定义时提出候选和理由，经审核入库；只提取直接涉及、宣布改变或有来源变化的变量，不推测后续传导变量。〔2.2.3，L213–249；3.3–3.4，L418–432；4.5.5，L600〕
5. **增量与历史管理**：复核事件身份后判断新增、进展、实质补充、纠正、仅增加来源、重复、无法判定；不同分类对应不同更新、评级与通知动作，支持新证据触发重新归组并记录合并/拆分审计。〔2.2.4，L290–301；3.5，L434–448〕
6. **金融意义评价**：在固定宏观观察范围和研究期限下评价 M 及投资/融资/投机情绪用途；支持多用途、无法判断、初评/复评、规则版本及历史。用途类别不自动决定 M，M 不是风险程度、行情涨跌或收益概率。〔2.2.5，L307–331；3.6，L450–472；4.5.10，L667–678〕
7. **持久化、检索、变更分发及横向治理**：统一校验结构、关联 ID、时间、状态及更新幂等性，保存事件及全部关系/更新/评级；提供检索和变更通知；保存原文、规则/提示词/模型版本、审计轨迹及必要原始结构化输出，支持复核与重新处理。〔1.2，L28–30；2.2.6，L369–380；5.2，L696–703〕

主流程为准入 → 采集预处理 → 事件识别归组与对象变量关联 → 增量判定 → 按需评价 → 统一校验存储分发；归组与增量可以往返。〔2.1，L82–100；5.1，L684–694〕

## 状态、失败、幂等、人工确认与历史约束

- 未准入/停用信源结束；不能解析或追溯则待补采/复核；抽取结构/引用不合格则待复核或重新处理；没有宏观事件则保留资料后结束。归组无法可靠判断为 UNRESOLVED，记录依据并保留任务，禁止强行合并。〔2.2.1–2.2.2，L123–148、L166–189、L203–205〕
- 对象不确定允许 Event 无 Target；能确定 Target 但变量不确定，保留 EventTarget，三元关系为空；变量候选未审核不得伪造 ID。缺少依据不得补全关系。〔2.2.3，L216–249；5.2，L698–703〕
- NEW_EVENT 生成首条更新及来源；EVENT_PROGRESS/MATERIAL_ADDITION 追加更新并按需调整状态/关联；CORRECTION 保留旧版、追加纠正并更新描述；SOURCE_ADDITION 仅增来源，沿用评级，不伪装业务进展；DUPLICATE 不重复更新或通知；UNRESOLVED 返回归组。〔2.2.4，L294–301〕
- 正文另有“仅来源增加通常无需复评”措辞，主流程则直接沿用已有评级；两处口径差异应保留为待澄清，不能据“通常”虚构例外触发条件，也不能擅自确认不存在例外。〔2.2.4，L299；3.5，L443〕
- 事件状态候选包括 expected / announced / in_progress / effective / completed / cancelled / unknown；区分发布、发生/预计、采集时间，以及公告/预期生效/真实执行时间。原稿没有完整合法迁移矩阵，不能推出必须线性依次推进。更新同时保存变化时间和记录时间。〔3.2，L400–401；4.5.3，L565–572；4.5.9，L654–661；5.2，L699–700〕
- 每个 Event 至少一个可追溯来源；Information 可关联零到多个事件；Event 可零到多个 Target。修改事件状态/说明不得删除历史更新/评级。三元关联必须对应既有事件对象关系和全局变量，所引资料应已属于该事件。〔4.3，L508–512；4.5.8，L637–645〕
- 新进展仅在影响评级依据时复评；权重未定时 M 总分可为空且保留维度/草案，评级保留时间及规则版本。〔2.2.5，L307–331；4.5.10，L670–678〕
- 最终校验失败进入复核/重新处理；完成复核回对应环节，保留归组合并/拆分审计。人工审核仅明确用于复核/变量候选等，未规定所有事件都需人工批准。原稿未给重试次数、退避/超时、失败通知对象或重放幂等键。〔2.2.6，L339–380；5.1，L688–694；7.3，L820〕

## 跨域交接与验收依据

- 上游输入：已准入信源、原始资料、Target 字典、统一 Variable 字典、事件历史、评级配置；下游获得创建/有效更新/评级更新/来源附加四类变化。通知命名只是建议，不强制消息总线。〔6.1，L748–759〕
- 下游可引用 event_id/event_update_id，但不得修改 L0 原始历史；Target 与 risk.observation_target 必须确认含义与范围一致才映射；下游决定变量驱动/传导/缓冲/验证角色，形成风险判断/快照/演化；AI 概述不能替代原出处。〔1.5，L68；2.2.6，L380；6.2，L763–769〕
- **原文明示验收**：同公告抓取 3 次不重复更新；两机构同事件保留双来源；一报告两个独立决定生成两个 Event；两政策可共享一个 Target；不同事件可使同一 Target 引用不同变量；Target 已知 Variable 未知关系仍成立；宣布到落地保留更新并按需复评；缺失变量先候选不伪造 ID；修订关键数字保留版本并追加 CORRECTION；风险上升判断由下游管理。〔6.3，L773–784〕
- **由明示规则转为可测条件**：待归组事件不被强行合并；多事件之一失败不阻断其余；纯来源增加不产生实质事件进展通知；未知发布时间不被采集时间覆盖；未经确认评分权重不能输出已确认总分。此处是规则验收化，未新增性能阈值。〔2.2.2，L205–207；2.2.4，L299–301；4.5.2，L552；2.2.5，L331〕

## 未决、状态张力与不能推出的结论

- **M 方法论未确认**：五维、权重、量化锚点、等级阈值均待历史校准；30/25/20/15/10 与公式只属候选工程提案，不可写为已通过业务参数；多 Target 的全局或分对象评级也待定。〔3.6，L454–468；7.2，L808、L814〕
- Target 编码/同义边界、长期主题与单次决定归组粒度、合并拆分后 ID 与历史引用迁移、候选变量审批/同义去重、来源信用 S 量化实现、是否增跨事件关系均待确认。〔7.2，L809–813〕
- **EventTarget 决策状态需显式保留**：正文要求当前版保留、可验收场景依赖该关系，但决策表仍标“本文补充建议”，其余多数条目标已确认；不得悄悄提升为用户已确认决策。〔4.4，L514–518；6.3，L780；7.1，L800–801〕
- 无法推出 UI 端形态、权限矩阵、产品成功指标、采集周期/吞吐、AI 准确率门槛、可靠性 SLA、合规认证、商业模式、微服务部署。部署方式明确不要求六环节各自独立服务。〔1.1–1.6，L11–78；2.1，L100；5.1，L684–694〕

## 技术机制补充候选（不自动升级为产品强制方案）

- Event/Target/Variable 独立领域身份、EventInformation 多对多、EventTarget 及 event_target_variable 三元关联、统一 variable_config；数据库字段类型/长度/索引仅建议。联合关系唯一性承载上述业务一致性，落地机制另行设计。〔4.1–4.5，L478–522、L621–645〕

- AI-01 抽取、AI-02 归组/身份复核、AI-03 对象变量识别、AI-04 增量、AI-05 金融意义；输入→Prompt 版本→Schema→规则→持久化/人工复核；程序负责字段、引用、ID、状态、分值和幂等校验，最终统一事务校验。〔5.1，L682–694〕

# 风险识别与纳管领域资料提取（L1）

提取日期：2026-10-12。唯一业务来源：`02-业务架构与领域设计/RiskHot_L1_风险识别与纳管层_业务架构与领域设计.md`（V1.0 讨论整理稿，2026-10-09，共 1158 行）。以下引文采用“章节 / L行号”；全文分四段完整读取，未读取文中引用的 Wiki、旧需求、实现、测试或外部资料。本提取区分来源已确定原则、来源待讨论项及从原则转写的验收条件；不证明功能已经实现。

## 1. 产品目标、角色与形态

- 目标：将 L0 结构化事件及有效更新转化为定义清晰、身份稳定、证据可追溯、观察变量明确的 MonitoredRisk，交给 L2 持续观察；回答“有什么风险、是否已经纳管、跟踪什么”。责任包括定义完整性、身份复用/准入、长期观察配置、事件关联及下游交付。（1.1 / L13–17）
- 首版仅纳管宏观经济金融风险；观察对象可为经济体、宏观主体（如政府/央行）、市场、金融系统。行业、企业、单项资产仅作为背景、证据、传导环节或受损范围，不独立纳管。（1.4、3.3、4.6.1 / L53–60、L464–473、L873–878）
- 明确的操作主体只有系统、AI、人工发起者、初期共享变量治理审核者。AI 提识别与匹配建议，系统校验/建立身份/落地；没有确定最终用户画像、组织规模、岗位名称、商业模式、付费主体或产品平台。（1.6、2.2.1、3.4.5、6.1 / L82、L153–159、L563–580、L1092–1103）
- 展示场景确定四类数据边界：今日新增风险依据纳管时间；已纳管列表依据身份与跟踪状态；当前风险等级/状态取 L2 最新快照；减弱节点取 L2 分析结果。没有确定页面布局、导航、Web/移动/桌面形态。（5.4 / L1058–1066）
- 非目标：重新抓取或去重原文、事件归组、金融意义 M 评分；本轮变量数值、风险大小/等级/兑现/趋势/减弱节点判断；投资交易与应对决策。M 可辅助排序，既不等于风险等级也不决定风险是否存在。（1.5–1.6、2.2.1 / L70–83、L163）

## 2. 完整业务能力与独特约束

### 2.1 接入、识别、命名与对象区分

- 四个业务环节是承接触发→风险识别→检索匹配与纳管→事件关联分发。新事件、有效更新和人工发起进入同一增量/重复检查；保留事件时间、阶段、M、对象/变量线索与原文定位，不重新提取上游事件。（1.3、2.2.1 / L38–43、L128–163）
- 一次识别输出 0..N 个完整候选，某一项待复核不阻断其他候选；允许无风险和无法可靠判断，不强行生成。已宣布、预计实施、尚未兑现事件也可作为线索，但不能丢掉时间/阶段。（2.2.2 / L207–232）
- 风险名称不含当前等级；定义应稳定地表达风险问题及潜在损害，机制解释形成、传导、持续/缓冲条件；候选还须包含观察对象/范围、损害对象、风险源/维度、关键变量、识别依据、证据引用与不确定性。（2.2.2、4.3、4.6.1 / L214–232、L764–775、L850–878）
- 区分三种对象：L0 Event Target 是事件直接作用对象，L1 观察对象是风险判断针对对象，损害对象是可能沿传导路径受损主体/系统。身份与范围一致才可映射；不得机械复制。损害对象可多个或在不确定时为空，须保留暴露渠道、条件、潜在损害及依据；不意味着损害已经发生，也不逐个自动建风险。（1.5、2.2.2、4.6.1 / L75、L219–229、L873–878）
- 关键变量必须从风险机制中选择，说明驱动、传导、缓冲、损害验证角色与作用条件，不能仅抽新闻关键词或直接照搬上游事件变量。（1.5、2.2.2、3.4.4 / L75、L220–231、L550–555）

### 2.2 稳定身份、准入与风险档案

- 完整候选先形成一次，之后再检索存量；匹配阶段不再重新开展完整定义。核心同一性依据为定义（风险问题/潜在损害）、观察对象、范围；名称、来源、维度、机制与变量只辅助。不同事件/风险源不必新建风险；范围部分重叠、证据不足或机制冲突无法解释时待复核。（2.1、2.2.3、3.2 / L118、L275–297、L405–428）
- 匹配成功复用真实有效 risk_id，保留已有定义；确属新风险且准入通过才创建，检索零召回也不得跳过准入。新风险要求明确问题、对象/范围、潜在损害、可追溯事件与必要观察条件；最低变量数及自动准入规则未定。（2.2.3 / L275–297）
- MonitoredRisk 是唯一 L1 核心实体：稳定身份、名称/定义、机制、观察对象/范围、损害对象、风险源/维度、跟踪状态、纳管时间、创建/修改时间。它跨事件、跨观察周期存在。候选与匹配结果不是核心实体，是否独立持久化未定。（4.1–4.3、4.6 / L715、L741–780、L836–852）
- 正式纳管不能只保留标题或摘要，必须保留损害对象及相应机制/证据。正式 ID、关系 ID、纳管时间由系统产生或复用，不由 AI 自行生成。（4.3、4.6.3、6.1 / L764–775、L905–910、L1103）
- 已有风险机制或变量出现实质差异时提出维护建议；未确认建议不得直接覆盖。已关闭风险优先考虑复用历史身份，恢复条件未确认前不能预设自动恢复。（2.2.3 / L277、L292–297）

### 2.3 跟踪、关联、退出与分发

- tracking_status 候选为 observing / monitoring / paused / closed，表示是否/如何跟踪，不表示风险强弱。暂停、关闭、恢复、审批及完整状态转换矩阵均待讨论；不能自行规定自动退出条件。（1.4、1.6、3.1 / L58、L81、L386）
- 风险与事件多对多，正式风险才可建立关联；记录关联理由和首次依据。非空 EventUpdate 必须属于对应 Event；首次依据不能被后续更新覆盖为“最新更新”。关联是否有效不等于风险加剧/缓和/解除，也不代替跟踪状态。（2.2.4、4.5 / L339–347、L807–832）
- 证据通过 Event→首次关联依据 EventUpdate→Information 回溯，关联表不再存一份原文正文；保持必要时间语义和可定位引用，不用 AI 概述替代依据。（4.5.2、5.1 / L829–832、L1021–1026）
- 新风险身份、初始关键变量配置、初始事件关联须一致完成；不完整时待复核/补齐且不交给 L2。补齐后返回对应步骤。重复输入不得重复创建风险、关联或分发；具体幂等键、重试和补偿协议未定。（1.2、2.2.4、2.3、4.5.2、5.5 / L31、L334–347、L360、L832、L1076–1081）
- 分发区分新风险纳管、已有风险关联新事件、跟踪状态变化，通知名称仅候选。事件关联本身不构成风险增强或缓和结论；暂停风险是否触发新快照、何时分发仍待讨论。（2.2.4、5.3 / L336、L343–344、L1049–1056）

## 3. 共享变量体系、治理和版本能力

- 采用分层核心因素体系，渐进建设“基础池→动态发现→候选治理→知识演化”；先满足首批宏观风险，不必先穷尽变量。区分分类、稳定因素定义、指标配置/实际值、事件证据、风险源、具体风险与风险关联；分类不直接产生状态，因素不一定有单一数值。（3.4、3.4.1–3.4.3 / L477–504、L508–542）
- 分类与因素分解分开，分类不得循环；可独立分析的上层因素需自己的稳定定义。共享同一变量身份，不按类别/风险源/使用方复制；汇总不得重复计算父子因素或同一证据代表的压力。上层状态不自动为子状态平均、求和或投票。（3.4.2、3.4.7 / L520–524、L600–606）
- 基础分类示例为宏观经济、货币金融、市场行为、产业结构、地缘政治；因素示例须治理确认后启用，不是已初始化真实数据。每项启用变量至少具名称、定义/边界、分类/上层因素、观测依据与分析口径。（3.4.3 / L528–542）
- 发现时先联合检索名称、别名、定义、分类、范围、口径、历史替代关系，辨别同义/上下层/范围差异/新因素。正式匹配填真实有效 ID；无匹配填候选名称和依据，不伪造 ID；宽泛、歧义、废弃匹配需复核。相同候选应聚合证据和提出历史。（3.4.4 / L548–559）
- 初期治理必须“AI 提议、程序校验、人工审核”；新增/别名/拆分/合并/重新分类/机制修订未经审核不改变正式共享定义。审核材料覆盖定义、范围/粒度、归属、观测依据、复用场景、存量比较、来源/时间、关联风险/事件与缺口。（3.4.5 / L563–565）
- 审核可复用、接受新变量、转维护、退回补充/暂缓、拒绝；保留结论原因、处理主体、时间和映射，不删除原始事实。落地前再次查重防并发重复；实质变化材料不能沿用旧版本审批。全局变量审核、具体风险关系维护、风险准入分别判断。（3.4.5 / L567–580）
- 生命周期 Candidate 不可作正式引用；Active 经审核生效后仍需范围/版本/机制校验；Deprecated 保留历史但不供新增引用。Candidate 可审为 Active 或映射存量；Active 可审为 Deprecated，恢复须重新审核，不清空废弃记录。（3.4.10 / L643–651）
- 名称/别名/解释补充或重新分类，含义范围不变保留 ID 并版本化；拆分产生独立身份，原因素有综合价值可留，否则废弃与映射；语义等价合并选保留身份，含义实质变化则新身份。原关联不能机械复制到所有子变量，变量合并/拆分也不自动合并/创建风险。（3.4.6 / L584–596）
- 版本须保留变更前后、原因来源、审核主体结论、记录/生效时间、替代映射；ID/稳定编码不回收给别的含义。每次分析可还原变量定义、长期关联/机制、证据及其可获得时间；新版本/纠正不覆盖旧快照。执行中锁定版本，更新须显式重分析；历史比较先验可比性，不用未来证据倒填历史。（3.4.10 / L653–660）
- 长期变量角色/机制属于风险关系，不是全局因素固定属性；变量状态归 L2，当前作用必须结合具体风险独立判断。相同 ID 不是状态可复用的充分条件，还需版本、范围、统计口径、窗口、截止时间与方法相容，复用要保留来源并检查反证/过期。（3.4.7–3.4.8 / L604–627）
- 因果网络与分类分开：相关性、同类或同时变化不证明因果；保存方向、成立/失效条件、滞后与支持/反对证据。未验证关系为假设，单轮推断进入治理后才能成为共享知识；不许循环自证或无限递推为事实。（3.4.9 / L631–639）
- 运行缺口须显式表达：必要观察条件依赖未确认候选时暂缓纳管；仅补充线索且有效变量已足够则可带缺口继续。废弃/不兼容配置标维护需求，证据缺失/过期/冲突不写成中性或零影响；没有正式 relation_id 的 L2 候选不能冒充快照正式明细；无有效比较基准不强行判断变化。（3.4.12 / L677–692）

## 4. 跨域交接与可测试验收转写

- L0 输入 Event/Update、Target、事件直接变量、M、Information/原文；保留事件时间与记录时间差异，L1 不改上游身份/原始记录。事件通知订阅和完整识别触发条件未定。（5.1 / L1016–1029）
- L1→L2 交付 risk_id、完整定义/范围、损害对象及解释、风险源/机制、长期关键变量关系、关联事件增量、跟踪状态/纳管时间。L2 分析当前状态/兑现/持续及演化，发现新因素/损害对象/机制向治理和 L1 反馈，不直接改身份/共享定义/长期关系。（3.4.11、4.6.1、5.2 / L666–673、L878、L1031–1044）
- 以下为已定业务规则的可测试转写，不是新增数值指标：①同一输入无增量重放，新增身份/同一关联/重复分发数均为零；②单事件包含多候选时逐项处理，某项待复核不阻塞其余；③仅名称相同而观察范围不同不得自动合并；④检索为空但准入缺失不得创建；⑤身份/变量/初始事件关联任一不完整不得交付；⑥每个正式变量和风险引用可解析到真实有效对象，候选名称不得冒充 ID；⑦首次事件更新引用只能指向本事件且不被后续进展覆盖；⑧无法判断损害对象时允许空集合并显示不确定性；⑨含义实质改变不可占用旧 ID，旧快照仍可还原；⑩审核中的候选实质变化需重新审批；⑪必要变量未批准暂缓纳管而无关风险继续；⑫缺失数据不得输出为稳定/中性/零影响。（2.2–2.3、3.2、3.4.5–3.4.12、4.5–4.6 / L159、L209、L275–297、L334–360、L424、L579、L592、L657–660、L683–690、L828–832、L878、L907–910）

## 5. 未决、缺口与原文内部衔接问题

- 决策状态归属需精确区分：L1 负责正式风险纳管以及跟踪管理流程，但 observing / monitoring / paused / closed 仅表达跟踪安排，具体进入/转换条件没有定案；L1 不负责变量当前状态事实、风险当前等级、兑现、方向或减弱结论，这些由 L2 判断。来源没有“L2 结论自动切换 L1 跟踪状态”规则，不能补出此联动。（1.4–1.6、4.3、5.2 / L58、L72、L80–82、L773、L1041–1044）
- 人工审核的已确认对象是共享变量治理中的新增、别名归并、拆分、合并、重新分类、机制修订及其生效版本；并未确认每次风险纳管、所有风险配置维护、所有 L2 输出都须人工审核。风险自动准入条件、人工复核权限及维护审批规则仍待讨论，应分别列为未决。（1.6、2.2.3、3.4.5、3.4.10 / L82、L277、L297、L563–580、L651）

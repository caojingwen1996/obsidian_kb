# 金融对象配置中心与共享观察规格摘要

> 本摘要和伴随功能设计共同构成草案；详细业务流程、逻辑属性、状态、页面映射及31项验收以伴随文档为准。按项目规则将功能正文放在功能架构目录，本摘要不重复正文。

## 背景与目标

用户需要先手工维护可分层浏览的金融对象配置目录，再从中选择对象建立观察。现有事件Target与手工配置、主动观察需分开，避免对象尚无事件就不能观察，或保存配置等于自动观察。用户已确认全系统共享一份观察清单。

## 能力

- **CAP-1**
  - **intent:** 维护目录层级以组织金融对象。
  - **success:** 可新增、编辑、移动、排序；循环与非法父节点被拒绝，目录节点不能建立观察。
- **CAP-2**
  - **intent:** 手工维护对象定义及可选择状态。
  - **success:** 完整启用对象可被选来观察，草稿和停用对象不可选；保存配置不产生事件或观察。
- **CAP-3**
  - **intent:** 在查找和配置时区分同名不同范围对象。
  - **success:** 同一对象可复用，同名不同范围不自动合并，多分类不复制身份。
- **CAP-4**
  - **intent:** 从配置目录添加系统共享观察。
  - **success:** 无事件也能建立；重复及并发选择只返回一份共享观察，多人看到同一清单。
- **CAP-5**
  - **intent:** 管理观察生命周期并保留历史。
  - **success:** 支持暂停、结束、显式恢复；不删除对象、冻结事件历史或阻断F02保存。
- **CAP-6**
  - **intent:** 阅读所观察对象的有效关联动态。
  - **success:** 只采用已核定的直接身份映射，按全部来源权限过滤数量和内容，事件去重，已有历史可读。
- **CAP-7**
  - **intent:** 衔接事件Target与配置对象，保留缺口。
  - **success:** 无匹配和歧义有明确状态，Event仍能保存，不自动创建配置或观察。
- **CAP-8**
  - **intent:** 正确处理配置停用对共享观察的影响。
  - **success:** 禁止新选/恢复，活跃观察暂停并保留原因；重新启用不覆盖原暂停/结束状态或自动恢复。
- **CAP-9**
  - **intent:** 保留定义版本、历史引用和金融身份。
  - **success:** 目录移动不改对象身份；实质换对象须新建；影响观察口径的修订按草案先暂停待确认。
- **CAP-10**
  - **intent:** 使配置、观察和核定分别受控且可恢复。
  - **success:** 权限分别验证，变更可审计；空、错、未决、冲突区分；批量部分失败与原请求重试不建重。

## 约束

- 配置项、事件Target、共享观察三者不得混为同一业务对象；观察引用配置稳定身份，无需以事件Target存在为前提。
- 沿用六大金融分类及一级/二级配对规则；新树形目录不是恢复旧Target分类拆表。
- 截图中的研究主题/入口不按金融对象导入；父目录或共同分类不自动扩大观察和事件关联范围。
- 保留现有事件、Fact、证据、Target及历史定义快照；切换需处理旧手工写Target入口。
- 本轮只产出功能设计，不修改代码或数据库；物理表、接口、权限标识和新AI任务编号留待后续设计。

## 非目标

个人私有观察、自动导入对象全集、按父目录自动观察所有后代、间接影响/主题自动关联、新采集规则、主动通知、风险评级和交易建议。

## 成功信号

维护者在无事件时配置并启用“美元”，再从配置目录选择建立一份系统共享观察；另一授权用户可查看同一记录。核定相关Target映射后，双方各自按来源权限读取历史动态；暂停/结束观察不影响事实保存。

## 方案建议

首版采用目录/对象条目区分、三态配置及观察生命周期、映射至多一对一、人工核定、影响观察口径的定义修订先暂停待确认。这些为功能草案建议，未当成已发布规则。

- 技术/UI阶段确定物理存储、跨模块交接、权限标识、路由、候选匹配实现与具体页面布局。

# ADR-016：开发版落地与验收边界

日期：2026-10-12。状态：本地开发实现已落地，生产部署架构仍按系统设计分阶段验收。

## 已实现的边界

前端 React / Vite 独立构建；后端 Fastify 不导入前端，实现统一鉴权与 API。`packages/application` 汇聚命令，以 JSON Schema 为入口契约，组合领域动作、幂等回执和审计。领域不互相导入实现，跨领域审核由应用层组合。模型调用只在 Activity 中执行，不在 Workflow 或持有数据库事务时执行。

PostgreSQL 保存业务事实、版本历史、任务资格和 Outbox；Temporal 保存持久执行历史。重复交付靠稳定 Workflow ID、数据库请求回执和领域幂等键控制。批准时在同一数据库事务中同时保存快照并终止任务提交资格，避免批准后又取消的竞态。定时计划只受理研究任务或生成报告草稿。

本地验证锁定 React 19.3、Vite 8.3、Fastify 5.12、Temporal SDK 1.24、PostgreSQL 18.6、TypeScript 7.0；构建所用 Node 为 22.22。实际版本以 `pnpm-lock.yaml` 为准，生产运行时升级必须单独通过构建与场景检查。

## 有意保留的开发实现

| 主题 | 当前实现 | 升级条件与约束 |
| --- | --- | --- |
| 身份 | 本机初始化账号、scrypt、Cookie、CSRF、即时角色复核 | 生产接入 OIDC / 企业身份；不改变领域授权逻辑 |
| 模型能力 | 协议适配器 + 人工模式；模型只能给建议 | 用真实供应商评测引用、拒绝、截断与语义质量；只使用实际可用模型 ID |
| 数据存储 | 每域 PostgreSQL Schema；版本化 JSONB 记录 + 关联表 | 根据已批准查询和容量要求演进显式表与索引；保留稳定业务身份 |
| 写入协调 | 短业务事务持有全局 advisory lock；模型与网络在锁外 | 单机开发优先保证竞争下的业务不变量；并发吞吐未经容量验收，不宣称水平写入扩展已完成 |
| 查询 | 有界列表投影（最多10,000记录）和后端权限过滤 | 规模化前改为索引查询、游标分页与专用读投影 |
| Workflow 开发服务 | 本机 Temporal CLI + 持久 SQLite | 生产必须使用受支持的 Temporal 服务部署及持久化策略；本地启动不等于 HA |
| 依赖治理 | 契约生成、类型检查、静态导入边界检查 | 当前没有引入 Nx；边界检查只覆盖静态导入，不等同于数据库权限隔离 |
| 报告工件 | 固定快照内容、Markdown / 可打印 HTML、实时撤回校验 | S3 内容寻址工件、PDF、签名链接与对象存储恢复需独立验收 |
| 来源采集 | 人工录入、结构化指标导入、计划等待输入 | 真实来源抓取、附件、限速、认证和采集批次适配尚需逐来源接通 |
| 方法配置 | 缺失等级、时效、节点规则时保持未知或禁止确认 | D-01—D-12 业务决策不能由工程实现私自填入生产默认值 |

没有引入额外分析遥测。应用仅进行本机数据与 Temporal 交互，配置远程模型后才调用对应供应商；演示与场景夹具不访问真实市场来源。

## 验收声明

测试报告按实际运行区分数据库 / HTTP、浏览器与真实 Temporal。源码存在、命令能受理、模拟数据通过均不能独立证明生产完成。真实模型金融语义、灾备、性能、外部身份、来源采集和工作流升级回放仍有单独上线条件。

新模型能力增长只需要新增或升级适配器和评测基线，不能绕过领域契约、时间边界、权限或人工审核。Agent 并行开发应围绕这些可执行边界分工，以测试和审计结果完成交接。

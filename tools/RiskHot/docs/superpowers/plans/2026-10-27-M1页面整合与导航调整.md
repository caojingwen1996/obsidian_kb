- 日期：2026-10-27（上海时间）。
- 状态：已按用户批准实施，六步完成；验证结果见[[tools/RiskHot/docs/verification/m1-navigation|实施验证记录]]。
- 工作分支：main；工程代码统一放在src下。
- 工作模式：操作型工作台；面向维护信源、配置自动接入、查看执行状态和结果的用户。
- 本轮交付：工程实现、设计同步、验证截图及索引日志；真实服务验收使用既有数据。

## 1. 依据与已确认决策

依据[[tools/RiskHot/docs/system-design/03-系统功能架构/M1 信源管理中心功能设计#5. 页面设计与交互|M1现行页面设计]]、[[tools/RiskHot/docs/system-design/06产品UI原型设计/F02事件管理页面设计与交互|F02现行页面设计]]及[[tools/RiskHot/.impeccable/critique/2026-10-27T10-12-44Z__src-web-index-html|页面层级审查记录]]，以实际src/web实现为工程基线。

视觉继承[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/DESIGN|M1视觉规范]]中的绿色、字体、焦点与留白。历史原型的演示数据、旧页签和旧行为不作为当前工程事实；页面设计与检查使用Impeccable。

已确认决策：

1. M1由三个一级工作区收为“信源目录”“信息接入”；自动计划归入目录，并保留全量自动接入表。
2. 左侧菜单仅展示已实现且有实际产品入口的页面，未实现页面不显示；存在设计文档或静态原型不等于产品已实现。
3. 增加常驻分组“内容”“配置”；“信息接入与事件”改名“全部”，放在内容下；信源管理中心放在配置下。
4. 分组仅展示，不可点击、不可折叠，没有箭头、展开状态或折叠偏好存储。
5. 开启任务仍直接运行全部已启用且有权限的信源，不增加来源选择或二次配置。
6. 每轮任务结果只保留任务状态与统计，不恢复按信源明细。

边界：本次调整页面组织、入口与阅读路径，不修改Fact/Event模型、AI处理规则、资料去重规则、调度语义或正式事件审批。业务启停、计划启停、本轮暂停仍是三个不同操作。

参考图片：当前请求没有附带可读取的参考图。分组结构及不可折叠规则已确定；具体图标、尺寸和间距暂沿用现有样式，不宣称已按参考图复刻。图片补充后只核对视觉差异，无需重新讨论已确认导航。

## 2. 目标页面层级

```text
产品左侧导航（分组标题不交互）
内容
  全部                         → /events#events
配置
  信源管理中心                 → /m1#sources

信源管理中心
├─ 信源目录
│  ├─ 档案视图：统一搜索、筛选、信源列表与详情
│  ├─ 自动接入视图：全部信源的自动计划表
│  └─ 信源详情：档案 / 接入设置 / 关联资料 / 历史
└─ 信息接入
   ├─ 开启任务与当前任务状态
   ├─ 执行记录：手动、自动共用查询及定位
   ├─ 本轮结果：状态与统计
   └─ 累计处理结果
```

“全部”是现有事件入口的菜单名称，不意味着增加原文、Fact、Event混排的新内容产品。现有正式事件列表、时间线、详情、关联候选及返回状态保持；页面标题仍可明确“正式事件”。

### 2.1 左侧菜单

| 元素 | 目标行为 | 验收要求 |
| --- | --- | --- |
| 内容 | 常驻分组文字，其下仅“全部”链接 | 不进入Tab焦点顺序，无按钮语义、折叠图标或aria-expanded |
| 全部 | 打开现有事件列表；事件详情及只读候选路径仍归此菜单 | 当前项样式与aria-current正确；不清除事件页面已有返回状态机制 |
| 配置 | 常驻分组文字，其下仅“信源管理中心”链接 | 与内容分组同样不可交互 |
| 信源管理中心 | 进入M1目录；M1内部两工作区都归该菜单 | 切换内部工作区不改变侧栏归属 |
| 未实现条目 | 删除可见占位项 | 风险识别与纳管、风险态势分析、风险产品与发布、风险源管理中心、流水线全景、策略管理中心不出现；不删除对应文档、原型或后台代码 |
| 两页面一致性 | M1与事件页面采用相同菜单顺序和分组结构 | 不能只修改M1，事件页仍显示旧名称或旧分组 |
| 窄屏 | 在现有响应式机制内保证两个导航链接可达 | 可改为紧凑常驻导航区域；分组本身仍不折叠，不能直接隐藏所有跨页入口 |

面包屑随导航改成“RiskHot / 配置 / 信源管理中心”和“RiskHot / 内容 / 正式事件”；详情使用对应内容语义，不把“全部”误作筛选条件。

### 2.2 信源目录与自动接入表

- 目录提供“档案”“自动接入”两种展示模式，共用信源身份、搜索文本及所选信源；档案中的全部/事实核验/日常监测/专题研究是分组方式，不再与两种展示模式混列为六个同级选项。
- 档案默认平铺；保留有效分组能力，连续单一且无区分价值的“待补充”层压平。常用搜索、业务状态优先，其他筛选置于更多筛选，已选条件保持可见。
- 自动接入表保留“全部/已配置/未配置”范围，列出信源名称、业务状态、计划状态、周期、下次触发、最近运行摘要与管理入口；不逐个点开信源才能查看计划。
- 切换展示模式保留公共搜索和信源选择；模式专属筛选独立保存，不让档案中隐藏的条件造成自动接入表莫名缺项。目录总数和筛选后数量明确区分。
- “技术”改为“接入设置”，同一详情中分开呈现技术条件和自动计划；复用计划编辑表单，不产生两份计划配置。
- “关系”改为“关联资料”，历史继续独立。源详情移除全局开启任务按钮；编辑资料和信源启停保持原有权限、版本校验。
- 周期仍支持分钟/小时/天及现有1分钟至1天限制；暂停计划仅影响后续调度，源业务启用不自动开始采集。
- 表中最近运行只保留摘要及定位入口；取消计划页独立展开的另一套运行历史。按信源查看历史进入统一执行记录并携带信源条件，可一键清除条件返回全部。

### 2.3 信息接入与结果阅读

- 原“信息接入任务”工作区改名“信息接入”，保留既有链接兼容。
- 全局工具栏保留唯一主动作“开启任务”，相邻说明“全部已启用信源”；运行中、暂停和状态未知时继续锁定重复开启。
- 当前运行状态清晰展示真实进度；完成状态压缩为摘要入口，不在目录长期展示整块历史横幅。有异常时保留可识别提醒。
- 执行记录成为主要阅读区，统一手动与自动运行查询；显示触发方式及真实执行范围，不能把单源计划运行伪装成全源批次。
- 累计处理结果保留全部七项统计，可用折叠区降低首屏占位；保留展开状态、更新时间与统计口径。日期范围执行次数与累计资料数量不合并计算。
- 每轮展开继续仅显示状态、时间、编号及关联统计。资料/候选阅读不作为按信源明细重新塞回本轮展开区。
- 单次运行的资料阅读入口使用独立“查看资料”名称，区别于“查看本轮统计”；使用同一阅读器，在资料正文与候选之间同层切换，去除只有两个按钮的中转页面。
- 阅读器按需显示文件、交付状态、处理进度与恢复动作；保留原资料身份、版本、权限、返回焦点与打开上下文。多个资料用选择器切换；零资料、零候选和读取失败分别处理。
- 诊断入口保留在执行记录的“需处理”查询及对应运行阅读中；显示真实失败环节和现有恢复操作。聚合任务出现异常但不能直接定位时，明确跳转到限定本轮的异常运行查询，不自动重跑整轮，不增加第二套执行历史页面。

## 3. 路由、查询与旧状态兼容

以下为拟实现契约，不能当作现有能力。

| 旧入口或状态 | 目标 | 保护措施 |
| --- | --- | --- |
| /m1或#sources | 信源目录档案模式 | 有效选择保留，新会话默认平铺 |
| #schedules | 信源目录自动接入模式 | 旧书签仍能直达；用统一路由解析将其归为目录，不再显示第三个顶级工作区 |
| #intake-tasks | 信息接入 | 保留当前日期、状态、任务编号查询与已选批次 |
| 计划最近运行 | 统一记录中的真实执行 | 带入日期、信源和运行身份；不能把schedule_run_id直接当作operation_id或批次ID |
| 计划运行记录 | 信息接入，限定该信源 | 查询条件明显可见；清除后回到完整列表 |
| 旧sessionStorage | 兼容迁移到新展示模式 | 校验允许值，未知值回退；不丢弃未确认命令，不重发已受理任务 |
| 浏览器前进/后退 | 恢复工作区、模式、选择及查询 | 自动刷新不覆盖正在输入或阅读的内容 |

工程核对：当前task-batches查询仅支持日期、编号及状态，没有信源条件；计划历史来自独立schedule_runs查询。因此统一历史不是纯移动HTML，需要补充受权限约束的信源筛选和身份定位。

统一列表查询以既有执行记录为基础关联计划运行：有operation的计划运行与该执行去重；尚无operation的排队、失败或跳过记录仍须可见，明确“尚未开始采集”，不可伪造0份已成功结果。后台接口新增查询参数须同步schema、参数化查询、权限及测试；不要求修改数据库表结构。筛选范围下概览与列表使用同一日期/信源范围，状态/编号过滤口径沿用现有约定并明确说明。

## 7. 范围控制与剩余事项

- 本轮不重做事件时间线，不修改已回退的业务架构与领域设计文档。

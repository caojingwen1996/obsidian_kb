# F02 分批实施计划

> **执行说明**：后续实现按任务使用 superpowers:subagent-driven-development 或 superpowers:executing-plans；执行方式由用户在评审后选择。本次仅编制计划，不启动代码实现。

**目标**：第一批形成按八步目标运行的新事件完整闭环，后续补齐增量与治理。

**架构**：复用F01 material与公共能力，先隔离验证pg-boss，再迁移数据/任务契约和F02处理器，统一切换。事件保存与关联/用途补充独立恢复。

**技术栈**：现有TypeScript、Fastify、PostgreSQL；Node >=22.0.0；pg-boss精确版本由A1锁定。

**规格**：[[tools/RiskHot/docs/superpowers/specs/2026-11-01-F02八步闭环-design|实施规格]]；[[tools/RiskHot/docs/system-design/04-系统架构设计/03-模块技术详细设计/L0-信息处理层/F02-事件管理/八步闭环实施补充设计|技术补充]]；[[tools/RiskHot/docs/system-design/04-系统架构设计/03-模块技术详细设计/L0-信息处理层/F02-事件管理/AI任务技术详细设计/AI-08-Target候选识别|AI-08技术契约]]；[[tools/RiskHot/docs/audit/F02开发前差异核对-2026-11-01|差异核对]]。

## 全局约束

- 不重建F01资料/版本/交付表，不恢复EventRevision；历史原文、工件和用户数据不删除。
- 依据固定material_id、version、content_digest；多来源权限全部核对。
- 每模型节点最多3次、总预算10分钟、未知计次、全局并发1；首版单模型Worker。
- 业务状态与入队同事务；新旧引擎同对象同代次唯一归属。
- 新文件路径均为本计划提案；已有文件路径经仓库检索。迁移SQL序号执行前再次核对，不占用已存在007。
- 各任务先跑最快专项检查再扩大；不连接正式库执行测试。旧测试跳过/既有失败明确单列。

## 审查重点

1. 同号不同义任务包误复用：A3验证拒绝，不能只改提示词。
2. Fact跨来源撤权或正文变更：A4/A5验证全部依据及提交复查。
3. 业务提交成功但队列确认丢失：A1/A7验证同回执和无重复副作用。
4. 无Target与模型失败被混成合法空：A5/A6验证状态、取值保留及受限保存。
5. 旧运行/未决批准切新引擎：A3/A9验证代次栅栏、语义失效和预算连续。

## 批次与依赖

- A：A0→A1/A2→A3→A4→A5→A6→A7→A8→A9。A1/A2可独立准备；正式发布统一门禁，不能线上先切一半。
- B：REUSE五类增量、跨报道Fact复用、纠正/更正、正式评价方法、独立用途及定义补齐。A未支持的分支持久待处理，不默认新建。
- C：P1受控合并/拆分、治理和影响范围；操作权限与审批政策先明确。

所有勾选项初始未完成。A0确认执行边界后可先行A1隔离PoC；A2/A6/A7等涉及新增存储的编码必须等待对应存储提案评审。未批准的业务规则不得发布。

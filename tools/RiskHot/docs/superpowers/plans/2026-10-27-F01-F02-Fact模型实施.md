# F01/F02 Fact 与唯一事件模型实施计划

依据：F01 功能设计、F02 功能设计和 F02 数据模型与存储设计。沿用已确认业务规则，在 main 实施，代码位于 src。本计划不调用 Superpowers 工作流。

## 范围与顺序

1. 增加 schema4：独立 fact、event，资料、事件、主体、变量、评价通过关系表连接；保留 F01 资料版本与运行审计。
2. 迁移：从原候选及证据重建 Fact，保留 Event 身份；旧 F02 业务表与交付记录归档。无法对应的资料或依据阻断迁移；未完成的旧建议作废并回到身份核对。先隔离验证，再备份与切换本机库。
3. F01/F02 接收：现有资料交付继续使用固定版本；抽取结果保存 Fact 和证据，运行候选通过连接记录关联 Fact；重复接受不重复保存。
4. F02 七步流程：新契约使用 subject/action/event_time；以当前内容摘要复核并发变化，增量建议明确当前事实及引用依据。保存不建立事件版本链。
5. 查询与交付：当前事件详情、候选及多来源可查；消息携带固定确认内容，通过消息前序关系处理乱序，保留文件恢复和接收/应用状态。
6. 页面：保持现有视觉，替换修订入口为当前事实、候选及来源追溯，M1 资料入口显示下游 Fact 与事件状态。
7. 验证：日期精度、关联约束、迁移重跑/回滚、重复/纠正/并发、权限、文件损坏/重投/乱序、API与页面；完整回归、类型检查及代码审查后部署验证。

## 验收与边界

- 一份资料可支持多个 Fact，多份资料可支持同一 Fact；已归组 Fact 只能属于一个 Event。
- 纠正必须更新当前事实，原候选和原文仍可追溯；相同处理重试不新增业务结果。
- 新流程不读取旧事件版本表；新旧交付协议明确区分，历史工件不改写。
- 真实库保存与下游文件读取作为验收证据；身份、关系或正式保存遇到新业务决定时仍遵守既有复核规则，不代用户批准。
- 本轮不扩展 F01 尚无连接器支持的资料形态，不新增 M2/M3 正式治理或 F03/F05 风险分析；记录原有未实现能力。

## 执行结果

七项结构改造及本机切换已完成；194 项回归、类型检查、24 项浏览器检查、真实库隔离迁移及正式切换后的文件/回执读取均通过。正式事件验证沿用原批准记录；服务恢复后既有计划另完成新资料的真实模型抽取，没有代替业务审批。

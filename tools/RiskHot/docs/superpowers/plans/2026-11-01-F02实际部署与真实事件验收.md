# F02 实际部署与真实新事件端到端验收计划

> 执行方式：superpowers:executing-plans，先保存本计划，再连续执行；本轮用户明确要求“先写计划，再完成”，授权本机部署、迁移与一条真实新事件验收。遇到事实歧义保留待核，不发布自动审批政策。

**目标**：本机 localhost:18081 使用新队列处理真实官方公告，从信息采集到正式Event入库，保存可复核的来源、各步模型响应、身份与最终保存决定及数据库/页面证据。

**架构**：复用现有PostgreSQL与工件，原目录停旧进程后部署f8ddeabf及本轮必要修复；008/009增量迁移，单业务Worker与API。保留旧配置、旧任务、原始资料和回执；完成前不启用全量自动采集。

**技术栈**：Node22、PostgreSQL18.6、pg-boss10.3.3、现有Codex订阅模型、独立测试浏览器。

**规格**：[[tools/RiskHot/docs/superpowers/specs/2026-11-01-F02八步闭环-design|八步实施规格]]与[[tools/RiskHot/docs/verification/f02-eight-step|首批工程验证]]。

## 全局约束

- 仅本机现有RiskHot应用，现有40条信源、1份资料和2条待处理候选全部保留；不重建业务库。
- 停止旧应用任务后再备份迁移；共享PostgreSQL、身份服务和Temporal容器不删除，不清卷。
- 凭据仅在私有环境变量及权限600的备份中保存，日志/报告不输出连接密码或认证文件。
- 本轮先关闭计划扫描，单条手动官方资料验收后按原计划启用状态恢复；不擅自启用已有停用的来源计划。
- 新事件路径与文字草案模式；正式M方法/用途未发布仍等待，不伪造下游采用。
- 复核对照本次实际原文、身份召回、对象范围及变量证据；只处理本轮验收事件，不能以本轮授权批量批准存量候选。

## 审查重点

1. 原目录未提交文档被覆盖：先完整保全项目差异及文件副本，核对后再部署；不动库内其他项目与资料。
2. 同运行双引擎：记录旧运行清单，停旧进程；新任务不重用旧代次。
3. 管理角色通过、运行角色失败：在业务/接口/模型角色下分别验证读写与函数权限。
4. 模型输入/预算或认证隔离阻断：先做限定真实调用，保留尝试，不清零预算掩盖错误。
5. 页面健康但没有真实结果：最后核对正式Event、Fact归属、来源证据、提交回执，刷新页面再次读取。

## 任务1：保全工作区与备份

**涉及**：原目录及独立分支；私有 .riskhot/backups/f02-cutover-*；计划与报告。

- [ ] 读取原目录服务/运行库只读快照，保存schema、数量和待处理运行清单。
- [ ] 保存原目录未提交差异与未追踪项目文件；不处理其他Wiki修改。
- [ ] 停止原LaunchAgent及其子进程，确认18081不再监听且没有旧Worker/Relay运行。
- [ ] 用运行容器内同版本pg_dump生成custom备份，复制工件、私有配置和原服务plist；生成摘要。
- [ ] 将备份恢复至唯一随机校验库，核对schema及来源/资料/Fact/Event计数，再仅删除该校验库。

**完成标准**：备份可恢复、旧运行已停止，清单可追溯，原数据未被删除。

## 任务2：部署代码与增量迁移

- [ ] 复查40信源/资料/候选/Fact/既有回执数量与迁移前一致；新schema8/9及队列就绪。
- [ ] 私有配置设置pg-boss、固定handler、专用模型认证路径，计划扫描暂时关闭；不改原凭据。

**完成标准**：正式库增量迁移通过，原对象保留，API/业务角色可用；失败则停在当前阶段，不启动半套服务。

## 任务3：切换与受控采集

**涉及**：LaunchAgent、API、业务Worker、既有信源采集端口。

- [ ] 从原目录安装并启动常驻服务；核对只运行API+业务Worker、18081和新八步接口可用。
- [ ] 从已启用且连接就绪的官方信源（优先央行）选最新一份尚未处理的新公告，每源limit=1，固定幂等键手动提交。
- [ ] 通过真实队列等待资料保存及AI-01提取，记录source/task/material/version/digest/candidate/fact引用与模型工件。
- [ ] 遇重复资料保留复用回执；若无新的有效公告，选同一官方信源允许范围内另一篇公开详情，不虚构输入。

**完成标准**：真实网络获取与新模型抽取完成，正文及候选证据可读；不是把旧测试夹具插入正式库。

## 任务4：真实新事件入库验收

**涉及**：八步API/任务页、模型工件、Event/Fact/Target/变量/评级及回执。

- [ ] 使用新包和显式text-draft-v1发起F02，冻结范围、期限及定义引用。
- [ ] 核对实际原文和AI-08对象含义/逐项证据、Event身份召回、Target身份范围；有歧义不得直接批准。
- [ ] 对本轮授权验收事件逐项记录有依据的复核决定，继续至最终保存提案；不采用未发布的自动通过规则。
- [ ] 展示并核对最终事件事实、对象/变量、评价模式及缺口后保存，记录决定、回执、Event/Fact来源链。

**完成标准**：至少一条真实新事件经实际队列和模型完成正式入库、页面可读、证据/决定/回执齐全。仅完成AI-08调用或候选抽取不算通过。

# M4金融对象配置与共享观察实施计划

## 3. 技术补齐决策

- 主表沿用19字段与双版本设计。共享观察唯一键为config_id，状态历史独立追加；每次恢复保留采用快照。映射保留双方快照、理由、核定者及状态历史，有效映射分别对双方加部分唯一索引。
- 权限使用read、financial_config_manage、observation_manage、target_mapping_review；维护者不自动获得其他职责。显式本机初始化账号可授予这三项权限，迁移不批量升级所有event_review账号。
- 所有配置写入在表级串行锁内校验树、精确查重、版本与影响；观察/映射按同一锁序。影响确认使用服务端根据拟变更、当前版本和受影响记录计算的摘要，提交时重算；过期确认拒绝。
- 普通运行角色不能直接改M4表或历史；受控事务命令承担写入。补足配置快照的归属、内容、摘要和不可变检查。setup重复授权后仍须保持这一边界。
- API沿用认证、同源请求、幂等回执、DomainError和权限epoch。BIGINT用字符串；批量观察按项事务及稳定子幂等键处理，不吞掉失败原因。
- 关联动态复用事件存储布局与全部来源检查。Target版本变化时旧映射即时无效；配置展示名称可更新，历史采用定义不覆盖。核定界面必须展示双方范围及辖区，不能只按关键词批准。
- 配置修改必须声明同一身份澄清；改变身份要求另建对象。预览展示真正影响记录，保留原手工暂停/结束原因，重新启用不自动恢复。

## 4. 验收与命令

将功能设计AC-01～AC-31逐项映射到实际测试和证据，特别覆盖：跨用户并发重复、相互移动成环、快照错配/篡改、定义修订暂停、失效映射、所有来源鉴权、旧入口关闭、权限撤销后的回执重放、部分失败重试及网络结果未确认。

先运行 `npm run typecheck`，再运行 `node --env-file-if-exists=.env --import tsx --test --test-concurrency=1 src/tests/m4*.test.ts`。专项通过后执行 `npm test`；浏览器验收运行独立的 `src/tests/m4-browser.e2e.ts`，使用Chrome for Testing/Chromium，1440、390、320px截图。修改Markdown后运行 `python3 ../../rules/check_markdown_tables.py` 并检查UTF-8、引用与差异。

## 5. 迁移与交付边界

开发验证使用新建的隔离数据库，测试结束清理。实际运行库不在验证脚本中自动迁移；提供只读盘点、备份、显式迁移和重启步骤。迁移前后核对Target、Event、Fact数量及引用，新增目录为空。已有手工Target由维护者逐条选定配置与映射，不自动建立观察。

切换后保留旧Target只读检索供核定使用，旧手工POST/PUT返回明确迁移提示；AI-07/F02内部核定不受影响。采用过的新记录不删除回退，应关闭M4入口并前向修复，保留快照、审计和历史。

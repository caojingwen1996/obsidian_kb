# 全部信源接入扩展设计

> V0.1 · 2026-10-24 · 承接用户“继续把信源文件中所有信源接入”的执行要求。

输入是[[tools/RiskHot/src/data/source-catalog.js|40 条来源清单]]及[[tools/RiskHot/docs/system-design/04-系统架构设计/04-公共技术契约/来源候选切片实现契约|现有管线契约]]。沿用当前 EXTRACTION_ONLY、固定输入、权限、幂等、持久工作流及模型等待配置边界；本轮扩展来源覆盖，不增加产品 UI 或正式事件处理。

## 实现选择

采用注册表加按格式适配器：公开公告使用经实测的列表/详情或 RSS，统计/行情使用明确范围、带观测日期的原始表格或 JSON 快照。相较每站复制整条管线，此方案只扩展发现、获取和标准化，继续复用存储与状态；相较通用正文猜测器，正文选择器、字段和 URL 范围逐来源固定。

每条来源均有配置和接入状态。缺实际 URL 的发行人/官方账号保留“待补地址”；verifyUrl 只用于核验身份，不替代账号采集入口。需要登录、反爬或尚未取得有效内容的来源记录具体原因，不把首页、登录页、空行情、HTTP200 或目录登记视为已接入。实际访问中确认的公开替代入口须保持同一来源和内容主责。

来源配置随 source_versions 冻结，旧操作恢复不能读可变最新连接器参数。新增配置版本不改写既有原件和资料版本。就绪来源按用户要求启用，人工停用的来源不会被日常重复初始化反向开启；新旧配置变化记录版本。

## 边界与规则

- 原件≤1MiB、正文≤20,000码点、每次每源1～5条；超限明确失败，不能截断冒充全文。
- URL 逐连接器列明 HTTPS origin/path/query 范围，重定向每跳重新检查；禁止任意 URL、内网地址、凭据或未知查询参数。原件先保存再解析。
- HTML 保留段落/表格/码点与原定位，支持配置编码；RSS 只用于发现，摘要不能代替详情全文。JSON 快照固定字段/记录范围、标题、日期和原 JSON 定位，不用 AI 猜数值。
- 同一来源的不同内容类型保留明确 scope。已验证一个栏目、一个序列或最近一期，只声明此范围；不扩写成整站/全品种/全历史。
- API 返回连接器、就绪原因及最近操作；批量命令为每源独立幂等操作，并输出逐项结果。失败不阻断其他来源，不把无法访问变成零事件。
- 不自动借用日常浏览器登录态，不绕过验证码；专用浏览器适配或用户补地址只阻断对应来源。

## 验收

40 条均能查询明确接入状态。每个就绪连接器需实际抓取、标准化、保存成功；报告逐项标题/日期/摘要、版本和状态。未就绪来源列明实测阻塞与所需输入。自动化测试覆盖 URL 边界、重定向、不同编码、表格零值、JSON日期/空数据、RSS全文、来源配置冻结与跨源幂等；现有完整测试继续通过。模型仍缺配置时保持 waiting_config，不声称真实抽取完成。

缺少实际采集 URL 的 6 条已向用户请求；其余按实测结果独立推进。工程文件选择、固定栏目/序列及失败分类由实现者依据清单 focus 和真实响应确定，并在验收记录公开。

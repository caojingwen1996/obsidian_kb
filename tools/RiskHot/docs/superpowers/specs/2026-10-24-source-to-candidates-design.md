## 2. 方案选择与范围

已向用户比较真实接入与受控验证两种方式。用户选择真实接入：优点是能证明实际网站获取、正文解析与模型调用，代价是需要确定站点访问条件及模型配置。受控样本和模型替身仍用于重复、断点与故障测试，其结果不能替代真实运行验收。

建议采用既有模块化单体及分进程执行方案，只启用 M1 的必要来源管理、F01、F02 Step 1 和 S01 的必要运行能力。完整 F02 包含归组、关系识别、增量、评价、复核及正式事件提交，会扩大本次范围，暂不作为该切片的完成条件。这是本设计提出的范围决定，尚待用户确认。

首版提供 API 和可复制的操作命令，以持久查询完成状态监测。用户已确认这一范围。既有 UI 原型保留；连接原型、制作新页面、自动定时采集、多站点适配、PDF/OCR 和 L1～L3 另行安排。

## 3. 五步业务流程

| 步骤 | 本切片行为 | 必须保存的结果 |
| --- | --- | --- |
| 信源接入 | 登记唯一来源身份、入口、允许范围、启停及连接器版本；执行就绪与业务启用分别判断 | 来源记录、不可变配置版本、资格检查 |
| 抓取与解析 | 从已登记来源获取一份真实资料；先保存原始字节，再解析正文与可用元数据 | 获取时间、来源 URL、响应类型、原件摘要与解析结果 |
| 标准化 | 保留数字、单位、时态和段落；未知发布时间为空；识别同源身份与版本，保存正文和原文定位映射 | Information、固定版本、正文、分段及映射、保存回执 |
| AI 候选抽取 | 固定任务包与资料版本；真实模型输出 0～N 候选，程序检查完成原因、结构、覆盖和全部引用 | 模型尝试、响应工件、校验结果、一次固定的候选集合 |
| 结果与监测 | 返回本切片完成状态、资料版本、候选及证据；保留各阶段耗时、尝试、原因和恢复位置 | 持久状态、阶段记录、结果引用与查询响应 |

首条适配支持上述中国人民银行公开HTML公告，列表按站点顺序取有限条目并持久固定；资料身份使用同源规范化详情URL，每篇分别保存。首轮验收至少完整处理一篇资料，不以列表摘要代替正文；其他信源只有目录元数据，不宣称已有连接器。

登录和凭据采用环境配置引用，源档案、命令、日志和报告不保存凭据值。需要浏览器时使用项目规定的独立 Chrome for Testing / Chromium 和任务目录；浏览器抓取属于该连接器的明确适配，不能暗中回退为用户日常浏览器。

## 4. 运行结构和持久边界

API 负责来源登记、身份与契约检查、命令持久受理和查询。Workflow Worker 推进阶段；IO Worker 负责获取、解析、标准化、数据库及工件操作；模型 Worker 只调用模型和保存运行工件；Relay 负责启动意图及 F01→抽取端的可靠交付。PostgreSQL、Temporal 和工件卷使用新验证环境。

获取命令的完整输入、来源版本引用和幂等摘要在返回受理回执前持久化。来源配置只提供可信范围，执行获取时再次检查资格；原件和标准化正文完整保存后才允许抽取。F01 交付与抽取端接收沿用 Outbox/Inbox，接收回执丢失时重投同一消息。

ArtifactStore 保存不可覆盖的原件、正文、映射、任务输入和模型响应。PostgreSQL 保存来源、操作、资料身份和版本、工件引用、抽取处理、候选集合、尝试与回执。Workflow 历史只传引用和小状态，不能把正文仅放在进程内存或 Temporal 历史中。

### 4.1 真实获取与现有文本受理的衔接

现有 F01 请求工件及 T02 提交接口要求受理时已经包含完整文本，不能直接用于“先受理、后获取”。本稿选择扩展 F01 的输入命令，在同一 `material_operations` 下区分直接文本与来源引用两种明确类型，不另建一套可写的采集事实。以下新增契约须在编码前同步 T01/T02/T03/T05 和 F01 关键接口与数据设计：

- 直接文本输入继续保存完整文本，不改变已有语义。来源引用输入保存完整获取描述：来源 ID 与固定配置版本、允许的资源 URL、已知外部身份、连接器与解析器版本、必要的非敏感请求参数，以及凭据引用。两种输入采用互斥 Schema；来源引用不填写伪造正文。
- 来源引用的 intake-command 工件在受理前持久发布；操作、输入工件引用、摘要、命令回执和启动意图同事务提交后才返回 202。此时只承诺描述可恢复，不承诺网站内容已取得。
- F01 Step 2 获取后将网站实际响应字节保存为独立 raw 工件，核验摘要并持久绑定操作和获取记录；Step 3 只从已绑定原件解析。重启若已有有效 raw 绑定则复用，未绑定才允许重新获取；网络内容可能变化的再次获取保留新的获取记录，不覆盖原件。
- 原件发布成功但绑定事务失败时，不标记 Step 2 完成；暂存对象按既有工件协议校验后恢复绑定。已有固定原件或资料版本的恢复不得重新访问网站替换输入。
- 来源列表与资料正文分开处理：连接器若需先枚举列表，应保存本次已发现的条目及稳定身份，再为每份资料持久建立上述来源引用操作。列表阶段与条目级故障分别记录，不以一个成功条目冒充整批成功。首个来源的枚举范围待 URL 明确后固定。

非纯文本来源的正文到原件映射也属于本次连接器扩展，必须保留可复核的原文位置及解析规则版本；缺乏可靠映射时进入待处理，不能仅生成文字后声称原文追溯已通过。

## 5. 候选切片与完整 L0 的兼容

现有完整流程要求 AI-01 接纳集合后启动各候选的 AI-02～05；本切片停在集合保存。为防止停在 Step 1 却误报完整 L0 成功，提出以下显式扩展，批准后须同步 T01、T02、T03、F02 数据设计和实际 Schema：

1. 为处理记录增加 `processing_scope`，区分 `EXTRACTION_ONLY` 与 `FULL_EVENT`；完整流程的规则不变。
2. 本切片使用固定 `analysis_key=EXTRACTION_ONLY`，与完整流程的 `INITIAL` 隔离。普通重投、技术重试、任务版本升级不自动生成新的处理或候选；任务包在首次处理时冻结。
3. `EXTRACTION_ONLY` 原子保存候选集合后不创建 AI-02～05 的启动意图；候选保持 `pending`，不生成正式 `event_id`、CommitReceipt 或事件变化消息。
4. 查询分别返回 `processing_scope`、`extraction_status`、`result_status` 和 `slice_status`。非空集合保存后，抽取为 `completed`，完整事件结果仍为 `pending`，本切片为 `completed`；空集合经有效完整响应接纳后为 `NO_EVENT`。故障时数量未知，不以 0 代替。
5. 将来启用完整事件流程使用独立 `FULL_EVENT/INITIAL` 处理；不把本切片的候选直接改成已正式提交。本次不实现跨模式复用或提升，避免未经验证的恢复语义。

这一扩展影响处理身份、集合接纳和监测投影，不能只靠前端文案隐藏差异。未批准前不修改上游权威架构文件。

## 6. 模型与证据

依据现有 AI-01 任务及提示词草案形成明确标识的验证任务包，冻结 Prompt、JSON Schema、模型配置引用、输入摘要和运行预算。模型服务及模型名待用户提供；实现时核对该服务实际请求协议、完整结束标志和结构输出能力，不默认任何厂商兼容其他厂商接口。

输入包括固定资料版本、标准化段落、EvidencePack 和覆盖清单。候选最少保留标题、描述、行为主体、动作、阶段、原文支持的时间语义、证据和不确定性。分类字典缺失时允许相应字段为空，不虚构枚举或正式身份。

程序按固定版本核验段落及码点区间，要求引文与原文一致，候选集合任一结构或引用无效则整体不接纳。截断、拒答、空字符串、超时和覆盖不完整属于异常；只有完整成功的空数组才是无事件。输入长度及候选上限沿用现有切片约束，超限明确待处理，不静默截断。

模型最大尝试、超时、退避及并发沿用 T03 验证参数；适配器不叠加隐藏重试。调用前持久预留尝试，结果接纳时检查输入、任务包和执行代次，迟到结果只能留作审计。

### 6.1 预算耗尽与授权恢复

初始窗口沿用最多 3 次、总预算 10 分钟。耗尽后保持 `recoverable`，不自动重开窗口；相同请求重投或普通 retry 不增加额度。窗口内的临时失败按剩余额度恢复，结构或证据错误进入待复核，不靠预算恢复绕过校验。

本切片提供显式的“授权重新尝试”操作：具有模型预算恢复权限的操作者提交原 processing、预期执行代次、原窗口身份和非空理由。短事务检查权限、未完成、未取消及窗口确已耗尽，写新的固定政策窗口、命令回执和启动意图，并推进执行代次；模型调用在事务外执行。输入、任务包、processing 及已有候选身份不变，新窗口仍最多 3 次/10 分钟，累计尝试不清零。

预算窗口及每次尝试的窗口关联须持久化，旧窗口的迟到结果不能推进新代次。并发恢复只接纳一个有效窗口，重复命令返回原回执；无有效权限或已固定集合时分别拒绝或返回已有结果。此处属于 T03/T04 的显式扩展，实施时同步预算账本及恢复接口，禁止只重置内存计数器。

## 7. 操作入口与监测

复用既有目标路由中的资料版本、操作、processing 和 candidate 查询。新增能力需要来源登记/启停、发起来源获取、按时间范围查询运行批次；这些是待实现的接口能力，不宣称现有代码已提供，精确请求 Schema 与路由在实施计划中与 T02 一并定版。

一次手动触发生成一个时间批次，记录原计划/触发时间。列表按时间倒序及日期、状态筛选，详情下钻到来源与资料；首版只有一个真实信源，也不把信源身份充当批次身份。查询提供五步进度、资料保存状态、抽取状态、候选数、失败原因、恢复位置和结果链接；基于数据库事实返回，不以 Worker 存活或 HTTP 202 表示成功。

写操作要求授权和 Idempotency-Key，同键异体拒绝；模型密钥不进入浏览器。隔离环境按 T06/T08 建立专用测试身份域和显式授权，缺少授权配置时阻止写操作。首版不要求接入用户现有生产身份域。

模型不可用时保留已保存资料与查询能力。技术恢复从失败阶段继续；抽取失败不重新抓取已保存版本。模型已有完整集合时不再调用；相同来源身份及版本重投不增加候选。来源身份或版本顺序无法判定时进入待复核，不能自动覆盖旧版或靠重复提交绕过。

## 8. 验收标准

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| MVP-01 真实链路 | 登记真实来源，获取一篇资料并调用指定真实模型 | 保存原件与标准化版本，真实响应经过校验后形成 0～N 候选，查询可完整回溯；记录来源、模型、任务及运行版本 |
| MVP-02 多候选 | 使用有两项独立行动的受控资料 | 一次原子接纳两个候选，证据分别有效；不产生正式事件；模型替身结果单独标注 |
| MVP-03 无事件 | 使用纯背景资料及故障响应分别运行 | 有效完整空集合正常结束；超时、拒答、截断、无效 JSON 和伪引用均不变成 NO_EVENT |
| MVP-04 幂等 | 同键重投、不同键同版、并发提交及回应丢失后重试 | 复用资料版本、抽取身份及已固定候选；同键异体拒绝；尝试记录可增加，业务结果不重复 |
| MVP-05 原文追溯 | 打开候选证据，再取得来源新版本 | 引文定位固定旧版本；新版本不覆盖旧原件、正文或映射；错误区间及版本引用被拒绝 |
| MVP-06 恢复 | 在受理、保存、模型响应和集合接纳附近中断后重启 | 持久输入、意图和回执可恢复；只重做未完成阶段；迟到结果及重复恢复不新增集合 |
| MVP-07 状态监测 | 按日期查询时间批次并查看故障详情 | 区分受理、执行、保存、抽取及本切片完成；非空候选的完整事件结果保持待处理；故障有原因与恢复位置 |
| MVP-08 资格与配置 | 停用来源、缺模型凭据或撤销权限后操作 | 明确拒绝或待配置；不伪造成功，不泄露凭据，不影响有权读取的既有结果 |
| MVP-09 预算恢复 | 耗尽模型预算后普通重投，再执行一次授权恢复并重复该命令 | 普通重投不放大预算；授权恢复只开一个新窗口，累计次数保留；旧代次结果不被接纳，最终只固定一个集合 |

真实运行验收须检查业务记录、工件及模型尝试，不以页面截图或 200/202 单独通过。真实模型样本由人工核对候选、时间性质和证据，并如实记录漏抽或误抽；一次成功不等于模型质量达标。使用受控输入和故障注入验证机制时，不冒充真实站点或真实模型结果。

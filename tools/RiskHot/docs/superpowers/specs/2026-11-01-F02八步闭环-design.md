# F02 八步闭环实施规格

> V0.1 · 2026-11-01 · 待评审的开发规格。用户已授权差异核对、技术补齐和计划编制；本文的新增技术建议未视为用户批准，未执行产品编码、迁移或部署。

## 1. 目标与依据

以[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0|F02 V1.14]]及[[tools/RiskHot/docs/system-design/04-系统架构设计/01-数据模型与存储设计/F02事件管理模块数据模型与存储设计|存储 V1.11]]实现 F01 当前 material 到正式新事件、证据阅读、独立关联与可靠交付的闭环。现状依据[[tools/RiskHot/docs/audit/F02开发前差异核对-2026-11-01|差异报告]]，技术决定落在[[tools/RiskHot/docs/system-design/04-系统架构设计/03-模块技术详细设计/L0-信息处理层/F02-事件管理/八步闭环实施补充设计|实施补充设计]]。

沿用 TypeScript、Fastify、PostgreSQL、现有认证/工件/模型调用适配；执行目标采用已确定的 pg-boss 业务交接。Node 约束沿用 package.json 的 >=22.0.0；具体 pg-boss 版本由 PoC 核验兼容后锁定，不擅自升级整套依赖。

## 2. 方案取舍

| 方案 | 收益 | 代价/结论 |
| --- | --- | --- |
| 先在 Temporal 实现全部 F02，再迁队列 | 暂时减少执行层变动 | 新步骤、恢复和复核要迁移两次；不推荐 |
| 先 PoC 队列，隔离完成存储/业务适配，最后统一切换 | 尽早排除事务风险；F01 继续运行；新逻辑只接一套目标执行器 | 需严格维护迁移清单和切换门禁；本轮推荐 |
| 先线上切队列，再开发 F02 | 提前结束旧引擎 | 当前 F02 语义和存储尚未对齐，故障归因与回退复杂；不推荐 |

第二项是本轮技术建议，不改变已确定的队列选型。保持上线前旧引擎单独拥有旧运行；隔离环境可并行验证新引擎，禁止同一运行双写。

## 3. 首批边界

A 批包含准备与工程阶段：契约冻结、队列 PoC、增量迁移、AI-01/object 适配、AI-08、AI-02/07、NEW 初始事实、变量提取和直接观测、显式文字评价或待规则、正式保存、Step 8、查询/复核/交付以及恢复。

代表性验收必须至少有一例真实可核对的 Target 和变量取值，不能全部选择无 Target、无变量样例逃避完整链路。另测合法无对象、缺定义、合法零候选和多候选独立等待。没有已发布评分方法时，真实验收明确选择 text-draft-v1；正式评分只验证机制且不冒充正式 M 业务验收。用途规则缺失保留待配置，B 批完成分类运行。Step 8 完整空召回可以产生有覆盖依据的合法无关联，另用至少两个受控正式事件验证非空关联快照。

B 批完成 REUSE 五类增量、多来源 Fact 身份核定、纠正与迟到资料、变量定义补齐恢复、正式方法接入及用途独立补充交付。C 批完成经业务授权的受控合并/拆分与治理能力。A 批遇到未支持的 REUSE/跨来源身份争议必须持久待处理，禁止当作 NEW 绕过。

不重建 F01，不更换鉴权方案，不重建资料版本表或 EventRevision，不自动清理用户数据，不实现 F03/F05 风险推理。

## 4. 安全与可靠性约束

- 资料依据固定 material_id、version、content_digest；准备、接纳和保存均校验，过期明确待核验。
- 模型并发上限1，每节点最多3次调用、总预算10分钟，未知调用计次；队列重投不重置预算。
- 新包输入政策固定 `input_encoding=o200k_base`、`max_input_tokens=24000`、`max_input_bytes=96000`。资料正文、上下文、prompt及输出Schema只序列化一次进行本地计量；此编码用于项目预算，不声称等于供应模型真实计费token。旧任务包继续原字节检查。
- 业务状态、运行登记和下一 Job 同事务；原文/网络/模型不进入长事务。
- Event 与 Target 身份、语义争议、最终保存分别按适用规则复核；文档批准不代替业务批准。
- 多来源权限必须覆盖全部采用依据；模型子进程无数据库、审批凭据，不能继承父进程全部环境。
- 首版只部署一个会调用模型的 Worker；API 独立；浏览器验收使用独立 Chrome for Testing/Chromium。

## 5. 成功标准

A 批可从当前 F01 新资料开始，得到可查询的 Event、Fact、对象/变量/观测、评价模式与缺口、独立关联结果及逐消费者交付状态。重投、重启、旧结果迟到不重复保存或通知；资料变更及撤权能拒绝失效提交。

工程验证分四层：契约/纯逻辑、隔离数据库和队列、隔离浏览器、真实资料与经授权的模型/业务复核。每层记录实际结果，旧历史报告不计作本轮通过。F01 计划、采集、资料读取、重试和权限全部回归。

## 6. 待评审决定与落点

本轮建议：采用第二项实施顺序；A 批明确受限模式；AI 任务按语义节点映射；保留旧包只读；观测证据采用现有主表 JSON 字段候选方案。后者涉及已确认16列设计的扩展，须在 A0 评审后回写权威存储文件，批准前不改DDL。具体任务及阻断关系见[[tools/RiskHot/docs/superpowers/plans/2026-11-01-F02分批实施|实施计划]]。

## 6. 本轮工程裁定补充

2026-11-01：新包AI-01原始中文prompt约31KB，旧24000字节检查不能代表标称24000 token预算。按本轮授权，锁定js-tiktoken 1.0.21，复用本地o200k_base编码器，并同时执行96000字节硬上限；不裁剪prompt。实际输入中的任务包仅保存task_id/version/digest引用，避免重复保存同一prompt与Schema；旧包摘要规则保持。

运行登记增加input_payload，用于队列清理后的固定小命令和不可变引用恢复；不存正文或凭据。资料抽取一次Job只执行一次受控尝试，已持久完整响应优先接纳；失败按原model_budget_windows累计，Job完成不等于业务成功。未自动安排的抽取恢复由显式命令受理，不能无界循环。关联可恢复任务初值30秒后续办，最多3份dispatch，耗尽保留recoverable等待人工处理；正式Event不因关联失败回滚。

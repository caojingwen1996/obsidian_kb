# S01 任务执行数据契约

> V1.0 · 2026-10-30 · pg-boss目标数据设计，未迁移。运行算法以 [[tools/RiskHot/docs/system-design/04-系统架构设计/02-专题技术架构/T03-任务编排与可靠性架构|T03]] 为准。下列为拟建逻辑/物理契约，不表示数据库已有这些表。

## 1. 数据主责

业务表保留计划、material、Fact、Event、复核与业务结果；S01使用不透明owner_ref定位对象，不复制领域状态机。pgboss内部表由锁定版本库迁移和维护，应用只经适配器访问。队列记录可清理，业务回执及可恢复运行不得依赖其永久存在。

## 2. 公共运行登记

拟建 `platform.task_runs`，是技术运行身份与恢复索引，不是第二套任务队列；不自行抢占执行。

| 字段 | 类型与约束 | 语义 |
| --- | --- | --- |
| run_id | uuid，主键 | 逻辑运行身份 |
| task_type / payload_version | text / integer，非空 | 注册类型及载荷版本 |
| owner_module / owner_ref | text / jsonb，非空 | 主责模块及不透明引用 |
| operation_key | text，非空 | 所属模块稳定操作身份；同键不同摘要拒绝 |
| execution_generation | bigint，非空且正数 | 有效控制代次，取消/恢复产生栅栏 |
| input_digest / manifest_ref | text / text，非空 | 固定输入和执行包 |
| runtime_state | text，非空 | ready、running、waiting、succeeded、recoverable、cancelled、superseded；仅技术含义 |
| resume_ref / result_ref | jsonb，可空 | 领域恢复点和结果引用，不复制领域内容 |
| next_eligible_at | timestamptz，可空 | 允许恢复时点，不能绕过领域资格 |
| correlation_id / causation_id | uuid / uuid，可空父ID | 请求与父运行链 |
| engine | text，非空 | pg-boss或迁移期间temporal；同对象同代次只有一个所有者 |
| created_at / updated_at | timestamptz，非空 | 创建和投影更新时间 |

逻辑唯一约束为(owner_module,task_type,operation_key)；同一运行的代次通过条件更新推进。索引覆盖(runtime_state,next_eligible_at,run_id)及owner定位；领域正式幂等键与回执继续由领域拥有。

拟建 `platform.task_dispatches` 关联每次投递：dispatch_id uuid主键、run_id外键、generation bigint、dispatch_seq integer、job_id uuid可空、dispatch_state text、created_at timestamptz。UNIQUE(run_id,generation,dispatch_seq)。job_id是库返回的关联值，不对可清理的库内部表建立外键。创建投递、入队和绑定job_id同事务；重复投递检查锁定run，不依赖永久队列记录。

待队列确认完成但领域未终态时，对账通过运行登记识别等待/恢复，不将Job完成映射成业务完成。发生库重试时更新尝试关联，不新建业务运行；显式延迟续办使用新dispatch_seq。投递状态不是pg-boss内部状态的完整镜像，只保存关联、确认及恢复判断所需信息。

## 3. 模型与业务检查点

沿用既有公共模型尝试与预算的业务语义，由当前数据契约逐项映射，不能创建一套默认清零的平行预算。每个模型调用绑定run_id、代次、节点、输入摘要、任务包、attempt_id、预算窗口及截止时点；数据库锁下预留尝试；未知调用也计次。模型响应引用保存后才能标记可复用。

领域步骤检查点继续归领域：节点、有效输入、建议、复核、提交身份与结果引用；控制字段与业务版本不能混用。迁移映射保留全部成功步骤、已批准依据、正式提交回执、原消息及累计尝试，不要求F01新增资料分析记录。

## 4. 周期扫描登记

拟建 `platform.job_runs`：id uuid主键、schedule_key text、scheduled_at timestamptz、started_at/finished_at timestamptz、status text、counts jsonb、error_code text、policy_version text；UNIQUE(schedule_key,scheduled_at)。索引(schedule_key,scheduled_at)及(status,started_at)。只统计周期扫描，不记录每份资料的业务触发。

通用周期注册保存期望配置版本和应用结果；信源计划在F01。每轮扫描的计数来源于实际受理结果；回滚不计成功，重放不重复计数。

## 5. 事务、清理及安全

- 业务写入、运行登记、投递绑定和队列send必须使用同一PG连接；事务内不进行外部调用。
- pg-boss初始化和Schema迁移由发布账号完成，运行账号无DDL权限；所需队列权限经PoC核验，不复制库私有SQL。
- 业务永久回执、未完成运行、有效审批、未知模型尝试与未确认消息不得随队列清理删除。终态运行清理需先满足审计保留和引用政策，具体天数在部署阶段确定。
- 模型子进程不访问上述表；父消费者使用当前模块限定的数据库连接与公开端口。凭据不放信封。

## 6. 旧表迁移边界

现行execution_intents保留只读审计及旧运行排空，不作为新Job的中继来源。新旧运行的engine归属和代次由迁移清单唯一登记；不能仅凭工作流不存在就补新Job。队列表、运行表及业务库同批备份与恢复；恢复后先暂停消费，再核对回执和未完成登记。

物理SQL、字段与现行模型预算表的精确映射、pg-boss内部版本和权限仍属工程准备工作；验收前必须形成可执行迁移，本文不声称已完成落库。

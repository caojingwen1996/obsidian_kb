## 关系未决复核与固定响应重校验

2026-10-27 补充：Step 3 的格式、引用、有效定义ID/版本先严格校验；合格响应含 unresolved_issues 时保存建议与 pending_governance 定义候选，候选状态 review / RELATION_REVIEW_REQUIRED。新增 reviews scope=relations，仍使用原复核接口和 APPROVE/REPREPARE；摘要覆盖当前候选、建议代次、结果与固定输入上下文。

APPROVE 要求当前 Step 3 review、event_review 与来源资格，原子记录决定、把 Step 3 标为合格并续 Step 4。它不清空未决项，不发布定义，也不代替 commit 复核。正式提交再次校验该关系复核记录、当前角色权限和复用事件的全部来源范围。

为恢复旧实现拦截的合格响应，恢复活动可读取同候选/同 AI-03 输入摘要下最后一次 RELATION_REVIEW_REQUIRED 响应，重新验证输入摘要、响应完整性、Schema、原文定位及定义版本；不预留模型调用、不扩预算。重校验接纳、审计 event-response-revalidated、建议和文件意图在同一事务保存，审计保留原拒绝原因。过期或已耗尽的调用窗口不妨碍读取既有固定响应，但仍不能新增调用。提示词、任务包和原输入均不变。

schema3 增量脚本兼容重跑，仅扩大 review scope 约束；同时撤回 API/Relay 对候选表的 INSERT，保留业务复核所需 UPDATE，候选新增仍由 IO 执行。实际角色反例覆盖迁移后的权限，不修改原权限测试期望。

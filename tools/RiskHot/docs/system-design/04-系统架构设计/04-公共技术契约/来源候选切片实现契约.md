# 来源到候选切片实现契约

> V0.3 · 2026-10-24 · 已批准设计的当前实现映射；来源扩展见第6节，订阅执行与后台计划见第7节。仅约束 EXTRACTION_ONLY 切片，不代表完整 L0 已实现。

依据[[tools/RiskHot/docs/superpowers/specs/2026-10-24-source-to-candidates-design|已批准设计]]和[[tools/RiskHot/docs/superpowers/plans/2026-10-24-source-to-candidates|实施计划]]，本页补充 T01～T08、F01 来源引用输入及 F02 AI-01 的实际工程契约。完整事件设计继续作为目标；当前运行不调用 AI-02～05，不创建 Event、CommitReceipt 或事件变化消息。运行证据见[[tools/RiskHot/docs/verification/source-candidates|执行验证记录]]。

## 1. 接入与不可变输入

M1 从 `src/data/source-catalog.js` 导入 40 条参考元数据，保存来源身份与不可变配置版本；首轮只启用央行，现按第6节扩展。状态不采纳原型演示字段。API、交付接收和实际模型调用均复查来源及操作者当前资格。

`POST /api/v1/l0/source-fetches` 接收 `{source_key, limit, url?}`，limit 为 1～5；央行保持原有范围，新增来源按固定连接器的 HTTPS origin/path/query 范围验证，禁止凭据和范围外 URL。URL 在命令摘要、发现、解析和资料身份前统一规范化。省略 url 时只覆盖声明的首页/栏目/数据快照，非全站或全历史覆盖。

受理前发布完整 `intake-command` 工件：来源 ID/配置版本、来源 key、连接器、规范化请求 URL 及参数；不虚填正文。操作、来源版本外键、工件引用、请求摘要、幂等回执和启动意图在一个事务中保存，提交后返回 202。完整文本输入仍是目标设计，本次来源接口没有伪装成直接文本提交。

ArtifactStore 采用内容摘要寻址，硬链接原子发布不可覆盖对象，读取时核验大小和 SHA-256。发现列表和原件另以 operation UUID/phase 原子发布 `payload + receipt.json` 目录并 fsync，先于任何数据库获取回执；恢复可依据 owner/phase/摘要将原对象重新登记。列表快照同时冻结当次条目，原件已固定后不得重新联网替换。未完成发布的临时目录不算获取成功。当前没有自动垃圾回收，避免清除待绑定输入。

连接器先保存实际响应字节，再以 UTF-8 严格解析 `#zoom`，读取 `ArticleTitle`、`PubDate`。保留段落、数字 0、表格单元格、Unicode 码点与原 HTML 定位；正文缺失、登录/验证页面、合并单元格无法可靠映射、超过 1MiB 原件或 20,000 码点正文时明确阻断。

## 2. 数据主责及身份

物理 DDL 是 `src/db/001-init.sql`，逻辑名称映射如下；目标文档中的完整领域模型并未因此全部创建。

| 所有者 | 当前表 | 不变量 |
| --- | --- | --- |
| M1 | `m1.sources`、`source_versions` | catalog_key 唯一；历史配置不可覆盖 |
| F01 | `information.operations`、`acquisitions` | 时间批次与逐资料操作分开；已发布原件按操作复用 |
| F01 | `information.materials`、`material_versions`、`material_segments` | 同来源规范化 URL 为身份；正文摘要复用固定版本；分段绑定版本 |
| F02 | `information.processing_runs` | 唯一 version_id + analysis_key；当前 scope/key 均为 EXTRACTION_ONLY |
| F02 | `information.event_candidates` | 一次完整集合原子接纳；候选始终 pending |
| 平台 | `platform.artifact_objects`、`command_receipts`、`action_receipts`、`audit_log` | 不可变工件、按身份和命令类型幂等、授权审计 |
| 平台 | `platform.execution_intents`、`messages`、`inbox` | 持久启动及 F01→F02 交付，确定身份去重 |
| 平台 | `platform.model_attempts`、`model_budget_windows` | 调用预留、真实领取、窗口预算、代次围栏 |

同键同体返回原回执，同键异体 409。不同键同版复用 material/version/processing；候选已固定时不再调用模型。来源出现不同正文但修订顺序不可判定时返回 `VERSION_REVIEW_REQUIRED`，保留旧版并停止自动覆盖；版本顺序的人工裁决界面和命令尚未实现。

`EXTRACTION_ONLY` 与将来的 `FULL_EVENT/INITIAL` 身份隔离。抽取完整非空集合：`extraction_status=completed`、`candidate_count=N`、`result_status=pending`、`slice_status=completed`；有效完整空集合：count=0、result_status=NO_EVENT。任何抽取故障或未完成状态的 count 均未知，不以 0 表示失败。

## 3. 模型契约、预算及复核

`src/information-ingestion/processing/extraction.ts` 提供严格 JSON Schema：未知字段拒绝、候选最多 50、覆盖清单须与固定版本全部段落一致。输入冻结标准化版本、分段和 Prompt/Schema/模型配置，形成任务清单与输入工件；修改环境配置不改写已经冻结的任务包。本地验证包由 AI-01 提示词草案派生，不发布或替代 M3 正式方法资产。

证据包含 segment_id、start_cp、end_cp、quote，按码点闭开区间核验。只有模型两端均未提供区间且引文在指定分段恰好出现一次时，程序可解析区间；给定错区间、重复引文、伪引用或错版本均拒绝整个集合。

当前 HTTP 适配支持 `openai-chat`：完整 Chat Completions 端点、Bearer 凭据、单一 choice、JSON content、`finish_reason=stop`；其他结束原因不算完成。实际服务未确定，未声称任意供应商兼容。响应原文先持久化再解码；HTTP 429/5xx、网络故障可按预算重试，拒答、截断、无效 JSON、结构/覆盖/证据错误均不产生 NO_EVENT。

初始窗口最多 3 次、10 分钟；累计 attempt_no 不清零。调用前预留尝试，模型 Worker 在真实发 HTTP 前经 `platform.claim_model_call` 原子领取一次性许可，复查代次、固定输入、来源、原操作员权限、预算截止及未完成/未复核状态。HTTP 最长 120 秒且受剩余窗口限制；Temporal schedule-to-close 也限制排队时间，接纳时再检查截止、代次与来源。超时不暗中再发同一调用；可能已送达供应商的中断请求只作为未知尝试保留。

技术重试最多按 30 秒、120 秒退避，消耗原窗口；耗尽后须持 `model_budget` 权限及非空理由显式追加窗口。缺模型配置时不建尝试，`MODEL_NOT_CONFIGURED` 投影为 waiting_config。结构或证据错误进入 review，普通 retry/追加窗口均返回 `OUTPUT_REVIEW_REQUIRED`。

`POST /api/v1/l0/processings/:id/reviews` 接收 `{expected_generation,basis_digest,decision:"RETRY_FIXED_INPUT",reason}`。需 read/model_review 权限；basis 来自查询，绑定 processing、资料版本、固定输入/方法、当前代次、被拒尝试及响应工件。依据变化拒绝。通过只推进代次并允许基于固定输入再次尝试，不接纳无效候选、不增加预算、不直接调用模型；随后显式 retry。

## 4. 执行、查询及隔离

API、Workflow、IO、Model、Relay 各为独立进程。Workflow 仅执行确定流程；IO 处理正文和业务事务；Model 运行时持受限工件/尝试数据库角色，纯 HTTP 适配器不持数据库对象；Relay 以租约和确定 workflow_id 连接持久意图与 Temporal。父流程不承担候选业务完成语义。

环境按角色白名单传入。模型密钥只进入 Model 子进程，管理库凭据不传入任何运行子进程，API 不具有候选表写权限，Model 不具有业务表写权限。当前为同机进程和文件权限隔离，未提供容器级网络白名单或独立对象存储服务；这些生产隔离能力不作为本地验证已完成项。

2026-10-26 按用户“去掉登录”指令，本机默认 `AUTH_MODE=local`：页面和 CLI 不依赖登录服务，API 使用固定 `riskhot-local-operator`，权限由初始化脚本登记，变更继续审计。只接受回环连接与配置 Host，写请求验证同源 Origin。`GET /api/v1/session` 返回当前权限及 authentication=local，页面不显示登录/退出。

`AUTH_MODE=oidc` 保留可选账号模式，采用专用 Keycloak realm，浏览器走 PKCE/state/nonce 和服务端会话，CLI 使用本地测试客户端；写会话验证 Origin。两种模式的权限均来自服务端 actor 登记，不能从请求体自授权。原件下载受来源权限保护，以附件和 CSP sandbox 返回；无公开工件目录。全部服务只绑定回环地址。

| 路由 | 契约 |
| --- | --- |
| `GET /api/v1/m1/sources`；`PATCH /api/v1/m1/sources/:key` | 授权范围内查询；PATCH `{state:ACTIVE或DISABLED}` 生成来源版本 |
| `POST /api/v1/l0/source-fetches` | 持久受理并返回 operation_id/status_url |
| `GET /api/v1/l0/operations/:id`；`GET /api/v1/l0/runs` | 数据库派生状态；runs 接 from/to/status，上海日期、含结束日，筛选后取最新 100 批次 |
| `GET /api/v1/l0/processings/:id` | 状态/候选/尝试/预算/复核依据；cursor 为偏移，limit≤100 |
| `GET /api/v1/l0/candidates/:id`；`GET /api/v1/l0/versions/:id[/raw]` | 固定候选、版本化证据、原件附件 |
| `POST /api/v1/l0/operations/:id/retry` | `{expected_generation,reason}`，只恢复原检查点；已交给抽取的操作用 processing 恢复 |
| `POST /api/v1/l0/processings/:id/retry` | `{expected_generation,reason,open_budget}`，原固定输入及方法，授权新窗口单独判断 |
| `POST /api/v1/l0/processings/:id/reviews` | 当前依据、明确理由与复核权限；决定只允许重试固定输入 |

所有业务写请求要求 Idempotency-Key；错误响应含稳定错误 code，未认证 401、无权限 403、冲突/代次变化 409、过大 413。slice 状态包括 queued/running/completed/partial/review/recoverable/waiting_config；partial 保留已完成子项。手动批次和每 5 秒 CLI 查询继续提供，自动日程及本机提醒按第7节扩展，未接入指标平台。

## 6. 全部信源接入扩展

依据用户继续接入全部来源的要求，采用[[tools/RiskHot/docs/superpowers/specs/2026-10-24-all-sources-design|扩展设计]]。`source-connections.json` 与 `SourceConnector` 描述 kind、readiness/reason、scope、入口、URL范围及格式规则；6 条无实际地址按用户答复保留 missing_url。26 条可执行范围取得真实入库证据，8 条访问/登录受阻。完整清单见[[tools/RiskHot/docs/verification/all-sources|逐源验证记录]]。

连接器完整配置存入 source_versions；受理命令同时冻结解析后的入口及来源版本，日期参数在受理时解析。旧操作读取旧配置，来源初始化只为新就绪来源启用，保留人工暂停。原央行旧版配置可恢复，后续技术规则变化使用新连接器标识及新来源版本，历史原件和标准化工件不改写。

HTML/RSS/JSON、字面脚本链接、公开浏览器渲染分别执行明确规则。RSS只发现详情；脚本仅解析声明的字面字符串/ID，不执行远程代码。响应缺媒体头可先保存字节再按固定解析器严格验证；明确的非支持媒体拒绝。JSON内嵌HTML声明的charset不改变外层UTF-8解码。合并表头保留行列跨度标记，不猜测填值。

快照保存 snapshotAtText；仅实际观测日设置 observedAtText，发布类日期写 publishedAtText，列表更新时间不当观测日。快照身份由来源、稳定资源范围和对应日期组成；dateQueries中的抓取窗口参数从身份中排除，完整URL仍保存于操作和原件定位。无日期、非法日期或空数据阻断；DR007和FR007另有日终/收盘资格校验，原件仍保留。

GET sources 返回 connection、connector_configured 和 latest batch 的 last_operation_id/last_status/last_reason；最新发现失败也必须显示。批量CLI逐源独立受理、最多2并行，单源失败不阻断其他来源。后台计划由第7节的独立 scheduler 承担。

浏览器只接受独立Testing/Chromium可执行文件，每次使用新临时目录并在finally关闭；导航执行来源路径规则，普通子资源仅允许来源及明确官方依赖origin。当前39号只需来源与static.wscn.net，其他资源默认拒绝。无日常浏览器或旧登录目录复用，无系统/容器级网络隔离完成声明。

## 7. Codex 订阅、持久计划与安静提醒

用户在确认整体流程和日常免干预边界后要求按订阅方案实施，依据[[tools/RiskHot/docs/superpowers/specs/2026-10-24-codex-subscription-design|订阅扩展设计]]。`codex-exec` 使用 endpoint=codex://local 与显式模型别名，读取本机 ChatGPT 登录，不需要平台 API key；真实证据和当前验收结果见[[tools/RiskHot/docs/verification/codex-subscription|订阅验证记录]]。HTTP模式仍按第3节保留，实际分派以冻结 manifest.provider.protocol 为准。

模型 Worker 在一次性调用许可后启动 CLI，独立临时目录、只读、非交互、忽略用户配置并关闭 shell/插件/MCP/浏览器/子代理等工具；只白名单传入登录所需主目录、执行路径及语言/证书配置，业务数据库与身份密码不进入 CLI。启用现有系统代理读取以沿用本机网络路由。任务规则和固定正文从 stdin 输入，最长150秒且受剩余窗口约束，输出受2MiB上限；必须进程成功、一个 turn.completed、一个最终消息，无非预期工具条目。

CLI 的结构化输出传输格式移除不被服务支持的 uniqueItems；本地 AI-01 Schema、覆盖唯一性与全部证据校验完整保留。响应先保存再消费，失败诊断限长并遮蔽常见凭据格式，错误码与诊断引用同次更新绑定；失败不会变成空事件。尝试表示一次 CLI 执行，不证明供应商内部传输重连次数或精确计费次数；模型别名及 CLI版本不冒充不可变权重版本。

`platform.source_schedules` 保存每来源计划，`schedule_runs` 保存应运行时刻、唯一来源/时刻和操作回执。默认每小时最新1条，30秒推进，最多2条在途，模型串行；来源启用/ready、操作者权限仍在受理与执行时核验。单实例数据库锁协调调度进程，命令幂等键绑定持久 run.id，提交后回应丢失从同一回执恢复；错过的小时不逐个补采。既有未冻结 MODEL_NOT_CONFIGURED 资料优先续接。

`model_service_state` 持久保存订阅暂停，实际 claim_model_call 同样检查，防止已排队任务继续调用。额度不足至少退避6小时；登录失效定期检查，成功后解除。有效窗口中的 Workflow 自己继续有限重试，scheduler 不抢代次。本次用户授权的常驻策略增加专用 auto_retry 权限：只处理订阅临时失败，每个 processing 每24小时最多1个新预算窗口，在同事务锁定 processing、验证资格/错误/窗口/暂停、登记 automatic_recoveries、推进代次、写审计与启动意图。原人工恢复仍需 model_budget 权限；review 不自动越过。

`runtime_alerts` 保存问题持续期、恢复时间、通知状态和有限交付尝试；正常成功/开始/无新内容不通知，同一持续异常只提交一次系统通知，恢复后复发可再次提醒。OS通知提交不证明用户实际看到。数据库不可用时 supervisor 另以私有 service-alert.json 保存服务故障和通知抑制状态。`GET /api/v1/l0/monitor` 与 `npm run monitor` 展示授权来源的计划/最近运行/未解除异常；本机 LaunchAgent 登录后启动并异常重启，可独立卸载，电脑休眠与 Docker依赖不可用会暂停实际工作。

# T06 系统安全架构

> V0.6 · 2026-10-24 · 安全约束落实在资料读取、模型调用、复核与正式提交边界。

## 1. 信任边界与权限

| 主体 | 允许能力 | 不允许能力 |
| --- | --- | --- |
| 资料提交者 | 在授权来源范围内提交、查自己的运行状态 | 绕过M1准入、修改历史证据 |
| 资料处理Worker | 读取授权原件、写本模块建议与保存命令 | 直接修改其他模块正式对象 |
| 模型适配器 | 读取本次最小输入包、返回建议 | 数据库凭据、任意文件/网络、审批/正式提交 |
| 复核者 | 对指定范围和建议摘要作决定 | 批准已失效建议、改变未授权方法 |
| 下游接收者 | 按契约读取获授权的固定修订 | 任意遍历原文或反写L0对象 |

首切片可以由同一个真实用户承担提交和复核，但两种动作仍有独立权限检查与审计，不声称具备多人职责分离。生产是否要求双人审批属于部署前待决政策。

## 2. 模型与输入防护

原文属于不可信数据，来源中嵌入的指令、URL或工具请求不能成为系统授权。程序约束工具允许清单、读取范围及预算；模型输出的URL、ID、路径都须按已有引用解析，不能直接请求或执行。模型建议不携可执行脚本。

只向模型发送完成任务所需的资料片段与允许字典；供应方的数据保留、部署区域与资料许可需在启用真实模型前确认。不符合政策的资料进入待处理，不通过删掉来源元数据后偷偷外发。

## 3. 证据与复核保护

原件、建议、正式修订按访问范围授权。ResolveEvidence每次检查读取权限，不能因持有evidence_id便取得原件。下载入口使用受控访问或有限时效凭证，内部对象存储路径不直接暴露。

ReviewDecision保存授权人、时间、策略版本、建议摘要与理由；正式提交再次验证权限及代次。撤销授权、取消执行与提交按[T03](T03-%E4%BB%BB%E5%8A%A1%E7%BC%96%E6%8E%92%E4%B8%8E%E5%8F%AF%E9%9D%A0%E6%80%A7%E6%9E%B6%E6%9E%84.md)的事务条件排序。审计追加记录，不用改写历史审批来补救错误；已正式提交的错误通过纠正修订处理。

确认非事件使用独立candidate_disposition权限，不能仅凭提交、普通identity_review或运维retry权限执行。权限覆盖候选所关联资料及证据范围；首切片须由真实授权复核者发起，模型不能自行否决。受理决定与IO Worker最终处置均检查当下权限和固定依据；撤权先发生则不终结，处置先提交则保留已形成的审计回执。普通拒绝某个模型建议不等于确认非事件。

F01使用information_review和information_retry两种独立权限，并检查接入操作及被比较资料的来源范围；F02的候选审批/重试权限不能替代。身份尚未确定时从material_operations.source_id解析授权，不依赖不存在的资料或候选ID。复核依据与计划由程序冻结；人工不能越过M1停用、强身份冲突、缺失原件或越权资料。API记录复核时与IO Worker保存前都重检权限；恢复入口无权改写原件、固定规则或已保存版本。复核/恢复和保存按T01的F01锁序排序，拒绝先完成时旧保存不得生效。

## 4. 密钥与审计

模型、数据库、对象存储及编排服务凭据通过运行环境的密钥机制注入，按服务最小权限分配，文档和日志不记录密钥值。日志默认仅记录ID、摘要、错误类别和计数；原文与模型完整响应进入单独授权的证据存储，避免日志复制敏感资料。

安全验证包含越权原文访问、伪造candidate/event引用、过期审批、提示注入及模型工具越权；检查拒绝动作与审计记录，同时确保没有正式事件副作用。生产安全评审未执行，详见[验收报告](../05-%E6%9E%B6%E6%9E%84%E6%B2%BB%E7%90%86%E4%B8%8E%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E6%94%B6%E6%8A%A5%E5%91%8A/L0%E6%9C%80%E5%B0%8F%E9%97%AD%E7%8E%AF%E9%AA%8C%E6%94%B6%E6%8A%A5%E5%91%8A_%E5%BE%85%E6%89%A7%E8%A1%8C.md)。

## 5. 认证、会话与权限的具体方案

采用 OIDC Authorization Code + PKCE，由 API 在服务端交换令牌。固定 issuer、client_id 和 redirect_uri；校验 state、nonce、签名、iss、aud、有效期，拒绝不允许的算法和未知签名密钥。协议依据为 [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html)，本节为 RiskHot 的接入设计，尚未验证供应方兼容性。

浏览器使用高熵不透明会话标识；服务端仅保存其摘要。Cookie 为 Secure、HttpOnly、SameSite=Lax、Path=/，使用 `__Host-` 前缀，不设置 Domain。写请求同时验证 Origin 和会话绑定的 CSRF token；OIDC 临时 state/nonce/PKCE 数据单次使用。设计默认会话绝对寿命8小时、闲置30分钟，权限每次请求查询，不把角色永久缓存于 Cookie。

首切片不自建口令库。用户身份以 (issuer,subject) 唯一；角色由应用管理员明确授权。身份认证成功不代表拥有提交、复核或原文读取权限。外部身份停用通过管理同步使本地会话失效；生产需验证同步时效，不能声称外部撤权瞬时生效。

| 目标表 | 主要字段与约束 | 用途 |
| --- | --- | --- |
| identity.principals | id uuid；issuer text；subject text；status；UNIQUE(issuer,subject) | 登录身份与本地主体映射 |
| identity.sessions | token_digest bytea PK；principal_id FK；csrf_digest；expires_at；idle_expires_at；revoked_at | 服务端会话与注销 |
| identity.permission_epochs | scope_id uuid PK；epoch bigint | 单组织首切片的权限变更排序点 |
| identity.grants | id uuid PK；principal_id FK；scope_id FK；permission；source_scope；active；UNIQUE(principal_id,scope_id,permission,source_scope) | 提交/读取/information_review/information_retry/identity_review/commit_review/candidate_disposition/retry/recompute 独立权限 |
| platform.audit_entries | id；actor_id；action；object_ref；before/after_digest；reason；recorded_at | 追加式业务与权限操作审计 |

正式提交取得组织 permission_epochs 的共享行锁，读取当前授权，再按T01锁序锁 processing、candidate、事件集合及event；非事件处置仅锁到candidate，不写事件集合或事件。撤权事务对同一权限行取得排他锁、修改 grants/会话并递增 epoch；提交资格因而有可证明的先后。复核者当下权限与建议摘要都必须有效；权限撤销后未提交建议回到待复核，不能复用已失效授权。所有涉及权限与业务锁的路径遵守这个统一顺序。

## 6. 数据库角色和模型隔离

API 角色可受理命令、查询授权对象和写复核决定；IO Worker 角色可执行本模块保存和提交；Relay的中继连接角色仅处理启动/交付意图与回执；模型 Worker 角色只能读指定输入、写尝试和响应，不得写 Event/Revision/CommitReceipt。迁移角色独立且运行进程不持有。模型供应方只收到最小输入包，不拥有任何数据库连接。

模型 Worker 与 IO Worker 在验证拓扑中为不同进程。权限隔离防止模型执行路径意外写正式表，但不能替代提交校验、代码审查和语义质量评测。

Relay进程装载接收模块端口时，接收端口使用独立的受限数据库角色和连接池。以F02为例，该角色只允许核验固定资料引用、写Inbox、创建/复用processing_runs及写启动意图；不得写Event、Revision、CommitReceipt或评级。中继连接与接收连接不能混用，接收业务事务仍由接收模块应用服务拥有。此为同进程内的职责与连接权限划分，不宣称能抵御整个Relay进程被完全控制；需要更强隔离时应把接收端口迁至独立进程，并按ADR评估通信和部署成本。

Workflow Worker只取得Temporal连接与固定流程代码，不持业务数据库、工件存储或模型凭据；需要数据或副作用的操作调度至IO/模型Activity。上述角色的正向交接及越权拒绝由总体Q-11验证，当前仅为权限设计。

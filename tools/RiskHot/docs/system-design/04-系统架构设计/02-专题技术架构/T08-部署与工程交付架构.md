# T08 部署与工程交付架构

> V1.0 · 2026-10-30 · pg-boss业务任务模式的目标部署；未实施。旧拓扑见 [[tools/RiskHot/aihot/归档/2026-10-30-Worker调度架构/归档说明|变更前快照]]。

## 1. 首版部署单元

| 单元 | 主责 | 持久化与权限 |
| --- | --- | --- |
| Web/API | 页面、授权、命令受理、查询与复核 | 业务事务和队列入队共用连接，用户请求不等待模型 |
| 后台Worker | 注册业务消费者、Cron、恢复与告警 | 业务队列分并发；按模块限定连接和公开端口写入 |
| 受限模型子进程 | 按调用执行固定输入，返回响应后退出 | 最小环境、无数据库凭据、无审批或正式写权限 |
| PostgreSQL | 业务库、运行登记、pgboss队列与回执 | 同库不同schema，统一一致备份；库内部表由迁移工具管理 |
| 工件存储 | 已固定模型输入输出和依法需留存的证据 | 独立持久卷；不强制F01保存已取消的原件；跨主机须共享适配 |
| 身份服务与入口代理 | 会话认证、TLS及API入口 | 沿用现有身份协议，不开放数据库和队列管理面 |

不部署新的Temporal Server、Workflow/IO/模型三类常驻Worker、独立启动Relay或独立采集Scheduler进程。对外交付由业务Worker的deliveries.send消费者执行；Outbox/Inbox业务语义保留。运行态现有进程在迁移验收前继续使用旧拓扑。

## 2. 启动与停止

发布阶段使用独立账号完成业务Schema和pg-boss迁移，预注册队列、版本化任务及周期定义。运行账号无DDL权限；启动校验数据库版本、任务包、队列注册、工件与供应方能力。只有队列及任务版本兼容后才领取任务，首次启动不能隐式升级生产队列表。

API接收就绪要求业务写入和同事务入队可用；Worker离线而队列可写时可有限受理并显示排队，积压达到部署冻结阈值后拒绝新增长任务。模型故障不隐藏已有查询结果。Worker单独暴露健康状态：心跳、已注册消费者、最后扫描及依赖故障，进程存活不等于执行就绪。

停止先停Cron与新领取，再通知业务处理和模型子进程取消；初始排空窗口210秒，进程守护器终止宽限240秒，均待PoC验证。长采集在安全边界保存恢复点；超过窗口终止子进程，未确认外部结果保留未知，不能标成功。重启由队列与领域恢复扫描续接。

## 3. 容量与隔离

首版一个Worker，队列并发和全局模型许可见 [[tools/RiskHot/docs/system-design/04-系统架构设计/02-专题技术架构/T03-任务编排与可靠性架构|T03]]。业务队列隔离消费额度，但同进程CPU、内存、连接池仍共享；采集/解析需设置输入大小和超时，CPU瓶颈经测量后拆执行组，不把多队列宣传为强故障隔离。

扩多Worker之前必须完成共享模型配额、计划去重、跨实例恢复互斥、工件共享及数据库连接容量测试。不得让每实例各自获得一份“全局模型并发1”。队列连接与业务连接池配置总预算，监测同库竞争；生产可用性、RPO/RTO及实际资源规格另行冻结。

## 4. 安全与网络

API/Worker只连接授权数据库、工件和必要外部服务。模型子进程使用白名单环境、最小目录及出网策略；不继承父进程数据库凭据和任意shell工具。业务消费者是可信应用程序，多个模块在同进程并不构成抵御进程完全失陷的模块隔离；更强隔离需另设部署组。

新任务只能调用已登记处理器；后台管理、恢复与复核重核权限并审计。pg-boss管理权限不向浏览器或模型开放，不把payload、原文、密钥输出到运行日志。

## 5. 从现行Temporal切换

1. 在隔离环境完成 [[tools/RiskHot/docs/system-design/04-系统架构设计/05-架构治理与验证/架构验证/Worker任务队列切换验证方案|切换验证方案]]，冻结版本、SQL、任务Schema和配置。
2. 暂停新受理和计划；盘点现有工作流、启动意图、人工等待、未知模型调用、成功回执与待交付。
3. 能排空的旧任务先完成；不能排空的逐项登记owner、恢复点、任务包、预算、引擎归属和新代次，停止旧领取并使旧代次失效。
4. 原子登记新引擎归属与Job；未确认旧模型调用状态时先查回执或按未知预算处理，不默认无调用。
5. 启动新消费者，再开启API和计划；逐项核对业务数量、待办、调用预算与交付回执。
6. 全部通过后退出旧服务；旧执行历史和启动意图按保留策略只读保存，不直接删除。

同业务对象同有效代次仅允许一个引擎执行。切换清单由公开命令和迁移工具执行，不通过手动改completed规避未完成项。

## 6. 回退与灾难恢复

备份业务与pgboss schema、运行登记、回执、被引用工件和任务包；迁移期同时保留旧Temporal恢复材料。恢复先禁止领取，再核对提交事实和输入工件，最后恢复未完成任务及交付。

应用回退先停新任务与领取，核对已经提交的新结果，保留其回执；仅将未完成、兼容的运行重新登记给旧引擎，并提升执行栅栏。不能整库回滚抹除切换后合法结果，也不能两引擎同时开写。无法兼容的任务保持待处理，查询继续提供已保存事实。

## 7. 工程交付门槛

本轮不修改package.json、compose.yaml、src或现行启动命令。工程阶段需提供可执行迁移、最小授权、事务适配、队列配置、受限子进程、运维命令、README及验证证据。必须通过事务/幂等/复核/预算/过期/退出/双引擎防重后才能替换后台。

# T05 信息与知识工程架构

> V0.4 · 2026-10-24 · 负责资料到事件证据的可追溯转换；L0不整体等同于知识工程，还包含接入、运行、事务与交付。

## 1. 数据链与权威边界

原件 → 标准化资料版本 → 可定位分段与证据包 → 候选建议 → 受验证的事件关系与修订。F01负责前三项；F02负责候选、事件及直接关系；M2维护正式Target/Variable定义。F01不提取事件、不判断风险、不接入指标实际值。L0不推导风险传导链，不把模型的常识补充写成原文事实。

## 2. 定位模型

| 对象 | 必须记录 |
| --- | --- |
| 原件引用 | information_id、固定version_ref、raw_object_ref、raw_digest、媒体类型 |
| 标准化分段 | segment_id、normalized_text、正文版本摘要、顺序及section/page信息 |
| 映射 | segment_id到原件段落/页码/区域/结构路径，normalizer_version及mapping_digest |
| 模型引用建议 | 允许的segment_id、start/end、quote；不得自行构造对象路径 |
| 正式证据 | 程序生成evidence_id、原件与正文版本、解析后定位、引文摘要、证据用途及映射质量 |

偏移统一定义为**规范化分段文本的Unicode码点索引，左闭右开**，不是UTF-8字节或JavaScript UTF-16单元。规范化文本已冻结；渲染高亮时由读取端做明确转换。段落/表格分段与原件位置映射单独保存，不能用规范化偏移直接切原件字节。

## 3. 引用验证与回溯

1. 核查segment属于本次输入包且使用指定资料版本，检查访问权限与允许集合。
2. 核查偏移边界；按相同码点规则切片并与quote逐字比较。不接受模型自由改写后声称为引文。
3. 校验分段摘要、正文摘要、原件摘要和映射清单；解析对应原始段落或页区。多段依据必须逐项引用。
4. 记录证据角色及结论引用关系；程序查一致性，语义复核判断引文是否真正支持结论。
5. 阅读事件时先展示当时的引文、资料版本和出处，再定位保存原件；在线来源URL只作补充，不替代保存原文。

受控文本切片要求确定的原件段落映射。OCR或复杂表格可记录位置与不确定性，但若映射无法可靠回溯，资料不能标为本切片可分析输入；保留待处理原件并说明原因。后续扩展需单独评测，不能假设所有格式都有精确字符映射。

## 4. 覆盖与时间

EvidencePack保存input_digest、资料版本、分段列表、覆盖范围、分段规则及排除原因。资料超出模型窗口时可按固定分块处理，必须等全部必要分块成功，再统一消重并固定候选集合；任一必要块失败不能宣称全篇无事件。首切片限定可完整输入的文本规模，超限明确拒绝或待处理。

发布时间、资料获取时间、事件发生/预计发生时间分开保存。发布时间未知保持未知；事件时间不能用发布时间填补。历史评估记录known_at与as_of及资料当时的可用依据；不能把今天取得的资料反向当作过去已知，或对空发布时间机械计算可用时间。

## 5. 定义与变更

Target/Variable匹配使用固定定义版本；未匹配项进入定义候选，不能自动新增正式字典。可保存有证据的EventTarget并暂不建立三元关系。原文修订、标准化修订、提示词升级和正式定义变化各自保留版本；资料新版本不覆盖旧EventRevision的证据。

验证需覆盖中文、非BMP字符、标点、表格、重复段落、同句不同版本和缺失原件，见[AI质量评测](../05-%E6%9E%B6%E6%9E%84%E6%B2%BB%E7%90%86%E4%B8%8E%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E8%AF%81/AI%E8%B4%A8%E9%87%8F%E8%AF%84%E6%B5%8B/L0%E6%A8%A1%E5%9E%8B%E4%B8%8E%E8%AF%81%E6%8D%AE%E8%B4%A8%E9%87%8F%E8%AF%84%E6%B5%8B%E8%AE%BE%E8%AE%A1.md)与[契约验证](../05-%E6%9E%B6%E6%9E%84%E6%B2%BB%E7%90%86%E4%B8%8E%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E8%AF%81/%E5%A5%91%E7%BA%A6%E4%B8%8E%E9%9B%86%E6%88%90%E6%B5%8B%E8%AF%95/L0%E5%A5%91%E7%BA%A6%E4%B8%8E%E9%9B%86%E6%88%90%E9%AA%8C%E8%AF%81%E8%AE%BE%E8%AE%A1.md)。

## 6. ArtifactStore对象键、映射与读取过程

### 6.1 首切片存储实现

ArtifactStore使用不可变对象语义；首个单机验证环境选择独立持久卷目录作为LocalArtifactStore，目标根目录设计为`/var/lib/riskhot/artifacts`，本轮不创建该目录。生产/多主机可替换为S3兼容适配器，业务只使用artifact_id，不感知本地路径或bucket。此选择使最小切片不依赖未确定的云供应商。

对象键格式固定为`l0/{kind}/{artifact_id}`，kind取intake-command、raw、normalized、mapping、model-input、model-output、revision-export。文件名不使用来源标题、模型文本或用户传入路径，防止路径穿越。先分配 artifact_id 并登记 staged；写入流计算 SHA-256 和大小。临时文件写完并同步文件内容后，使用同卷“不覆盖目标”的原子发布机制，再同步父目录，最后将 artifact_objects 设为 ready。禁止普通覆盖式 rename；目标已存在时核对摘要，相同则回原对象，异内容报冲突。验证环境须支持所选文件系统的原子发布与 fsync 语义，断电恢复仍由 PoC 验证。

putIfAbsent对同键异内容报冲突；read每次经权限与版本清单解析；对象存在性不能单靠数据库ready，关键分析准备阶段检查stat及摘要。S3适配时保留对象版本号及供应方校验信息，不假定ETag必然等于文件摘要。

### 6.2 证据解析的确定路径

EvidenceRef → material_segments(version_id,segment_id) → 验证码点区间并切出quote → material_versions.manifest → mapping_artifact → raw_artifact。返回EvidenceView包含quote、information_id、version_id、source_id、原文段落/页区、raw_digest和受控原件读取地址；不直接返回服务器文件系统路径。

首切片规范化保留行序，映射记录`raw_byte_start/raw_byte_end/raw_line_no`及换行归一化映射。程序使用码点序列切分正文，前端若用UTF-16索引需显式转换；不能以JavaScript字符串length作为字符定位依据。

### 6.3 完整性与修复

对象准备失败不产生ready；ready但后来缺失标unavailable并告警，暂停相关新提交。恢复必须从原始备份恢复同一字节摘要，不能让模型重新生成“相似原文”。暂存对象清理使用引用扫描及保留政策，初始验证环境默认不自动删除审计和失败工件；真实保留时长在部署政策中单独确认。

### 6.4 接入请求工件的引用保护与清理

intake-command保存F01完整接入请求，Schema、摘要层次和受理顺序见[F01数据§7.1.1](../03-模块技术详细设计/L0-信息处理层/F01-信息接入与标准化/关键接口与数据设计.md#711-完整接入请求的持久化定义)。它在Step 2原件生成之前已持久存在；内容敏感性与原文相同，读取必须检查原接入操作/提交主体和来源范围。尚未绑定的上传只允许创建它的受控受理过程访问，不能仅凭artifact_id向读者公开。

对象发布与业务受理不是跨系统原子事务。写入中崩溃留下staged或临时对象；ready后受理事务失败、幂等竞争失败留下未绑定ready对象。这些均不得被当成已受理资料，客户端以原幂等键恢复；已有material_operations.command_artifact_id引用的对象属于受理依据，即使操作saved或rejected也不能按“未使用上传”删除。

首切片保持默认不自动删除失败/审计工件。未来启用清理时，只有超过已批准保留期、无业务引用的对象才可进入清理：清理事务锁artifact_objects行，重新检查全部引用，再将state置deleting并提交；物理删除在事务外执行，失败保留deleting供重试。绑定事务也锁同一对象行且只接纳ready。绑定先完成则清理发现引用并退出；清理先标记则受理不得绑定或返回202，可在原请求未被受理的前提下重新准备工件。不得仅凭一次异步引用扫描直接删除ready对象。

deleting对象不能被读取为有效输入或重新绑定；被引用的输入工件不进入该状态。临时文件/孤立发布对象须先核对登记与引用后按保留政策清理，不能扫描目录按文件年龄直接删。已经受理的对象发生损坏则走unavailable及同摘要恢复，不走清理或重新生成内容。

> V1.0 · 2026-10-30 · 待执行。本轮仅技术架构重构，不能引用旧Temporal测试作为pg-boss验收。

## 1. 输入与证据

## 2. 阻断性场景

| 编号 | 场景 | 必须满足的结果 |
| --- | --- | --- |
| WQ-01 | 事务send后抛错；业务写后send失败 | 两种情况业务、运行登记和Job均回滚；不能用不同池连接伪造同事务 |
| WQ-02 | 下一Job入队成功，当前队列确认前退出 | 重投返回已保存结果，下一业务效果和正式提交各一次 |
| WQ-03 | 去重返回空值或同键不同输入 | 有效同任务可复用；无可靠登记或摘要不同回滚，不假报交接成功 |
| WQ-04 | 进程在模型调用前、响应收到后、接纳后退出 | 未知调用计预算；已持久响应复用；已接纳结果不重复调用 |
| WQ-05 | 重试、恢复扫描、手动恢复并发 | 原运行身份稳定，有效投递不重复，调用不突破共享预算 |
| WQ-06 | 同源自动/手动触发，计划并发修改及多扫描器 | 计划时点幂等、无违规重叠，推进next_run_at与受理同事务 |
| WQ-07 | 停机跨多个周期、时区边界 | 按政策补一次检查，不补每个漏期；统计扫描与业务任务分别正确 |
| WQ-08 | 等待复核、重复批准、过期批准、撤权 | 等待不占Worker；有效决定同事务续办；重复/过期不能越权推进 |
| WQ-09 | 取消/暂停与模型返回、保存竞争 | 旧代次不提交；已提交回执仍保留，恢复不重复正式效果 |
| WQ-10 | 资料版本或事件上下文变化 | 旧建议不覆盖新状态；回最早受影响步骤，审批重新核验 |
| WQ-11 | 多候选部分成功及合法空集合 | 不回滚成功项；空结果与失败区分；恢复只处理未完成项 |
| WQ-12 | 正式保存后交付回应丢失 | 原message_id重投，接收端原回执，无重新分析或重复提交 |
| WQ-13 | 队列清理及数据库恢复 | 永久幂等不丢失；按运行和业务记录修复缺失投递，成功项不重做 |
| WQ-14 | 多业务队列同时请求模型 | 单Worker实际在途模型调用<=1；许可等待不提前扣预算；未知尝试不清零 |
| WQ-15 | 优雅停止、超时强停、租约过期 | 停新任务，有界排空；子进程无遗留无控制调用，旧结果受栅栏拒绝 |
| WQ-16 | 旧任务包、不支持的载荷与错误处理器 | 未知版本阻断，兼容包按原版本，不静默升级AI含义 |
| WQ-17 | 模型子进程及队列运行账号越权 | 子进程无DB/正式写权限，运行账号不能DDL或跨模块写入，合法交接仍通 |
| WQ-18 | 切换时Temporal仍有在途运行或迟到结果 | 同对象同代次只属一个引擎；登记与栅栏拒绝另一方，不重复调用/保存 |
| WQ-19 | 新引擎失败后应用回退 | 停新领取、核对已提交效果；只重新映射未完成运行，不整库回滚抹除新事实 |
| WQ-20 | 连续积压、长任务及恢复扫描分页 | 非模型队列可推进，游标无饥饿；记录等待和恢复时延，不凭并发数承诺容量 |

## 3. 实施顺序与退出条件

1. 冻结版本与事务适配PoC，确认库初始化和最小数据库权限；不通过则暂停迁移。
2. 补齐可执行数据迁移、任务Schema及现行字段映射，验证保留预算、回执和恢复点。
3. 在隔离环境实现消费者与调度，以同输入覆盖WQ-01～20；真实模型质量单独验收。
4. 停新受理/计划，排空旧工作或逐项登记引擎归属、恢复点和新代次；保存旧代码与数据库备份。
5. 启用新消费者和生产入口前验证WQ-18；切换后比对来源任务、资料、Fact/Event、预算和交付计数。
6. 满足验收才退出旧服务；旧历史按审计政策留存。失败先停新领取，再按WQ-19回退，不让两套引擎竞争。

旧L0方案中的业务验收要求继续有效，Temporal历史重放/signal测试改用本方案对应恢复/续办测试。实现和验收结果写入工程验证目录；本文只定义待执行标准。

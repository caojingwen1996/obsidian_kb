# L0 最小业务闭环验证方案

> V0.1 · 2026-10-24 · 验证设计，尚未执行。本文落实用户五项要求，不包含测试代码或开发任务。

## 1. 验证范围与前置条件

从受控原始文本进入F01开始，经保存、交付、F02候选处理、正式提交、原文查询，到持久接收端回执为止。以[总体架构](../../01-%E7%B3%BB%E7%BB%9F%E6%80%BB%E4%BD%93%E6%8A%80%E6%9C%AF%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1.md)和[L0架构](../../03-%E6%A8%A1%E5%9D%97%E6%8A%80%E6%9C%AF%E8%AF%A6%E7%BB%86%E8%AE%BE%E8%AE%A1/L0-%E4%BF%A1%E6%81%AF%E5%A4%84%E7%90%86%E5%B1%82/L0-%E4%BF%A1%E6%81%AF%E5%A4%84%E7%90%86%E5%B1%82%E6%8A%80%E6%9C%AF%E6%9E%B6%E6%9E%84.md)为被验证设计。

执行前须确认输入格式与长度限制、M1来源、M3任务包/Schema、复核政策和授权身份；具备数据库/对象/工作流/模型适配器的隔离验证环境及可查询审计证据。测试数据必须标识为虚构，不向真实业务下游交付。具体实现、数据夹具文件和测试程序不在本轮创建。

验收分开记录：受控模型替身验证系统契约与故障安全；固定版本真实模型验证候选语义和引用质量。替身通过不能证明真实模型质量，文档审查通过也不能证明系统已实现。

## 2. 最小样本设计

| 样本 | 内容与预期 | 用途 |
| --- | --- | --- |
| S-MULTI | 虚构机构甲宣布调整政策利率；另一段宣布一项独立准备金政策，标注两项独立决定及各自原文 | 2候选、2新事件、不同证据 |
| S-NONE | 仅解释术语和一般背景，无具体行为、决定或状态变化 | 0候选正常结束 |
| S-REPEAT | S-MULTI同来源、同强身份、同版本再次提交 | 接口与业务多层幂等 |
| S-EVIDENCE | 含中文、非BMP字符、数字、条件、重复句及另一修订版本 | 定位、引用版本、防错引 |
| S-FAULT | 同一有效输入，在每个模型节点分别注入超时/拒答/截断/伪引用 | 失败不越过正式门槛 |
| S-SOURCE | 另一来源报告已存在的同一变化 | 新资料而非新实际变化 |
| S-CORRECT | 同来源明确更正原决定中的数字或适用范围 | 追加纠正及保留历史 |

标注包括候选边界、期望身份、时间语义、允许证据范围、是否需要评价和适用业务效果。标注者与复核理由应可追溯。不得只选模型已经答对的样本作为评测集。

| L0-AC-05 模型故障安全 | 分别在AI-01～05注入故障，并注入迟到成功响应与过期审批 | AI-01不固定0候选；下游必要任务失败时该候选不新增/修改正式事件、关系、更新、评级、修订或事件消息；已完成独立候选不受损；恢复后只提交一次 | 故障点、attempt、状态/恢复点、正式表差量、代次拒绝及恢复回执 |

AC-01的“2事件”仅适用于标注为两项独立新事件的样本；一般情况下N个候选不必对应N个正式事件，归组可复用同一事件。AC-05保证执行故障及被识别的无效建议不产生正式效果，不宣称系统能自动识别所有事实错误。

## 5. 证据与判定

每次执行记录环境/契约/任务版本、样本摘要、操作顺序、故障位置、预期和实际对象差量、业务状态、校验/审批、原文定位及回执。不以HTTP成功码、工作流成功或页面截图单独作为通过证据。

五项硬性场景必须全部通过；AC-06～13作为对应不变量的覆盖要求，失败不得被总体通过掩盖。出现无授权正式写入、重复业务效果、错版本引用、失败当无事件均为阻断缺陷。时间/成本/吞吐仅记录实测，未定阈值不填写虚构SLA。

业务处理完成与交付完成分别验收，技术替身与真实模型结果分别验收；真实模型样本规模、语义质量门槛需在评测前冻结。若没有批准量化M政策，明确记录量化分支未覆盖，不能影响正常文字评价切片的执行，但不得宣称量化评分已验证。

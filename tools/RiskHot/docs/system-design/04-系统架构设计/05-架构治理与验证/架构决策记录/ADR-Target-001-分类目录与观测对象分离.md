# ADR-Target-001：Target 分类采用字段存储

## 状态

2026-10-30 按用户反馈修订：保留分类与对象身份的语义区别，取消独立分类表、分类关系表、别名表和范围细分表，改用 Target 主表字段。设计未实施，尚未迁移运行库；文件路径保留以兼容已有引用。

## 背景

项目内参考[[tools/RiskHot/docs/references/金融风险研究对象分类索引 V1.0|金融风险研究对象分类索引 V1.0]]包含六大类、33个二级分类，并允许对象跨分类。用户要求直接用字段表示分类，取消对象业务编码，项目设计不跨项目引用知识库页面。

## 决定

1. 取消 target_code，以 UUID 表达稳定身份；名称、别名、辖区及范围用于业务核定，分类不是身份。
2. Target 主表采用 categories JSONB 字段，保存一级分类 primary_category 与二级分类 secondary_category 的配对数组；不设 target_category、target_category_relation 或分类外键。
3. 支持一个对象多个分类；两个分类层级作为一项成对保存，避免独立数组错配。名称取值和配对按有效规则校验，不只验证 JSON 格式。
4. 别名直接使用 aliases TEXT[] 字段，默认空数组；保留核定、归一化去重和跨对象重名规则，不单独建立别名表。范围使用已有 scope_definition TEXT 字段，不再建立范围细分关系表或父对象引用。分类、别名和范围均随对象定义版本及快照保留。
5. 物理字段、约束、索引与迁移以[[tools/RiskHot/docs/system-design/04-系统架构设计/01-数据模型与存储设计/F02事件管理模块数据模型与存储设计#3.3 Target：分类目录与已收集观测对象|Target 数据模型]]为准。

## 备选与权衡

| 方案 | 取舍 |
| --- | --- |
| 独立分类表及多对多关联表 | 原提案，按用户要求撤回；本阶段无需独立分类对象治理 |
| 一级和二级各一个文本字段 | 简单，但只能表达一项分类，不能保留来源允许的交叉归类 |
| 两个独立文本数组 | 容易破坏一级/二级的配对关系，不采用 |
| categories 配对数组 | 采用；无需分类关联查询，支持多分类；需要明确 JSON 结构及配对校验 |

## 影响与验证

沿用现有 PostgreSQL，不增加搜索服务或网络依赖。分类检索按一个数组项内的完整配对执行；规则变化不自动覆盖对象。修改实际分类时递增对象定义版本，保留采用的规则版本和历史快照。

写入时须校验非空数组、两个必需键、合法字符串、无重复项及一级/二级合法配对。保留停用、权限、旧定义迁移与回退要求；上述检查尚未替代实际数据库验收。

## 修订记录

原提案将分类作为独立目录表并使用关系表。2026-10-30 用户要求直接用字段表示，本次移除两张分类表；其余 Target 身份、别名、范围关系及历史引用约束保留。

2026-10-30 后续修订：用户明确别名不单独建表，取消 target_alias，改用 aliases 字段；正式 Target 新增目标表剩 target 与 target_scope_relation。

2026-10-30 再次修订：用户确认以 scope_definition 说明对象范围，撤回 target_scope_relation 表及外键、索引和循环约束；当前新增目标表仅 target，保留既有 Event—Target 业务关系。

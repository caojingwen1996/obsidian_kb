# ADR-L0-004：F02八步闭环实施顺序

- 日期：2026-11-01。
- 状态：建议，待评审；未实施、未部署。
- 依据：[[tools/RiskHot/docs/superpowers/specs/2026-11-01-F02八步闭环-design|实施规格]]、[[tools/RiskHot/docs/audit/F02开发前差异核对-2026-11-01|差异核对]]及[[tools/RiskHot/docs/system-design/04-系统架构设计/05-架构治理与验证/架构决策记录/ADR-L0-003-业务任务队列替代Temporal|队列选型决定]]。

## 决定建议

先在隔离环境验证pg-boss同事务交接，再增量迁移存储并实现八步业务，最后统一切换F01/F02运行入口。保留现行F01直至切换；新引擎只在隔离环境验证，不与旧引擎争用同一运行。新任务包以语义节点映射，旧同号任务包保持只读原语义。

首批完整验收新事件；正式评分方法未发布时，真实验收显式使用文字草案，M为空；用途规则缺失独立等待。不能把这一受限模式报告为全部F02功能完成。

## 备选与代价

先在Temporal实现会重复改编排、复核和恢复；先线上切队列会把执行与业务未完成风险叠加。所选方案要求隔离副本、明确迁移清单、单次受控发布和完整F01回归，但减少双轨业务实现。

## 存储补充建议

观测主表增加basis JSONB以保存逐条依据，不恢复独立证据表；代价是16列主表扩为17列及JSON引用完整性校验。未关联变量结果、用途与关联快照分别持久化，避免混入Rating或丢失无Target结果。具体字段唯一维护在[[tools/RiskHot/docs/system-design/04-系统架构设计/01-数据模型与存储设计/F02事件管理模块数据模型与存储设计|存储§11]]与[[tools/RiskHot/docs/system-design/04-系统架构设计/01-数据模型与存储设计/F02变量观测记录数据模型与存储设计|观测§8]]的待评审提案中。

## 验证与退出

A1事务PoC通过、A2迁移与恢复演练通过、A9切换门禁通过才发布；同对象双引擎、预算丢失、证据丢失、回执重复任何一项失败均停止切换。新写入前可恢复旧库/代码；新写入后先停消费对账，不以旧二进制直接接管新结构。详见[[tools/RiskHot/docs/system-design/04-系统架构设计/03-模块技术详细设计/L0-信息处理层/F02-事件管理/八步闭环实施补充设计|实施补充]]。

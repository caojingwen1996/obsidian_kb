# ADR-L0-002 独立技术选型与设计基线

> 2026-10-30：本ADR中的Temporal选型、三类Worker及启动中继分工已由 [[tools/RiskHot/docs/system-design/04-系统架构设计/05-架构治理与验证/架构决策记录/ADR-L0-003-业务任务队列替代Temporal|ADR-L0-003]] 替代；其他业务不变量保留。本文件保留历史决策，不表示新目标继续采用Temporal。

> V0.3 · 2026-10-24 · 架构评审稿。依据业务闭环要求独立选型；旧应用已清除，全部组件按重新实现设计。本稿不批准开发、模型发布或生产上线。

## 1. 设计输入与明确假设

唯一业务输入为 L0～L3 业务架构、F01 六步、F02 七步及五项闭环验收要求。旧应用代码、依赖锁文件、数据库结构和测试结果均不作为技术约束，也不作为新方案通过验证的证据。业务与提示词文档中的未决规则继续保持未决。

本次设计假设：首切片单组织、单验证环境；输入为受控 UTF-8 文本；多个候选可并行分析；可能等待人工复核；模型通过远程接口提供推理。团队语言熟练度、生产规模和模型供应方尚无已确认资料，不能把这些未知项写成选型事实。以下选择是当前可评审的目标方案，未来实测不满足时通过新的 ADR 调整。

## 2. 从业务要求推导技术机制

| 业务要求 | 必要技术机制 | 本方案落点 |
| --- | --- | --- |
| 一份资料产生多个候选 | 一对多持久记录、集合一次接纳、候选独立执行 | processing_runs → event_candidates；集合与每项启动意图同事务 |
| 无事件正常结束 | 有效空集合与执行失败分开建模 | 完整且有效的 AI-01 响应才写 count=0/NO_EVENT |
| 重复提交幂等 | 请求、资料版本、初始处理、提交、接收分别唯一 | PostgreSQL 唯一约束和回执；重试保留业务身份 |
| 引用回溯原文 | 不可变原件、版本清单、确定性坐标映射 | ArtifactStore + material_segments + EvidenceRef 校验 |
| 模型故障不污染正式事件 | 隔离建议、验证与提交，失败默认阻断 | AI 不持正式写权限；F02 Step 6 单事务提交 |

## 3. 候选方案比较与决定

| 决策点 | 比较的方案 | 本轮选择与业务理由 | 代价及重新评估条件 |
| --- | --- | --- | --- |
| 部署结构 | 模块化单体；按 F01/F02 拆微服务 | 模块化单体，API、Worker、中继分进程。资料、候选和正式结果需要明确事务边界，首切片没有独立团队或跨区域部署要求 | 同库耦合；出现独立扩容/隔离要求后按已定义端口拆分 |
| 应用语言 | TypeScript；Python；Java | TypeScript：接口、任务契约与浏览器共享类型表达，业务以异步 IO、校验和编排为主；数值计算由受控公式完成 | 不推定团队已有熟练度。若后续需要本地模型或大量专用科学计算，再评估独立 Python 计算适配 |
| HTTP 框架 | Fastify；FastAPI；Spring | Fastify，与所选语言一致；HTTP 只负责鉴权、契约和持久受理，不承担长工作流 | 必须显式配置严格验证；框架默认行为不能代替本系统契约 |
| 数据库 | PostgreSQL；文档数据库；SQLite | PostgreSQL：复合外键、并发唯一键、修订锁与正式结果/消息原子提交是本切片核心 | 专用表和迁移治理增加工作；SQLite 不作为多进程并发验收基线 |
| 持久执行 | PostgreSQL 任务表自建调度；队列加手写状态机；Temporal | Temporal 负责长等待、计时、活动恢复与执行历史；业务幂等仍由 PostgreSQL 负责 | 增加服务和运维成本。若实测资源不可接受，须完整验证替代方案的故障窗口，不能退回内存队列 |
| 持久层 | 显式 SQL + pg；查询构造器；ORM | 显式参数化 SQL + pg：锁序、条件更新、受影响行数和复合约束可直接评审 | SQL 与领域映射需维护；禁止绕过统一事务入口随处写正式表 |
| 对象保存 | PostgreSQL 大对象；本地持久卷；共享对象存储 | 单机验证使用不可覆盖持久卷；多主机使用满足同一端口语义的对象存储 | 单机故障域明确；扩容前必须替换存储适配，不能复制同名目录假装共享 |
| AI 执行方式 | 固定任务管线；自主 Agent 循环 | 固定 AI-01～05 管线，每步输入/输出/预算确定；首切片不允许模型自行调工具或改流程 | 灵活性受限，但易定位失败与追溯；新增工具能力需单独授权和设计 |
| 检索 | 关系过滤；向量检索；搜索引擎 | 关系过滤加受控文本召回，召回不充分进入复核 | 中文近义召回能力需样本验证；不能把没有命中当作不存在事件 |
| 消息 | PostgreSQL Outbox/Inbox；独立消息总线 | 首切片使用数据库消息和租约中继，可与提交原子写入 | 轮询与积压管理；吞吐超出经验证容量后再接消息总线 |

这些是依据上述约束作出的设计判断，并不表示某技术在所有项目中更优。选择相同技术名称不产生旧代码、旧表结构或旧路由的复用义务。

## 4. 确定的目标技术组合

浏览器采用 React、TypeScript、Vite 构建静态应用；API、应用核心和 Worker 采用 Node.js/TypeScript。JSON Schema 2020-12 是 API 与 AI 数据契约来源，Ajv2020 做运行时校验；TypeScript 类型不能替代边界校验。PostgreSQL 保存业务事实，Temporal TypeScript SDK 执行持久流程，pg 执行参数化数据库操作。模型供应方通过单独适配器接入，型号和许可在真实评测前冻结。

认证采用服务端 OIDC 登录与服务端会话，应用角色/资料访问范围在本系统维护；验证环境使用专用 OIDC 测试身份域。完整部署拓扑见 T08，认证、权限撤销与提交竞争见 T06。生产身份提供者品牌、基础组件补丁版本和实际模型型号不在当前资料中，不能虚构为已确认配置。

## 5. 从空环境建立设计基线

1. 新环境从空业务库建立专用关系模型；保留的旧运行数据不自动挂载、不自动迁移。
2. 单独发布可信信源、允许的 Target/Variable、任务包和运行政策快照；记录批准人、版本和摘要。没有批准配置则任务明确待配置，不使用代码中的默认业务定义。
3. 身份域建立显式授权的提交者/复核者，不开放“首位访问者自动成为管理员”。
4. 首个切片通过受控文本走完整流程；模型替身验证故障机制，固定真实模型验证语义，两类结果分别报告。
5. 所有运行验收从零开始。旧实现的构建和场景报告只保留历史意义。

旧 architecture.manifest.json、agent-work-packages.json 及 ADR-016 都属于历史工程记录，不是新设计的执行清单。两份 JSON 已于 2026-10-24 清理，其原用途见[旧版开发与交付记录](../../../../../aihot/%E5%BD%92%E6%A1%A3/%E6%97%A7%E7%89%88%E7%B3%BB%E7%BB%9F%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1/08.%20%E5%BC%80%E5%8F%91%E4%B8%8E%E4%BA%A4%E4%BB%98.md)。当前仅完善文档，不创建新的源码、依赖清单、DDL 或部署脚本。

## 6. 官方机制依据与使用边界

2026-10-24 核对以下一手资料；这些资料证明组件机制，不能证明 RiskHot 的组合已实现或性能已达标。

- [PostgreSQL 显式锁](https://www.postgresql.org/docs/current/explicit-locking.html)：行锁用于本方案的提交竞争控制，锁顺序和事务范围由本方案定义。
- [Temporal Workflow Execution](https://docs.temporal.io/workflow-execution)：持久执行和历史重放支撑跨故障推进；数据库提交与外部模型调用仍需业务幂等。
- [Fastify 验证与序列化](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)：支持自定义校验器，其默认数据转换行为需按本方案关闭。
- [Ajv Schema 方言](https://ajv.js.org/guide/schema-language.html)：明确采用 2020-12，禁止混用默认方言而不经兼容验证。
- [node-postgres 事务](https://node-postgres.com/features/transactions)：同一事务必须使用同一个数据库客户端连接。
- [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html)：使用标准认证协议；具体会话、角色、撤销与对象权限由本系统落实。

# M4金融对象配置与共享观察技术设计

## 输入与边界

依据[[tools/RiskHot/_bmad-output/implementation-artifacts/spec-m4-financial-objects|实施规格]]、[[tools/RiskHot/docs/superpowers/plans/2026-11-05-M4金融对象配置与共享观察实施|实施计划]]、[[tools/RiskHot/docs/system-design/03-系统功能架构/M4 金融对象配置中心与观察管理功能设计|功能设计]]及[[tools/RiskHot/docs/system-design/04-系统架构设计/01-数据模型与存储设计/全局配置表数据模型与存储设计|配置数据模型]]，实现手工配置、系统共享观察、人工映射、直接关联动态。沿用已确认目录树＋列表/详情布局，不导入原型种子，不修改F01/F02队列，不推送。

配置UUID、Target UUID与观察UUID互相独立。配置创建不产生观察或Target；观察创建不产生事件；F02保存不自动建立配置。初始目录为空。

## 组件与事务

| 组件 | 职责 |
| --- | --- |
| src/financial-objects/categories.ts | 六类及33个二级分类的唯一程序来源；旧Target契约继续重导出兼容 |
| src/financial-objects/contracts.ts | 输入规范化、BIGINT字符串、树可选性、分页及类型 |
| src/financial-objects/service.ts | 配置/观察/映射命令，影响预览，权限与回执，关联动态查询 |
| src/runtime/m4.ts | 认证上下文、封闭请求Schema、幂等键及接口 |
| src/db/010-m4.sql | 表、约束、不可变历史和受控写函数 |
| src/platform/m4-migration.ts | schema8前置、重复迁移、前后数量校验及收窄授权 |
| src/web/m4.*、m4-view.js | 配置页、共享观察、编辑、树形选择器、影响与映射核对 |

所有写命令复用Repository.action：先锁定幂等键，锁权限epoch，再检查read及独立职责；回执重放同样重新检查权限。M4写操作统一取得配置表SHARE ROW EXCLUSIVE锁，比方案中观察命令的SHARE锁更保守，避免共享唯一性与联动相互竞争。需要Target时再以FOR UPDATE锁定Target行，与F02保存的FOR SHARE互斥，串行建立同版本首份快照；随后处理观察与映射，锁序一致。

普通API/IO/Relay角色无四张M4表的直接DML。API只可调用platform.m4_lock、platform.m4_persist；函数固定search_path，撤销PUBLIC执行。受控写入口再次核查职责、配置与快照配套、双版本、精确联动集合、观察状态转换和采用前提、映射依据与一对一约束。配置命令不能只附带任意观察修改；历史与审计由数据库强制生成，不依赖客户端附送历史。重复setup授权的最后一步再次撤回M4 DML及快照UPDATE/DELETE。

所有定义快照禁止UPDATE/DELETE。配置提交时延迟约束核对kind、身份、完整版本、完整行及摘要；观察和映射分别校验采用快照归属。Target同版本已有快照优先复用；不存在时使用AI-07扩展定义形状，F02保存使用同一采用快照，防止同版本不同payload冲突。摘要复用支持Date的event-management/contracts.ts canonical/digest。

## 配置变更与影响确认

配置全部19字段维持原模型。config_version在实际变化时推进；对象范围、辖区和分类变化推进identity_version。同身份名称修订不改变口径。改名/口径调整必须显式声明same_identity；实际不同对象另建，系统不以文字相似度自动确认金融同一性。

预览在锁内根据拟变更、原快照、整个树的版本/可用性、受影响观察及映射版本计算摘要。保存时重新计算；受影响对象、观察或映射不为空就必须匹配impact_token。任一影响依据变化均返回409，原修改不提交。目录/对象停用或移入不可用分支，暂停活跃观察但保留原手工暂停、结束记录；身份口径改变还将有效映射改为pending。恢复配置不恢复观察。

数据库入口按修改后的树和口径再计算精确联动集合，并要求提交集合完全一致；既防漏暂停，也防借配置权限修改无关观察。任何约束、历史、审计、回执失败均回滚同一事务。

## 接口契约

全部接口前缀为`/api/v1/m4`；写请求携带`Idempotency-Key`，actor仅取认证会话。ID为UUID；BIGINT（包括sort_order、版本和历史中的版本）为十进制字符串。Schema拒绝额外字段。

| 方法与相对路径 | 输入要点 | 结果 |
| --- | --- | --- |
| GET /configs | q、category、jurisdiction、status、parent_id、offset、limit | items分页；完整目录/对象树、权限、分类字典 |
| GET /configs/:id | 配置身份 | 当前定义、不可选理由、全部版本、观察、映射及映射历史 |
| POST /configs | 完整定义字段、reason | 配置及changed，不生成其他业务实体 |
| PUT /configs/:id | 完整定义、expected_config_version、same_identity、reason、可选impact_token | 原子修改、快照与联动 |
| POST /configs/:id/impact | 与修改相同的拟变更及版本 | 影响对象、活跃观察、映射与impact_token；不写业务记录 |
| GET /observations | q、category、jurisdiction、status、offset、limit | 共享清单及按账号计算的可读动态数量 |
| GET /observations/:id | offset、limit、from、to | 当前定义、采用快照、历史、映射状态、可读动态分页 |
| POST /observations | config_id、expected_config_version、reason、可选note | added / exists / restore_required；全状态config_id唯一 |
| POST /observations/batch | 1～100个唯一config_id项目 | 每项独立事务、稳定子幂等键及逐项错误；成功项保留 |
| PUT /observations/:id | action、expected_version、reason；恢复另带expected_config_version | pause / end / restore / note；恢复原记录并采用最新快照 |
| POST /mappings | 双方ID与expected版本、decision、identity_confirmed、reason | approve / conflict；revoke另带mapping_id与expected_version |

操作说明先统一去除首尾空白，再写快照、映射和历史。批量命令先独立登记整批输入摘要，之后逐项提交；同一批次键改变项目或说明时拒绝，不增加新项。撤销映射同时核对mapping_id、双方身份及版本。

列表默认每页20、最大100。树节点返回完整轻量结构，适合首版人工目录规模；如目录扩大需另外设计虚拟化/分层加载。动态日期筛选按记录更新时间，界面继续展示事件原始event_time，不把观察时间解释为发生时间。

## 权限、映射与动态

| 职责 | 标识 | 不隐含的职责 |
| --- | --- | --- |
| 共享读取 | read | 不获得任何写入 |
| 配置维护 | financial_config_manage | 不获得观察管理或映射核定 |
| 观察管理 | observation_manage | 不修改对象定义 |
| 映射核定 | target_mapping_review | 不批准事件事实、不自动建立观察 |

人工核定需同时展示双方范围、辖区及版本；明确辖区矛盾、未确认身份或无效Target拒绝批准。同一配置或Target只允许一个approved映射；冲突保留记录并使相关旧有效映射待核定。纯改名/排序不破坏原身份依据；任一Target版本改变、失效，或配置identity_version改变时，查询即时停止使用旧映射。

只从event_target读取直接关联。事件通过EXISTS去重；同一事件任一采用来源不在账号source_keys内时，数量与列表都排除，详情使用同一规则。暂停和结束不冻结资料，不停止采集。未核定/待核定/冲突/失效、合法零可读事件、读取错误分别表达。映射说明只承载人工定义比较，不接入原文证据导出。

## 页面与切换

schema10存在时，`/m4`提供配置中心，`/targets`切换共享观察，现有产品页面导航动态加入M4；尚未应用schema10时保持原页面。旧手工Target POST/PUT在命令层返回M4_MANUAL_TARGET_RETIRED，旧Target GET保留供人工核定，内部AI-07/F02写路径继续可用。

编辑使用完整页面；移动/排序单独预览影响。观察选择器提供目录树、对象预览、不可选原因、多选与逐项结果。页面与弹窗分别按请求代次采用结果，关闭或切换后忽略迟到响应。选择器执行100项上限，跨页结果沿用提交时名称；失效选择撤回，必须重新核对后显式选择。保存结果未知（包括写入成功但返回JSON损坏）时按账号保留原请求，重新加载后仍使用相同幂等键；确定的版本失败保留输入。401/403清理受限内容并重新读取权限。跳到主要内容只移动焦点，不改变业务路由。手机提供目录折叠、44px触控及分行的一级/二级金融分类。

## 运行与回退

`npm run migrate:m4`只读盘点，`npm run migrate:m4 -- --apply`显式迁移；不会自动执行schema8或改变队列。执行前先备份并完成F02前置迁移。新账号初始化可带三项职责；现有账号用`npm run grant:m4 -- 账号 权限...`逐项显式授予，可重复执行。迁移不批量升级event_review账号。

已按用户后续授权完成本机实际库迁移、账号授权与服务重启，见[[tools/RiskHot/docs/verification/m4-live|实际部署验收]]。已有Target保留，只由维护者手工选择配置及映射。一旦出现采用记录，回退应关闭M4入口并前向修复，不删除快照、观察或映射；不提供破坏性down迁移。运行与验证证据见[[tools/RiskHot/docs/verification/m4|M4验证记录]]。

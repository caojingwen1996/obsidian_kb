## 2. 输入与输出

| 方向 | 内容 |
| --- | --- |
| 输入 | 程序固定的评价范围、研究期限、方法版本及允许维度，当前 Event/Fact、原文证据、既有适用评价与新增依据。 |
| 输出 | 逐维分析、financial_usages、reasoning_summary、limitations 和 evidence_refs；有正式批准规则才给允许范围内的维度建议分值，不输出自行决定的总 M 或审批状态。 |
| 运行信封 | 运行/Fact 关联、任务包、输入摘要、有效代次、预算窗口、真实尝试和证据工件由程序记录 |
| 不再使用 | EventRevision、expected_revision、event_update_id；保留资料/定义/方法版本 |

## 3. 校验与交接

程序决定初评/复评、验证有效输出，并按批准方法独立计算；将评价通过关系表关联 Event 和采用的 Fact。相同操作重试复用评级，不新增重复记录。

1. M 衡量金融研究意义，不等于风险等级、损害程度或资产价格涨跌方向。
2. 保持输入范围、研究期限、方法和证据边界，不为得到分数自行改变口径。
3. 有批准量化锚点才给维度建议分值；无方法时维度评分和 M 合法为空，文字评价保留草案。
4. 区分事实、解释与不确定性。缺少到期量、历史比较或适用范围时明确限制，不推断净投放或降息。
5. 同一事件不同范围/期限的评价分别表达，不相互覆盖。
6. 来源增加、纯重复或评价依据未变可由程序跳过；调用后失败不伪装成合法空分。
7. 评价依据为当前 Event 和采用的 Fact/原文，保留方法版本，不要求事件修订号或前后评级版本链。

业务关联采用独立关系表。模型只能提出关系和当前字段变更建议，不能直接写库、生成审批或绕过字段/证据校验。

## 4. 执行与恢复

IO Worker 准备固定输入，模型 Worker 执行受预算限制的调用，IO Worker 校验并接纳；Workflow 负责推进。模型等待和人工等待期间不持数据库锁。

响应格式、证据和允许引用先严格校验，语义歧义再交复核。输入或归属变化导致旧建议失效；恢复不得替换输入摘要或清零预算。尝试、原响应、校验、复核和拒绝原因保留审计。

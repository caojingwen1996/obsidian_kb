# AI-05 金融意义评价技术详细设计

> V0.2 · 2026-10-24 · 对应[L0 §3.6及§6.1.5](../../../../../02-%E4%B8%9A%E5%8A%A1%E6%9E%B6%E6%9E%84%E4%B8%8E%E9%A2%86%E5%9F%9F%E8%AE%BE%E8%AE%A1/RiskHot_L0_%E4%BF%A1%E6%81%AF%E5%A4%84%E7%90%86%E5%B1%82_%E4%B8%9A%E5%8A%A1%E6%9E%B6%E6%9E%84%E4%B8%8E%E9%A2%86%E5%9F%9F%E8%AE%BE%E8%AE%A1V1.0.md)、[F02 Step 5](../../../../../03-%E7%B3%BB%E7%BB%9F%E5%8A%9F%E8%83%BD%E6%9E%B6%E6%9E%84/F02%20%E4%BA%8B%E4%BB%B6%E7%AE%A1%E7%90%86%E6%A8%A1%E5%9D%97%E5%8A%9F%E8%83%BD%E8%AE%BE%E8%AE%A1%20V1.0.md)。金融意义M不是风险等级；本稿不批准候选权重、评分公式或阈值。

## 1. 触发与上下文

程序先判断新事件初评或变化是否影响既有评级依据。无需复评时记录沿用/不适用决定，不调用模型，不创建重复评级。需要评价时固定EventContextRef、assessment_scope、research_horizon、method_version、相关关系/增量及证据，保存输入摘要。

评价依据记录既有事件basis_revision_no及本次待提交变化摘要；新事件尚无正式修订，使用候选上下文和待提交内容，Step 6保存时解析为本次实际依据修订。不能用之后的“最新修订”回填当时依据。

## 2. 模型职责与输出

| 内容 | 要求 |
| --- | --- |
| 范围、期限与方法引用 | 透传固定值，不由AI修改 |
| 维度分析 | 按输入方法解释影响、程度、期限、范围和阶段；讨论中的维度仍标为讨论状态 |
| 维度分值建议 | 仅已批准锚点且证据充分时给出；否则为空并说明缺口 |
| financial_usages | 投资、融资、投机/情绪观察等用途，可多选；不能代替M |
| reasoning_summary | 概括金融意义、证据、限制与复评变化，不要求内部思维过程 |
| evidence_refs / warnings | 逐维或逐结论关联可定位证据与不确定项 |

模型输出的总分、评级状态、rating_id、记录时间不具有写入权威。本稿建议新Schema不让模型承担确定性总分计算；旧Schema若包含总分，适配器仅保留原始响应供审计，最终值由程序重新计算或置空。

## 3. 程序计算与保存交接

验证范围/期限/方法一致、维度集合和建议值合法、证据及缺口明确。已批准方法且输入充分时，程序按固定计算规则独立求值，检查值域；不复制模型总分。权重或方法未批准时只接纳有效文字分析，M为空、rating_status=draft。

规则已批准但输入不足时保持明确的待补充/草稿状态并按方法政策处理；无政策不能自行补齐缺失维度。模型超时、拒答或结构失败则当前任务待恢复，不能生成空M草稿绕过失败。

程序形成待保存EventRating：assessment_key、范围、期限、维度、用途、理由、method_version、依据、证据和适用历史关联。rating_id、evaluated_at及状态由程序/复核流程管理，Step 6统一提交。相同评价操作重试复用assessment_key；不同范围或期限为不同评价组，同组复评保留历史与supersedes引用。

## 4. 失效与复评

前序身份、关系、增量或事件修订变化时，程序判断本次评价依据是否仍成立；受影响则重新准备并使旧建议/审批失效。方法升级不会让在途任务静默改分；授权新评价使用新分析/评价身份且保留旧版本。

## 5. 验证

至少覆盖：合法文字草稿、获准方法的确定性复算、模型伪造总分、范围/期限漂移、无证据维度、纯来源增加不调用、模型故障不产生评级、并发依据变更、重复评价不重建。没有已批准量化方法时，量化分支验收标为不适用/待条件满足，不能用候选公式假装正式规则；核心切片仍须验证正常文字评价与模型故障的区别。

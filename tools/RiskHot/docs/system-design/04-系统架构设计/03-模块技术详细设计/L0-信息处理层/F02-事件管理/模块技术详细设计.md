## 1. 输入与数据职责

F02 接收 F01 已保存的确定资料版本，提取 Fact 并关联资料，再归组到唯一 Event。Fact 与 Information 多对多，Event 与 Fact 一对多，所有业务关联用关系表。没有候选的资料保持正常无事件结果。

业务规则见[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0|F02 功能设计]]；具体表结构见[[tools/RiskHot/docs/system-design/04-系统架构设计/01-数据模型与存储设计/F02事件管理模块数据模型与存储设计|F02 数据模型与存储设计]]；事务与恢复见[[tools/RiskHot/docs/system-design/04-系统架构设计/03-模块技术详细设计/L0-信息处理层/F02-事件管理/事件数据与状态设计|事件数据与状态设计]]。本文件不重复物理表定义。

## 2. 内部职责

| 组件 | 职责 |
| --- | --- |
| 接收与查询 | 持久接收固定资料，查询 Fact、Event、原文及处理/交付状态 |
| 抽取协调 | 准备全文和规则，接纳完整候选集合，保存或明确复用 Fact |
| 归组与分析协调 | 推进 AI-02～05，管理建议代次和独立复核 |
| 正式提交 | 检查当前上下文、权限和证据，事务保存当前事件与关系 |
| 交付与恢复 | 固定当次提交内容，重试投递/回执，处理重复和先后依赖 |

组件沿用现有 API、IO Worker、模型 Worker、Relay 与 Workflow 分工，不增加部署服务。

## 3. 七步协作

| 步骤 | 输入与处理 | 结果 |
| --- | --- | --- |
| 1 / AI-01 | 固定 Information 与证据，提取候选陈述 | 合格 Fact 与资料关系；0候选是明确正常结果 |
| 2 / AI-02 | Fact、真实召回 Event 与已关联事实 | NEW / REUSE / UNRESOLVED 建议与身份复核 |
| 3 / AI-03 | 候选/事件、有效定义、直接证据 | 主体/变量关系建议、说明或定义缺口 |
| 4 / AI-04 | 当前 Event 与已关联 Fact、本次 Fact | 七类差异结果、明确字段/关系变更建议 |
| 5 / AI-05 | 程序固定范围、期限、方法及 Fact 依据 | 维度分析、评价或合法沿用说明 |
| 6 / 程序 | 全部有效建议、批准、证据和并发上下文 | Event 当前事实、关系、评价、审计、回执及交付意图 |
| 7 / 程序 | 已提交固定内容 | 接收与应用回执，失败单独恢复 |

每项 Fact 处理独立完成或待复核，同一资料部分完成不误报全部成功。Fact 已在 Step 1 存在，不在每次有增量时重复创建。

## 4. 保存与变更规则

- 取消事件版本和更新历史模型；现行 EventUpdate 不能直接改名为 Fact。
- subject、action 均为实际文字；不保留事件类型或行动编码字典。
- event_time 只表示发生时间，精度由单字段表达；计划日期保留在描述与原文。
- 纠正必须明确更新当前标题、描述等字段，并保留原 Fact、F01 版本和操作审计。
- 关系删除必须明确批准；本次未提及不是撤销依据。
- 评价引用 Event 和采用的 Fact，保留方法版本，不再依赖事件修订。
- 新事件必须有 Fact 及有效原文证据；未归组 Fact 不生成空 Event。

## 5. 并发、权限与恢复

按照执行状态设计第7章锁序、共享集合校验和当前内容摘要复查。未满足门槛则零正式写入；批准过期回相应比较步骤，不只换摘要。全部来源资格按关联链核对，多个 Fact 的权限不能缩减为当前触发资料。

模型失败恢复当前任务，不能变成无事件。提交响应丢失按原提交身份查询回执。交付失败只恢复原文件和消息；不可重新分析或覆盖固定交付内容。非事件处置保留候选/原文和审计。

## 6. 接口与页面变更影响

目标读取入口是 Event 当前详情、Fact 详情、来源链、评价、审计与交付状态。旧的 revision 查询、event_update_id、basis_revision_no 与事件类型过滤不再是目标契约。

旧消息和历史文件保留旧 Schema 解释；新协议需独立标识并逐一切换生产者、接收方及页面。不能把旧更新 ID 当作 Fact ID，不能无提示删除已保存的历史验收工件。

## 7. 实施验收

实施需同步迁移数据库、任务包、API、查询、页面、交付、恢复和测试。重点覆盖：多对多来源、唯一事件归属、事实纠正、重复与并发、原文可追溯、撤权、模型失败、交付乱序及重启恢复。

本轮只修改设计；旧模型真实验收可作迁移前基线，不能视作新模型已通过。

# AI-01 事件候选抽取技术详细设计

> V0.2 · 2026-10-24 · 对应[L0 §6.1.1事件抽取](../../../../../02-%E4%B8%9A%E5%8A%A1%E6%9E%B6%E6%9E%84%E4%B8%8E%E9%A2%86%E5%9F%9F%E8%AE%BE%E8%AE%A1/RiskHot_L0_%E4%BF%A1%E6%81%AF%E5%A4%84%E7%90%86%E5%B1%82_%E4%B8%9A%E5%8A%A1%E6%9E%B6%E6%9E%84%E4%B8%8E%E9%A2%86%E5%9F%9F%E8%AE%BE%E8%AE%A1V1.0.md)和[F02 Step 1](../../../../../03-%E7%B3%BB%E7%BB%9F%E5%8A%9F%E8%83%BD%E6%9E%B6%E6%9E%84/F02%20%E4%BA%8B%E4%BB%B6%E7%AE%A1%E7%90%86%E6%A8%A1%E5%9D%97%E5%8A%9F%E8%83%BD%E8%AE%BE%E8%AE%A1%20V1.0.md)。提示词业务资产见[候选事件提取提示词V0.1草案](../../../../../03-%E7%B3%BB%E7%BB%9F%E5%8A%9F%E8%83%BD%E6%9E%B6%E6%9E%84/AI%E4%BB%BB%E5%8A%A1%E4%B8%8E%E6%8F%90%E7%A4%BA%E8%AF%8D/AI-01%20%E5%80%99%E9%80%89%E4%BA%8B%E4%BB%B6%E6%8F%90%E5%8F%96%E6%8F%90%E7%A4%BA%E8%AF%8D%20V0.1.md)；本稿定义系统运行契约，不发布提示词。

## 1. 调用边界

程序确认F01资料固定版本已保存、正文与原件定位可读，取得/复用processing_id后调用。任务只识别具体行为、决定或状态变化并切分独立候选，允许0个；不分配正式event_id、不做事件归组、不评价风险。

一次资料处理只能接纳一个完整候选集合。已有集合时恢复候选处理，不再调用AI-01；普通重交命中同一INITIAL。方法升级只有通过授权重算才创建新处理。

## 2. 输入与输出契约

| 方向 | 逻辑字段 | 来源/约束 |
| --- | --- | --- |
| 输入 | processing_ref、information_id、version_ref、input_digest | 程序产生，模型不得修改 |
| 输入 | 标题、来源、发布时间及是否未知、正文分段、必要附件文本 | 固定资料版本；时间分别表达 |
| 输入 | EvidencePack及coverage_manifest | 全文必要内容覆盖；引用只限给定分段 |
| 输入 | task_manifest_ref及候选抽取规则 | M3固定版本，资料内容不作系统指令 |
| 输出 | candidates数组，允许空 | 非空元素必须具有独立业务语义 |
| 候选元素 | 临时输出序号、事件标题/描述、行为主体、动作、状态、发生/预计时间及精度、地点/范围（有则给出） | 未知明确为空；序号不是持久candidate_id |
| 候选元素 | evidence_refs、信息缺口、切分依据 | 每项引用对应原文；不得虚构精确日期 |
| 输出 | 覆盖说明、warnings | 程序结合实际输入和响应结束原因判定完整性 |

以上为语义结构设计，正式字段枚举与JSON Schema须随任务包评审发布；不将业务示例中event_id误作模型应生成的字段。

## 3. 程序前后处理

输入准备保留原始数字、单位、条件和时态，按[T05](../../../../02-%E4%B8%93%E9%A2%98%E6%8A%80%E6%9C%AF%E6%9E%B6%E6%9E%84/T05-%E4%BF%A1%E6%81%AF%E4%B8%8E%E7%9F%A5%E8%AF%86%E5%B7%A5%E7%A8%8B%E6%9E%B6%E6%9E%84.md)提供可定位分段。首切片只接收能完整覆盖的文本；超限明确待处理。扩展分块时必须记录全部块并汇总成功后再固定集合，不能把第一块结果当全文。

程序检查响应正常结束、结构完整、候选字段与证据可解析、发布时间未替代事件时间。任一元素结构或定位失败，当前抽取集合整体不接纳，保留原响应供修复/重试；**集合成功接纳后**的语义歧义在各候选内独立复核。这区分“集合完整性”与“逐候选业务处理”，不以丢弃坏元素伪装完整结果。

通过后以processing代次条件原子保存集合、candidate_count及候选身份。并发或迟到尝试只允许一个被接纳，其他留存为被替代尝试。candidate_key由程序在接纳时固定，后续不得重新按模型列表顺序计算。

## 4. 结果与异常

完整有效空数组产生NO_EVENT处理结果，记录资料版本、方法包、证据包覆盖及完成时间；Event、关系、更新、评级和事件变化Outbox均为0。模型空字符串、拒答、超时、JSON截断或覆盖不完整都不是空数组成功，candidate_count仍未知。

非空集合交各候选Step 2；“可能是同一事件”留给AI-02，不能在抽取时跨资料自动合并。提示注入、无法解析引用进入明确失败/复核，不允许扩大工具权限。

## 5. 验证与审计

必须覆盖：同文两项独立决定、同一决定的多段说明、纯背景说明无事件、预计与已实施混合、未知时间、截断、伪引用、两次返回候选顺序不同及迟到响应。记录输入/输出摘要、覆盖、结束原因、集合接纳代次及候选数；期望见[AC-01/02/04/05](../../../../05-%E6%9E%B6%E6%9E%84%E6%B2%BB%E7%90%86%E4%B8%8E%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E8%AF%81/L0%E6%9C%80%E5%B0%8F%E4%B8%9A%E5%8A%A1%E9%97%AD%E7%8E%AF%E9%AA%8C%E8%AF%81%E6%96%B9%E6%A1%88.md)。语义漏抽与误抽需[真实模型评测](../../../../05-%E6%9E%B6%E6%9E%84%E6%B2%BB%E7%90%86%E4%B8%8E%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E8%AF%81/AI%E8%B4%A8%E9%87%8F%E8%AF%84%E6%B5%8B/L0%E6%A8%A1%E5%9E%8B%E4%B8%8E%E8%AF%81%E6%8D%AE%E8%B4%A8%E9%87%8F%E8%AF%84%E6%B5%8B%E8%AE%BE%E8%AE%A1.md)，不能由结构校验代替。

# AI-02 事件身份判断技术详细设计

## 1. 调用前提与召回

输入候选已固定且有原文证据。程序依据主体、行为、时间、辖区、政策/行动标识召回真实Event，提供每个事件的固定修订、来源和差异依据。召回机制首切片可以使用结构过滤与文本检索，不依赖向量库；候选截断、索引延迟和查询失败必须在检索清单中说明。

正常召回0条与召回失败不同：前者允许提出新建建议，仍需按政策复核；后者待恢复，不能当作“库里没有，所以新建”。关键标识存在冲突或检索覆盖不足时不能自动认定无匹配。

## 2. 契约

| 方向 | 内容 | 约束 |
| --- | --- | --- |
| 输入 | candidate_id、候选要素与证据、固定资料版本 | 只分析当前候选 |
| 输入 | matching_candidates：event_id、revision_ref、事实/身份要素、历史证据 | 程序真实召回，形成允许引用集合 |
| 程序上下文 | retrieval_manifest：快照ID、scope_key、catalog_epoch、条件、时间、检索规则、授权范围/权限代次、事件修订清单、是否截断/异常与覆盖依据 | 程序冻结并参与输入摘要及审批绑定；模型不能生成或修改校验版本，不隐瞒召回缺口 |
| 输出 | identity_suggestion：NEW / REUSE / UNRESOLVED | 本稿技术映射；发布时与业务枚举确认 |
| 输出 | proposed_event_id（仅REUSE）、逐项异同、证据与待确认问题 | ID只能来自输入集合；NEW不生成ID |

模型比较行为主体、决定/行动、时间、范围和标识，不把同一政策主题等同于同一具体事件。不自动合并或拆分正式事件；涉及已有事件合并/拆分转既有受控能力。

## 3. 程序裁决与交接

检查ID真实、允许集合、事件修订、对比证据及判断冲突。NEW必须有新建理由及已执行的检索记录；REUSE须保留匹配依据。若自动通过规则尚未发布，采用授权复核，不添加自定义置信度阈值。UNRESOLVED保持候选待复核。

程序生成IdentityDecision，记录candidate_id、决定、拟复用event_id、expected_revision、检索/建议/复核引用与有效代次。随后建立[T04定义的EventContextRef](../../../../02-%E4%B8%93%E9%A2%98%E6%8A%80%E6%9C%AF%E6%9E%B6%E6%9E%84/T04-AI%E4%B8%8EAgent%E6%9E%B6%E6%9E%84.md)：新事件为candidate上下文，已有事件为event上下文。此处确定身份方向但不正式插入Event；Step 6消费决定后才分配新event_id。

## 4. 并发与恢复

已有事件修订变化时，重新比较受影响身份要素。复核更改归属或AI-04发现独立事件时回到本步，使后续关系、增量、评级建议及审批失效。模型故障恢复本步，不改为默认NEW。

同一身份决定只能正式消费一次，阻止重试创建两个Event。不同资料或同一资料内不同候选同时建议NEW，采用[F02数据设计第7.2节](../事件数据与状态设计.md#72-不同候选并发新建的集合版本校验)的事件集合版本校验：程序冻结召回版本，Step 6在集合锁内检查；过期返回IDENTITY_SNAPSHOT_STALE并持久失效，恢复到Step 2，重新生成身份决定及必要审批。模型等待和人工复核期间不持集合锁。

该恢复保留processing/candidate及Step 1固定集合；Step 2～5旧建议、身份批准和最终批准不可复用。新召回可能转REUSE，也可能仍为独立NEW，不能只修改epoch或随机换event_id重放原建议。检索失败、覆盖不足及模型失败均不得默认NEW。恢复沿用T03预算约束，不能因集合冲突无限追加调用。数据库标题唯一键不能保证语义归组正确；集合校验仅阻止旧快照直接提交，不宣称任意同义文本完全去重。

## 5. 验证

追加不同candidate_id在同一集合版本获得NEW批准的并发场景：一项先提交后，另一项必须零正式写入并回Step 2；用受控AI-02/复核结果分别覆盖“改为复用同一事件”和“确认独立后新建”。还应验证旧审批重放、集合版本回滚、提交回应丢失、召回读取中发生写入及检索覆盖不足，具体断言见契约方案第6.1节。

准备已存在匹配、同主体不同决定、同主题不同时间、两个歧义匹配、真实0召回、召回故障、伪造event_id、过期修订及复核改归属场景。检查无效身份不进入Step 3/6，新建时程序分配ID且能反查身份决定。依据见[契约方案](../../../../05-%E6%9E%B6%E6%9E%84%E6%B2%BB%E7%90%86%E4%B8%8E%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E8%AF%81/%E5%A5%91%E7%BA%A6%E4%B8%8E%E9%9B%86%E6%88%90%E6%B5%8B%E8%AF%95/L0%E5%A5%91%E7%BA%A6%E4%B8%8E%E9%9B%86%E6%88%90%E9%AA%8C%E8%AF%81%E8%AE%BE%E8%AE%A1.md)和[质量方案](../../../../05-%E6%9E%B6%E6%9E%84%E6%B2%BB%E7%90%86%E4%B8%8E%E9%AA%8C%E8%AF%81/%E6%9E%B6%E6%9E%84%E9%AA%8C%E8%AF%81/AI%E8%B4%A8%E9%87%8F%E8%AF%84%E6%B5%8B/L0%E6%A8%A1%E5%9E%8B%E4%B8%8E%E8%AF%81%E6%8D%AE%E8%B4%A8%E9%87%8F%E8%AF%84%E6%B5%8B%E8%AE%BE%E8%AE%A1.md)。

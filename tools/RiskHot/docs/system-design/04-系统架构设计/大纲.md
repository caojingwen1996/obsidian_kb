# 系统架构设计文档大纲

## 文档职责

| 类别 | 主责与设计深度 |
| --- | --- |
| 总体架构 | 全系统边界、组件关系、运行、数据、接口、部署及质量视图 |
| 数据模型与存储设计 | 各模块表结构、字段类型、主外键、关系基数、约束、索引与迁移；业务领域文档只定义对象、关系和业务规则 |
| 专题架构 | 跨模块复杂机制的设计、权衡、异常边界与验证；保留现有 T01～T08 稳定编号 |
| 模块详细设计 | 内部组件及调用关系、功能实现、交互时序、状态、数据访问、事务及异常恢复；引用公共机制 |
| 公共技术契约 | 集中定位现有权威定义、版本和适用边界；目前提供契约索引与约束，精确内容继续在明确的权威章节维护 |
| 治理与验证 | 架构决策、质量场景、验证证据、风险与演进；运行验收状态保持待执行 |

## 后续规划

以下为后续设计范围，尚未创建空目录或空文档：

- L1-风险识别与纳管层：F03、F04。
- L2-风险态势分析层：F05、F06。
- L3-风险产品与发布层：F07、F08。
- M1～M3 及 S01：按业务支撑和公共运行职责分组，不归入 L0 的业务模块。

各分组在 `03-模块技术详细设计/` 下建立；层级总览负责组内协作与交接，不重复维护模块的内部算法和事务细节。

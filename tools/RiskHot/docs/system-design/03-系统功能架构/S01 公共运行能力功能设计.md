# S01 公共运行能力功能设计

## 1. 模块定位与职责边界

S01提供跨模块可复用的运行受理、调度、执行控制、可靠投递、幂等、重试、技术告警及操作审计。业务方定义处理对象、资格、结果、重执行条件与业务完成判定；S01接收不透明业务标识、授权上下文、执行入口及校验结果。

采集计划、信息采集任务、material、分析结果与采集统计归所属业务模块。S01不维护信源配置、来源资格或资料业务状态，不因提供调度就拥有业务任务。

## 3. 运行对象与信息组织

| 公共对象 | 职责与边界 |
| --- | --- |
| 执行受理与投递登记 | 确保任务可靠入队、重投及追踪；队列受理不等于业务完成，具体机制归技术设计 |
| 运行与尝试 | 通用执行身份、状态、代次、开始结束时间、租约与错误；不复制逐资料业务记录 |
| 命令幂等回执 | 同账号、命令类型、键及内容摘要返回原结果；不作为实时业务状态 |
| 技术异常提醒 | 按不透明对象与问题键跟踪故障及通知结果，不解释业务数据质量 |
| 管理审计 | 记录操作者、动作、时间、前后操作结果及理由，业务含义归调用方 |

业务结果只保存引用，通用对象不承载伪装的资料接入、获取、分析或交付状态表。字段、约束和SQL只在公共技术设计中维护。

## 4. 功能详细设计

### 4.1 受理与幂等

校验调用身份和权限，由业务方校验参数与资格。请求键与摘要一致时返回原确认结果；不同拒绝。业务任务创建后投递执行，原结果未知时按原键恢复，不制造第二份业务效果。

### 4.2 定时触发设施

业务方持有计划、周期和下次触发时点，S01按约定回调业务受理入口。重复触发必须携带稳定周期身份，漏期策略由业务方明确。S01不另建业务“触发记录”替代业务任务。

### 4.3 执行控制

提供排队、资源限制、租约、超时、暂停／继续／取消请求及确认。任务完成事实与控制请求分开；旧代次的迟到结果拒绝提交。业务状态及业务计数由所属模块更新。

### 4.4 重试与恢复

技术错误按可重试分类和预算执行。是否允许业务重执行由业务方重新校验，不能绕过复核、资格与授权。没有可安全复用的输入时返回业务方重新取得输入；不要求任何模块保存独立原件或分析记录。

### 4.5 告警与审计

运行不可用、超时、连续失败、投递异常可形成通用问题。外部业务异常只接受既有判定与入口，S01不推导业务质量。操作审计与业务版本历史分开，不要求信源配置版本或资料版本表。

### 4.6 人工交接

投影业务方待办及其入口，接收已授权决定后校验关联和代次并唤醒。复核结论由业务模块保存，不在公共层另建领域事实。

## 5. 页面与交互边界

S01只提供公共运行信息查询与授权控制的通用契约，不定义采集入口、信源计划表、采集任务列表、material阅读器或采集统计。业务页面归M1／F01等模块设计。通用查询区分运行状态、业务结果引用及告警投递状态，不显示模拟进度。

## 6. 跨模块协作与交接契约

| 方向 | 交接信息 | 主责 |
| --- | --- | --- |
| 业务方→S01 | 业务对象引用、执行入口、授权上下文、幂等键、触发或恢复要求 | 业务方定义资格、参数、结果和计划 |
| S01→业务方 | 受理结果、执行状态、技术错误及控制确认 | S01负责可靠执行，业务方解释业务效果 |
| 业务方→复核交接 | 待办引用、入口及已确认决定 | S01仅传递／唤醒，不定义候选和资料语义 |

[[tools/RiskHot/docs/system-design/03-系统功能架构/F01 信息接入与标准化模块功能设计 V2.1|F01]]拥有采集业务。[[tools/RiskHot/docs/system-design/03-系统功能架构/M1 信源管理中心功能设计|M1]]拥有信源当前档案和业务入口。F02拥有候选与事件业务。公共技术表不列入F01业务表清单。

## 7. 通用规则

每次恢复重核权限；幂等键重放原结果；控制版本与执行代次不等于业务内容版本；技术成功不自动代表业务成功。调用业务对象及输入后须防止变化后的错误提交。公共告警失败不删除业务结果，审计不得暴露秘密或受限内容。

## 8. 功能验收场景

用两个不同业务模块验证同一种受理、调度和重试机制，不依赖信源或material特有语义。覆盖重复命令、并发投递、超时与迟到结果、暂停确认、权限变化、故障恢复、未知结果恢复、重复复核回执以及告警重投。F01/F02本次切片已覆盖通用受理、投递、代际、预算与恢复，见[[tools/RiskHot/docs/verification/ingestion-migration|工程验证]]；其余完整公共场景仍须分项实施。

旧AC-S01编号仅保留在历史验收材料；本轮按去业务化契约重新编写可执行用例，旧采集切片通过不代表公共目标验收通过。

## 9. 待定事项与后续设计工作

公共运行表的权威数据契约、引擎控制适配和资源预算需同步技术设计。原automatic_recoveries依赖资料分析记录，必须随其退出迁移；不得把业务专属恢复登记原样保留在S01。本次schema5已移除旧processing_id依赖，公共执行、模型调用、预算与投递使用不透明owner身份和必要输入引用，业务状态由所属对象解释。公共专题与完整能力验收仍需继续同步，不能把本次切片等同全部目标完成。

# F01 信息接入与标准化模块功能设计

> V2.2按2026-10-29确认清单修订。文件路径沿用V2.1以保持链接稳定。本机接口、页面和运行库已切换schema5；具体验证覆盖及尚未实现的完整功能边界见[[tools/RiskHot/docs/verification/ingestion-migration|迁移验证记录]]。

## 1. 模块定位与职责边界

### 1.1 模块定位

F01维护信息采集计划与单信源采集任务，获取、解析、标准化并保存资料，向F02提供可读取的material。material是唯一正式资料术语，保存正文、表格及必要来源信息。不独立保存原件，不另设资料版本表及资料接入、原件获取、资料分析、资料交付四类记录。

### 1.2 输入与唯一业务输出

输入包括M1当前信源身份、启停及允许范围，授权链接或文件输入，以及任务触发身份。文件可作为解析输入，但不作为必须长期保存的原件。

输出为已持久保存的material。业务保存成功与F02后续分析完成分别判断；F02分析失败不改写采集任务已取得的资料保存事实。

### 1.3 资料接入与交付职责

F01负责来源核验、内容保真、身份去重、版本字段维护、保存及资料可用性。F02负责候选与事件业务；S01负责通用执行、可靠投递、幂等、重试和审计。公共对象及其表结构不在F01重复定义。

### 1.4 适用形态与使用者

支持自动周期采集、授权手动采集、链接或文件补录。自动与手动均一任务一信源，多选N个信源形成N个任务。管理员管理计划与任务，授权阅读者按来源权限读取资料。

## 2. 功能架构与详细清单

### 2.1 功能结构

采集计划 → 单信源信息采集任务 → 获取并标准化内容 → 保存material → 向下游提供资料。信息采集任务承接业务状态，计划触发不另建记录对象。

### 2.2 末级功能清单

原11项功能编号保留，按最新职责调整其名称和完成标准。

| 功能编号 | 功能 | 完成标准 |
| --- | --- | --- |
| F01-SF01.01 | 信源资格核验 | 启动、重试及保存前读取当前启停、范围和权限，无信源版本依赖 |
| F01-SF01.02 | 技术就绪检测 | 判断输入可获取、内容可解析；连接错误不改变M1启停 |
| F01-SF01.03 | 自动采集与授权补录 | 每次任务只处理一个信源；多选分别受理，失败不伪造成功 |
| F01-SF01.04 | 正文读取与标准化 | 保留原意、数字、表格、注释及必要附件内容，输出material内容 |
| F01-SF01.05 | 重复与修订判别 | 身份、内容摘要和规范化规则共同判断重复或内容变化 |

### 2.3 计划与任务管理

每个信源一份采集计划，计划可以暂停。周期使用时长配置，本次重建补齐40份一天周期且停用的计划；不因此改变以后新建计划默认值。每个任务只引用一个信源；自动触发按计划及计划时点去重，手动触发按命令幂等键去重。计划暂停影响后续触发，已受理任务由任务控制单独处理。

## 3. 业务对象定义

### 3.1 领域本体

业务对象及关系统一使用中文名称；数据库表名、字段标识保留英文，用于存储映射。

| 对象 | 职责 | 主责及目标存储 |
| --- | --- | --- |
| 信源 | 当前来源身份、地址、分类、启停及允许范围 | M1；F01只引用source_id，不引用配置版本或配置历史 |
| 采集计划 | 一个信源的周期与启停配置 | F01；infomation.ingestion_schedules |
| 信息采集任务 | 某信源一次自动或手动采集 | F01；infomation.ingestion_tasks |
| 资料 | 可持续引用的资料身份和当前有效内容 | F01；infomation.ingestion_material |

不把存储关系、正文片段或公共运行机制列为新的领域本体。任务信源项、原件、独立版本及四类处理记录已取消；不得通过改名为“任务资料明细”恢复同义处理记录。

### 3.2 领域属性

| 对象 | 属性 | 业务含义与规则 |
| --- | --- | --- |
| 信源引用 | 来源标识、当前资格、范围 | 当前资格在启动、重试及提交前复核；身份归M1维护 |
| 采集计划 | 信源标识、启停、周期、下次计划时点 | 一源一计划；暂停计划不改变已创建任务 |
| 信息采集任务 | 任务标识、信源、计划引用、触发方式、计划时间、发起者 | 自动、手动使用同一种对象；自动计划时点固定，人工操作不伪装为自动触发 |
| 信息采集任务 | 状态、阶段、暂停、失败原因、结果摘要 | 承接本次发现及处理结果；摘要描述失败入口等诊断，不建逐资料状态机或记录表 |
| 资料 | 资料标识、来源侧标识、标题、原始链接、来源 | 同来源稳定标识或详情链接识别身份；不同来源分别保存 |
| 资料 | 正文、表格、原始元信息、标准化规则标识 | 保留内容语义，不用摘要替代资料，不补造缺失数字 |
| 资料 | 发布时间、取得时间、更新时间 | 发布时间未知留空，不用采集时间替代；时间精度不能补造 |
| 资料 | 内容指纹、版本字段、内容定位 | 首次保存版本为1；有效内容变化递增；同内容重取不递增，正文位置随版本值校验 |
| 资料 | 必要的下游可用性结果 | 保存状态与F02业务结果分开；所需最小通知状态由资料字段及公共投递机制承接，不建交付表 |

版本字段表示当前内容版本，不承诺读取旧版正文。若下游依据的版本值与资料当前值不同，明确提示依据已变化，重新核验；不得将旧评价或旧定位默认为新内容结果。

### 3.3 领域关系

| 关系 | 基数与业务约束 |
| --- | --- |
| 信源—采集计划 | 每个信源一份计划；每份计划归一个信源，缺失计划受控补齐且不自动启用 |
| 信源—信息采集任务 | 一个信源可多次创建任务；每个任务只关联一个信源 |
| 采集计划—信息采集任务 | 一个计划产生多次自动任务；同计划同计划时点只有一个自动任务 |
| 信息采集任务—资料 | 一个任务可关联零至多份资料，资料可被不同任务复用；仅保存关联，不建立逐资料执行记录 |
| 资料—正文片段 | 可按需组织正文位置；片段是内容组成，不是独立业务资料或处理记录 |
| 资料—事件管理业务结果 | 下游以资料标识、版本值、内容摘要及位置引用；事件管理模块维护候选事件、正式事件等业务结果 |

未发现资料是成功的空发现结果，发现失败与部分失败必须有原因。任务成功需本次发现及资料处理均完成，不能因存在一份保存资料即判整项成功。不同任务复用同一资料时，累计资料数按资料身份去重，不能相加各任务计数。

## 4. 功能详细设计

### 4.1 总体流程

核验当前信源与权限 → 获取内容 → 解析与标准化 → 身份与内容比较 → 保存material → 向F02提供已保存资料。每步失败更新任务阶段与原因；不为每一步建立独立记录对象。

### 4.2 Step 1：核对信源资格与接入条件

M1为ACTIVE且权限、范围满足时才接入；DISABLED阻断新接入及后续业务提交。技术不可用单独报告，不将连接错误当作信源停用。补录仍需来源凭据及权限，不强制存在自动连接器。

### 4.3 Step 2：获取资料内容

按任务的唯一信源及允许范围读取网页、文件或结构化内容。发现零份资料不伪造material；多份资料逐份解析。输入仅供处理，不要求保存原始文件副本；无内容可用时任务记录入口和原因，按恢复条件重新获取。

### 4.4 Step 3：正文读取与资料标准化

保留正文、数字、单位、表头、注释及必要附件中的有效内容；只移除可确认的导航、广告等噪声。不平均冲突值，不把空白补零。正文截断、必需内容缺失或无法可靠识别时报告失败，不用不完整内容覆盖已有material。

通过条件为来源可核验、正文或结构化内容有效、取得时间真实及必要字段齐备。原件下载或持久原件引用不再是检查条件。标准化规则及内容摘要属于material属性。

### 4.5 Step 4：识别重复与资料版本

先按source_id限定来源，优先使用可靠外部标识，其次稳定详情链接，最后结合内容指纹与出处核对。标题或指纹相同不能单独决定身份；独立来源同文资料分别保存。

| 判断 | material处理 |
| --- | --- |
| 新资料 | 新身份，版本字段1 |
| 同资料、有效内容不变 | 复用身份与当前版本值；任务建立资料关联，不新增获取记录 |
| 同资料、有效内容变化 | 更新同一material内容并递增版本字段，记录变化原因类别 |
| 规范化规则变化但有效内容不变 | 可更新规则信息，不递增内容版本 |
| 身份冲突、比较口径不同或疑似旧内容回流 | 任务待核对，不自动覆盖较新的有效内容；必要时重新获取和比较 |

并发保存按同一资料身份加锁或条件更新，提交时复查内容摘要；相同内容不重复递增版本。无法从material当前内容验证的旧依据明确标识失效，不承诺用已取消原件重算。

### 4.6 Step 5：保存material

在事务中确认来源资格、资料身份与并发前提，更新内容、来源、时间、摘要和版本字段，建立必要任务关联。完整提交后才计入保存成功。失败不公布可读取结果；恢复以当前material和任务结果核对，不能靠重复插入新的资料身份绕过冲突。

### 4.7 Step 6：提供下游资料

F02读取material_id、版本值、内容摘要、正文或内容读取引用、来源、时间和内容位置。公共可靠投递支撑通知与去重，业务结果写回保留的任务／material必要属性，不设资料交付或资料分析独立记录。重复请求按资料及版本值幂等，资料通知失败不重新采集成功内容。通知前后校验版本，过期消息不得读取新内容后冒充旧版本分析。

### 4.8 处理状态与恢复

任务业务状态区分排队、运行、暂停、完成、部分完成、待核对、待恢复、阻断及失败；状态集合与转换以数据模型为准。逐份失败原因可在任务结果摘要中表述，不增加独立记录或持久的逐资料状态机。恢复重新核验当前资格，按有效内容幂等处理。业务复核不能由自动重试绕过。

## 5. 页面与交互组织建议

入口沿用M1。信源目录提供“任务计划”，每源一计划；信息采集任务及历史一行一项单信源任务。手动多选仅是批量创建入口，N个信源返回N个独立任务，控制与结果按任务反馈，不建立多信源父任务。

资料阅读展示material正文、表格、来源、时间及版本字段；不展示原件下载、旧版正文回放或六步进度。任务详情显示material关联和任务结果，不恢复四类记录的详情入口。权限不足、无数据、读取失败分别表达，未知数不补零。

## 6. 跨模块协作与交接契约

### 6.1 协作矩阵

| 协作方 | F01引用或提供 | 主责边界 |
| --- | --- | --- |
| M1 | 当前来源身份、启停、范围 | M1维护当前档案，无配置版本或配置内容历史 |
| S01 | 请求通用执行、幂等、重试、审计，接收技术执行事实 | F01解释业务结果；公共对象与字段仅在主责文档定义 |
| F02 | 已保存material及版本值、摘要与位置 | F02维护候选和事件业务，不另建被取消的资料分析记录 |

### 6.2 输出与交付约束

material完整保存且权限允许后可供下游读取。读取及消费须核对资料标识、当前版本值和内容摘要；变化后需重新核验旧依据。内容引用不扩大权限，异常摘要不泄露凭据或受限正文。公共能力详见[[tools/RiskHot/docs/system-design/03-系统功能架构/S01 公共运行能力功能设计|S01功能设计]]。

## 7. 核心业务规则

一源一计划、一任务一信源；自动与手动共用任务对象；触发记录合并到任务。material只保存当前资料，版本用字段；不保存独立原件。重复不递增版本，不同信源不混合资料身份。取消四类记录不得借改名或移到公共层恢复。任务、计划与material归F01；业务表统一使用infomation schema。

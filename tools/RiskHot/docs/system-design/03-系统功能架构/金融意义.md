本文独立存放金融意义评价与金融用途分类的功能设计，2026-10-31 从[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0#4.7 Step 6：知识增强与业务评价|F02 原 Step 6]]迁入。原 §4.7.1～§4.7.7 对应本文第1～7节，涵盖职责、触发、输入、处理、异常、输出验收及金融用途分类。

本次为文档拆分，保留既有业务规则、功能编号和流程交接；不据此新设模块编号或变更运行归属。本文 Step 编号沿用[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0#4.1 总体流程|F02 业务流程]]：承接 Step 4/5 的事实、变量及对象关联结果，评价或跳过结果交[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0#4.8 Step 7：事件结果保存|Step 7 保存与交付]]。量化规则、任务资产、机器契约及运行接入的待完成状态按正文保留。

## 1. 功能目标与职责

**主要职责：基于已确认的事件事实、变量与直接关系，按适用规则形成金融意义评价和独立的金融用途分类，为研究排序、结果阅读及后续业务使用提供有证据的评价结果。** 对应 F02-SF03.01、F02-SF03.02。

本功能回答三个业务问题，各自产出如下：

| 职责 | 要回答的问题 | 形成的结果 |
| --- | --- | --- |
| 确定本次评价范围与模式 | 当前事件应初评、复评、沿用还是跳过？采用哪个观察范围、研究期限和有效方法？ | 评价触发依据、固定上下文与模式，或跳过、待处理及失败原因 |
| 形成金融意义评价 | 在给定范围和期限内，事件的五维依据与分数是什么，金融研究重要性如何？ | 经校验的五维结果、程序计算的总分 M、证据与限制，以及待保存的 EventRating；文字草案保留空分 |
| 独立形成金融用途分类 | 事件适用于哪些投资、融资、投机／情绪观察用途，各有什么依据？ | 独立用途标签、分类依据与状态；不参与 M 计算，不表示交易建议 |

**与前后步骤的分工**：Step 4 提供初始事实或增量，Step 5 提供适用变量与直接关系。本步由程序固定事实、范围、期限与方法，校验五维结果并计算 M；金融意义评价任务只匹配给定规则、返回逐维依据与分数，不制定规则、不改变上下文、不计算正式 M 或决定审批状态。其新 AI 编号仍待定，不占用 AI-05。授权人工复核证据与评分歧义，方法批准归 M3；人工不能替代缺失规则、虚构证据或绕过程序重验。用途由独立分类任务形成，程序校验、授权人工处理歧义，缺失或失败不阻断已满足条件的评分。Step 7 统一校验保存，本步不补造事实、不扩展未经授权的外部获取，也不推断风险等级、风险方向、行情涨跌或收益概率。

**执行位置**：在 Step 5 完成适用范围核对后、Step 7 保存前，分别判定评价与用途分类的执行条件；结果或合法跳过依据交 Step 7，待处理项按既有受限保存规则处理。用途允许在事件保存后独立补做，核对当前事实后补充保存与交付；其任务编号、机器契约及运行接入仍待落实，历史用途记录继续保留追溯。评价动作见 [[tools/RiskHot/docs/system-design/03-系统功能架构/金融意义#4. 核心处理规则|核心处理规则]]，用途规则见 [[tools/RiskHot/docs/system-design/03-系统功能架构/金融意义#7. 金融用途分类|金融用途分类]]。

## 2. 触发条件

程序依据 Step 4 已校验的增量结果、当前事件事实及已有评价判定，并记录命中规则、变化依据和初评/复评/跳过原因。“满足评价条件”指事件归属明确、评价上下文及证据可用，且所选模式满足 [[tools/RiskHot/docs/system-design/03-系统功能架构/金融意义#3. 输入要求|输入要求]]与[[tools/RiskHot/docs/system-design/03-系统功能架构/金融意义#4. 核心处理规则|核心处理规则]] 的条件。

| 事件情况                | 处理规则                                                  |
| ------------------- | ----------------------------------------------------- |
| Step 3=NEW 且初始事实已确认 | 满足评价条件时执行初评；条件不齐进入对应待处理状态，不以默认分数完成初评                  |
| `EVENT_PROGRESS`    | 变化影响一个或多个维度的评分依据时触发复评；未影响时记录原因并沿用适用评价                 |
| `MATERIAL_ADDITION` | 新增重要事实改变评分依据或补足原有关键缺口时复评；没有既有评价时按初评处理                 |
| `CORRECTION`        | 纠正内容影响已有评分事实、证据或规则匹配时复评；保留被纠正评价与依据，标明其当前适用性           |
| `SOURCE_ADDITION`   | 仅来源增加且评分依据未变时跳过；若发现实质补充或纠正，应回 Step 4 核定增量，不继续按纯来源增加处理 |
| `DUPLICATE`         | 跳过，复用已有处理结果，不调用金融意义评价任务、不创建重复评级                       |
| `UNRESOLVED`        | 待完成事件归组并重新核定增量后再判定；不以归属不明的事实评价正式 Event                |

同一轮包含多种变化时，应检查所有影响评分的有效变化，不能以“包含重复或来源增加”覆盖实质进展或纠正。决定沿用时必须定位同一 Event、同一范围、研究期限及方法下仍适用的评价；无适用评价则记录“未评价/不适用”及原因，不能虚称沿用。

补齐输入或证据后重新判定评价条件；可比旧评价存在时执行复评，否则执行初评。范围、研究期限或方法变化属于独立评价请求，须记录请求与授权依据，不能覆盖原口径结果，也不因方法发布自动重算历史。仅同范围、同期限、同方法的结果允许直接比较分值变化。

## 3. 输入要求

程序在调用金融意义评价任务前固定本次输入，确保每项引用可读、版本确定且属于本事件。输入准备不提前创建正式 Event 或改写 F01 资料内容。

| 输入                | 必须明确的内容                                                         | 缺失或不合格时处理                                                                                  |
| ----------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 当前 Event          | 唯一事件或已明确的新事件归组建议、当前事实、阶段、适用范围；新事件的正式身份在保存与交付环节落实                | 归属歧义回 Step 3；不得为了评分创建空事件                                                                   |
| 有效 Fact 与增量       | 本次采用的候选事实、归属依据、增量类型、相对既有事实的具体变化；纠正时同时保留旧依据                      | 待补齐/复核；未确认事实不得作为确定评分依据                                                                     |
| Target 与 Variable | 关联观测对象、有效变量定义、直接关系及方向、定义版本和支撑 Fact                              | 区分“经核对无适用关系”和“尚未识别/定义缺失”；后者按缺口分别交 Step 3（Target 身份）、Step 5（变量关系）或 M2 补齐；不得用 Subject 代替 Target |
| 评价范围与研究期限         | 固定的 assessment_scope、研究期限及其业务含义                                 | 缺失时不调用金融意义评价任务；AI 不得自行扩展辖区或补造期限                                                            |
| 评分方法与版本           | method_version、适用范围、批准及有效状态、五维定义、逐维评分锚点和允许分值、权重/公式、M 范围及精度/舍入规则 | 正式评分模式下缺项、未批准或失效均不得计算；文字草案模式也须固定独立方法版本                                                     |
| 证据资料              | 已保存的 material、material版本值、原文位置与可读内容，及证据与 Fact/维度的对应关系           | 不可读交 F01 恢复；错误事件、错误版本或虚构定位不得进入评分                                                           |
| 既有评价与本次请求         | 已有时提供同口径 EventRating、采用事实及历史依据；明确初评/复评原因、模式和适用复核要求              | 无可比历史可初评，但不得编造前值；不得将不同口径评价用于直接分值比较                                                         |

关系经核对为空时，仅在有效评分方法明确允许且五维仍有充分依据的情况下正式评分；否则等待补齐。允许保留关系缺口不等于满足评分条件。证据不足、无法判断与最低分是不同结果，不能默认以 0 分代替缺失。

## 4. 核心处理规则

**处理顺序**：判定模式 → 逐维处理 → 校验 → 程序计算 M → 整理交接。

五维含义继承[[tools/RiskHot/docs/system-design/02-业务架构与领域设计/RiskHot_L0_信息处理层_业务架构与领域设计V1.0#3.6 金融意义 M 及金融用途|L0 五维框架]]。维度选择按本节明确，具体权重、量化锚点与公式须另经批准；领域文档中的候选数值不因本次功能设计补全而生效。

| 维度       | 金融意义评价任务提取与判断内容               | 评分约束                       |
| -------- | ----------------------------- | -------------------------- |
| B：底层变量关联 | 与货币、信用、财政、供需等基础约束的直接联系及有效变量依据 | 区分直接关联与推测传导，按本次方法的关联标准匹配   |
| D：影响程度   | 对观测对象的作用程度、数量变化、比较基准及必要的规模分母  | 绝对金额不直接等于高影响；缺少规则所需基准时标明不足 |
| T：持续时间   | 事件时点、工具/合同期限、实施期限与经济影响持续时间    | 不把工具到期日直接等同于经济影响终点         |
| W：影响范围   | 有依据的市场、辖区、部门、主体或金融环节覆盖范围      | 区分直接覆盖与可能外溢，不把局部事项扩为全市场影响  |
| L：作用落地   | 预计、宣布、实施、生效、完成、取消及已观察效果的证据    | 行动完成不等于经济效果已实现，按评分锚点判断     |

### ① 程序判定与准备

依 [[tools/RiskHot/docs/system-design/03-系统功能架构/金融意义#2. 触发条件|触发条件]] 决定执行或跳过；检查模式和输入，固定事实、证据与方法。

- 正式评分规则未批准时返回“待评分规则”；仅明确选择文字草案模式时，才进入定性分析。

**本步输出**：执行、跳过或待规则的决定与评价模式。

### ② 金融意义评价任务逐维处理

每维返回维度标识、事实依据、匹配的评分条款/锚点、分数、评分理由、证据引用及限制。

- 正式评分须覆盖五维且各出现一次；无依据或无法匹配标准时明确返回缺口，不猜分、不生成总分。

**本步输出**：五维评分建议、依据、理由及缺口。

### ③ 程序校验

核对 Event、Fact、范围、期限、方法和输入一致；检查五维完整且无重复、分值类型/范围/精度符合规则、评分条款属于固定方法、引用属于本事件固定资料版本且可定位。

- 证据是否足以支撑规则匹配存在争议时进入复核，结构校验通过不等于语义正确。

**本步输出**：校验结果及待复核争议。

### ④ 程序计算 M

仅在规则已批准且有效、五维全部合格、证据充分时，按已批准方法版本的权重/公式与舍入规则计算；记录采用的维度分数、规则及结果，校验 M 的允许范围。

- 不得临时补权重、将缺维当 0、对剩余维度重新归一化或直接采用 AI 返回的总分。
- 计算失败、规则缺项或复算不一致均停止交接。

**本步输出**：程序计算的 M 或阻断交接的问题。

### ⑤ 程序整理与交接

将评分、理由、证据、范围、期限、方法、模式及限制整理为待确认的 EventRating，复评关联旧评价并说明变化原因。

- 交保存与交付环节再核对上下文及授权后保存；保存前依据变化时，重判受影响步骤，原结果不得直接提交。
- 相同请求重试复用已完成结果，不新增重复评级。

**本步输出**：待保存的 EventRating、复评关联及限制。

### 文字草案模式的单独处理

保留为独立定性模式，必须明确标识“文字草案/未量化”，固定草案方法版本；五维逐项给出有依据的文字判断，缺证据的维度明确写“依据不足”，不伪造引用。

- 维度分数与 M 全部为空，空分原因单独记录。
- 草案不进入正式评分排序、阈值判定或分值涨跌比较。
- 正式评分失败不得静默降级成成功草案；需改用草案模式时另记录处理决定，并保留原失败记录。
- 规则批准后仍须重新执行正式评分，不能只修改草案状态使其成为正式评级。

**本模式输出**：五维文字判断、空分原因及适用限制。

## 5. 异常处理

下表为业务状态语义，具体存储枚举由技术设计映射。部分结果只能作为过程记录或明确标识的草案保留；不能据此生成正式 M，或将本步标记为评分成功。

| 情况                                 | 本步业务状态与处理          | 可保留内容                            | 恢复、复评或复核方式                                      |
| ---------------------------------- | ------------------ | -------------------------------- | ----------------------------------------------- |
| Event 归属不明、有效 Fact 不足、范围/期限等关键输入缺失 | 待补齐输入或待归组；不调用正式评分  | 输入快照、缺口清单与已有合法事实                 | F02 返回对应步骤，定义问题交 M2；补齐后重新判定触发                   |
| 规则未批准、失效或缺少评分锚点/计算规则               | 待评分规则；不得执行正式评分     | 已有事实和证据；明确选择文字草案模式后可保留草案         | M3 完成方法治理后准备新请求；不得默认采用候选规则                      |
| 部分维度证据不足或资料不可读                     | 待补充证据；不能计算 M       | 已核对的文字依据、可用证据及不足维度；已有分数仅作未接纳过程结果 | 内容不可读交 F01 恢复，事实缺口由 F02 补充；新证据到位后重评受影响维度并重验完整五维 |
| 事实矛盾、评分锚点匹配有歧义                     | 待业务复核              | 冲突证据、候选判断及争议原因                   | 授权人工说明采信与修正依据；程序核定新输入后重新分析/校验，不能凭人工结论绕过有效规则     |
| 模型超时、调用失败、响应截断或无法解析                | 待执行恢复；保留失败状态       | 运行记录、错误原因及原响应工件；可解析片段不作为有效评级     | 由 S01 按运行策略恢复；输入未变可重试原请求，已变须重新准备，不自动清除失败记录      |
| 漏维/重复维度、越界分数、错方法/范围/期限、虚构或跨事件证据    | 待结果修正或复核；拒绝接纳评分    | 原响应、逐项校验错误和合法证据                  | 固定正确上下文后重试；持续不合法交授权复核，不截断分值、不补默认分               |
| 计算失败、M 越界、同输入复算不一致                 | 待计算恢复或规则复核；不输出有效 M | 已通过校验的维度、固定规则及计算失败记录             | 修复计算或规则问题后复算；规则变更时重新核对维度评分，不必无条件重跑所有 AI 分析      |
| 评分后事实/归属/定义变化，或提交授权失效              | 待重新校验或复评；原结果不可直接提交 | 原评价建议、变化依据及历史评价                  | 返回受影响步骤，重新固定输入；按既有授权流程取得有效决定后交保存与交付环节           |

复评未完成时，保留旧评价作为历史，并显示“当前待重新评价”及原因；旧分数不能冒充已覆盖本次变化的新结论。评分等待不回滚已保存 Fact，也不阻断其他事件的独立处理。保存与交付环节如允许提交本事件其他已核定结果，须明确记录本次评价未完成，且不得交付“评级已更新”的成功结果。

## 6. 输出与验收标准

| 结果类型        | 必须包含的业务内容                                                                                  | 交接与使用要求                                                |
| ----------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 五维评分已计算、待确认 | 当前 Event/新事件归组依据、采用的 Fact、五维分数、各维评分条款与理由、逐维证据引用、评价范围、研究期限、有效方法版本、程序计算的 M、限制、初评/复评原因及适用历史引用 | 交保存与交付环节校验并确认保存后形成正式评价；AI 原响应和计算记录可追溯                  |
| 文字草案        | 同一事件与事实依据、五维文字分析/缺口、可核查证据、范围、期限、草案方法版本、模式、限制与空分原因；所有维度分数及 M 为空                             | 按草案确认保存，不作为正式量化结果；后续量化须重新评分                            |
| 跳过/沿用       | 增量类型、判定依据、跳过原因；沿用时包含仍适用的旧评价引用                                                              | 不调用金融意义评价任务、不新建 EventRating；适用事实与来源变化仍交保存与交付环节的保存与交付阶段 |
| 待处理/失败      | 所处步骤、具体原因、缺失或不合法项、已保留部分结果、处理责任及恢复位置                                                        | 不声称完成评价；恢复状态与历史成功评价分开记录                                |

正常评分必须满足“五维齐全、逐维有据、规则有效、口径固定、程序可复算、历史可追溯”六项条件。验收同时检查结果内容、是否调用 AI、是否计算 M、是否新增评级，以及保存与交付环节保存前后的状态区别；具体可执行场景见[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0#7. 功能验收要求|F02 功能验收标准]]中的 AC-F02-14～15、AC-F02-36～38 及 AC-F02-47～59。验收用批准规则夹具验证计算，不将测试规则或 L0 候选权重作为正式发布方法。

## 7. 金融用途分类

对应 F02-SF03.02，与金融意义评分分别执行，不占用 AI-05（事件变量提取），不把用途标签作为 M 的分值依据。采用已发布的用途分类规则；投资、融资、投机／情绪观察等标签允许多选，但不代表交易建议。

| 项目    | 处理规则                                                                                 |
| ----- | ------------------------------------------------------------------------------------ |
| 触发    | 事件身份方向明确且本次获准范围内的事实与适用变量核对完成后，新增事件或事实变化影响分类依据时执行；没有既有结果时可独立补做；来源增加或纯重复且分类依据未变时沿用有效结果 |
| 输入    | 本次事件事实、支撑 Fact、适用变量及增量结果、分类规则及版本、已有分类和采用依据；不得以 M 的高低直接推导用途                           |
| 执行    | 程序固定输入，由独立分类任务给出标签、逐项理由和 Fact 引用；程序校验规则、证据归属及输入版本，语义争议交授权人工复核                        |
| 结果    | 保留所属事件、用途标签、逐项依据、规则版本、采用事实、限制和分类状态；区分已分类、经判断无适用用途、证据不足待判断、待规则及执行失败                   |
| 保存    | 已通过校验的结果随本次事件提交独立记录，不塞入新 EventRating 的必填属性；分类晚于事件保存完成时，核对当前事实后以补充提交保存，保留旧分类及其适用性     |
| 查询与交付 | 事件详情独立展示当前用途及依据、历史和待处理原因；已保存的新增或纠正分类形成用途变化交付，引用原 Event，不重建事件或重算 M；沿用无变化不重复通知         |
| 缺口与失败 | 规则未发布时待规则，证据不足时待补齐，调用失败由 S01 恢复原分类任务；上述状态不阻断已满足条件的评分和事件保存，但交付必须说明用途未完成               |

事实或规则变化使旧分类不再适用时，先标为待重新分类；新分类未完成不得将旧标签当作本次已确认结论。规则发布或版本变化不静默覆盖历史，程序按显式分类请求重新执行。任务尚未接入时记录待执行，不显示为已分类。

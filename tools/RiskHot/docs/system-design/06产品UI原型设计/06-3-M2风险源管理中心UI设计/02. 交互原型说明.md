# M2 风险源管理中心 · 交互原型说明

[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-3-M2风险源管理中心UI设计/M2风险源管理中心交互原型.html|打开原型]]。直接用浏览器打开，无需服务端；保留同级“原型资源”，图标、样式和脚本均本地加载。

## 体验步骤

1. 在“风险源目录”查询八类宏观基线，正式风险源默认可用，无启用／停用操作、状态标识和状态筛选；点击条目查看定义、核心问题、同层父分类及边界。首次打开直接显示八类风险源，系统预置，无需用户初始化。四类风险类型同样直接预置且默认可用，无启停标识或使用状态筛选，列表及详情保留版本；旧状态筛选不再限制查询，修订与历史版本保持可用。
2. 切换“全局变量库”，变量详情显示对应字段标签：逻辑字段、后端数据、原型扩展或界面计算；标签不代表全部已定版物理表字段。按 Active／Deprecated 筛选；别名、定义、范围都可搜索。未分类的定性变量仍能查询，废弃变量保留替代说明与历史。
3. 点击“进入候选审核”打开列表，支持名称搜索、审核状态及提议来源筛选；默认待核对、每页20条，可选50／100条。点击行内“审核”打开详情抽屉，去掉横向候选按钮；关闭按钮、Esc或点击外侧关闭后，列表条件、页码和滚动保留。抽屉单栏展示候选资料，不提供已有相似变量、双栏比较或差异提示。“美元资金可得性”命中已有别名时阻止新建，可以退回或暂缓。未提交输入按候选保留。
4. 候选可新建、退回、暂缓或拒绝。新建须先逐项审核，再统一确认变量及通过配置。退回／暂缓／拒绝不建档；入库前可重新审核，处理后只读。处理结果更新列表，抽屉支持按当前筛选审核下一项。
5. 在“全局变量库”选择变量，切换详情的“观测指标”，点击关联指标的“查看与维护”，查看统计对象、范围、单位、频率、时间规则、允许来源与逐条映射解释。“居民消费价格指数”展示一指标映射两个变量，以及允许来源停用的独立缺口；不是实时数值或风险评分页。
6. 风险源和风险类型点击“新增定义”使用弹框录入；可保存草稿或校验后提交审核。取消、关闭、Esc或点击遮罩可关闭，背景目录和筛选保留，焦点回到新增按钮；校验失败保留弹框与输入。手机弹框表单单列，底部操作保持可达。从定义详情选择“修订定义”，保存草稿或校验并提交审核；顶部“修订审核”可重新查看当前定义与提议差异，当前生效定义不被覆盖。变量主要从AI分析进入候选，本页没有手动新增变量按钮；审核可接受候选为新变量。
7. 首版移除“使用关系”标签及独立变更影响查询。定义详情仅保留“定义与边界”“历史版本”；维护反馈仍可从详情底部进入。
8. 在“历史版本”选择 v0.9 查看演示旧定义；当前版本保持不变。维护反馈按缺口类型记录建议主责方，本原型不会真的发往其他模块。
9. 在手机宽度体验单列目录与详情、候选资料及审核。保存失败校验保留表单输入；返回目录保留筛选。详情选择在窄屏会定位到详情区域。

## 示例与未接入范围

- 初始 8 个风险源、5 个演示正式变量（4 Active、1 Deprecated）、3 个指标、4 个风险类型、3 个候选。身份以 DEMO 开头；候选没有正式 variable_id。
- 所有正式变量／指标、数量、引用与历史为演示夹具；风险源和类型的详细定义也是 UI 文案示例，不代表已批准的生产配置。
- 原型在当前页内存保存。刷新恢复基线，未使用数据库或自动外网请求。聊天版的宿主设计调节不是保存版必需依赖；保存版默认紧凑密度。
- 页面提供变量身份与逐项观测结论模拟、新指标定义独立确认、草稿与差异查看、维护反馈；没有真实审批权限、版本冲突处理、原子发布、变量拆分合并执行、在途阻断或跨模块接口。
- 候选首次观测方案支持本地演示审批、来源选择与映射生效，正式指标详情可查看获批关系；变量详情支持共享定义、允许来源和当前映射的维护提议；真实发布及 M1 查询未接入；“缺口反馈”只形成演示维护记录，不发送消息。不能将本地交互检查当作后端验收。

## 首次观测配置体验

1. 核对候选资料后，直接审核下方指标，无需先分配变量身份。选择“接受为新变量”后，底部显示“确认变量及观测指标”。
2. 查看美元融资利差的定义与口径、适用解释、范围、局限、来源及缺口，点击“审核通过”，在该行展开的表单填写理由并勾选本项核对，点击“确认通过”；其余建议仍待审核。点击“审核不通过”也须填写理由后提交。
3. 新调查指标先审核定义与来源，再审核本候选适用关系，结论暂存在候选内，不提前创建指标。来源停用、版本变化或定义不完整阻止通过。
4. 指标仅通过／不通过；尚未提交的项目不能统一新建，可关闭后按“部分审核”筛选继续处理。各项均通过／不通过且至少一项通过后统一提交，最终版本、来源或查重失败不部分入库。
5. “美元资金可得性”命中已有别名，不允许重复新建，可退回或暂缓。“政策沟通一致性”先通过事件证据再统一入库，不强配量化指标。空方案或全不通过提示缺口并阻止新建。

所有新增身份、来源、审核人员、材料版本及关系均为演示数据，刷新恢复基线；没有真实 AI 调用、数据采集或后台发布。


## AI 观测指标审核与统一入库（2026-10-15）

变量详情中的按钮统一称为“添加观测指标”，弹框和维护记录使用同一名称；仍从已有正式指标中选择，形成待审关联建议，不复制共享定义，也不自动批准映射。

候选抽屉统一展示“AI 观测指标审核”，事件证据通过行类型区分。五列包括指标／事件证据、定义与口径、为什么适用、数据来源与待解决问题、审核；完整定义、时间规则和引用材料可行内展开。待核对候选无需正式身份即可审核，每项通过／不通过均须理由，通过还须勾选核对。新指标先在候选内审核定义与允许来源，再审核适用关系，不提前建立共享指标或正式映射。指标审核只保留“审核通过／审核不通过”，不提供暂缓、退回、更多处理或独立重新审核按钮；新定义核对入口位于数据来源列。各项均通过或不通过且至少一项通过后，点击“确认变量及观测指标”，重新校验版本、来源和重复项，一次入库变量及通过配置；失败不部分生效。空方案和全不通过保留缺口并阻止新建；事件证据通过也可入库。入库前可通过同一组通过／不通过按钮重审并保留历史，候选处理后只读。关闭重开保留输入及候选内结论，手机按卡片显示。业务依据见主功能文档 §4.3.3 审核-01～08。

正式流程由 AI 随候选提出观测方案；指标可以复用已有定义，无法复用时提出新定义建议。当前原型显示预置演示数据，未连接真实 AI 服务，界面对此明确标注。

## 候选审核文案说明（2026-10-14）

2026-10-15 已移除“已有相似变量”选择框、对照栏及语义差异提示，候选资料采用单栏。AI 建议表格顶部显示：“确认用哪些指标或事件证据，判断这个变量的状态和变化。”

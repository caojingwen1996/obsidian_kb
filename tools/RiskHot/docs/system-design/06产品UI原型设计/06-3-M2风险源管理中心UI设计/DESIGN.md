# M2 视觉与组件规范

本设计依据 [[tools/RiskHot/docs/system-design/03-系统功能架构/M2风险源管理中心功能设计|M2 功能设计]]，延续 [[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/DESIGN|M1 工作台]]。2026-10-14 按用户要求移出使用关系功能，其他视觉和业务边界沿用已有方案。

## 色彩与排版

- 背景 `#f5f5ef`；纸面 `#fffef8`；正文 `#233b34`；次级文字 `#647067`；分隔 `#dfe4d8`。
- 主操作 `#295c47`；选中背景 `#f0f4e7`；侧栏 `#edf0e6`；警告 `#856019`；错误 `#a1392c`。
- 深色模式使用对应的深绿纸面和高对比文字。颜色与文字共同表达状态，不给四类风险类型配置严重度颜色。
- 字体沿用 PingFang SC / Microsoft YaHei，正文 14px，标签 12–13px，页面标题 24px；编码使用等宽字体。
- 4/8/12/16/24/32px 间距；5–9px 圆角；以细分隔、轻背景区分层级，避免概览图表和装饰统计卡占据治理空间。
- 默认紧凑布局；提供舒展密度的设计调节。主按钮每个动作区一个；停用、废弃不使用快速开关。


保存版使用紧凑密度。会话中的宿主密度调节不是独立 HTML 的运行依赖。截图以保存版实际布局为准。

## 页面构成

侧栏展示四阶段及三支撑中心，M2 为当前模块；四类定义采用同级标签页。页内包含目录操作、共享搜索筛选工具区、列表与详情。新增定义采用居中弹框，背景目录保留；全局变量下分为正式变量与候选审核列表；正式变量和候选审核区域均去掉重复的区块标题及说明，变量由AI分析流程提出候选，不提供手动提议新变量按钮；候选用表格展示，点击行内审核打开右侧详情抽屉，背景列表保留；修订仍使用完整工作区。风险源和风险类型直接预置，不显示初始化按钮。只显示定义数与待处理候选数，不添加实时风险评级图表。

## 组件状态

- 目录条目：中性色分隔；选中使用浅绿纸面与左侧绿线，名称为主，核心问题／范围为辅。
- 状态：风险源默认可用且不显示启停；变量生命周期、其他配置启停和修订待审分别标注；风险类型不使用严重度颜色。
- 定义详情：身份、版本、定义／历史内容分组；编码可换行，避免窄屏截断。
- 候选审核列表：名称、来源、适用范围、提交时间（Asia/Shanghai）、审核状态与审核／查看操作；名称搜索、状态及来源筛选；默认待核对，每页20条，可选50／100条，按提交时间倒序，筛选变化回到首页。手机为带字段标签的纵向列表。
- 候选详情抽屉：桌面右侧展开、手机全屏；标题和底部动作固定，内容独立滚动，无横向候选按钮。关闭后恢复候选列表筛选、页码、滚动与审核行焦点；当前行不再显示时恢复搜索框焦点。关闭保留未提交输入，更换对照项需重新确认；记录结论后可按当前搜索／筛选范围审核下一项。
- 候选对照：等宽双栏；差异提示使用琥珀色并配文字；正式身份未确认时显示“尚未分配”。
- 新增弹框：原生dialog，桌面最大宽度760px，标题和底部操作固定、表单内容可滚动；手机距屏幕边缘10px并单列排布。支持取消、关闭按钮、Esc和遮罩关闭，焦点恢复到新增按钮。
- 表单：原生标签、输入和按钮；必填项有文字提示，错误区具备 alert 语义；拒绝与退回需要明确依据。
- 首版范围：移除使用关系标签、引用数量和独立变更影响查询；历史版本及现有指标映射保留。
- 操作：一个动作区内仅一个主按钮；状态变化通过受控申请，不使用直接启停开关。

## 响应式与可访问性

900px 以上为侧栏＋列表与详情；900px 以下列表和详情上下排列；600px 以下收起侧栏并使用单列对照／表单。手机保留所有定义入口和必要动作，点击列表项可定位详情。支持原生键盘导航及可见焦点，状态不只依赖颜色；所有背景和正文支持浅／深色配对。

## 变量详情字段标记

变量详情的八项信息直接显示字段标签，标签描述当前原型映射和依据状态，不修改真实数据结构：

| 页面信息 | 标签字段名 | 标签类别 |
| --- | --- | --- |
| 定义 | `definition` | 逻辑字段 |
| 适用范围 | `range` | 原型扩展 |
| 观察粒度 | `grain` | 原型扩展 |
| 别名 | `alias` | 原型扩展 |
| 可选标签 | `tags` | 原型扩展 |
| 观测依据 | `evidence` | 原型扩展 |
| 分类与语义边界 | `boundary` | 后端数据 |
| 观测方式 | 无独立字段 | 界面计算 |

`definition` 对应 [[tools/RiskHot/docs/system-design/02-业务架构与领域设计/RiskHot_L0_信息处理层_业务架构与领域设计V1.0|L0 §4.5.5 变量字典]]的逻辑字段；`boundary` 在 [[tools/RiskHot/packages/domains/reference/index.ts|现有后端变量数据校验]]中使用。现有数据库采用JSONB数据载体，标签不宣称这些名称都是独立物理列。

“原型扩展”表示业务信息要求存在，但正式存储结构尚未定版；“界面计算”表示根据观察粒度拼接显示，不虚构独立字段名。标签只用于当前变量详情，其他目录、候选审核与弹框保持已有交互。


## 首次观测配置审核（2026-10-14）

候选列表分别显示“变量身份”和“观测方案”，增加观测状态筛选；查询已确认身份的待补方案时，将变量身份筛选为全部，再按待确认／部分确认查询。仍采用搜索、来源筛选、20／50／100条分页和行内抽屉，不恢复横向候选按钮。

抽屉内提供“1 · 变量身份”“2 · 观测方案”两个步骤。第一步比较语义并确认身份；第二步展示 AI 建议的已有指标、新指标或事件证据及解释、适用范围、局限、来源和材料版本。身份通过后自动进入观测步骤，身份未确认时可以查看建议，但不能批准。关闭、切换步骤或再次打开保留各项未提交输入。

观测建议逐项确认、暂缓、退回或拒绝，各项理由与结果独立记录。修改解释、范围、局限或新指标定义／来源须重新勾选确认。新指标先确认统计定义与允许来源，取得演示指标身份后仍须单独确认映射；复用变量沿用已有配置，额外建议不自动生效。部分通过只生效获批项；仍有待补项显示“部分确认”，全部处理完但有拒绝项显示“部分生效”；暂缓／退回保留缺口，列表可继续审核。定性事件方案不生成量化指标。确认结果保留操作者、时间、材料和定义／关系版本；配置获批不代表数据已接入。

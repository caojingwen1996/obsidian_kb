## Schema及待定项的表达

- 原通用 `analysis/evidence_refs/uncertainty/result_status` 对象已由逐任务字段草案替换。这里的Schema是已命名逻辑字段的 `$defs` 片段，未设置未定的顶层对象／数组包装，不可直接充当完整运行校验协议。
- 字段语义和来源沿用文档，已明确的字符串、数组、数值范围和可空要求据逻辑模型表达。文档没有明确的任务级类型、必填集合、序列化和引用嵌套不擅自补齐；不把数据库非空约束当作AI任务返回约束。
- 未命名业务项保留在 `x-business-items`，不发明technical_field_name。文档待定状态和任务待定说明进入字段标记及“待定事项”；`x-`信息为说明注解，标准Schema校验器不会据此执行语义校验。
- 候选枚举保留为 `x-candidate-values`，未锁定为正式枚举。L0已有event_status与L1已有四类variable_role按文档列示。
- AI-01不让候选生成event_id；集合包装、初步观测主体及证据定位结构标为待定。
- AI-02与AI-L1-02的匹配身份仍为待包装业务项，不发明matched_event_id或matched_risk_id。
- L1 `damage_targets` 是字符串集合；`key_variables` 严格五字段，候选观测方案单独保留；evidence_refs不补造内部字段。
- L2来源／应对／损害结果保留变量明细与业务摘要的区别；当前状态只有四个维度及status_summary，affected_scope为TEXT；不新增可信度或realization_degree。方向／持续性／节点使用已有change_reason的内容分工，不创造子字段。
- L3的sections是逻辑组合而非确定物理字段；ReportSection及ReportRiskItem只展示各自字段片段，不推定items等未讨论嵌套键，也不推定comparisonSnapshotId的正式可空性。

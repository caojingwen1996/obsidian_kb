## 业务边界

依据 [[tools/RiskHot/docs/system-design/03-系统功能架构/M3策略管理中心功能设计|M3 功能设计]]，M3 管理处理蓝图、AI 分析定义及版本评估。领域规则来源于 L0～L3；正式 Event、MonitoredRisk、RiskSnapshot、RiskAnalysisResult、RiskReport 由业务模块拥有。画布中的“保存业务结果”表示交由业务模块执行，不是 M3 直接写事实。

系统参与角色只有系统管理员、授权阅读者。审核和维护是操作职责，不新增“审核员”等角色。原型管理员具备全部演示权限；正式实现按动作和对象范围授权。读者仅浏览授权内容，不能修改、审核、生效或发起评估。

## P01 策略目录与创建

侧栏“流水线全景”固定展示RiskHot整个系统的业务流程，授权阅读者和管理员均只读。页面不提供流水线选择、版本、完整性检查及返回目录工具；使用侧栏切换工作区。六条策略及其历史版本仍由C01目录进入详情，依据角色与草稿状态控制编辑；目录筛选保持。

目录字段：名称、稳定编码、业务层、主责模块、当前生效版本、最新版本状态、关联 AI 任务数、最近评估摘要、修改时间。当前原型小样本不分页；原型目录默认按业务层L0→L3、主责模块、稳定编码升序排列；正式分页规模及服务端筛选契约由实现阶段确认。

筛选支持关键字、业务层、主责模块、版本状态及版本字符串。状态条件匹配任一版本，列表状态展示最新版本，因此筛选“已停用”仍可能展示该策略的最新草稿；正式实现应在命中版本旁增加提示，避免歧义。筛选为空提供清空入口。返回目录保留筛选。

新建字段：名称、唯一编码、业务层、模块、业务场景和目标。编码转大写并查重；业务层与模块需匹配。新建得到 V0.1 草稿，不获得生效资格。复制以当前查看版本为基础，必须使用新稳定编码；原版本和固定依赖保持不变。首批六条策略编码沿用功能文档建议，并非正式注册表。

原型新建提供最小骨架，其“待引用领域规则”会触发校验阻断。管理员应配置流程和正式规则后再提交。六个已有场景已分别依据总览及L0～L3业务图整理，源码资料定义在flow-data.js。节点职责、章节、分支与待定项可追溯；仍不是实际运行DSL或生产编排。

## P02 策略详情与流水线

详情按基本信息与适用范围、流水线编排、规则与AI Task引用、版本治理与生效排列。默认打开核心编排；顶部保留版本选择、复制与保存草稿/创建新修订，提交审核、生效、停用和退回集中在治理分区。四项导航在窄屏按原顺序两列排列。该调整只改变展示分组与动作到达路径，状态和权限条件保持。

流水线采用左侧流程全景、右侧节点详解，系统全景默认选中F01来源资格、接入与版本保存，L2状态详情默认选中“结果结构及引用有效？”。右侧阅读区展示执行主体、输入输出、模型调用与成本来源、分支出口及规则说明；流向中的目标名称可点击切换。节点配置默认收起，展开后编辑，切换节点时保留展开状态。配色保持不变，条件分支与逻辑并行分组明确区分。

AI 节点的标题与摘要下方内嵌 C02 五标签：任务定义、Prompt / Skill、输入输出、工具与约束、引用与版本。默认打开任务定义，始终只读，严格匹配节点任务编号与固定版本；缺失定义显示明确提示，不回退。内嵌引用列表不提供页面跳转，节点自身输入输出、规则、流向、配置继续保留。点击节点只局部替换详情；切换标签只更新任务正文，保留左侧位置和未提交的节点表单。右侧 AI 面板独立滚动，桌面保留 6:4，窄屏延续纵向排列。

详情维持策略 ID + 版本上下文。切换版本后清空上次校验结果；已生效、审核中、已停用只读，修改需创建独立草稿。原型采用演示递增版本号，不代表正式版本算法。

节点配置规则：

| 类型 | 必须呈现 | 原型交互 | 正式实现补齐 |
|---|---|---|---|
| START / END | 入口上下文、结束结果 | 名称、输入输出和规则字段 | 结束类型及契约选择 |
| PROGRAM | 确定性目的、输入输出、规则、成功/失败流向 | 编辑字段与后继 | 可用程序动作注册表、规则版本选择器 |
| AI | AI 任务固定版本、上下游映射、继续/失败条件 | 选择目录内任务 @1.0，原地查看固定版本五标签 | 完整版本选择、契约字段映射、三类结果流向 |
| HUMAN | 介入原因、证据/版本/差异、允许动作及后继 | 批准、退回、暂缓各后继 | 按业务场景配置授权动作与上下文 |
| CONDITION | 可判定条件、分支与出口 | 两条或多条后继路径 | 字段白名单、表达式校验和分支覆盖 |

添加节点后先处于未连接状态。必须从已有节点配置入口，且为新节点设置后继。节点保存只应用于草稿，点击其他节点前未应用的表单输入不会持久保存；正式产品建议补充未保存提示。

原型完整性检查执行九组规则：唯一入口且所有节点可达；非结束节点有有效后继；AI 引用在演示目录中且固定 @1.0；邻接节点的简化输入输出类型一致；规则字段非空且非待引用占位；人工操作若有定义则有明确后继；条件节点至少两个有效出口；明确未定的准入/发布门槛阻断检查；汇合分析的前置依赖完整。

这些检查只覆盖本地示例图，不解析真实领域规则仓库、完整 Schema、复杂条件覆盖或所有循环终止性。正式系统必须按功能文档九项完整性要求补齐，并在提交审核及生效时重新验证，不能只信任客户端检查结果。

基本信息中编码和模块只读，适用范围及变更原因可编辑。正式版本还应按功能文档提供触发类型、范围条件、输入输出边界、使用说明和固定配置引用。原型以文本范围演示，不虚构表达式语言。

依赖页呈现 AI / Prompt / Skill / Schema 固定版本、领域规则来源、消费模块及在途/历史运行。每个节点展示所属业务文档、章节和对应规则；L0/L1按章节或已存在编号引用，不虚构统一规则注册编号。L2 规则来源为 [[tools/RiskHot/docs/system-design/02-业务架构与领域设计/RiskHot_L2_风险态势分析层_业务架构与领域设计V1.0|L2 领域设计]] 的 BR-L2-02～06；“文档 V1.0”是原型的来源标记，不等于已存在独立规则版本注册服务。

## P03 版本治理

演示生命周期：草稿 → 审核中 → 已生效 → 已停用；审核中可退回草稿；其他版本可复制为新修订。

提交审核：先执行完整性检查，失败停留节点/校验面板。通过后弹框展示策略、版本、当前生效、影响模块、在途任务和新运行影响，要求说明及已核对确认。提交后只改变为审核中。

审核并生效：仅系统管理员可操作；再次检查定义，填写审核依据及变更摘要，展示关联评估与退化候选。本版演示假设同一策略同范围单一生效，生效后原版停止供新运行选择。在途 DEMO-RUN-017 始终锁定 V1.2。原型不会真实发起业务任务。

停用：通过影响确认后停止新选择，不删历史定义、评估或运行记录。停用后暂无生效版本时目录显示“—”；不自动回退到旧版。恢复需要新修订。

审计记录：操作者、操作、时间、原因。原型角色只有演示管理员，无真实用户 ID；时间按 Asia/Shanghai 展示。正式实现补充前后版本快照、权限结果、请求标识及并发冲突处理。

历史对比设计应覆盖基本信息、结构、节点、AI、规则、范围六类差异。原型展示节点变更数、版本摘要、范围和依赖入口，尚未提供逐字段高亮或任意两版差异引擎。

## P04 AI 智能分析管理

目录完整列出功能文档的 16 项逻辑 AI 任务：L0 五项、L1 两项、L2 八项、L3 一项。任务与模型调用次数无一一对应关系。

详情按五个页签组织：

1. 任务定义：编号、名称、版本、业务目标、完成标准、分析步骤、后续处理。
2. Prompt / Skill：文本、用途、上下文占位、固定方法引用和版本历史。
3. 输入输出：按各层任务定义逐项列出输入字段、输出字段、内容与使用要求、来源及待定状态；展示结果形态、交付边界、待定事项及可展开的输出Schema字段片段草案。
4. 工具与约束：逻辑工具许可、模型能力要求、证据和禁止项、通过/受限/人工复核兜底。
5. 引用与版本：消费策略及其版本，历史依赖与草稿。

原型支持检索、浏览、Prompt/Schema/原因修订及 JSON 对象校验，保存为 @1.1 草稿；可引用 @1.0 不变。任务发布过程待业务确认，界面不提供无依据的直接发布。其他字段和工具权限目前展示设计示例，不声称已经可配置。

16项任务的 Prompt / Skill 标签均提供只读 Prompt 用途、业务文档依据及任务专属指令，任务目录与流水线内嵌共用。AI-01 沿用此前按 L0 §6.1.1 补充的定义；其余15项按 L0～L3 各任务定义列出触发、输入要求、分析步骤、输出要求和交付边界，并标注 [[tools/RiskHot/aihot/AIHOT 业务处理架构与 AI 任务拆解 V2.0#6. AI 任务与源码资产映射|AIHOT 第6章]] 的方法参考。AIHOT 与 RiskHot 的编号、关系枚举和评分规则不直接对应；L2只借鉴通用证据和表达方法。用途随固定定义展示，当前修订表单仍仅维护 Prompt/Schema/原因。此次完善的是 @1.0 原型基线，未模拟正式任务发布；Schema、Skill 和占位技术映射仍待详细设计。来源与验证见 [[tools/RiskHot/docs/system-design/06产品UI原型设计/06-4-M3策略管理中心UI设计/验证/全任务提示词补充记录|全任务提示词补充记录]]；[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-4-M3策略管理中心UI设计/验证/AI01提示词补充记录|AI-01 初次补充记录]]保留为历史记录。

16项任务的输入输出已依据L0～L3 §6.1逐项补齐，共312行输入和151行输出；数据保存在本地 `task-contracts.js`。字段表与来源为只读，目录和流水线共用固定任务定义。Schema以已命名逻辑字段的 `$defs` 片段表示：未知业务项保留在说明中，不虚构技术字段；候选取值用 `x-candidate-values` 标注，未确定的必填集合和顶层包装不强制生成。修订表单带入当前任务的Schema草案，保存仍仅产生 @1.1 草稿；这里只检查JSON对象，不声称完成运行级语义校验。来源、字段覆盖及边界见 [[tools/RiskHot/docs/system-design/06产品UI原型设计/06-4-M3策略管理中心UI设计/验证/全任务输入输出补充记录|全任务输入输出补充记录]]。

M3 不展示供应商密钥或重试并发设置。AI 无权自行批准正式结果。Schema字段片段尚需结合未定项完成正式运行契约；Skill和上下文占位技术映射仍待详细设计。

## P05～P08 评估闭环

### 创建评估

选择同一策略的基线、候选、固定评测集及运行条件。相同基线与候选被阻止。正式设计可支持无基线的单版本评估；当前演示只实现 L2 两版对比请求。提交保存各依赖和输入快照，状态停留“等待运行”。没有接入运行服务，不生成伪造的实际执行结果。

正式状态建议：等待运行、执行中、已完成、失败、取消。后端失败应保留请求、已完成案例和错误来源，并区分部分完成；状态枚举尚需执行能力确认。当前原型仅有固定已完成示例和等待运行的新请求。

### 比较条件与摘要

默认展示固定 DEMO-EVAL-021：STR-L2-01 V1.2 与 V2.0、评测集 @1.0、输入 E-20261015-01、同模型/配置。可加入 V1.0 观察三列比较。模型不一致预览会显示“比较受限”，禁止将差异直接归因为策略优化。

摘要示例：100 个案例，改善21、持平74、退化候选5；基线通过90/失败6/待复核4，候选通过94/失败2/待复核4。改善/持平/退化和通过/失败/待复核是不同维度，不能相互替代。指标全部是评审示例，并未运行生成。

指标分业务质量、人机协作、稳定性、效率。百分比变化用百分点；耗时、调用量及 Token 明确单位。指标配置需保存名称、类别、适用策略、计算口径、分母、方向、版本及说明；正式公式和阈值未定，本版只有口径展示，不提供自动准入评分。

### 案例差异

以相同输入和证据为公共头部，两栏显示策略/AI/Prompt/Skill/Schema、执行路径、结构化输出、程序校验、人工结果及最终评估。退化标签使用“候选”，不直接断言业务变差。例如自动完成转人工可能纠正基线过度自动化，仍需人工判断。

当前提供三个固定代表案例，可按改善、持平、退化候选筛选；100 是演示汇总，不是已载入100个完整案例。任意版本、完整样本逐项分数、原因标注和参考结果修订属于后续实现。

### 评测集与历史

每个案例应有稳定 ID、版本、场景、固定输入、证据/配置版本、参考约束及标签。原型支持查看三例和新增边界案例形成集合新版本；旧评估固定 @1.0，新请求可引用 @1.1。只演示引用锁定，不实现真实数据快照仓库。

历史页将离线评估与生产运行参考分开。后者明确未接入，不混用生产统计。评估成功不自动生效，失败也不自动停用策略。

# 流水线文档依据与节点对照

## 依据优先级

按用户本轮指定，流程语义以《系统功能架构总览》的模块边界、端到端流程和交接关系，以及L0～L3《业务架构与领域设计》的业务图、任务职责、规则和未决项为主。M3功能设计继续约束策略治理页面与版本操作；其中简化的串行示例不再作为业务依赖的唯一依据。用户截图只决定布局与点击方式。

本次通过RiskHot Knowledge读取五份文档的目录、总览§5.2/§6.2～6.6、各领域详细业务图及有关任务定义，再在本地同源文件上核对路径。不是逐份全文重新评审，也不表示原领域文档中的待定项已获确认。

原始flow-data.js保留F01～F08模块级总览与六个详细场景蓝图，以下122节点是这七份源蓝图的基线对照。现行“流水线全景”通过system-panorama.js组合六个详细场景，并补充总览中的F01、F07及横向治理，展示118个具体业务节点；每层从Step 1编号。程序、AI、条件及边界仍区分执行职责，正式事实由对应业务模块拥有。

## 展示分层

现行全景仍按系统总览§4.2组织L0～L3与独立横向治理，各层直接展开处理步骤、分支和条件出口。组合节点保留origin、源文档、规则、固定任务和未决项；跨层交接及事件评级展开仅作用于全景副本，原六条策略图保持不变。以下模块级总览表用于来源基线；现行组合及展示核对见[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-4-M3策略管理中心UI设计/验证/流水线全景细化验证记录|流水线全景细化验证记录]]。

## 主要修正

- L0：区分无事件、待归组、来源增加、重复及纠正；对象/变量缺口允许留空或反馈M2；AI-02在身份复核中复用，不新增AI任务；评级先判断初评/复评必要性。
- L1：AI-L1-01先完整定义0..N个风险候选，再程序检索并交AI-L1-02判断同一性。匹配复用、未匹配准入、歧义暂缓、已关闭待确认恢复分别表达；初始关系未完整不向L2交付。
- L2当前状态：来源、应对、损害逻辑可并行；两股力量依赖来源与应对；整体四维汇合全部结果。部分指标缺失可受限分析，身份无效需先补齐。
- L2变化：方向与持续性分别分析后再识别减弱节点；首次或历史不可比则变化待判断，不补写“维持”。
- L3：固定周期与截止，组织已确认结论，程序校验后保存RiskReport，再按权限及已确认条件发布。强制复核与完整发布/撤回状态机仍待定，没有统一强制人工批准节点。

## 边界和表达选择

L2领域图④合并表达快照、变量与变化结果保存；系统总览将当前快照归F05、附属变化归F06。因此UI分别展示F05保存/交接与F06一致性检查/附属结果保存，并明确实际事务、协调与部分失败策略待技术设计，不把它们虚构为两个确定独立事务。

逻辑并行表示输入依赖允许同时分析，不代表已确定模型调用次数、并发调度或实际运行时序。真实关系以右侧后继与前置汇合为依据；图中只为直接连续的节点显示箭头，避免长路径字符串干扰分层阅读。独立业务出口、后续动作与横向支撑使用语义分隔。

原型把复核/补齐未决机制显示为业务暂停出口，保留原因与来源，不擅自定义批准、退回、暂缓三种统一动作。L1自动准入和L3正式发布门槛仍待定，原型对含这些未决门槛的蓝图给出阻断检查，避免误读为可直接执行；这是原型的保守校验选择，不是新确立的领域准入规则。

节点输入输出说明来自文档语义；表单内`context`仅为原型映射占位，并非生产Schema。@1.0、V1.2/V2.0、DEMO运行与评估数值均仍为演示。当前各演示策略版本共用本轮校订的业务蓝图，不能据此声称已还原实际历史流程或产生了真实评估结果。

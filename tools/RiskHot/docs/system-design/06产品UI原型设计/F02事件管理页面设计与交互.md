## 1. 页面定位与导航

事件管理用于阅读正式事件、理解金融意义、追溯关联候选及原始资料，并查看结果交付状态。页面沿用工作台的深绿导航、浅色阅读区、统一按钮与焦点样式，优先呈现业务内容。

§1～8 描述当前已实现的页面；§9 是本次补齐的目标操作与结果查询要求，尚待页面实现和单独验收。


| 页面       | 入口                                          | 主要内容与操作                            |
| -------- | ------------------------------------------- | ---------------------------------- |
| 正式事件列表   | 从侧栏“内容 → 全部”进入，默认打开；详情中可点击“返回事件列表”          | 浏览已保存事件，按页读取，点击事件打开详情              |
| 正式事件详情   | 点击列表中的事件，或从已归组候选打开所属事件                      | 标题摘要、Subject、Target、金融意义、关联候选及交付下载 |
| 资料的候选事实  | 从已保存资料的候选事实与归属入口、计划运行记录的资料阅读流程进入；旧资料处理地址可转入 | 查看该资料抽取的候选及其当前归属，打开正式事件或未归组候选      |
| 候选事实只读详情 | 从资料候选列表选择未归组候选，或使用保留的候选事实地址                 | 阅读候选陈述、发生时间、阶段、正式事件归属和来源证据         |


侧栏常驻“内容 → 全部”“配置 → 信源管理中心”，分组标题不可交互、不可折叠，未实现模块不显示占位；窄屏仍可达。正式事件页面移除顶部“正式事件 / 信息接入”工作区切换行，正文直接呈现事件列表或详情；页头提供“刷新状态”，详情保留“返回事件列表”。信息接入任务属于M1/F01协作入口，默认执行概览按独立计划的信源展示当前执行与最近结果；历史视图“任务批次记录”按一次采集批次展示一行，批次详情包含关联统计及逐份资料的“任务实际采集记录”，设计见[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/信息接入任务与计划页面设计|信息接入任务与计划页面设计]]。

独立“候选处理”工作区、逐项处理页面及资料处理配置页已移除。既有身份、关系和正式保存复核规则继续有效，移除页面不等于批准待复核项。自动合并、拆分和重新归属也不因页面调整自动开放。

## 2. 正式事件列表

列表标题为“正式事件”，辅助说明为“按展示时间 · 最新在前”。每条白色卡片展示真实信源、标题、完整 description 与阶段；只有标题链接进入详情，来源与时间说明独立展开。日期与星期为分组标题，标记“本页N条”，可收起；时间列、节点及细线形成阅读顺序。窄屏将时间移至卡片顶部，长标题、正文与来源自然换行。

展示时间与业务发生时间 `event_time` 分离：设原文发布时间为 P、该版本首次成功收录为 C。0≤C−P≤72小时（含边界）时采用 C，超过72小时时采用 P；不使用当前时间、Event 建档或更新时间。采用最早成功收录且具有本事件实际证据的版本，C/P 始终同版本配对；修订、重复抓取与普通转载不得重新置顶。同刻按事件ID稳定排序，按上海时间归日，全局排序后再偏移分页。

仅有日/月/年的发布时间保留精度，按可能范围判断；成功收录可将该低精度范围上界收紧到 C。整个可行范围均在72小时内才采用收录时间，全部超过阈值才采用原文时间；跨阈值、非法日历、缺失/无法解析或完整未来时刻采用 C 并说明待核实。完整时刻无明确时区不猜测。无 C 时可采用可解析 P；两项皆无归入“展示时间未明确”。完整日期组在前，月/年各自进入该年月值的“展示日期不完整”组并排在其后，不补造午夜；组内排序用范围起点，页面仍显示原精度。

多来源按信源ID去重，同名不同ID保留；时间依据的信源在前，其余按最早来源关联时间与ID稳定排序。一个 Event 只出现一次。只要事件关联来源中存在无权读取者，整事件及来源数量均不返回，与详情权限保持一致。


| 交互或状态  | 页面表现                                       |
| ------ | ------------------------------------------ |
| 默认进入   | 读取正式事件时间线，不进入候选处理队列                        |
| 浏览记录   | 每页最多20条；全局倒序后分页；有前后页时显示“上一页”“下一页”；切页定位列表顶部 |
| 打开事件   | 标题链接进入当前正式事件详情，携带经过校验的分页与事件锚点；支持原生新标签页操作   |
| 返回列表   | 显式返回与浏览器后退恢复原页、可见阅读锚点、焦点及展开状态；单独打开详情返回首页   |
| 阅读依据   | 可展开其他信源及时间说明，显示原始发布时间、首次收录与选择原因；原文沿用详情证据入口 |
| 刷新     | 无内容变化不重建；有变化保留可见事件锚点、键盘焦点、日期和来源展开状态        |
| 刷新失败   | 已读取列表保留，说明失败并指向“刷新状态”重试；首次失败与无权读取分别说明      |
| 没有正式事件 | 显示“还没有正式事件。已抽取的候选可从信息接入任务查看。”，不将候选充作正式事件   |


当前列表仅提供浏览、分页和打开详情。[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0#4.11 共用能力：事件查询与证据追溯|F02 多维检索要求]]及[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0#4.4.4 核心处理规则|实例融合的受控合并／拆分与关联调整要求]]属于完整功能要求，尚未作为本列表的已实现控件交付。偏移分页在静态数据下稳定；并发新增或时间纠正可能改变跨页位置，不提供快照分页保证。本次运行结果见[[tools/RiskHot/docs/verification/event-timeline|事件时间线验证]]。

## 3. 正式事件详情布局

阅读顺序为返回入口、标题摘要、主体与金融意义、关联候选、结果交付与下载。前两个内容版块承担主要阅读任务，追溯和操作信息置于后方。


| 区域          | 展示内容                                     | 交互与缺失处理                                |
| ----------- | ---------------------------------------- | -------------------------------------- |
| 标题与摘要       | 事件标题、当前事实摘要；发生时间和阶段作为辅助信息                | 默认直接显示；原文未明确发生时间时如实提示，不补造时间            |
| 主体 Subject  | 实施行动的主体                                  | 与Target分开展示；缺失时显示主体待确认                 |
| 观测对象 Target | 已保存的正式观测对象名称及关联说明                        | 没有有效关联时显示“尚未确认观测对象”，不能用Subject代替Target |
| 直接变量        | 已保存的变量名称及说明                              | 有变量时提供“直接变量（数量）”展开项，不强行补充缺失关系          |
| 金融意义        | 已保存的评价摘要、五维分数/文字依据、评价范围和研究期限；已有研究用途注明其来源 | 显示草案、已确认或待重新评价；没有评价时明确提示尚无已保存评价        |
| 评价依据与限制     | 评价中已保存的限制和缺口                             | 默认收起，显示数量，点击后展开；不将尚未验证的解释当作事实          |


Subject与Target在桌面并列，金融意义位于其下；窄屏改为顺序阅读。金融意义只呈现已有评价；M 为空时按原因显示“文字草案，未量化”“待补齐依据”或“评价失败，待恢复”，不得将所有空分统一显示为成功的文字评价；已有评价需重评时保留历史并标明当前待重新评价。多个评价可分别展示，不将不同范围或期限的评价混为单一结论。

## 4. 关联候选与原文追溯

正式事件在主要阅读版块下直接展示“关联候选事件（数量）”，不要求进入独立候选处理页。


| 内容或动作     | 展示与规则                               |
| --------- | ----------------------------------- |
| 候选概要      | 直接显示每项候选的标题、摘要及其对当前事件的关联作用和说明       |
| 关联作用      | 按已有归属显示初始事实、进展、补充、纠正或佐证；不自行改变已确认关系  |
| 查看候选详情与原文 | 在本页展开该候选的主体、行动、发生时间、阶段及逐条引文         |
| 查看对应版本原文  | 从引文旁打开所引用版本的原始资料，保留当前事件阅读位置         |
| 候选范围      | 仅显示已经确认归入本事件的候选；未归组候选及其他事件的候选不能混入   |
| 证据对应      | 每项候选仅展示与自身关联的原文证据，不把同资料其他候选的证据混到该项下 |
| 无关联候选     | 如实提示“尚无已关联的候选事件”，不生成占位候选            |


“查看候选详情与原文”、直接变量、评价限制及交付区的展开状态，在同一事件自动刷新时保持。切换事件后按新事件默认状态展示，避免沿用前一事件的展开内容。

## 5. 资料候选列表与只读详情

“资料的候选事实”页以一份已保存资料为范围，列出其全部候选事实的标题和当前归属。点击“查看正式事件”进入已确认的所属事件；点击“查看未归组候选”进入只读候选事实详情。页面提供“返回信息接入任务”。

候选事实详情展示标题、摘要、主体、行动、发生时间、阶段、事件归属及来源证据。已有正式事件归属时提供“查看所属正式事件”；尚未归组时显示“尚未确认归属，保留为候选事实”。引文旁提供material当前正文入口，版本不匹配时提示依据已变化，页头可返回正式事件列表。

候选列表没有结果时显示“尚无候选事实，请查看接入任务的抽取状态”。这些现行页面承担阅读与追溯，不提供人工批准、事件新建或归属修改表单；目标复核入口与恢复动作见 §9，入口尚未实现时保留待办，不能通过查看页面自动推进。

## 6. 结果交付、下载与恢复

“结果交付与下载”作为详情末尾的折叠区，默认收起。展开后提供当前结果下载，并逐项展示已有交付及文件状态。


| 状态或动作       | 页面表现与限制                       |
| ----------- | ----------------------------- |
| 下载当前结果      | 下载当前已保存的正式事件结果                |
| 已接收并采用      | 接收端已持久接收且已采用该结果               |
| 已接收，等待前序交付  | 结果已经收到，但采用顺序尚不满足；不得显示为已经采用    |
| 等待交付或文件待恢复  | 如实显示当前状态，不能因文件未生成而显示成功        |
| 下载当次交付结果    | 当对应交付文件可读取时显示，供核对该次实际交付内容     |
| 下载接收回执      | 对已接收的交付提供对应消费者回执              |
| 重新交付／重新生成文件 | 当前用户有恢复权限且该项可恢复时显示，提交前须填写恢复说明 |
| 无交付结果       | 显示“当前没有待交付结果”，不伪造接收记录         |


恢复操作提交时立即显示“操作正在提交…”，锁定相关按钮，受理后读取最新交付状态。结果暂未确认时保留“重试本次原操作”，重试沿用原操作，不通过重新创建请求制造重复效果。

页面明确说明验收接收端用于验证可靠交付，F03/F05风险分析尚未接入。资料已接收、候选抽取完成、正式事件已保存、交付已采用是不同业务状态，不可互相替代。

## 7. 页面状态、刷新与历史入口


| 场景        | 页面反馈与恢复                                        |
| --------- | ---------------------------------------------- |
| 首次打开或切换内容 | 显示读取状态，避免把上一页内容暂时当作当前结果                        |
| 手动刷新      | 点击页头“刷新状态”重新读取当前内容                             |
| 自动刷新      | 当前页面可见且没有进行中的提交或输入时，每5秒读取状态；用户正在输入或操作控件时暂缓自动重绘 |
| 读取失败      | 显示暂时无法读取和刷新重试提示，不填充默认成功状态或把未知数量改成零             |
| 无查看权限     | 明确提示当前账号无权查看此内容，不显示受限资料和证据                     |
| 恢复操作失败    | 保留错误提示与可执行的恢复动作；结果不明时允许重试原操作                   |


旧入口继续可读：旧候选处理地址按实际归属进入所属正式事件或未归组候选的只读资料；旧资料处理和版本入口进入资料的候选事实列表；旧候选队列入口进入正式事件列表。跳转不创建事件、不批准候选，也不修改候选归属。

## 8. 布局、可访问性与交互验收

保持标题、摘要、主体、观测对象和金融意义的阅读层次。桌面并列的信息在手机上按顺序排列，长标题、分析说明和原文引文自然换行。展开操作使用有文字说明的控件，下载与跳转入口保留明确名称；键盘可进入主要内容，操作控件有可见焦点，读取反馈可被辅助技术感知。


| 验收场景       | 验收要求                                                |
| ---------- | --------------------------------------------------- |
| 浏览列表并打开事件  | 列表可分页，详情可返回列表，刷新后仍能读取当前事件                           |
| 阅读主要内容     | 标题摘要优先，Subject、Target和金融意义可明确区分；缺失Target不以Subject代替 |
| 阅读评价       | 显示范围、期限及真实评价状态；空M不补零，限制可展开                          |
| 追溯关联候选     | 在事件页直接读候选概要，各候选引文对应自身来源；未归组候选不进入正式事件                |
| 展开后刷新      | 同一事件的展开状态保持；切换事件不混用原内容                              |
| 查看交付与恢复    | 区分接收和采用，仅展示真实可用下载；恢复需要权限和说明，未知回执可重试原操作              |
| 手机阅读       | 1440、390和320像素宽度下主要内容、关联候选及操作可读，无横向溢出               |
| 使用旧入口或缺少权限 | 跳转不产生业务写入；受限内容不泄露，读取失败不冒充空结果或成功                     |




## 9. 待实现：事件处理任务、复核与新增结果查询

本节只定义操作与功能映射，界面布局及实现另行验收。“事件处理任务”作为统一待办入口，复用任务导航，不恢复独立“候选处理”工作区。未归组项按 Fact 进入，已有正式身份的项按 Event 进入；事件详情与候选详情显示待办原因并链接同一任务。现有空白任务入口不代表具备下列能力。

操作者为具有对应权限的系统管理员；授权阅读者只能查看允许内容。程序在任务产生时记录责任步骤、待处理原因和依赖结果，在提交决定时重新校验权限及被审内容，查看页面不构成批准。


| 待办及功能归属                | 操作与必须提供的依据                                                       | 提交后的恢复位置                                |
| ---------------------- | ---------------------------------------------------------------- | --------------------------------------- |
| 抽取歧义：知识抽取    | 展示原文与候选属性，提交有依据的修正或补证；已保存 Fact 保留旧依据                             | 回 Step 1 修正抽取；字段映射错误回 Step 2，重验依赖结果                |
| 身份歧义：知识实例融合            | 展示候选事件与比较依据，确认 NEW、指定已召回 Event 的 REUSE，或保留 UNRESOLVED；非事件处置需说明理由 | 回 Step 3 核定身份，再继续增量与关联；改正式归属走受控维护       |
| 变化/变量对应歧义：增量识别、知识关联    | 展示前后事实、变量定义与范围，确认采信依据或保留缺口；Target 身份缺口转 Step 3，正式定义缺口转 M2          | 事实变化回 Step 4；仅匹配歧义回 Step 5；重验受影响评价与保存范围 |
| 受限范围与最终提交：知识存储         | 逐项展示拟保存事实、变量、关系、评价、用途和缺口，明确批准范围与理由；拒绝时保留原因                       | 重验当前依据和必需批准后保存；已过期则退回责任步骤               |

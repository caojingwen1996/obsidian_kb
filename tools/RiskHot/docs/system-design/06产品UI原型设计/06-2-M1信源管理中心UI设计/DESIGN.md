# M1 信源管理中心UI规范

## 统一视觉与修改边界

本版先补充[[tools/RiskHot/docs/system-design/06产品UI原型设计/DESIGN|M1/M2/M3统一UI规范V2.1]]，再在现有styles.css之后加载ui-v2.css，采用深绿导航、白色工作面、14px正文和统一控件。下文保留的交互/字段约束继续有效；旧组件表中涉及浅绿侧条等视觉描述由统一规范取代，业务含义不变。

保留本中心[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/EXPERIENCE|交互契约]]及现有业务JavaScript。三中心导航使用静态相对链接，原有控件ID、data属性和内联脚本不改。禁止通过新增状态或字段改变业务。

## 现行页面组织

信源直接进入搜索/筛选/四视图共用工具区，不重复加入大标题与说明。树状分层和全部平铺视图保留；六段详情、业务/技术双状态、表单查重、启停确认、关系和历史统一排版。960px详情抽屉断点保持与app.js一致；侧栏900px以下隐藏，手机详情/表单保持全屏。正文14px、名称15px、详情标题20px、标签12px；主要控件8px圆角。历史静态图稿仅作旧版存档，现行界面以可点击原型为准。

## 沿用的组件与业务展示约束

## Components

组件名同时在行为契约中定义；以下为唯一视觉命名表。辅助的字段、链接、提示、骨架属于相应组件内部，不另建未定义组件。

| 组件名 | 视觉结构与状态 |
|---|---|
| `workspace-nav` | 继承左侧导航和顶部位置导航；当前 M1 深绿文字＋选中底色。手机入口显示当前模块名称与菜单，不用只有图标的无名入口。 |
| `section-tabs` | 仅详情四页签使用文字与底线，不再设置参考／正式分区。选中态有文字加粗和底线，焦点独立可见。 |
| `search-filter-bar` | 搜索框左、筛选右；已选条件呈可移除文字标签并提供“清空条件”。折叠不隐藏已选条件数。读取失败保留输入。 |
| `view-switcher` | 全部／信源等级／日常监测／专题研究同权重按钮；选中深绿，默认专题研究。按钮与组织规则说明并入搜索筛选面板底部，共用底色和外边框；宽屏并排，窄屏换行。“全部”使用平铺列表，不显示树节点、展开／收起操作或分组重叠说明。 |
| `group-list` | 树节点逐层缩进并有父子连接线；金融属性根节点深绿强调，观察层级浅底，关注优先级暖白；每层标明维度名称、展开标识和数量；总数与“分组计数可重叠”在面板上方。辅助入口单列，不伪造 T1 等级。 |
| `source-row` | 主行名称、次行发布主体／编码；正式行附等级、接入方式、业务状态、技术信息。选中行用浅底＋左线，技术错误不整行涂红。 |
| `source-detail` | 标题、身份、分段内容、入口、操作；正式详情固定版本和状态区，再进入档案／技术／关系／历史页签。长文本换行，分类演示值带文字标签。 |
| `classification-tags` | 同色系、具维度标签；T1_5 显示 T1.5，内部值不暴露给一般用户。空值写“待补充”，不渲染成空白标签。 |
| `status-pair` | 分别标“业务状态”“技术接入”；启用深绿、停用中性；未就绪／未知独立说明，不画合成通过率。 |
| `source-form` | 段标题、字段标签、必填时机、控件、帮助／错误顺序固定；建议预填有“待确认”标识。错误边框配说明；保存区持续显示“保存不自动启用”。 |
| `duplicate-comparison` | 名称／发布主体／渠道／定位／代码逐行比较；差异加粗和文字标记，不只染色。同代码冲突置顶，并突出“打开已有信源”。 |
| `action-button` | 主动作深绿实底；次动作暖白边框；停用在普通详情为次动作，确认层显示明确动词。加载态保留宽度、动词改为进行中，禁止重复按。 |
| `operation-dialog` | 顶部显示来源、当前→目标状态与版本；主体为核验或影响、选填理由输入；底部为取消与明确动作。操作结果未知时反馈取代提交，不能显示成功图标。 |
| `feedback-panel` | 就地显示加载、空、失败、无权限、离线或提交未知；图标可作为辅助手段，必须有文字和可执行恢复入口。表单错误摘要可定位具体字段。 |
| `relation-list` | “允许来源的指标／实际引用资料”分区，显示名称、关系性质、来源版本与可用定位信息。跨模块入口带目的地说明；引用数量未知不用 0。 |
| `version-timeline` | 最新在前的时间记录 [ASSUMPTION]；操作、前后版本与状态为主，操作者／时间为辅，理由完整展示。选中历史版本加只读标识，不提供回滚按钮。 |

## Do's and Don'ts

| 应做 | 不应做 |
|---|---|
| 同时展示业务状态、技术就绪及自动接入条件 | 用一个“正常／异常”灯吞掉两个独立状态 |
| 单一在册目录、名称清楚、启停反馈明确 | 用“登记成功”暗示“已启用”或“已连接” |
| 所有六维独立展示与维护，排序规则可读 | 信源优先级转成信用分、信息价值分或星级 |
| FRED 等聚合入口显示逐序列回源提醒 | 对整个平台套 T1，或为过校验伪造等级 |
| 缺项、无权限、未知结果均写具体原因 | 只弹“操作失败”，或把查询失败显示为“暂无” |
| 沿用已有视觉并提高关键小字可读性 | 引入新字体库、新网络素材或与来源身份无关的装饰 |

## 三中心紧凑标题统一（2026-10-16最新）

遵循上级统一规范：57px位置栏、14px模块h1、20px当前任务标题、20px内容顶间距和16px标题底间距。桌面标题说明同排，手机保持自然换行。M1原有无正文大标题的工具区直接进入设计保留；M2模块名称与原修订审核动作在顶栏，正文不重复；M3流水线标题先于选择工具区并保持只读和6:4。当前布局以此补充及现行原型为准。

标题区域共同约束见[[tools/RiskHot/docs/system-design/06产品UI原型设计/标题区域设计规范|标题区域设计规范V1.0]]；逐页结果见[[tools/RiskHot/docs/system-design/06产品UI原型设计/验证/标题区域全页面检查记录|全页面标题检查]]。标题规则以此共用规范为准，其他组件及业务契约保持。


## 2026-10-16 · 三中心页面与页签操作统一顶栏

本模块全部现行页面执行[[tools/RiskHot/docs/system-design/06产品UI原型设计/标题区域设计规范|标题区域设计规范V1.1]]：页面／页签操作进入应用顶部位置栏，弹窗及抽屉操作进入各自标题行；保持单行并允许操作区横向滚动，保留原控件、权限、表单归属和焦点。此规则覆盖此前正文操作区及底部表单操作的历史布局。具体覆盖及验证限制见[[tools/RiskHot/docs/system-design/06产品UI原型设计/验证/三中心操作统一顶栏记录|三中心操作统一顶栏记录]]。


## M1目录操作与导航分离（2026-10-22）

信源列表标题行左侧为去重总数，右侧为目录操作组：次要文字按钮“展开全部／收起全部”，实底主按钮“新增信源”。按钮与列表相邻，面包屑仅表达所在位置。操作组使用8px间距，分组按钮内部4px；沿用现有绿色、圆角与焦点样式。

640px及以下将操作组放在计数下方，允许自然换行，按钮至少44px高；平铺视图隐藏分组按钮，只读角色隐藏新增。控件以data-local-actions保留在列表，共用迁移器不将它们移入顶栏。此条覆盖本模块旧有“三个目录操作统一顶栏”的布局要求，详情及弹层操作规则保留。

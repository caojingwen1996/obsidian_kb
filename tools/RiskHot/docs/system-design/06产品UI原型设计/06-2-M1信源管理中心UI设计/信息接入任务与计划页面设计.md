# 信息接入任务与计划页面设计

2026-10-26。依据用户“优化信息接入任务和任务计划，现在太乱了”的要求，使用 Impeccable 精简当前实际页面。本文描述 `src/web/` 实现；历史离线原型及演示数据保留原归属。

## 使用目标与视觉依据

模式为 Operate：先看状态与结果，再按需处理异常或调整下一次自动接入。沿用[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/DESIGN|现有 M1 视觉规范]]的深绿导航、浅色工作面、字体与控件，不新增视觉主题。延续[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/EXPERIENCE|M1 交互契约]]的执行历史、结果追溯和权限边界；本次实际页面组织以本文为准。

## 信息接入任务

页面依次为标题与唯一主要操作、紧凑概览和筛选、执行列表。移除大块指标卡片、重复异常横幅、页面内重复刷新入口及可见架构编号；全局刷新仍可使用。

| 区域 | 内容与交互 |
| --- | --- |
| 开启任务 | 无进行中的手动任务时可开启；直接受理全部已启用且有操作权限的信源，保留回执恢复及每源最新1条配置 |
| 紧凑概览 | 全部、运行中、需处理、待执行；点击设置状态筛选。数字只按所选日期范围统计，不随编号/状态过滤改变 |
| 查询 | 起止日期、任务编号、状态；保留上海日期口径与重置 |
| 执行列表 | 计划时间、短任务编号、信源完成/待处理数、批次状态、已确认保存数、查看结果及暂停/继续 |
| 行内结果 | 在当前批次下展开，不要求滚动到整页末尾；各信源再按需展开，直接进入资料与抽取结果 |
| 次级信息 | 六步处理进度、完整任务编号及运行信息折叠；需要恢复时进入执行记录，不丢弃已有工件或错误 |

删除待执行行里重复的“开启任务”按钮：该批次已经受理并存在启动意图，行内只保留暂停/继续；页头的一键开启负责创建新批次。

### 点击「开启任务」后的交互

2026-10-26补充：开启入口按整轮任务生命周期管理，收到受理回执不再立即解锁。任务页和信源详情采用相同规则；信源中心顶部设置一个持续更新的任务状态区，正常情况下替代静态受理提示，不叠加第二条成功横幅。

| 阶段 | 用户看到什么 | 操作与恢复 |
| --- | --- | --- |
| 点击当下 | 按钮立即变为「正在开启…」并禁用，提示「正在确认已启用信源…」 | 先确认没有进行中的手动任务，再读取最新启用名单；同源标签页串行开启，发现已有任务时转为展示它，不再创建 |
| 等待受理 | 提示「正在开启任务，等待受理…」 | 保持按钮禁用并标记忙碌；连续点击只发送一次创建请求，自动刷新暂缓 |
| 已受理、等待执行 | 状态区显示「任务已开启 · 等待执行」、编号、时间及信源完成数；按钮显示「任务等待执行」并禁用 | 切到本次任务并展开结果；「查看进度」再次定位，「暂停任务」作用于本轮 |
| 任务执行中 | 显示「任务正在运行」、动态时钟标记及「已完成 X / N 个信源」的真实进度条；按钮显示「任务运行中」并禁用 | 每5秒读取状态；显示异常数量或保存数量，直接查看各信源进度和结果 |
| 已暂停 | 显示「任务已暂停」，停止动画、保留进度，开启按钮继续禁用 | 提供「继续任务」，从原任务继续，不新建批次 |
| 本轮结束 | 显示「本轮任务已完成」或「本轮任务已结束」，保留数量与「查看结果」，停止动画 | 所有进行中的手动任务均结束后恢复「开启任务」；有异常时明确提示需处理，不把部分完成当作全部成功 |
| 已受理，但状态读取失败／断网 | 显示「任务状态待确认」，停止动画并保留上次进度；开启按钮禁用 | 重新读取状态，不创建替代任务；回执已确认但列表读取失败时保留原任务的查询入口 |
| 未收到受理回执 | 明确操作结果尚未确认，保留「重试原操作」「查询当前状态」 | 重试沿用原请求；再次点击开启入口会定位到待确认提示，不新建任务 |
| 创建前读取失败／没有启用信源 | 显示错误或「暂无已启用的信源，请先启用信源」 | 不创建空任务；读取失败须重新确认状态后才恢复开启，无启用信源时禁用按钮 |

“已受理”只表示任务创建已确认。排队、运行、失败、完成及资料／候选数量继续取真实结果，不把受理提示当作采集或抽取成功。

状态区查询不使用执行列表的日期、编号或状态筛选，刷新页面及跨日任务仍能恢复。已有多个手动任务时显示数量，优先展示最近的进行中任务；自动计划运行保持独立，不持续占用手动开启入口。部分信源已结束但还有信源排队、运行或暂停的任务，仍视为进行中。

动态效果只表达服务端已确认的运行状态，不模拟进度增长。页面隐藏、状态区离开可视区域或用户选择减少动态效果时停止时钟动画，保留文字与数字反馈；无进行中任务时维持15秒刷新。暂停／继续成功由状态区直接反映，避免重复成功提示。

自动更新不打断输入：用户正在填写列表筛选时继续更新顶部状态区，暂不重绘筛选表单；已展开的信源结果及其处理进度在刷新后保持展开。

## 任务计划

默认展示已配置计划，未配置来源通过同级筛选进入；搜索匹配信源名称与稳定编号。来源业务启停、计划启停与单次运行暂停仍分别管理。

| 信息或入口 | 行为 |
| --- | --- |
| 信源 | 名称优先，来源停用时明确提示，不重复展示每条来源的全部档案 |
| 计划状态 | 独立显示启用/暂停，未配置与尚未执行分别表达 |
| 周期与下次触发 | 分钟/小时/天自然单位与下一次计划时间；继续保留1分钟至1天范围 |
| 最近运行 | 当前执行状态及该次计划时间；暂停从真实操作读取，避免调度缓存仍显示运行中 |
| 查看结果 | 直接读取对应 operation 的资料、抽取状态与恢复入口，无需再按日期寻找批次 |
| 运行记录 | 在当前计划行下展开最近最多50条计划执行；每条均可进入结果；加载、失败、空记录分别展示 |
| 管理计划 | 沿用数值＋单位与计划启停表单；不直接改写既有运行状态 |
| 系统异常 | 保留可见的异常数量，具体原因按需展开，避免重复整屏告警 |

## 结果阅读与返回

计划最近运行或历史记录 → 接入结果 → 已保存资料／候选抽取。接入结果先展示来源、状态、保存数量与实际资料入口，六步进度和技术身份后置折叠。进入资料或候选后可以返回接入结果；关闭阅读层返回原入口焦点。

抽取完成且候选数为0时明确显示“本次未提取到事件候选”；未完成或失败不能显示为0。结构化候选详情按需展开，原文下载及固定版本追溯继续保留。候选仍为 pending，不把它表达为正式事件。

## 数据契约与保护

- `GET /api/v1/l0/task-batches`：保留现有日期、筛选、批次去重及保存计数契约。
- `GET /api/v1/l0/task-batches?status=active`：按授权范围查询尚未结束的手动批次，另返回 `latest_batch` 用于结束摘要；网页不传列表日期和筛选条件。开启前再次查询，同源标签页使用浏览器 Web Locks 串行化此流程；已有写入接口和自动计划的并行执行契约不变。
- `GET /api/v1/l0/monitor`：补充最近计划时间，按实际 operation 派生最近状态；读取失败保留已读数据。
- `GET /api/v1/l0/schedules/:key/runs`：新增只读查询，返回 `{source_key, items, limit:50}`；项包含计划时间、operation_id、状态、原因及已确认保存数。先核对来源读取权限，不能查询未授权来源。
- 本次没有新增计划写入格式、外部服务或模型调用；已有幂等、预期版本、同源、预算和资格检查继续生效。

## 响应式与验收

桌面使用紧凑表格；手机将每条记录组织成可扫描的分区，主要结果与操作保留文字，历史在原行展开。沿用原型调色，不通过添加卡片、图标或动画装饰数据。

功能与截图证据见[[tools/RiskHot/docs/verification/m1-management|M1 实现验证记录]]，包括原有一键开启、暂停/继续、周期单位和权限回归，以及新增计划历史和直接查看结果。


## 2026-10-27 资料交付与结果文件

沿用现有操作型界面。在信源执行结果的资料行增加“交付状态与文件”，并在资料和候选详情中显示三个独立事实：资料已保存、F02 已接收、候选抽取状态。接收后抽取失败仍显示已接收，失败数量为待确认；完整零候选显示无事件原因，非空候选说明等待事件归组。

已存在的交付资料、接收回执和完整候选结果分别提供下载，未生成的文件不显示成功下载入口。交付失败显示“重新交付”，抽取失败沿用“重试固定资料”，文件失败显示原因及授权“重新生成文件”。恢复沿用现有带理由表单和未知回执保护。技术身份集中折叠展示；不增加仪表盘或第二套任务配置。

桌面与手机共用有序状态、下载操作和错误说明；320/390/1440 宽度检查无横向溢出。实际状态来自同源接口，独立浏览器用受控数据验证，真实任务证据另存工程验证报告。

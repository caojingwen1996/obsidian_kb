# 信息接入任务与计划页面设计

> 现行工作区的页面设计与交互汇总见[[tools/RiskHot/docs/system-design/03-系统功能架构/M1 信源管理中心功能设计#5. 页面设计与交互|M1功能设计第5章]]，涵盖信源目录（档案／自动接入）和信息接入。本文保留任务与计划页面的细化设计和演进记录。

2026-10-26。依据用户“优化信息接入任务和任务计划，现在太乱了”的要求，使用 Impeccable 精简当前实际页面。本文描述 `src/web/` 实现；历史离线原型及演示数据保留原归属。

## 使用目标与视觉依据

模式为 Operate：先看状态与结果，再按需处理异常或调整下一次自动接入。沿用[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/DESIGN|现有 M1 视觉规范]]的深绿导航、浅色工作面、字体与控件，不新增视觉主题。延续[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-2-M1信源管理中心UI设计/EXPERIENCE|M1 交互契约]]的执行历史、结果追溯和权限边界；本次实际页面组织以本文及M1第5章为准。侧栏常驻“内容／全部”“配置／信源管理中心”，分组仅展示、不可折叠；未实现入口不显示。

## 信息采集任务

默认打开执行概览，使用页面内“执行概览／批次记录”切换；不增加顶层工作区。页头的开启任务继续采集全部启用且有权限的信源。

| 区域 | 内容与交互 |
| --- | --- |
| 执行概览 | 每个已配置计划的信源一行，显示计划启停、当前执行、最近结果、下次执行及批次入口；手动与自动执行均纳入当前情况 |
| 当前与最近结果 | 运行中的批次与最近已结束结果并列；没有已结束结果时显示已知状态，已结束记录显示本轮结果更新时间，否则标明触发时间，不编造精确结束时间 |
| 状态与异常 | 空闲、尚未执行、排队/运行、批次暂停、待恢复/复核及失败各自表达；计划暂停和信源停用单独说明；成功未发现资料不显示为失败 |
| 搜索与筛选 | 信源名称/编号；全部、执行中、需处理、空闲、未执行；只按信源最近情况计数，不累计旧故障 |
| 批次入口 | 当前执行优先提供查看当前批次；否则查看异常或最近批次；每源批次历史跳入历史视图并限定信源 |
| 批次记录 | 一行一次实际触发；自动为单源，手动整轮可为多源；来源独立计划不按时点合并；重试保留原批次 |
| 历史筛选与统计 | 日期、信源、编号、状态；最多100条，提示总数与限制；累计七项处理统计折叠展示，历史条件不影响概览 |
| 批次详情 | 批次状态与七项统计、任务实际采集记录，一行一份资料；资料入口、时间、信源、状态、保存结果及采集/正文/候选入口 |
| 信源发现补充 | 尚无资料或存在异常原因时单独补充，零资料时默认展开；不创建伪资料行 |
| 返回与恢复 | 从概览返回概览并保留搜索/焦点，从历史返回原筛选；直接打开、刷新、前进后退及旧详情链接可用 |
| 读取失败 | 概览失败明确提示并可重新读取，历史视图仍可独立查看；不把失败显示为没有计划或空闲 |

本页复用既有表格、状态色及窄屏纵向记录样式；目录自动接入负责改计划，本页负责执行监测。

删除待执行行里重复的“开启任务”按钮：该批次已经受理并存在启动意图，行内只保留暂停/继续；页头的一键开启负责创建新批次。

2026-10-27补充结果统计口径：数字来自持久化资料、抽取记录、候选事实及正式事件关联，不能用当前列表页的记录数量代替。资料按已保存版本去重；抽取与完整事件处理各取同一资料版本最新的处理记录；Fact与Event分别去重。多个任务复用同一结果时，各任务数量不能相加得到累计数量。只有抽取成功且候选数为零，才计入“未发现事件”；未交付、排队或处理中计入尚未完成，失败和待复核分别显示。仅统计当前账号可读取的数据，跨来源结果须满足全部关联来源的读取权限。

统计区说明来源、口径与更新时间。读取失败显示失败和刷新指引，不使用零或旧数字冒充当前结果；累计统计失败不阻止读取已有执行记录。窄屏将环节与数量上下排列，保留原有任务操作。

### 点击「开启任务」后的交互

2026-10-26补充：开启入口按整轮任务生命周期管理，收到受理回执不再立即解锁。全局开启入口仅在信息接入，单信源详情移除此动作；信源中心顶部设置一个持续更新的任务状态区，正常情况下替代静态受理提示，不叠加第二条成功横幅。

| 阶段 | 用户看到什么 | 操作与恢复 |
| --- | --- | --- |
| 点击当下 | 按钮立即变为「正在开启…」并禁用，提示「正在确认已启用信源…」 | 先确认没有进行中的手动任务，再读取最新启用名单；同源标签页串行开启，发现已有任务时转为展示它，不再创建 |
| 等待受理 | 提示「正在开启任务，等待受理…」 | 保持按钮禁用并标记忙碌；连续点击只发送一次创建请求，自动刷新暂缓 |
| 已受理、等待执行 | 状态区显示「任务已开启 · 等待执行」、编号、时间及信源完成数；按钮显示「任务等待执行」并禁用 | 留在任务列表持续展示状态；点击查看批次详情进入独立页面；「查看进度」再次定位，「暂停任务」作用于本轮 |
| 任务执行中 | 显示「任务正在运行」、动态时钟标记及「已完成 X / N 个信源」的真实进度条；按钮显示「任务运行中」并禁用 | 每5秒读取状态；显示异常数量或保存数量，查看本轮批次详情与结果统计 |
| 已暂停 | 显示「任务已暂停」，停止动画、保留进度，开启按钮继续禁用 | 提供「继续任务」，从原任务继续，不新建批次 |
| 本轮结束 | 显示「本轮任务已完成」或「本轮任务已结束」，压缩为结束摘要、时间及「查看批次详情」，异常提供独立待处理定位，停止动画 | 所有进行中的手动任务均结束后恢复「开启任务」；有异常时明确提示需处理，不把部分完成当作全部成功 |
| 已受理，但状态读取失败／断网 | 显示「任务状态待确认」，停止动画并保留上次进度；开启按钮禁用 | 重新读取状态，不创建替代任务；回执已确认但列表读取失败时保留原任务的查询入口 |
| 未收到受理回执 | 明确操作结果尚未确认，保留「重试原操作」「查询当前状态」 | 重试沿用原请求；再次点击开启入口会定位到待确认提示，不新建任务 |
| 创建前读取失败／没有启用信源 | 显示错误或「暂无已启用的信源，请先启用信源」 | 不创建空任务；读取失败须重新确认状态后才恢复开启，无启用信源时禁用按钮 |

“已受理”只表示任务创建已确认。排队、运行、失败、完成及资料／候选数量继续取真实结果，不把受理提示当作采集或抽取成功。

状态区查询不使用执行列表的日期、编号或状态筛选，刷新页面及跨日任务仍能恢复。已有多个手动任务时显示数量，优先展示最近的进行中任务；自动计划运行保持独立，不持续占用手动开启入口。部分信源已结束但还有信源排队、运行或暂停的任务，仍视为进行中。

动态效果只表达服务端已确认的运行状态，不模拟进度增长。页面隐藏、状态区离开可视区域或用户选择减少动态效果时停止时钟动画，保留文字与数字反馈；无进行中任务时维持15秒刷新。暂停／继续成功由状态区直接反映，避免重复成功提示。

自动更新不打断输入：用户正在填写列表筛选时继续更新顶部状态区，暂不重绘筛选表单；已展开的本轮结果继续保留，同一轮统计口径说明在刷新后保持展开。

## 目录内自动接入

2026-10-27整合：计划作为信源配置，目录顶部“档案／自动接入”切换，计划表共用信源搜索并保留全部／已配置／未配置范围，不再作为第三个一级工作区。旧计划链接自动进入该模式。

| 信息或入口 | 行为 |
| --- | --- |
| 信源 | 显示业务启停；点击打开单源接入设置，档案与计划配置同一来源身份 |
| 计划状态 | 独立显示启用/暂停，未配置与尚未执行分别表达 |
| 周期与下次触发 | 分钟/小时/天自然单位与下一次计划时间；保留1分钟至1天范围 |
| 最近运行 | 实际执行状态、时间及查看执行入口；携带日期、来源和执行身份定位信息接入 |
| 执行记录 | 转到统一列表查看该源历史；删除计划表内独立历史展开 |
| 管理计划 | 复用数值＋单位与计划启停表单；不改写既有运行状态 |
| 系统异常 | 显示异常数量，原因按需展开 |

统一执行查询按权限关联自动计划与采集任务，已有任务不重复计数；尚无采集任务的排队、失败、跳过记录不丢失，明确尚未开始采集。手动批次的信源子执行不再作为任务列表行；异常来源在该批次详情中筛选，整轮按真实ID保持一行。

## 结果阅读与返回

计划最近运行／执行记录 → 批次详情及其逐份资料实际采集记录 → 资料与候选阅读器。同层切换资料正文与候选，多个资料使用选择器；交付文件、进度和运行身份按需展开。关联资料也复用阅读器，关闭返回原入口焦点。

抽取完成且候选数为0时明确显示“本次未提取到事件候选”；未完成或失败不能显示为0。结构化候选详情按需展开，原文下载及固定版本追溯继续保留。候选仍为 pending，不把它表达为正式事件。

## 数据契约与保护

- `GET /api/v1/l0/task-batches`：保留现有日期、筛选、批次去重及保存计数契约。
- `GET /api/v1/l0/task-batches?status=active`：按授权范围查询尚未结束的手动批次，另返回 `latest_batch` 用于结束摘要；网页不传列表日期和筛选条件。开启前再次查询，同源标签页使用浏览器 Web Locks 串行化此流程；已有写入接口和自动计划的并行执行契约不变。
- `GET /api/v1/l0/monitor`：补充最近计划时间，按实际 operation 派生最近状态；读取失败保留已读数据。
- `GET /api/v1/l0/schedules/:key/runs`：新增只读查询，返回 `{source_key, items, limit:50}`；项包含计划时间、operation_id、状态、原因及已确认保存数。先核对来源读取权限，不能查询未授权来源。
- 本次没有新增计划写入格式、外部服务或模型调用；已有幂等、预期版本、同源、预算和资格检查继续生效。

## 响应式与验收

桌面使用紧凑表格；手机将每条记录组织成可扫描的分区，主要结果与操作保留文字，历史在原行展开。沿用原型调色，不通过添加卡片、图标或动画装饰数据。

功能与截图证据见[[tools/RiskHot/docs/verification/m1-management|M1 实现验证记录]]，包括原有一键开启、暂停/继续、周期单位和权限回归，以及新增计划历史和直接查看结果。


## 2026-10-27 资料交付与结果文件

沿用现有操作型界面，资料和候选详情中区分三个独立事实：资料已保存、F02 已接收、候选抽取状态。接收后抽取失败仍显示已接收，失败数量为待确认；完整零候选显示无事件原因，非空候选说明等待事件归组。2026-10-27按用户要求精简后，每轮任务结果只保留状态与统计，移除原信源资料行及其交付文件入口；计划运行记录仍可进入原有资料阅读与恢复流程。

已存在的交付资料、接收回执和完整候选结果分别提供下载，未生成的文件不显示成功下载入口。交付失败显示“重新交付”，抽取失败沿用“重试固定资料”，文件失败显示原因及授权“重新生成文件”。恢复沿用现有带理由表单和未知回执保护。技术身份集中折叠展示；不增加仪表盘或第二套任务配置。

桌面与手机共用有序状态、下载操作和错误说明；320/390/1440 宽度检查无横向溢出。实际状态来自同源接口，独立浏览器用受控数据验证，真实任务证据另存工程验证报告。

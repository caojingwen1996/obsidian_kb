# RiskHot 产品理念与页面设计

版本：V1.0 · 产品评审稿  
整理日期：2026-10-16  
交付范围：产品定位、阅读路径、信息架构、六类页面、核心交互、业务边界及本地原型  
状态：本次产品设计建议；未修改现行项目文档，未代表业务系统已经实现。

> **从风险的变化出发，用变量解释，用证据校验，用条件理解机会。**

## 1. 产品定位

RiskHot 定位为**以风险为中心的持续观察与研究工作台**。

产品把可信信息与核心变量观测组织成一项项具有稳定身份的风险，帮助阅读者持续理解：哪些风险值得关注、风险处于什么状态、相较历史如何变化、变化由什么驱动、哪些条件会改变当前判断，以及这些变化如何影响资产研究。

首页承接注意力分配；风险详情承接判断理解；变量与证据承接验证；资产映射承接条件性研究；周期报告承接阶段性回顾。

### 1.1 用户每次打开产品应带走什么

| 阅读层次 | 应获得的结果 | 对应页面 |
|---|---|---|
| 快速浏览 | 知道哪几项风险发生了值得进一步阅读的变化 | 关注清单 |
| 深入研究 | 理解程度、方向、驱动变量与证据限制 | 风险详情 |
| 持续观察 | 知道下一轮要观察哪些条件，何时需要修订判断 | 详情中的观察重点、演化时间线 |
| 资产研究 | 理解传导路径、已有市场反应与条件性机会线索 | 市场映射，规划能力 |
| 周期复盘 | 看清一个周期内判断如何演进，并回到当时引用的快照 | 周期报告 |

“快速浏览”和“深入研究”的完成时间可在后续可用性测试中设定目标。本稿未进行真实用户计时验证。

## 2. 产品理念如何进入页面

### 2.1 变化优先，程度与方向并列

当前严重程度回答“现在有多严重”；历史变化方向回答“相较明确基准发生了什么变化”。两者不能互相代替。

页面允许“高程度 + 继续增强”“高程度 + 边际减弱”“中程度 + 增强”等组合。当前程度相同，方向仍可能不同。关注清单分列展示两者，详情并排比较基准快照与本轮快照，演化时间线保留每一轮的程度、方向和解释。

首页同时保留“最近评估”“严重程度排序”两种入口，满足变化阅读与存量严重风险检查。严重程度只对可比等级排序；缺少评级或口径不可比的结果单列。

项目依据：《业务架构总览》§4.3.1–4.3.2，第 200–218 行；L3 领域设计 §1.5，第 70–77 行。[S1][S2]

### 2.2 一项风险是一条持续研究线索

用户围绕同一 riskId 完成发现、跟踪、理解与映射。四个任务组成阅读路径，不机械扩展成四个相互割裂的一级菜单。

新闻与指标作为风险的证据进入详情。它们的更新可以促成新一轮评估，但发布数量、传播热度、信息更新时间不直接充当风险强度。

页面保留风险名称、稳定编码、分类、当前状态、历史基准及证据截止。风险更名、定义修订与暂停跟踪不应让历史解释失去归属。

### 2.3 结论渐进展开，证据与解释分别阅读

默认层呈现一句话判断、关键变量和下一轮观察；展开层呈现指标或事件事实、变量状态与风险机制；追溯层呈现来源、原文位置、时间口径、修订版本、快照及基准引用。

所有主要结论都应能回答两个追问：“依据是什么？”“什么新证据会改变这个判断？”

支持证据、相反证据、数据缺口应并列呈现。没有足够证据时，页面明确显示待判断。首次观察缺少历史基准时，不默认填入稳定。以上遵循 L2 已有语义边界；本次新增的是阅读呈现方式。[S1]

### 2.4 观察结果需要能够修订

每项风险详情固定保留“下一轮，验证什么？”模块。其内容引用本轮分析形成的 next_observation，不由界面临时推断。

观察重点应是具体变量、条件或证据缺口。例如：“融资溢价能否继续回落？政策支持是否覆盖承压主体？”避免只写“持续关注后续发展”。

演化时间线保存当时判断。新一轮结果可以修订理解，不能无痕改写历史记录。数据修订与判断修订在后续正式实现中也需要分别标注。

### 2.5 机会采用条件性表达

资产映射应分开处理风险事实、传导机制、市场定价与机会假设。风险减弱之后，改善可能已经进入价格；风险增强期间，市场也可能已计入相应补偿。

每条机会线索至少呈现研究命题、成立条件、相反证据、失效条件和下一轮验证。页面不将风险方向自动翻译成买卖指令，也不提供缺乏上游模型支持的目标价格、胜率或收益预测。

情绪周期与风险态度周期分别提供背景解释。情绪极端只能促成进一步研究，不能单独完成机会确认。

### 2.6 阅读与治理分层

阅读者的核心动作是筛选风险、打开详情、查看依据、选择个人关注和阅读报告。

信源维护、变量定义、指标映射、分析策略、重新评级和正式发布属于对应后台职责。本次产品页面不新增逐项人工维护或审核任务。

“本机关注”只改变阅读偏好；“跟踪中 / 已暂停 / 已结束”表达正式管理状态。两类操作和状态分别处理。本原型不会通过收藏动作修改正式纳管对象。[S2]

## 3. 信息架构

```text
RiskHot 阅读工作区
├── 关注清单（默认首页）
│   ├── 最近评估 / 增强中 / 减弱中 / 稳定 / 待判断
│   ├── 待评估（独立展示无快照对象）
│   └── 风险详情
│       ├── 当前判断
│       ├── 演化时间线
│       ├── 变量与证据
│       └── 影响映射（规划）
├── 风险档案
│   └── 全部建档、跟踪中、暂停、结束及无快照对象
├── 变量观察
│   └── 变量定义、观测事实及各风险中的作用
├── 市场映射（规划）
│   └── 资产类别、传导机制、市场反应、两类周期、条件性线索
└── 周期报告
    └── 日报 / 周报 / 月报、引用快照与版本信息
```

风险详情通过清单、变量关联和报告条目进入，不再占用一级导航。全局搜索跨风险名称、稳定编码、变量及指标名称查询。

管理工作区保持独立。本稿沿用已有视觉语言，未修改 M1/M2/M3 的既有导航与页面结构。

## 4. 页面一：关注清单

### 4.1 页面目标

回答“此刻有哪些风险值得继续阅读？哪些判断发生了变化？”。首页采用紧凑阅读工作台，优先呈现风险对象与变化原因。

### 4.2 页面布局

顶栏保留路径、全局搜索、原型数据标识及上下文操作。正文顶部呈现标题、简短任务说明与统一示例截面时间。

正文第一层为“本轮值得看的变化”，提供一段来源明确的变化摘要，直接链接其引用风险。摘要需受候选条目、数据截止及上游结论约束；不能由页面重新定级或补造趋势。

正文第二层为左右双栏：左侧为关注清单，右侧为少量研究焦点与下一轮观察提醒。聚焦入口只提供阅读路径，不增加一套隐含推荐评分。

### 4.3 风险条目

| 信息 | 呈现方式 | 语义要求 |
|---|---|---|
| 风险身份 | 名称、稳定编码、类别 | 保持长期可定位 |
| 核心变化 | 一到两行摘要 | 引用已有分析结果 |
| 核心变量 | 少量可点击标签 | 展开进入风险上下文的变量与证据 |
| 严重程度 | 文字等级 | 使用上游风险等级，不能自行合成分数 |
| 历史方向 | 增强 / 稳定 / 减弱 / 待判断 | 与比较基准一起显示 |
| 评估截止 | 月日、时分、时区 | 使用 snapshot_time，展开可看完整日期 |
| 个人关注 | 星标 | 仅影响个人阅读偏好 |
| 新纳管 | 独立标签 | 与最近评估、当前趋势分别处理 |

### 4.4 视图与排序

“最近评估”对应已有“最新风险”的阅读语义：每项风险取最新有效快照，按评估截止时间倒序。名称调整减少对“刚刚出现的新风险”的误解。无快照风险在待评估及全部档案中展示。[S1]

本原型关注清单建议默认查看跟踪中的风险；暂停与结束对象进入全部档案。此状态过滤属于产品建议，正式过滤细则仍需确认。

严重程度排序仅用于共享可比等级口径的结果。实际接入需明确评级规则集、规则版本及可比范围。原型中的高、中、低仅为共用演示等级，不能当作已确认正式枚举。

首页不提供虚构的“综合风险指数”“AI 置信度百分比”“机会总数”或以风险数量绘制的装饰性风险走势。

## 5. 页面二：风险详情

### 5.1 页面目标

回答“这个风险当前是什么状态？变化由什么驱动？什么证据支持或限制判断？接下来验证什么？”。这是产品的核心研究页。

### 5.2 头部与固定上下文

风险名称、稳定身份、类别、严重程度、方向、跟踪状态、评估截止与一句话总结共同构成头部。个人关注操作放在顶栏，不与正式跟踪状态混用。

暂停或结束对象出现历史提示：当前显示最后有效评估，不能用旧结论描述当前市场。无快照对象保留待评估界面。

### 5.3 当前判断页签

主要区域并排展示比较基准与本轮快照。下方显示对应的变化解释。阶段、当前影响范围、持续性与持续条件分项展示。

压力端与缓释端采用机制说明。不能通过数指标、数证据、数报道得出两端力量百分比；同一事实被多个变量引用时，也不能重复累计成多份风险压力。

右侧固定“下一轮验证”与“支持 / 反证 / 缺口”。用户在得到结论的同时，看到结论的边界。

原型允许切换“较上一轮”和“较首次观察”，两组结果分别预置。生产端只允许选择已有可比分析的基准；任意基准组合没有已形成结果时，应显示尚无比较分析，或进入经过授权的后台分析流程。界面不自行推算趋势。

### 5.4 演化时间线页签

每个节点对应一轮快照，包含评估日期、程度、方向、变化摘要与基准信息。节点可展开当轮引用。

用户可以看清“程度高位维持，压力仍继续增强”的过程。减弱信号、持续性变化与减弱节点确认分别表示；未达到明确规则时，节点不自动进入确认态。[S1]

原型历史轮次只提供状态和摘要；未纳入历史逐项证据的记录会明确标注，避免拿当前数据冒充当时证据。

### 5.5 变量与证据页签

每个变量按照“变量定义 → 截止时点可用观测 → 变量状态 → 在本风险中的作用”展开。指标数值只是事实层输入。

相同变量可以在不同风险中产生不同作用。变量全局定义复用，风险机制解释保留上下文。例：较高实际融资利率可能维持再融资约束，也可能对需求端通胀形成抑制，具体作用需要各自证据。

风险详情与证据抽屉必须受该风险快照的截止时间约束。本原型给演示指标设置明确可用时点，并在较早快照中剔除后续观测。正式实现还需处理数据观察期、发布时间、入库时间与修订版本，不能只按数据所属日期截取。

### 5.6 影响映射页签

保留当前风险上下文，展示规划中的传导结构，并进入市场映射页面。当前影响范围复用已有 L2 结论；新增的未来资产情景必须有独立分析契约与证据。

## 6. 页面三：风险档案

风险档案负责完整性与长期身份检索。它覆盖全部建档对象，包括跟踪中、暂停、结束、待评估。

列表显示真实跟踪状态和最后有效评估时间。管理状态变化不会把风险严重程度自动改成低或零。阅读端不直接提供纳管、合并、关闭风险等管理动作。

本页是“没有近期变化但仍需查找”“暂停观察后回溯旧判断”“已建档但尚未完成评估”等场景的稳定入口。

项目依据：《业务架构总览》§4.4.1，第 230–236 行；L3 领域设计 §1.5–1.6。[S1][S2]

## 7. 页面四：变量观察

本页从变量侧反向观察风险网络。每张变量卡呈现名称、领域、已有分析状态、核心指标及关联风险数。

抽屉展示统一定义、观测事实、各风险中的具体作用、反证和数据缺口。全局视图说明其观察截止；从风险详情进入时，锁定相应风险的证据截止，防止时点混用。

变量定义维护、指标映射配置与候选治理仍留在 M2。阅读端提供查询与解释，不承担治理写入。

## 8. 页面五：市场映射（规划能力）

### 8.1 页面目标与边界

回答“风险变化会经过什么机制影响哪些资产？市场是否已经反映？还值得验证哪些条件性线索？”。

现行 L3 已确认范围包含三类风险列表与日、周、月报告，并排除了潜在市场冲击预测、交易执行和持仓指令。因此，资产传导、市场定价、情绪与风险态度的系统化分析需要新增领域设计，本原型统一标记规划能力。[S2]

### 8.2 页面结构

采用资产类别切换与研究内容主栏。每类资产依次呈现风险变化、传导机制假设、条件性资产影响、已观测市场反应、两类周期与待验证线索。

资产类别是阅读入口，同一风险可影响多类资产，同一资产也可能受到多项风险共同作用。原型用单风险示例演示界面，尚未实现多风险合成、净影响归因或去重。

### 8.3 两类周期必须分别表达

| 维度 | 核心问题 | 观察方向 | 页面要求 |
|---|---|---|---|
| 情绪周期 | 参与者此刻如何感受市场？ | 恐惧、谨慎、中性、乐观、贪婪等定性状态 | 附心理情绪相关证据、样本主体和时间 |
| 风险态度周期 | 参与者愿意接受何种风险？ | 风险厌恶较高至风险容忍较高 | 附实际风险承担行为及风险补偿要求证据 |

不能把情绪恐惧直接等同于风险厌恶，也不能让同一个指标未经解释同时确定两个维度。还应明确观察市场、主体类别、时间窗口及样本覆盖。

极端节点的判定需要历史基准、适用口径与验证规则。在规则未定义前，界面保留定性位置或待判断，不补造 0–100 指数，也不画成固定顺序、必然重复的周期时钟。

本原型的横向位置条仅用于定性布局评审，不代表量化测量；缺少观测的示例完全不显示位置。

### 8.4 条件性线索卡

| 内容 | 页面要表达的含义 |
|---|---|
| 研究命题 | 哪个风险变化与市场定价之间的关系值得进一步验证 |
| 成立条件 | 哪些变量、传导环节和市场条件需要同时满足 |
| 相反证据 | 哪些事实限制当前解释 |
| 失效条件 | 何种变化会推翻线索 |
| 下一轮观察 | 继续跟踪哪些证据，如何更新判断 |

界面避免“恐惧极端 → 买入”“风险减弱 → 一定上涨”等自动化跳转。研究线索不提供自动交易执行按钮。

### 8.5 正式实现前应补齐的契约

需要确认资产识别与分类、风险—资产传导关系、传导证据及版本、价格或估值观测、情绪与风险态度的独立分析结果、观察窗口、条件性线索生命周期，以及这些分析的正式归属。

单纯增加页面组件无法补足上述能力。相关模型和判断应先在上游形成，L3 再按确定口径组织展示。

## 9. 页面六：周期报告

报告以已形成的风险结论组织内容，保留周期、数据截止、生成时间、发布时间、版本、发布状态与引用信息。

本稿建议栏目为：本期观察、压力增强、风险减弱与持续验证、保持稳定 / 尚待判断、下一轮观察。栏目与候选纳入规则属于产品建议，未当作现行正式规则。

日报、周报、月报切换改变报告对象及相应周期的引用集合。报告条目需要保留 riskId、snapshotId 及适用的 comparisonSnapshotId。阅读时可查看固定引用快照，不能把报告引用直接改写成最新状态。[S1]

原型提供本地 Markdown 导出，包含风险结论、反证、缺口、下一轮观察和快照引用。发布态仅用于界面展示，未连接真实后台发布。

月报样例标注“月内截至本轮”，明确其实际覆盖区间。它没有冒充一个尚未完成的完整月度报告。

## 10. 视觉与交互规范

### 10.1 视觉方向

沿用项目共用 DESIGN.md V2.2 的基础语义：深绿导航、暖灰画布、白色工作面、正文 14px、任务标题 20px、顶栏 57px、桌面侧栏 216px、本地字体和离线资源。[S3]

产品层采用研究阅读导向。通过字重、间距、分隔与少量背景变化组织层次；减少大面积营销图、装饰性图表和与任务无关的 KPI 卡片。

| 语义 | 颜色 / 表达 |
|---|---|
| 主操作与导航 | 深绿；继承项目主色 |
| 风险增强 | 暗红文字 + 方向符号 |
| 风险减弱 | 蓝绿色文字 + 方向符号 |
| 稳定 | 灰蓝文字 + 水平符号 |
| 待判断 | 中性文字 + 虚线标签 |
| 分析说明与规划 | 独立紫色语义 |
| 严重程度 | 文字等级，不依赖颜色单独表达 |

风险减弱的颜色不代表资产上涨。涨跌、风险方向和个人关注状态应保持独立语义。

### 10.2 渐进披露与导航

名称进入详情；变量标签打开上下文抽屉；引用打开快照信息。返回清单保留当前页面会话内的筛选条件。

弹窗和抽屉使用原生 dialog，提供关闭、Escape 与焦点恢复。键盘快捷键 Cmd/Ctrl + K 打开全局搜索。

窄屏隐藏侧栏并提供菜单；表格转为风险卡片，程度、方向及时间保留文字标签。复杂指标表在局部容器中滚动，页面本身避免水平溢出。

本机关注在允许的浏览器环境中尝试使用 localStorage；受限来源或不可用时降级到页面会话。不会读取账号、令牌、密钥或远程数据。

## 11. 状态设计与正式实现要求

| 情况 | 正确呈现 | 原型覆盖 |
|---|---|---|
| 已建档，无有效快照 | 待评估；保留身份；不参与有效快照排序 | 已提供 |
| 首次有效观察，无历史基准 | 当前状态可有结论；方向保留待判断 | 已提供 |
| 当前等级较高但趋势未变 | 程度与方向分别显示 | 已提供 |
| 相同等级内继续增强 | 展示增强解释和比较基准 | 已提供 |
| 暂停或结束观察 | 真实跟踪状态及最后评估时间；提示历史适用范围 | 已提供 |
| 搜索无匹配 | 明确无结果，可清除筛选 | 已提供 |
| 缺少情绪 / 行为证据 | 待判断，不补定性位置或指数 | 已提供规划样例 |
| 所选基准没有可比分析 | 尚无比较分析，不能自行推算 | 规则建议；原型仅提供预置可比组合 |
| 数据陈旧 | 按已确认阈值提示；保留截止时间 | 规则建议；正式阈值未定 |
| 来源数据修订 | 标注版本、影响范围与重新评估情况 | 待后台实现 |
| 分析失败或证据读取失败 | 区分失败与空结果，不显示稳定或空库 | 待真实异步链路实现 |
| 报告撤回或引用被修订 | 保留发布和引用的版本语义 | 原型未实现真实状态机 |

数据陈旧、等级口径、阶段判据、减弱节点与报告发布的若干规则在现行设计中仍有待定项。本次原型不将演示标签或数据伪装为已确认业务规则。[S1][S2]

## 12. 版本规划建议

### 第一阶段：形成风险阅读闭环

以关注清单、风险详情、全部档案、变量证据阅读和周期报告为主体。先让阅读者完成“发现变化 → 理解原因 → 查看证据 → 知道下一轮验证什么”。

变量阅读可直接嵌入风险详情，独立变量入口可根据首版工作量安排。个人关注属于轻量阅读偏好扩展，不改变 L1 的纳管职责。

### 第二阶段：补充市场映射研究

在资产传导、市场观测、两类周期与条件性线索的分析契约得到确认后，再开放正式市场映射结果。

验证重点应落在因果链及条件是否完整、已有市场定价是否被区分、两类周期证据是否独立、用户是否能够追溯线索失效原因。

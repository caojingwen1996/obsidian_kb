# 标题区域设计规范

本规范将已确认的紧凑标题方案固化为三中心共同约束。适用于 M1 信源管理中心、M2 风险源管理中心、M3 策略管理中心及其流水线、详情、子页、弹窗和抽屉。标题相关规则以本文件为准；其他视觉规则继续使用 [[tools/RiskHot/docs/system-design/06产品UI原型设计/DESIGN|三中心统一UI规范]]。历史静态图稿不作为现行验收对象。

## 1. 标题层级

| 角色 | 字号 / 字重 / 行高 | 内容与位置 |
|---|---|---|
| 模块名称 | 14px / 600 / 1.5（21px） | 顶栏唯一 h1：信源管理中心、风险源管理中心、策略管理中心 |
| 当前任务 / 对象标题 | 20px / 600 / 1.5（30px） | 目录、流水线、策略详情、信源档案、变量/指标详情及当前独立任务；不重复模块名 |
| 流水线节点详解标题 | 20px / 600 / 1.6（32px） | 节点检查面板；保留完整节点名，允许多行 |
| 弹窗 / 抽屉标题 | 20px / 600 / 1.5（30px） | 当前操作名称，与关闭按钮同排，桌面和手机字号一致 |
| 内嵌 AI 任务名称 | 17px / 600 | 节点详解内的任务子标题；外层节点主标题仍为 20px，不升级为新页面标题 |
| 正文分区标题 | 15px / 600 / 1.6（24px） | 档案、定义、治理记录、字段组等次级内容；不升级为页面标题 |
| 紧凑字段组 / 节点说明标签 | 12–16px，沿用组件角色 | 不属于页面标题；保留已有表单分组、节点属性和列表名称的字号 |

字号由信息角色决定，不因 HTML 标签不同而混用。M3 流水线 h2、策略编排 h3 均属于当前任务标题；不把所有 h3 统一放大到 20px。任务标题不再使用 24/28px 的展示式大标题。桌面和窄屏保持同一主层级，依靠换行适配。

## 2. 顶栏

- 外部高度 57px（含底部分隔线），纵向居中；无大面积标题背景或第二条模块标题带。
- 桌面左侧路径为 `RiskHot / 横向支撑 / 模块名称`，路径前缀 12px、次级文字色，模块名 14px、600；两者间距 12px。
- 所有页面及当前页签的操作统一放在最顶部位置栏：路径／模块名称 → 返回及当前上下文操作 → 全局工具。包括新建、编辑、启停、版本选择、复制、保存、修订、检查、审核、生效、维护、评估等现有操作；M1「预览设置」、M2「修订审核」、M3「预览角色」放在同一行末端。按当前对象、页签、版本和权限更新，不复制另一组操作。
- 顶栏背景沿用工作面，底部 1px 分隔线。M2 保留既有暗色方案。
- 不在顶栏增加演示徽标、模块说明、C01/C02/C03 编码或重复页面名；演示数据说明留在原页脚。
- 手机 M1 ≤640px、M2 ≤600px、M3 ≤650px 隐藏路径前缀，保留模块名称及操作；外部高度仍为57px。操作不折行、不压缩文字，空间不足仅顶栏横向滚动，页面整体不横向溢出；键盘聚焦可使屏外控件进入可视范围。

## 3. 正文任务标题

- 内容区顶留白 20px。独立页面的任务标题组与后续工具栏/内容之间为 16px，不叠加第二段模块介绍。
- 桌面标题与短说明同排并按文字基线对齐，水平间距 12px；空间不足时说明自然换行。
- 手机标题在前、说明在后；说明顶部间距 4px。标题与说明完整显示，不通过缩小字号、单行省略或固定高度裁切适配。
- 独立任务说明为 12–13px、次级文字色，仅解释当前任务。状态、版本、角色信息不嵌入标题文字，使用原有独立控件或状态区。
- 正文保留任务／对象标题、状态、编码、筛选及页签内容；页面和当前页签的主操作、返回操作统一进入顶部位置栏，不再单独占正文一行。搜索／筛选控件、列表行对象操作、逐项观测审核及节点内部表单保留原上下文。

### 各中心的组织方式

| 页面 | 正文开始方式 | 必须保留 |
|---|---|---|
| M1 四种目录视图 | 正文直接进入搜索、筛选及视图工具区；新增、分组展开／收起和当前详情操作位于顶栏 | 960px详情模式断点、六段档案及四个详情页签；窄屏详情操作进入详情弹层顶部 |
| M2 风险源 / 变量 / 风险类型 | 正文保留业务入口、任务、正式变量／候选入口；新增、修订、反馈、候选审核入口和当前观测页签的添加指标进入顶栏 | 修订审核、候选审核抽屉、指标维护及表单归属；切换页签清理旧操作 |
| M3 策略目录 / AI 管理 / 策略评估 | 仅当前工作区标题及短说明 | 侧栏子菜单仅名称，不追加编码或状态 |
| M3 流水线 | 正文保留「流水线」标题及流程详解；场景／版本选择和完整性检查置于顶栏 | 全系统与六条策略均只读；宽屏左右 6:4，窄屏按已有断点堆叠；L0～L3 分层与 M 横向支撑 |
| M3 策略详情 | 正文保留策略标题、状态与四个页签；版本、复制保存、编排与治理页签操作置于顶栏 | 默认流水线编排；基本信息、引用、版本治理的原内容及权限 |

## 4. 详情、弹窗与抽屉

对象名、弹窗名采用 20px 标题；对象身份区继续使用组件原有内边距与元信息组织，16px 任务区间距不覆盖详情工作面的内部留白。编码、历史版本、状态放在原元信息区域。复杂详情允许节点标题 1.6 行高。关闭按钮不覆盖标题，按钮与长标题之间保留独立空间。

弹窗／抽屉的全部页面级操作（含取消、保存、提交和关闭）置于各自顶部标题行，不能放在被模态弹层遮蔽的应用顶栏。标题与操作组同排，操作组空间不足时内部横向滚动；逐项审核表单保持所在对象上下文。按钮移出原表单时显式保留form关联、type、name、value及原事件监听。底部可保留说明，不再放一组重复操作。

弹窗桌面标题容器通常为上下 20px、左右 24px；手机沿用组件已确认的 16–20px 内边距。弹窗标题区域高度由真实内容决定，不强制为 57px；57px 仅用于应用顶栏。正文可滚动，关闭和提交操作仍可达。M1 手机详情/表单保持已有全屏形态。

## 5. 颜色与可访问性

- 正文任务、对象及弹窗标题主文字沿用 `#22352e`；顶栏上下文与次级文字沿用 `#58675e`；M2 暗色标题沿用 `#e7eee5`。主操作绿色 `#295c47`，不新增配色。
- AI 分析继续使用浅紫背景 `#eee8ff` / 深紫文字 `#624392`，与系统绿色区分；程序、人工、条件背景语义保持原方案。
- 每页仅一个模块 h1；独立任务使用 h2，次级分区使用 h3。对话框保留原有可访问名称与焦点恢复。动作迁移后不得改变按钮的disabled／hidden状态、所属表单或提交意图。
- 普通文字对比度至少 4.5:1；标题不靠颜色独立表达状态；保留键盘焦点。

## 6. 逐页验收

依次检查 M1 → M2 → M3，并覆盖现行入口场景页、各页签、对话框和可复现异常状态。每个场景在1440px、390px、320px检查顶栏及弹层操作归属、按钮唯一性、表单提交、角色权限、切换清理与滚动可达性，并测量可见标题：顶栏高度、模块字号/字重、任务及对话框标题字号、标题可读性、页面横向溢出及工具可达性。布局断点另沿用三中心既有六宽度检查。

检查报告必须列出实际场景清单、发现及修正、截图和未覆盖边界，不能将模板覆盖宣称为所有数据、版本、角色组合验证。历史静态稿明确列为排除项。

允许修改标题和操作区定位相关HTML/CSS及共用DOM迁移适配器；不得调整业务字段、排序/筛选、权限、节点引用、审核生效、候选治理、数据或业务处理函数。以修改前后脚本及领域数据哈希验证本轮业务保护。

## 7. 页面操作统一顶栏实施（2026-10-16）

三中心共用本目录原型资源/top-actions.js与top-actions.css；迁移现有控件，不重新创建业务按钮。M3页面操作沿用其pageTools，弹窗同用共用规则。页面重绘后移除失效操作；M1详情在桌面顶栏与手机详情弹层标题行间移动；M2恢复焦点时同时检索顶栏。

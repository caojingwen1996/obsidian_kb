# 流水线全景交互原型说明

打开 [[tools/RiskHot/docs/system-design/06产品UI原型设计/06-1-流水线全景ui设计/流水线全景交互原型.html|流水线全景交互原型]]，或从 M1、M2、M3 的同级“流水线全景”入口进入。入口无须依赖旧 M3 页面地址；直接打开或刷新均进入全景。

## 建议体验路径

1. 浏览默认展开的L0～L3一级容器及独立虚线治理区；层级导航定位并随滚动同步，层可单独折叠。
2. 展开默认收起的F01～F08模块，查看真实动作编号、判断的带标签出口及不占Step的路径；层与模块开合分别保留会话选择。
3. 点击节点，查看右侧输入、产出、流向和文档依据。F01按节点类型展示触发、程序动作、判断问题或结束结果；规则依据和只读配置按需展开。
4. 点击 AI 节点，查看任务定义、Prompt / Skill、输入输出、工具与约束、引用与版本五标签。
5. 从含层与模块限定的后继或跨层引用定位稳定节点；已收起的目标层和模块自动展开。
6. 在手机上查看下方详情，使用“返回当前步骤”回到选中节点。
7. 点击策略管理中心进入 M3 的策略目录；M1、M2 也有对应独立入口。

## 资源归属

| 资源 | 主责与复用方式 |
|---|---|
| 本目录原型 HTML、entry.js | 全景独立外壳与默认路由；主入口跳转独立页面 |
| 本目录 system-panorama.js | 全景组合数据及panorama展示元数据；现行115节点；F01遵循V2.1六步、F02遵循V1.0七步；F03～F08稳定身份、后继与固定AI版本保留；M3引用同一数据 |
| 本目录设计规范、节点规范、业务依据 | 全景设计与全系统流程表达约定 |
| 本目录专属验证、结果和历史截图 | 全景来源、折叠、导航及迁移证据 |
| M3 原型资源/app.js、styles.css | 共用查看器、节点详情及全景专属层级/编号呈现；资源不复制，C01保留现行策略契约 |
| M3 原型资源/flow-data.js、task-prompt-references.js、task-contracts.js | 版本化策略蓝图与固定任务定义；全景只读复用 |

本目录依赖同级 M3 资源和上级共用资源，交付时应保留整个“06产品UI原型设计”目录结构。单独复制全景子目录不构成离线独立包。所有依赖均为本地文件，没有新增网络接口。

## 与 M3 的关系

全景呈现业务全貌；M3 提供策略设计、AI 分析定义和策略评估三个管理工作区。全景打开 M3 时通过本地链接切换页面，演示内存不跨页面保存。旧 M3 的 #panorama 深链接保持兼容，正式入口统一使用本目录 HTML。

## 2026-10-23 · L0 任务定义按原文章节引用

AI-01～AI-05 的“任务定义”统一展示 L0 领域设计对应章节的“分析职责与步骤”，并保留可点击原文入口；不再展示原型手写的职责与业务边界摘要。对应关系依次为 §6.1.1 事件抽取、§6.1.2 事件匹配与归组、§6.1.3 Target 与 Variable 识别、§6.1.4 增量判定、§6.1.5 金融意义评级。

任务职责正文只在领域文档中维护；页面通过同步脚本提取原文章节，生成职责与步骤的只读离线展示数据，不另行编写职责正文。全景内嵌详情、策略 AI 节点和 M3 任务目录共用该入口；任务固定版本、输入输出展示及节点流向沿用现有规则。文档引用用于查阅业务定义，不代表将当前文档修订绑定为任务执行版本。


## 2026-10-23 · 直接展示任务定义原文章节

全景节点与 M3 目录的“任务定义”直接展示 L0 §6.1.1～§6.1.5 对应章节中的“分析职责与步骤”，按原文有序列表显示；保留章节原文跳转。任务定义不展示任务编号、触发条件、输入输出字段、交付边界或附注；输入输出仍在独立标签查看。

本地离线页面加载 `task-definition-references.js` 生成的职责与步骤数据，避免 `file://` 页面读取 Markdown 的限制。正文唯一维护源为 L0 文档；修改文档后，从 RiskHot 根目录运行以下命令同步，再刷新页面：

```sh
python3 'docs/system-design/06产品UI原型设计/06-4-M3策略管理中心UI设计/验证/同步任务定义引用.py'
```

同一命令附加 `--check` 可检查展示数据是否过期；章节缺失、链接不存在或出现未支持的文档结构会明确失败。正文渲染转义原始 HTML，链接仅引用项目内实际文件。展示当前文档内容不代表改变固定 AI 任务执行版本。


## 2026-10-23 · 任务定义仅展示职责与步骤

按用户要求收窄提取范围：同步脚本只提取对应任务章节的“分析职责与步骤”内容，原文章节链接继续保留。未修改 L0 原文及独立输入输出标签。职责与步骤缺失时同步明确失败。


## 2026-10-23 · F02 程序与 AI 执行过程同步

F02共26个节点、21个实际动作，保留七个业务步骤；全景共115个节点。程序、AI与条件判断分别用既有角色色、图标和文字标识，模块标题继续不显示说明小字。新增程序节点均有输入、处理动作、结果及后继详情。

Step 5的可读顺序为：判断是否评价 → 固定范围/期限/方法 → AI-05分析维度与用途 → 程序校验 → 按批准规则计算或复算M → 整理评级记录 → Step 6统一保存。无需评价的分支直接连接Step 6，身份存疑返回Step 2；执行失败与合法零候选／空分分开。

验证入口为本目录 `验证/F02程序与AI协作验证.mjs`，覆盖桌面与手机的角色展示、全部模块内连线、程序详情、AI原文引用和跳转；结构验证沿用 `验证/流水线全景验证.mjs`。结果分别保存在同目录的JSON文件。该同步不发布方法、不运行真实AI、不改变原C01策略图。

# F02七步流程与节点详情重构记录

依据[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0|F02功能设计]]§4.1～4.9及§6.2、[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-1-流水线全景ui设计/04.RiskHot 流水线节点视觉与编号规范|画布规范]]6.3～6.4和[[tools/RiskHot/docs/system-design/06产品UI原型设计/06-1-流水线全景ui设计/05.RiskHot_六类节点详情UI设计规范_V1.0|六类详情规范]]，沿用F01方式重构。

## 当前结果

- 七步主线：候选抽取、事件匹配归组、观测主体与直接变量、增量更新、M评价、统一校验保存、按实际变化交付。编号按F02模块独立从Step 1计数至Step 7。
- 无事件程序记录采用Step 1A.1，不把零候选当错误或新造空事件。五个AI任务各引用一次@1.0，移除重复身份分析与旧评级包装节点。
- 共13节点：1 START、5 AI、2 CONDITION、1 PROGRAM、4 END。L0共24节点；全景102节点、四层业务98节点、治理4节点；16项AI任务均保留。
- 模块内直接连接真实节点，复用、无变化、待复核有独立条件。无事件记录完成为实线；保存、交付恢复为虚线。跨模块仅保留F03/F05阅读入口，是否触发由实际变化决定。
- Target/变量合法缺口与M草案空分允许继续；归组歧义、关键证据或业务校验冲突隔离受影响候选。重复投递按受理范围续接，正式保存后仅恢复交付，不重新分析和写入。
- 非AI沿用F01分型详情；AI为五标签加默认收起的配置/流向，来源固定本文F02版本章节。待定阈值、Target治理和M方法直接提示，不发布未经批准分值。

## 修改与保护范围

修改全景F02组合数据与F02来源条目、共用查看器的模块流程/详情分派及限定样式、两份全景验证脚本与结果/截图、对应设计与来源对照、功能设计同步状态、索引和日志。未运行生产采集、AI、业务保存或交付。

与修改前工作副本比较：F01全部节点（含详情元数据）一致；F03～F08和横向治理非展示业务字段及后继一致；固定任务/Prompt定义、六条C01领域蓝图、业务提交处理文本一致。F02不再逐节点复制旧L0蓝图，旧版本蓝图仍保留在C01中。

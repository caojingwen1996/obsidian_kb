## Important 1：历史回填用操作创建先后推断原保存者，会选中后续重采

- 文件：`src/db/002-information-handoff.sql:31-35`，尤其第 35 行 `ORDER BY op.created_at,op.id LIMIT 1`。
- 触发条件：旧库中 A 操作先创建但获取或保存延迟，B 操作后创建却先保存资料版本；A 随后抓到完全相同原件和标准化工件、复用该版本。两操作可以绑定不同来源配置版本。002 会选择 A，即使 A 的 acquired_at 晚于资料版本 created_at。
- 缺失历史依据时也存在同类问题：原保存操作的可核验关联缺失，但保留一次后续相同字节重采，迁移会直接把后者当原保存者。
- 影响：回填错误 source_version、operation_id、acquisition_id、collected_at，随后交付包会合法通过当前 verify；把后续获取的配置/时间解释为旧版来源，违背计划 §3.4 的歧义阻断及 F02 版本溯源要求。
- 建议：首先排除晚于版本保存时刻才创建/获取的操作；对剩余多个不一致来源依据必须显式判定歧义，不以最早创建者消歧。只有能证明的原保存操作才回填，否则保留 HANDOFF_PROVENANCE_REQUIRED。时间过滤只是必要条件，并非充分证明。
- 验证依据：静态 SQL 与旧版同内容复用逻辑可确定此路径；未修改数据库复现。新增“缺失关联”测试尚不涵盖仍有后续重采匹配项及并发乱序保存。建议增加这两个隔离数据库反例。

## Important 2：验收脚本不核对导出候选内容与已保存候选一致

- 文件：`src/scripts/verify-handoff.ts:15-19`，尤其第 18 行。
- 触发条件：candidates.json 保持 candidate_id、candidate_key、数量和合法证据，但 payload 中 title、description 等内容与数据库候选不同；目前仅比较身份，随后验证导出内容本身是否合法。
- 影响：验收脚本仍返回成功，不能证明用户要求的完整候选导出就是已固定业务结果。同样没有核对候选 ordinal/status，以及结果 input_artifact_id、manifest_artifact_id、result_status 与 processing 一致。
- 实验：运行只使用内存对象的 `node --import tsx --input-type=module`，数据库快照候选 title 为“数据库原始标题”，导出候选 title 为“导出被更改的标题”，两者相同合法引用、身份及数量。调用 verifyHandoffSnapshot(...,{requireModelAttempt:false}) 返回 candidate_count=1 的成功结果，没有抛错。关闭模型证据要求只为隔离本项检查，开启该选项不会增加 payload 一致性校验。
- 建议：规范化后逐项核对 payload、ordinal、status 及固定输入/方法引用、处理结果状态；增加“同身份不同正文”和“错误输入/方法引用”反例测试。合法 schema/证据检查不能代替与保存结果比较。

## Minor 1：接收后回执文件失败写入未做文件代次围栏

- 文件：`src/information-ingestion/processing/handoff.ts:109-110`。
- 触发条件：一次 accept 已提交接收、正在较慢的 publishReceipt；另一个恢复或巡检完成较新的文件修复并标 ready；旧调用随后失败，第 110 行只按 version_id 把文件状态写回 recoverable，不核对 files_generation 或文件租约。
- 影响：较旧执行结果覆盖新修复状态，出现已可读文件仍显示待恢复及误报异常；不会产生第二份候选或额外模型调用，但违反独立文件代次的预期。后续巡检可能清除该状态。
- 建议：进入发布前固定文件代次，并在失败投影上做相同代次/所有权检查，或统一由已持文件租约的恢复执行者维护 files_state。添加“旧发布失败晚于新修复完成”的并发测试。
- 验证依据：静态并发时序，未执行故障注入。

## 已核对的有效设计

- 新保存事务固定 origin；已存在版本复用不会由正常新采集路径改写 origin。
- 接收在事务中创建/复用 processing、Inbox、extract 意图，文件失败不撤销已提交接收。
- 新接收会核对暂停、来源状态和原操作者 submit 权限；checkSource 的来源/操作者锁以及任务图锁保留在接收事务内。
- readAccepted 读取实际 information.json 并核验摘要和对应版本；准备抽取时核对冻结输入，留下读取审计。
- 完整候选导出读取全部候选而不是 API 首屏分页；未完成抽取拒绝导出，候选数量保持未知；合法零候选保留原因与覆盖清单。
- 历史附加抽取元数据从响应恢复失败时明确标注缺失，不重新调用模型。
- 接收与导出重复时复用身份和不可变内容寻址工件。

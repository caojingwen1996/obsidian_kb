## 为什么真实任务仍待复核

既有[[tools/RiskHot/docs/system-design/03-系统功能架构/F02 事件管理模块功能设计 V1.0|F02 功能设计]]要求缺少自动通过授权时进入复核。本轮没有发布自动身份或自动正式提交政策，工程计划确认不等于确认某个具体事件身份。

已向用户展示第一条候选的具体事实并请求身份决定，尚未替用户批准。第一条决定绑定 generation=1 和摘要 `25f40c1f5e83f107b6eaa4be511699a902ed1f855fd86d4dadf4db5811a4a5a5`；待办绑定保存在 `.riskhot/f02-events/pending-review.json`。身份通过后程序自动续 Step 3～5，最终待保存内容仍须独立复核。第二条若在首事件提交后沿用旧 NEW 上下文，提交栅栏会要求重新归组，不能直接更换 epoch。

所以当前尚未验证：真实 AI-03～05、真实正式保存、event.json/message.json/接收回执、真实同消息三次重投与重启后完整读取。这些项目保持未完成，不能引用受控测试代替。

## 实施取舍与限制

1. 按用户明确要求留在 main，保留其他任务的未提交修改；中文任务简报由执行账本承接英文解析脚本的限制。
2. 保留旧消息 version_id 唯一键，事件消息使用空 version_id 与独立 event/revision 唯一键；独立测试 fixture 验证旧切片兼容。预算沿用处理内全局尝试序号，新 owner/task 窗口隔离，代次变化不清零。
3. 新增 store/control/time 负责共享锁、恢复与时间投影；接收实现保留在 EventDelivery，不另建只有转发职责的 event-consumer 文件。事件权限隔离在 event-migration，未改变本机免登录模式。
4. 完整 V1 只绑定 Codex 和非空文本范围/期限；实际传输 Schema 由固定授权上下文生成，不由原文自定义。HTTP、复杂口径对象须独立适配；UTF-8 字节上界可能提前拒绝部分长输入。
5. 当前日精度只推进日期投影，预计/未知时间保留历史；模糊同日顺序不伪造精确时点。修订缺口只补原权威历史消息，没有原消息时保持可见缺口。
6. 语义同义归组/去重仍依赖模型与复核，SQL 唯一键不能证明不同表述是同一变化；合法 JSON 也不证明语义召回率。真实供应端 AI-05 能力、完整覆盖与量化质量尚未实测。
7. F03/F05 风险计算、完整 M2/M3、正式量化政策、合并拆分、历史候选批量升级、复杂附件及全部 F01 版本复核不在本轮范围。验收接收端不代表生产风险模块消费。
8. 单集合锁和有限召回适用于当前最小切片；跨区分片、索引扩展、超大规模、超安全整数代次及恶意宿主机/文件系统对抗不作保证。未发布自动通过政策前，完整流程有两阶段业务复核，无法宣称全程无人感知。

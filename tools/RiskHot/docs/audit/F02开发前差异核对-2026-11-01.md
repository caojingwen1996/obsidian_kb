## 3. 必须补齐与治理边界

1. 本轮补齐：八步语义节点、任务包隔离、AI-08 机器结构、资料/权限复查、队列端口及迁移顺序，见[[tools/RiskHot/docs/system-design/04-系统架构设计/03-模块技术详细设计/L0-信息处理层/F02-事件管理/八步闭环实施补充设计|实施补充设计]]和[[tools/RiskHot/docs/system-design/04-系统架构设计/03-模块技术详细设计/L0-信息处理层/F02-事件管理/AI任务技术详细设计/AI-08-Target候选识别|AI-08 技术设计]]。
2. 开发任务 A0 必须冻结：变量观测逐条证据载体、未关联变量结果、事件关联快照及独立用途的物理定义；现有数据模型明确这些缺口，不能把运行 JSON 临时存储宣称为正式业务存储。给出具体候选方案供评审，见实施补充设计 §7。
3. M3 方法、自动审批、金融用途分类规则属于业务发布权限；工程人员不能代为批准。首批支持显式文字草案与待规则状态，正式评分机制用批准规则夹具验证，不把测试方法部署到真实库。
4. pg-boss 精确版本、事务适配和租约语义由隔离 PoC 冻结；本报告不臆造库 API 或声称技术选型已验收。
5. F03/F05 若尚无实际接收端，允许在隔离验收验证契约；真实环境标待接入，不能用本机审计消费者替代下游采用。

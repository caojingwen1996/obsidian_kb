# Target 单表定稿后的 AI 任务与流程一致性审查

> 2026-10-30 · 文档审查。基准为 Target 数据模型 V1.5 与 F02 功能设计 V1.9。本次记录问题及建议，不修改已定稿表结构、提示词、运行契约或数据库；建议尚未作为新规则生效。

## 2. 需要明确的问题

### T-01：新建 Target 的定义由谁准备，没有落实到任务输入输出

**优先级：高。性质：职责与交接缺口。**

Target 主表要求正式名称、非空 categories 配对数组、非空 scope_definition。AI-01 只输出原文名称、单项 type 和 scope，后两项允许为空；旧类型字典也不等于新的一级/二级分类配对。Step 2 只允许原值转换。AI-07 的输出只有身份决定、比较和依据，不包含新建定义；它还明确不修改名称或定义。

定位：数据模型 §3.3.2、§3.3.4（第111～115、162～166行）；AI-01 §3/第二层/7（第417～431行）；AI-07 §2、§3/第四层（第52、81、109、137～145行）；F02 §4.4.4⑥（第785行）。

**影响示例**：原文明确出现某企业，且确实没有已有 Target，但 type 字典缺项。AI-07 可以识别出缺口，却没有明确接收分类补齐结果的步骤；程序也不能把旧 type 直接写入 categories。“按治理规则建档”尚不足以说明谁整理、谁核定、补齐后从哪里恢复。M2 当前主要规定变量等定义治理，不能默认其已有完整 Target 建档流程。

**建议**：在 Step 3 内明确“新建定义准备 → 校验与核定 → 程序写入”的责任和交接结构，包含 target_name、categories、scope_definition、可空 jurisdiction、已核定 aliases 及依据。身份判断继续由 AI-07（Target 同一性判断）承担。若定义整理交给 AI，应明确其任务名称、输入依据与草稿输出；若首版由人工填写，也应直写人工职责。不要让程序猜填，也不要把语义整理放回 Step 2。分类不能确定时保留待补齐，定义齐备后恢复本步骤。

**验收**：对象身份明确但类型字典缺项、原文只有简称、范围不足三种情况，均能找到明确的责任步骤、待办内容和恢复入口；未核定定义不能建档。

### T-02：分类、辖区和状态在召回时是筛选条件还是比较线索，不够明确

**优先级：中。性质：召回规则缺口，尚不能认定实现已过滤错误。**

F02 §4.4.4③要求按名称、类型、辖区和范围召回；数据模型 §3.3.8支持分类配对过滤。AI-07 第22、95行又明确分类不同不能直接排除同一身份，第83行要求已停用的同一对象返回 UNRESOLVED，不能绕过治理另建。

**影响示例**：同一对象拥有交叉分类，上游仅识别其中一种经济属性；若程序把分类当作硬性排除条件，已有对象可能根本进不了 AI 候选集。若只召回 is_active=true，停用的同一对象也可能被当作“没有对象”，形成重复新建建议。AI 不能纠正它未看到的召回遗漏。

**建议**：把目录浏览筛选与身份查重区分开。明确身份召回的最低覆盖规则：名称及已核定别名如何匹配；分类或辖区未知时如何放宽；跨分类候选如何保留；停用对象如何参与查重但禁止复用。完整性不能只表示某次过滤查询执行成功。保留原有权限边界，不向模型暴露无权读取的对象。

**验收**：跨分类同一对象、辖区未知、相同别名对应多个对象、同一对象已停用，均不会因筛选遗漏而直接支持 NEW。

### T-03：多个 Object 到 Target，再到变量结果的逐项绑定尚未形成完整契约

**优先级：中。性质：交接细节待明确；部分属于既有发布待办。**

AI-07 第51、139、154、166行要求 object_ref 绑定单个 Object，并保留多个 Object 指向同一 Target 时的各自依据，但没有定义该引用如何与已保存抽取结果绑定，以及重试、重排、修正后的有效性规则。AI-01 的 target_clues 只有 name/type/scope，候选级引用不能天然区分其中的多个对象。

下游也有同类缺口：AI-05 §2只列五项业务字段及 Event/Fact 上下文；其中 extraction_source=target 只能说明来源类别，不能指出具体哪个 Target。F02 §4.8.4的保存内容表（第1402行）已经要求保留实际来源对应的主体/行为/Target，因此属于上层要求明确、配套结构未补齐，不是必须改动这五项业务字段或 Target 主表。

**影响示例**：同一事件有两家银行，分别涉及相同变量；若只按 variable_id 或 target_clues 数组位置合并结果，就无法可靠区分两家银行的依据。对象顺序变化后复用旧结果也可能串到另一对象。

**建议**：在程序交接中定义对象引用与 Fact、抽取结果版本、具体线索及依据的绑定；相同有效输入重试沿用对应关系，输入变化时重验相关结果。AI-05 的逐项结果包装中保留来源对象引用或已确认 target_id、适用范围和依据；不能由程序根据同名变量猜配。多个 Object 指向同一 Target 时可复用身份，但各自事实依据继续保留。

**验收**：两个对象提取相同变量、同名不同范围、对象数组重排、多个 Object 复用同一 Target、部分对象未决，均可逐项追溯且不会覆盖其他对象的结果。

### T-04：“完整零候选”可能被误读为没有召回已有 Event 或 Target

**优先级：中。性质：流程措辞歧义。**

F02 §4.4.2第677行写“完整零候选或已有明确非事件处置：不执行归组”。该节同时讨论 Event 与 Target 的召回，未直接写明这里指的是 Step 1 没有抽取出事件候选。

AI-02 第127行允许正常空召回满足条件时建议 NEW；AI-07 第109行也允许完整检索无候选时，继续检查当前对象是否足以新建。若把“零候选”理解成召回清单为空，就会错误跳过首次出现的事件或对象。

**建议**：明确区分三种空集合：Step 1 抽取结果为空，结束本资料的事件分支；已有 Event 召回为空，继续判断是否 NEW；已有 Target 召回为空，继续判断新建条件。原文无作用对象另记为无适用 Target，不影响 Event 身份判断。此项与既有 AI-02 审查 A02-04相关，应一并修正，避免重复维护不同解释。

**验收**：没有抽取候选、有 Fact 但无已有 Event、有 Object 但无已有 Target，分别走正确分支。

### T-05：技术任务说明仍有旧编号和旧步骤，不能作为当前流程直接实施

**优先级：中。性质：已声明的同步欠账，不认定为新的线上故障。**

**建议**：后续同步时以“任务编号＋名称＋版本＋适用状态”建立明确对应，补齐 AI-07（Target 同一性判断）的技术交接，统一正式保存的章节称谓。保留旧实现的历史依据，但不能仅把旧任务改名后复用其输入输出；未完成适配前不发布新任务包。

## 4. 已经明确、应继续保留的规则

- Step 2 由程序转换，AI-02（Event 同一性判断）只比较 Event，AI-07（Target 同一性判断）只比较 Target。
- Target 的分类、别名、范围均由主表字段表达；AI-07 当前定义没有要求恢复三张已取消的表，也不要求 target_code。
- 别名只辅助召回，不能单凭同名复用；范围包含关系不等于同一身份；停用的同一对象不能绕过治理重复创建。
- AI 不创建正式 ID，不直接写库；Target 在 Step 3 按治理核定建档，正式 Event 及 Event—Target 关系由 §4.8 保存，两者并非相互矛盾。
- 原文无作用对象、部分对象待定、执行失败分别处理；已核定的独立范围可以继续，不能把局部完成报成全部完成。
- AI-03（Event 增量识别）不决定正式 Target 身份，AI-04（Event 关联）处理已保存事件之间的关联，不能代替 Event—Target 直接关系核对。

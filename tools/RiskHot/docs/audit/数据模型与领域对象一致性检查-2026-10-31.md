## 2. 十一类对象对照

| 领域对象与依据 | 当前存储对应 | 结论与处理 |
| --- | --- | --- |
| InformationSource，L0 §4.3.1 | 外部 M1 sources；F01 source_id 引用；资料 metadata.source_config_basis 固定实际采用口径 | 外部身份、名称、定位、分类和启停沿用 M1；补充配置依据承载，不恢复独立信源版本表。M1 完整治理表设计不在本目录覆盖范围 |
| material，§4.3.2 | infomation.ingestion_material 及可选内容片段 | 原有身份、正文、来源、版本和时间相符；附件引用、内容覆盖及配置采用口径原先缺少明确契约，已在 metadata 中定义，新增契约待实施 |
| Fact，§4.3.11 | fact、fact_material、fact_evidence | 原主表缺少业务上明确的客体承载；新增可空 fact.object，保留独立身份、跨报道复用及唯一事件归属 |
| Event，§4.3.3 | event，采用 fact.event_id 指向的 Fact | 主体、行为、客体、发生时间、阶段、统一描述及一对多事实归属一致；维持当前事实模型，不恢复事件版本表 |
| Target，§4.3.4 | target；定义快照及事件引用 | 名称、分类数组、别名、辖区、范围、启停及定义版本一致；分类与身份分开，不增加分类/范围实体 |
| Variable，§4.3.5 | risk_variable_definitions；定义快照 | 十一属性与五类 data_type 相符；发现来源允许四类多选，四态 status 与 active 正式引用资格一致；物理 schema 仍待核定 |
| FactMaterial，§4.3.6 | fact_material(fact_id, material_id)，来源证据另由 fact_evidence 固定 | 多对多、supporting/conflicting、首次关联时间一致；补足已保存 Fact 至少一个来源的提交检查，来源与事件归属角色分开 |
| EventTarget，§4.3.7 | event_target、event_target_fact、event_target_definition | 结构基本一致；补足每项关系至少一条本事件 Fact 依据、必需定义引用及移除最后依据的检查 |
| EventTargetVariable，§4.3.8 | event_target_variable、event_variable_fact、event_variable_definition | 三元归属、关联说明与识别依据一致；change_direction/impact_status 属于变化结果，不再列入关系目标字段；补足必需依据约束 |
| VariableObservationrRecord，§4.3.9 | variable_observation_records | 十项核心属性中，身份、归属、值、单位、性质、时间、方式、状态已覆盖；精确取值来源与原文证据映射仍未覆盖，不能以共享变量事实集合替代 |
| EventRating，§4.3.10 | event_rating、event_rating_relation、event_rating_fact | 范围、期限、方法、维度、M、理由、状态及依据相符；financial_usages 不再作为评价目标字段，历史值兼容保留；补足孤立评价及依据完整性检查 |

观测单主表、FactMaterial、多来源 Fact 及 Fact 直接事件归属均沿用已确认约定；没有恢复 EventMaterial、EventFact 或独立观测证据表。

## 3. 已修订的差异

| 编号 | 原差异 | 目标修订与迁移边界 |
| --- | --- | --- |
| D01 | Fact 有客体业务属性，主表却没有承载字段 | 增加可空 object；原文可核验才回填，不能用 Target 或已融合 Event 倒推 |
| D02 | 本次变量提取仍限于 subject/action/target 单选及四种类型 | 按 Subject、Action、Object、Semantic Information 多来源和五类类型表达；本次片段证据与共享 discovery_sources 标签分开；旧包装须重新适配 |
| D03 | 三元变量关联强制保存方向与影响阶段 | 从目标关联字段移除 change_direction、impact_status；具体观测与变化结果分别承载，保留旧数据待核验，不机械迁成观测 |
| D04 | EventRating 仍将金融用途作为必填 JSON | 新评价目标结构退出 financial_usages；用途按独立功能保存，已有值只作兼容读取，新结果载体仍待设计 |
| D05 | 领域要求各正式关系有事实依据，存储只明确评价的最少依据 | 补全 Fact 来源、对象关联、三元关联、评价的最小依据及定义引用检查，涵盖删除、并发与受控改组 |
| D06 | material 的附件、覆盖与采用信源配置口径缺少可检查的保存契约 | 定义 metadata.attachments、content_coverage、source_config_basis；未记录不冒充完整或无附件，不用最新配置反推历史 |
| D07 | 观测设计称已落实全部核心属性，但来源和原文映射仍空缺 | 改为部分覆盖，明确具体观测依据缺口与正式核验前提，保留现有16列及DDL |

本轮只将设计中的目标字段与规则改正确；V1.11、V2.2 的实际 SQL 和应用适配仍待实施。既有业务数据不因文档删除字段而丢弃，历史测试不能证明本次修订已实现。

## 4. 保留的设计缺口

| 缺口 | 业务依据与当前限制 | 完成条件 |
| --- | --- | --- |
| 精确观测—Fact—原文映射 | L0 观测属性与多对多取值依据已明确，字段映射仍待定；同一三元关系的全部事实不能自动等于每条观测的实际依据 | 定义单条观测采用的事实、资料版本、精确证据及更正历史的持久化契约，验证跨事件拒绝和逐条读取；不自行恢复已删除表 |
| 本次变量提取及待关联结果 | 业务允许无正式 Target/Variable 时先识别及取值，正式三元表不允许伪造身份 | 定义处理结果身份、来源列表、候选引用、采用口径与重试保存协议；再发布机器 Schema |
| 独立金融用途结果 | 领域已从 EventRating 职责拆出，当前无专门权威表结构 | 明确结果身份、事件/Fact/证据、方法、分类及生效规则；完成前不删除旧评级用途字段的数据 |
| M2 物理 schema 与外部治理边界 | 定义表业务属性已定，跨 schema FK、候选治理与审核等专门结构仍未确定 | 在所属技术设计中确定 schema、权限及有效定义引用实施方式，不靠默认搜索路径上线 |
| M1 完整存储与历史采用口径 | 本目录只定义外部来源引用及部分属性，不是完整信源治理模型 | 完整表结构由 M1 主责维护；新采集固定实际配置依据，旧未记录值保持未知 |

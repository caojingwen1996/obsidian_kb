## 2. 目标、范围与业务边界

### 2.1 业务目标

系统应把可信宏观资料转换为可追溯事件，识别并持续管理具体风险，基于时间截止内的证据形成风险状态与变化判断，再向用户提供可检索列表、详情、时间线及周期报告。使用者应能从任一正式结论回到当时的风险定义、变量机制、数据版本和原文依据。

### 2.2 首版包含的能力

1. 配置宏观对象、变量、风险源、风险类型、指标映射、评级规则和分析版本。
2. 管理可信信源，采集或人工补录资料，识别、归组、更新事件并评价金融意义 M。
3. 从事件一次形成完整风险候选，再匹配、复用或新建 MonitoredRisk，维护其观察配置与跟踪状态。
4. 从指标和事件分析来源压力、应对效果、两股力量、实际影响及损害，形成当前快照和历史变化分析。
5. 提供最新风险、最严重风险、完整目录、详情与 Timeline，以及日报、周报、月报的编制、发布、撤回与修订。
6. 提供人工复核、任务调度、失败恢复、权限、审计和历史追溯。

### 2.3 范围外

首版不独立纳管行业、企业、单项资产的微观风险；不做交易下单、仓位调整、收益预测或用户投资应对决策；不做市场影响力、传播热度或潜在冲击排名；不增加 L0 的独立 C 事实可信度分和 P 优先级分；不为 Target 预设固定 Variable 集合。

电子邮件、社交媒体、短信等外部推送，以及开放互联网匿名发布不属于本版必需交付。本文“发布”指进入系统获授权读者的可见范围，“分发”指层间结果交付；二者不等于向外部发送消息。报告下载属于授权用户主动操作。

### 2.4 端到端业务闭环

资料接入 → 原文版本与出处 → 事件及更新 → 完整风险候选 → 同一性匹配与纳管 → 变量和证据准备 → 当前状态快照 → 历史变化分析 → 校验与审核 → 列表、详情和报告 → 后续观察或回到 L1 维护。

用户可从事件页发起识别，从已纳管风险页发起观察，从报告中心编制报告；人工入口和自动入口遵循相同业务校验。任一分支待复核不阻塞其他独立事件或风险，系统应明确展示部分完成情况。

## 3. 用户角色、权限与操作入口

### 3.1 角色定义（N）

| 角色 | 主要职责 | 典型入口 |
| --- | --- | --- |
| 阅读者 | 查看已发布风险产品及允许查看的证据 | 风险总览、风险目录、风险详情、报告中心 |
| 研究员 | 维护草稿、发起识别／观察、核对证据、提交复核 | 信息工作台、风险工作台、分析工作台 |
| 业务审核员 | 审核纳管、身份调整、配置变更、分析结果和报告 | 复核中心、差异对照页 |
| 系统管理员 | 配置来源接入、账号权限、调度、运行恢复 | 配置中心、运行中心 |
| 系统任务／AI | 按配置执行程序处理或生成分析建议 | 任务详情；不拥有人的业务审批权 |

角色可由同一自然人兼任；每次关键操作均记录实际操作者及所用权限。首版不强制不同人员双签，审核与发布仍为显式动作。管理员只有同时获得业务审核权限时，才可确认业务判断。具体人员授权名册属于上线配置。

### 3.2 权限矩阵（N）

| 操作 | 阅读者 | 研究员 | 业务审核员 | 系统管理员 |
| --- | --- | --- | --- | --- |
| 已发布列表、详情、报告与下载 | 是 | 是 | 是 | 是 |
| 读取原文及内部分析草稿 | 按证据阅读授权 | 是 | 是 | 按数据权限 |
| 补录资料、发起识别／观察、修改草稿 | 否 | 是 | 是 | 仅故障恢复，不改研究判断 |
| 确认新风险、恢复关闭风险、改变正式定义 | 否 | 提交申请 | 是 | 否 |
| 确认事件归组调整、变量候选与正式配置 | 否 | 提交建议 | 是 | 维护接入配置 |
| 分析结果批准、修订或撤回 | 否 | 提交申请 | 是 | 否 |
| 编制报告草稿 | 否 | 是 | 是 | 否 |
| 发布／撤回报告 | 否 | 否 | 是 | 否 |
| 用户授权、运行参数、调度启停、技术重试 | 否 | 本人任务允许重试 | 业务任务允许重试 | 是 |
| 查询业务审计 | 否 | 自身及所管对象 | 是 | 是，凭据不展示 |

服务端必须实施同等校验，不能仅隐藏按钮。读取资料、导出文件和后台任务也遵守权限。失去权限不会抹去历史操作身份。

### 3.3 用户主要操作路径

- **研究新线索**：信息工作台 → 原文详情 → 查看事件 → 发起风险识别 → 候选对照 → 提交纳管／关联审核。
- **跟踪已有风险**：风险目录 → 风险详情 → 发起本轮观察 → 检查证据 → 查看当前状态与变化 → 提交审核 → 正式产品更新。
- **查看风险**：总览选择列表 → 筛选 → 风险详情 → 当前状态／变化／变量依据／Timeline → 原文版本。
- **制作报告**：报告中心 → 选择日报／周报／月报及周期 → 生成草稿 → 核对纳入条目 → 提交审核 → 发布 → 查看历史版本。
- **处理异常**：运行中心或复核中心 → 查看对象、失败阶段及原因 → 补资料／改草稿／重试 → 查看恢复结果及下游状态。

## 4. 全局业务规则与状态

### 4.1 跨模块不变量

| 编号 | 必须保持的业务约束 |
| --- | --- |
| BR-G-01 | Source 是信息发布来源；RiskSource 是致险类别；两者的 ID 不通用 |
| BR-G-02 | Event Target、风险观察对象、潜在损害对象、实际受影响主体分别表达，不能直接复制代替分析 |
| BR-G-03 | M 是事件金融意义；risk_level 是当前严重程度；trend 是相对历史方向；tracking_status 是跟踪管理状态，四者不互相转换 |
| BR-G-04 | 未知、缺失、不可比、无结果、技术失败分别表达；不得默认映射成 0、低风险、稳定或无风险 |
| BR-G-05 | AI 提供候选与分析；程序分配正式身份、校验引用和执行状态迁移；需审核的动作不能由 AI 自授权限 |
| BR-G-06 | 正式结论均有有效证据或明确待判断说明；原文、历史定义及分析版本保持可追溯，修订不覆盖过去判断 |
| BR-G-07 | 重复输入不重复创建业务实体、更新、快照或发布结果；有意重新分析必须登记新运行及原因 |
| BR-G-08 | L0 维护事件，L1 维护风险及长期配置，L2 维护当前状态与变化，发布模块只组织已可消费结果 |
| BR-G-09 | 数据保存与交付相互关联；保存失败不通知成功，交付失败可重试且不重新生成已保存业务对象 |
| BR-G-10 | 同一证据可被多处引用，不得因为多个变量、来源或角色引用而重复计量同一压力 |
| BR-G-11 | 页面、列表、报告显示截止时间、版本及不足；没有新消息不能作为风险维持的充分依据 |
| BR-G-12 | 已引用对象不提供物理删除业务操作；采用停用、失效、修订或撤回，历史引用仍可查看 |

### 4.2 时间口径（A+N）

发布时间、资料采集时间、事件发生／计划时间、指标观测期、指标发布时间、分析截止时间 snapshot_time、记录生成时间和发布时间（产品）分别保存或可追溯。默认业务时区建议为 Asia/Shanghai，可配置；展示必须明确时区。日期区间采用起点包含、终点不包含的口径。

本版建议“当时可用证据”取发布时间与系统首次取得该版本时间的较晚者，不晚于分析截止时间。后续补采的历史资料不进入当时判断的无痕重算；用户选择“追溯重算”时必须标记事后获取，原结果保留。首次可用时间不明时排除其作为确定判断的依据，展示缺口。该运行约定为 N，详细字段见 D-08。

未来计划可以用于持续性条件分析，必须以截止时间前已公开且已取得的计划为依据；未来预计生效日不等于已经生效。月份或季度精度不得虚构成精确日期；采集时间不得代替未知发布时间。

### 4.3 处理任务状态（N）

| 状态 | 进入条件 | 允许操作与后续 |
| --- | --- | --- |
| 待执行 | 请求校验通过且已登记 | 开始、取消；重复提交返回同一任务 |
| 执行中 | 工作节点已接收 | 查看进度；申请取消；不可再次并发提交相同运行 |
| 待补齐 | 缺少来源、必要配置或有效引用 | 展示缺口和责任角色；补齐后从受影响阶段恢复 |
| 待复核 | 存在身份歧义、证据冲突或审核事项 | 认领、退回、确认；不能直接绕过校验 |
| 部分完成 | 多子项中有成功、失败或待复核 | 成功项可按各模块规则交付；分别重试未完成项 |
| 已完成 | 约定结果已保存，交付情况可追踪 | 查看结果；有意重算另建运行 |
| 失败 | 技术错误且当前尝试结束 | 展示错误类别、重试资格；重试保留同一业务请求身份 |
| 已取消 | 取消在安全边界生效 | 未提交结果不再提交；已正式保存结果不回滚，列出已完成项 |

“无宏观事件”“未识别具体风险”“方向待判断”是业务处理结果，不是技术失败。失败次数和重试记录属于运行记录，不改变领域身份。

### 4.4 风险跟踪状态（A：取值；N：迁移）

| 当前状态 | 动作与目标状态 | 前置条件／权限 | 对持续观察的影响 |
| --- | --- | --- | --- |
| 未纳管候选 | 纳管 → observing | 审核员确认，符合 FR-L1-04 | 发起首次观察；候选不提前出现在正式目录 |
| observing | 转监控 → monitoring | 有可执行观察计划，审核员确认理由 | 执行已启用计划 |
| observing／monitoring | 暂停 → paused | 填写原因，由审核员确认 | 停止后续自动观察；在途结果提交前复核状态 |
| observing／monitoring／paused | 结束 → closed | 填写结束理由和依据，由审核员确认 | 停止自动观察，保留全部历史 |
| paused | 恢复 → 原活动状态或 observing | 复核定义、变量与计划，显式选择目标状态 | 恢复后产生新观察请求 |
| closed | 恢复 → observing | 先验证风险同一性与有效配置，审核员确认 | 复用原 risk_id；保留原 admitted_at 与新增恢复记录 |

禁止自动将 easing、recovery 或 confirmed 映射为 paused／closed。暂停和关闭不等于风险解除。关闭后出现实质不同的风险须重新识别，不为复用身份而覆盖原定义。

### 4.5 分析结果与报告状态（N）

分析结果采用工作流状态：草稿 → 待审核 → 已批准；退回进入草稿，撤回进入已撤回。只有已批准且未撤回、引用有效的结果可供产品使用。状态属于结果管理元数据，不新增风险评价维度。重算产生修订版本，旧版本保留。

报告采用：草稿 → 待审核 → 已发布；退回进入草稿；已发布 → 已撤回；修改已发布内容必须新建修订草稿、重新审核。报告页保留报告身份、版本、周期、数据截止时间、发布／撤回时间和理由。

本版默认人工审核新风险、正式配置变更、分析结果及报告，自动化完成采集、计算、候选生成与草稿编排。自动纳管／自动发布只有在相应业务决策定版后才启用；不得把这项默认人工流程解释为需要开发人员每次线下找人改数据库。

## 6. 共享配置功能

### FR-CFG-01 宏观作用对象与展示分类管理

- **来源／角色／触发**：A+N；S0 §3.3、4.5.4，S1 §3.3，S3 §3.3；研究员提出对象或分类，审核员确认。
- **输入／前置**：对象名称、代码、类型、国家／辖区、范围说明为必填；父对象和别名可选。新增前查询相近名称、代码与范围。
- **操作与处理**：进入配置中心“宏观对象”→检索→选择复用或新建草稿→录入范围→查看重名提示→提交审核。确认后获得稳定 target_id；被引用对象停用时列出影响范围。市场展示分类独立维护经审核映射，不强迫所有经济体成为市场。
- **输出／规则**：L0 允许五类 Target；L1 观察对象仍只允许四类。类型、辖区或语义边界改变须建立新版本或新对象，不原地改变历史身份。父级关系不能循环。
- **异常**：代码冲突阻止保存；相同名称但范围不同提示并要求解释；无法确认范围保留草稿；已被引用对象不允许物理删除。
- **验收**：AC-CFG-01-1：两个事件选择同一已确认对象，返回相同 target_id；AC-CFG-01-2：企业类对象不能作为首版独立宏观 Target 或 L1 观察对象通过；AC-CFG-01-3：对象停用后旧事件可读，新引用被拒绝。

### FR-CFG-02 全局变量与候选治理

- **来源／角色／触发**：A+N；S0 §3.4、4.5.5，S1 §4.6；研究员处理 L0／L1 产生的变量候选，审核员确认。
- **输入／前置**：名称、定义、观测边界、单位／状态项说明、已有变量候选与提出理由。
- **操作与处理**：打开变量候选→并排查看相近定义→选择“关联已有变量”“补全并新增”“驳回”→填写理由→审核。系统生成或复用真实 variable_id，再恢复受阻任务；新增变量不自动绑定全部 Target。
- **输出／规则**：统一 variable_config；同义名称作为别名或候选线索，口径不同不强行合并。候选未确认前只能有名称，不能出现伪造的正式 ID。
- **异常**：单位或定义冲突退回补充；停用变量对历史保留引用；候选重复提交汇入同一处理事项或返回既有处理结果。
- **验收**：AC-CFG-02-1：AI 提出未知变量时正式字典数量不增加；审核复用后受阻任务引用既有 ID；AC-CFG-02-2：不同国家或期限口径相同名变量不会被仅凭名称自动合并。

### FR-CFG-03 风险源与风险类型配置

- **来源／角色／触发**：A+N；S1 §4.8—4.9；研究员维护定义草稿，审核员批准。
- **输入／前置**：代码、名称、定义、核心问题；风险源还包括 analysis_level、可选父分类。识别依据、分类边界、示例可作为附属说明维护。
- **操作与处理**：配置中心选择风险源／风险类型→创建或编辑草稿→校验编码和父级→查看引用风险→提交。初始化四类维度 fundamental、liquidity、valuation、sentiment；初始化 S1 的八类宏观风险源，不伪造预存 ID。
- **输出／规则**：代码解析为正式配置 ID；候选 dimension_code 为单值，纳管对象 risk_dimension_ids 为数组。宏观首版只启用 macro 风险源参与自动识别。父源与子源须同分析层次且无循环。
- **异常**：不存在的代码或 meso／micro 输入转复核；被使用配置停用前提示相关风险，新任务不得静默改用另一分类。
- **验收**：AC-CFG-03-1：八类宏观源和四类维度可检索、各有稳定唯一身份；AC-CFG-03-2：候选代码正确解析到 ID，代码错拼不能作为正式 ID 存入风险；AC-CFG-03-3：父分类循环被拒绝。

### FR-CFG-04 指标定义、变量映射与观测数据

- **来源／角色／触发**：A+N+D；S2 §3.2 BR-L2-04、5.1；研究员配置映射、审核员批准、系统或研究员接入数据；关联 D-03。
- **输入／前置**：指标名称、统计对象、地域、单位、频率、允许来源、时间口径；映射需指定 variable_id、适用范围与解释；观测数据需有实际值、观测期、发布时间、来源和版本。
- **操作与处理**：配置指标→选择变量并解释映射→审核生效→接入或人工导入数据→预览逐行校验→保存有效记录并列出失败行。首版建议采用人工审核的显式映射，允许一变量多指标、同一指标供多个变量引用。
- **输出／规则**：指标定义、变量映射和实际观测值分开管理；历史修订保留旧数据。单位转换、同比环比计算由程序完成并保留原值与公式口径；没有明确口径不计算。
- **异常**：缺单位、来源或时间标记不合格；空值不是零；来源冲突并存且转研究员确认，不能平均消除冲突；陈旧阈值未设时显示“时效未配置”。
- **验收**：AC-CFG-04-1：一变量可引用两项已确认指标，分析能追溯到各自版本；AC-CFG-04-2：10 条导入含2条缺单位，明确列出8条成功与2条失败且重试不重复；AC-CFG-04-3：后发修订不替换旧快照引用的原值。

### FR-CFG-05 金融意义与风险判定规则配置

- **来源／角色／触发**：A+N+D；S0 §3.6、7.2，S2 §3.3，S3 §3.3；业务审核员配置并批准；关联 D-01、D-02、D-04。
- **输入／前置**：规则类别、适用范围、版本、生效时间、业务定义、计算／判断条件、校准说明及测试样本。M、风险等级、阶段、节点规则分别管理。
- **操作与处理**：新建规则草稿→填写适用范围→运行样例预览→检查边界值→批准启用。风险等级字典维护名称和严重度顺序，判断规则维护如何得出等级；不同规则集必须显式声明可比较关系。
- **输出／规则**：已批准版本供后续运行使用；历史结果固定引用旧版。S0 候选 M 权重不默认投入生产；未批准时保留维度说明、M 空值。无适用风险等级规则时 risk_level 待判断。
- **异常**：权重、区间或适用范围不合法阻止启用；不同等级体系未完成映射进入不可比较集合；未配置节点确认条件不得输出 confirmed。
- **验收**：AC-CFG-05-1：未批准 M 权重时系统无正式总分且仍可继续识别；AC-CFG-05-2：同一输入按两个已明确指定的规则版本回算时保留两份结果及版本；AC-CFG-05-3：不可比等级不混排。

### FR-CFG-06 配置、Prompt 与模型版本管理

- **来源／角色／触发**：A+N；S0 §5，S1 §6，S2 §6；研究员提交业务配置，审核员批准；管理员维护运行版本。
- **输入／前置**：配置或提示词内容、用途、变更理由、版本号、生效范围及样本验证记录。模型只保存可识别版本与运行参数，不记录秘密凭据。
- **操作与处理**：复制当前版为草稿→差异查看→样例验证→批准→选择生效时间。启动任务时固定版本集合；运行中的任务不切换到刚发布的新版本。回退是重新指定可用版本，不删除历史。
- **输出／规则**：每次 AI 运行可定位输入、输出、Prompt、模型、Schema 与业务规则版本。版本治理是横向元数据，不把所有内容强行加入领域核心表。
- **异常**：版本缺失或不兼容时阻止新任务并标明缺项；被停用版本仍支持历史阅读；直接修改已生效版本被拒绝。
- **验收**：AC-CFG-06-1：任务执行中发布新 Prompt，当前运行仍引用启动版本，下一任务使用新版；AC-CFG-06-2：回退后历史结果与其原版本一致，凭据不出现在差异和日志中。

## 7. L0 信息处理功能

### FR-L0-01 信源登记、准入与启停

- **来源／角色／触发**：A+N；S0 §1.2、3.1、4.5.1；管理员维护接入，审核员确认准入。
- **输入／前置**：来源名称、唯一代码、官方定位地址、来源类别、采集范围和方式；原始发布主体及转载主体分别记录。S 为可选，不要求填分才能准入。
- **操作与处理**：信源管理→新建草稿→填写范围和准入依据→测试连接并预览一份资料→提交准入→启用。支持暂停、停用及恢复；状态改变须说明原因。采集任务启动及提交前检查信源有效性。
- **输出／规则**：准入结果与 InformationSource；未准入来源不可进入自动分析。停用不删除历史资料，历史证据可见且显示来源当前状态。信源状态不直接改变历史风险判断。
- **异常**：URL 不合法或连接失败显示具体原因；凭据失效转管理员处理；来源可连接但资质未通过不能自动启用。在途采集遇停用可保存原始响应为待检查材料，停止后续分析。
- **验收**：AC-L0-01-1：未准入／暂停来源不能启动新采集；AC-L0-01-2：来源停用后历史原文和快照仍可回溯；AC-L0-01-3：S 为空不阻止通过其他准入条件的信源生效。

### FR-L0-02 自动采集、人工补录与补采

- **来源／角色／触发**：A+N；S0 §2.2.1、3.1；系统按计划采集，研究员可指定信源和日期窗口补采。
- **输入／前置**：有效来源、采集范围；人工补录需选择已准入来源，提供原始 URL 或可定位资料标识、标题、正文／附件及时间信息。
- **操作与处理**：采集入口选择来源和窗口→预览任务范围→提交→查看逐条结果。人工补录先保存原始文本或附件及出处，再进入同一预处理流程；不得仅以研究员摘要作为“原文”。支持失败项重试和历史窗口补采。
- **输出／规则**：原始材料、采集时间、来源元数据、任务统计。未知发布时间留空并提示补齐，不以抓取时间补造。人工上传的资料仍需来源准入，不绕过白名单。
- **异常**：网络超时可有限重试；无正文、无法打开附件、不可定位来源进入待补齐。批次部分失败不撤销已成功资料。历史补采按原文时间归档，不冒充当日新发布资讯。
- **验收**：AC-L0-02-1：同一窗口补采两次不增加重复业务记录；AC-L0-02-2：只有标题的长报告不能进入有效事件分析，任务显示待补正文；AC-L0-02-3：人工补录可追溯到提交者与资料出处。

### FR-L0-03 原文清洗、去重与版本保存

- **来源／角色／触发**：A+N；S0 §2.2.1、4.5.2；新资料或补采结果到达自动执行。
- **输入／前置**：原始内容、来源 ID、原始链接／外部 ID、发布时间、抓取时间。
- **操作与处理**：保留原始版本→抽取正文与附件定位→规范链接和时间→比较来源、外部标识、URL、内容指纹→判定相同版本、原文修订或新资料。在原文详情显示版本列表和内容差异。
- **输出／规则**：Information 及版本引用；同来源同版本复用，不再触发重复处理；同 URL 内容修订新增版本；不同来源同内容保留各自来源关系。清洗不能改变原文数值、否定词、单位与时间。
- **异常**：正文抽取不完整进入待补齐，原始内容仍保存；时间无法解析保留原始文字及未知标记；修订关系无法确认转复核，不能覆盖旧内容。
- **验收**：AC-L0-03-1：同一公告抓取3次只有一个有效资料版本；AC-L0-03-2：同 URL 把数值2改为3产生修订且旧值仍可查看；AC-L0-03-3：两家来源转载同一内容仍可查到两个出处。

### FR-L0-04 事件抽取与原文定位

- **来源／角色／触发**：A+N；S0 §2.2.2、3.2、5.1 AI-01；有效资料进入分析，研究员可从资料详情重新发起。
- **输入／前置**：指定 Information 版本、事件类型字典、有效分析版本。
- **操作与处理**：AI 提取0..N项宏观事件候选→程序检查主体、行为、时间语义、阶段、摘要与原文定位→研究员查看原文和候选对照。各候选独立进入归组，一份资料不强制对应一个事件。
- **输出／规则**：事件候选及其段落／页码／数据区块引用；没有宏观事件保存“未识别宏观事件”结果。预计、宣布、实施等阶段必须分别表达，宏观背景中的企业名称不自动成为独立 Target。
- **异常**：AI 结构不合法、引用片段不存在或无法识别主体行为进入复核／重试；不能用空事件占位。一个候选不合格不阻塞其他合格候选。
- **验收**：AC-L0-04-1：一份包含两项独立政策决定的材料生成两个候选且各有定位；AC-L0-04-2：无宏观事件材料正常完成，Event 数量不增加；AC-L0-04-3：计划未来实施的政策不被标成已生效。

### FR-L0-05 事件归组与身份判断

- **来源／角色／触发**：A+N+D；S0 §2.2.2、3.5；AI-02 建议，研究员处理疑难归组、审核员确认；关联 D-07。
- **输入／前置**：完整事件候选、相似事件及其来源、主体、行为、对象、时间范围和政策／行动标识。
- **操作与处理**：召回既有事件→逐项比较身份要素→返回“新事件／同一事件／无法判断”及理由→校验引用→新建或复用 event_id。用户在候选对照中可选择已有事件或提出新建，并填写差异理由。
- **输出／规则**：明确事件身份后才进行增量判断；同一政策宣布与落地通常共用身份；同机构不同时点的独立决定可为不同事件。未校准匹配阈值时不以相似度数值替代同一性说明。
- **异常**：多项匹配均合理时标记 UNRESOLVED；检索失败不等于“无匹配”，转重试；引用不存在的 event_id 拒绝保存。
- **验收**：AC-L0-05-1：两家机构描述同一决定得到一个 Event 和两个来源关系；AC-L0-05-2：同一主体两次独立决定不因标题相似而合并；AC-L0-05-3：检索服务失败不会自动创建新事件。

### FR-L0-06 事件作用对象与直接变量关联

- **来源／角色／触发**：A+N；S0 §2.2.3、3.3—3.4、4.5.7—4.5.8；AI-03 建议，研究员复核。
- **输入／前置**：已归组事件、宏观对象库、全局变量库、原文依据。
- **操作与处理**：识别直接作用对象→匹配或提出对象新增→建立 EventTarget→仅对有直接证据的变量匹配 variable_id→建立事件—对象—变量三元关联。界面按“对象→本事件涉及变量”组织，允许一个事件多个对象各有不同变量。
- **输出／规则**：三元关系须先存在对应 EventTarget；information_id 如填写必须属于该事件。没有对象可留空；有对象无变量仍保留对象关系。变量传导推演交给 L1／L2。
- **异常**：未知变量创建待审核候选，不填假 ID；对象类型越界拒绝；原文不支持变量方向时方向为未知。必要原文引用缺失的关系不进入正式关联。
- **验收**：AC-L0-06-1：同一 Target 在不同事件关联不同变量，无需预先配置 TargetVariable；AC-L0-06-2：央行政策利率公告只建立直接政策利率关系，不自动补入融资成本变化；AC-L0-06-3：已确定对象且未确定变量的事件仍可保存。

### FR-L0-07 增量分类与事件状态更新

- **来源／角色／触发**：A+N；S0 §2.2.4、3.5、4.5.9；AI-04 与程序在归组后执行。
- **输入／前置**：事件身份、当前资料版本、既有状态、来源和更新历史。
- **操作与处理**：复核事件身份→比较新增内容→判定增量类型→展示前后差异→生成相应记录。NEW_EVENT 生成首条更新；EVENT_PROGRESS、MATERIAL_ADDITION 追加更新；CORRECTION 追加纠正并保留旧状态；SOURCE_ADDITION 只增加来源；DUPLICATE 无重复更新；UNRESOLVED 转待归组。
- **输出／规则**：EventUpdate 保留变化适用时间和 recorded_at。状态 expected／announced／in_progress／effective／completed／cancelled／unknown 必须有来源支持；时间到达不会自动把 announced 改为 effective。纠正允许回退阶段，但需标记原因。
- **异常**：迟到资料按双时间轴保留，不能用较旧状态覆盖已经验证的新状态；增量无法区分转复核；互相矛盾的来源并列保留并登记冲突。
- **验收**：AC-L0-07-1：仅增加出处不增加实质进展通知；AC-L0-07-2：宣布、正式实施形成同一 Event 的两个阶段记录；AC-L0-07-3：重复更新不产生第二条 EventUpdate；AC-L0-07-4：过了计划日期但没有实施证据，状态不自动推进。

### FR-L0-08 金融意义评级与复评

- **来源／角色／触发**：A+N+D；S0 §2.2.5、3.6、4.5.10；新增事件或评级依据改变时触发 AI-05；关联 D-01。
- **输入／前置**：事件、对象、直接变量、明确 assessment_scope、研究期限、有效方法版本。
- **操作与处理**：固定评价范围及期限→生成维度判断、用途标签与依据→程序校验分值和规则→保存 EventRating。研究员可提出复评并填写理由；纯来源增加默认沿用已有评级，有实质内容再按更新规则处理。
- **输出／规则**：用途 investment、financing、speculation_sentiment 可多选或待判断；用途不直接决定高低。规则未批准时总分为空并显示草案状态，维度说明仍可保存。正式评级保留 method_version 和历史记录。
- **异常**：超范围分值、缺范围或缺方法版本拒绝确认；模型失败不阻塞有效事件的保存，但评级显示未完成；评级未完成不能伪装成 M=0。
- **验收**：AC-L0-08-1：无已批准权重仍能查看事件和维度说明，M 显示未定；AC-L0-08-2：同事件因实质新证据复评保留前次结果；AC-L0-08-3：M 高不自动产生高风险或纳管结论。

### FR-L0-09 事件检索、人工校正与归组调整

- **来源／角色／触发**：A+N+D；S0 §2.2.6、3.5、7.2；研究员提出校正，审核员确认；关联 D-07。
- **输入／前置**：事件、相关来源与历史、校正内容和依据；合并／拆分需提供目标事件及受影响关系清单。
- **操作与处理**：按关键词、主体、对象、状态、类型、发生／更新时间、M 范围筛选→查看事件详情→提交字段校正或合并／拆分建议→预览对 L1、快照和报告的影响→审核。新修订改变当前展示，历史保留原引用及修订提示。
- **输出／规则**：校正保留操作者、前后值和依据；事件合并保留旧 ID 的可解析入口；拆分逐一说明资料和下游关系归属。旧快照／报告固定版本不被批量改写。
- **异常**：仍有无法归属的下游引用时不执行归组调整；并发修改按版本冲突处理。D-07 未确认前提供建议和复核队列，但关闭自动迁移功能。
- **验收**：AC-L0-09-1：按事件详情能回看校正前后文字与原文；AC-L0-09-2：合并／拆分影响无法确定时操作被阻断，正式引用保持有效；AC-L0-09-3：启用已定版归组调整后，旧 ID 可定位到历史对象和调整说明。

### FR-L0-10 事件保存与下游交付

- **来源／角色／触发**：A+N；S0 §2.2.6、6.1；程序在单个事件结果校验通过后执行。
- **输入／前置**：Event、来源、对象、变量关联、增量和可选评级；所有引用有效。
- **操作与处理**：统一校验→一致保存事件及相关变更→登记交付记录→按实际变化交付创建、更新、评级更新、仅来源增加四类语义。交付状态可在任务与事件详情查看，失败支持补交付。
- **输出／规则**：只有保存成功的稳定 ID 和版本进入下游。原文已保存但结构化结果失败时，保留原文供恢复；不展示半完成事件为正式结果。交付机制不限定消息总线。
- **异常**：保存失败回滚本事件未完成的业务变更；通知失败保留已保存结果并仅重试通知；同一通知再次到达下游返回既有消费记录。
- **验收**：AC-L0-10-1：模拟关联保存失败，不出现缺少必需来源的正式 Event；AC-L0-10-2：保存后交付失败再重试，事件和更新数量不增加；AC-L0-10-3：DUPLICATE 不产生新业务通知。

## 8. L1 风险识别与纳管功能

### FR-L1-01 风险识别触发与上下文准备

- **来源／角色／触发**：A+N；S1 §2.2.1、5.1；L0 新事件／实质更新或研究员从事件详情发起。
- **输入／前置**：已保存 Event／EventUpdate、时间语义、对象、直接变量、原文定位及可用 M。
- **操作与处理**：登记请求→检查是否已处理该事件输入版本→准备完整上下文→执行识别。默认新事件、进展、实质补充、纠正触发；仅来源增加补证据索引、评级变化更新阅读排序，不默认全量重新识别。人工重算需理由。
- **输出／规则**：有效识别任务或重复跳过记录；M 为空不阻止识别，也不因低 M 判为无风险。人工入口不另行重采原文。
- **异常**：找不到输入版本或原文引用时待补齐；上游仍在纠正时锁定指定版本而非混读；同一事件多次快速更新可合并待执行任务，但必须列出所含更新并保留每个通知的处理去向。
- **验收**：AC-L1-01-1：同一 EventUpdate 通知三次只有一项有效识别运行；AC-L1-01-2：M 未定事件仍可形成风险候选；AC-L1-01-3：仅来源新增默认不重复生成完整风险候选。

### FR-L1-02 一次形成完整风险候选

- **来源／角色／触发**：A+N；S1 §2.2.2、4.6、6.1 AI-L1-01；系统识别，研究员核对。
- **输入／前置**：事件上下文、风险源／维度配置和变量字典。
- **操作与处理**：识别风险问题及潜在损害→界定观察对象与范围→解释来源和传导→识别 damage_targets 及暴露依据→选择变量与角色→汇总候选→结构和引用检查。候选一次形成，匹配阶段直接使用，不再次独立生成另一套定义。
- **输出／规则**：0..N项 RiskIdentificationResult，保持 S1 的12项字段及 key_variables 的5项字段。damage_targets 可空但说明不确定性；每个损害对象的机制和依据能够对应。候选无正式 risk_id，允许按运行工件保存待处理内容，不提升为独立领域聚合。
- **异常**：无具体风险记录“当前资料未识别具体风险”，不等于整体安全；证据不足或微观对象越界转复核；未知变量保留候选名，variable_id 留空。
- **验收**：AC-L1-02-1：一个事件可生成两项独立风险，各有定义、对象、机制、变量及证据；AC-L1-02-2：损害对象包含企业群体不会自动为每家企业纳管；AC-L1-02-3：无风险候选正常完成且不分配 risk_id。

### FR-L1-03 风险检索、同一性匹配与复核

- **来源／角色／触发**：A+N；S1 §2.2.3、3.2、6.1 AI-L1-02；系统匹配，研究员／审核员处理歧义。
- **输入／前置**：完整候选及所有跟踪状态的既有风险，包括 paused 和 closed。
- **操作与处理**：按定义检索→对照 definition、observation_target、scope_boundary→辅助比较名称、损害对象、机制、来源、维度、变量→给出“复用／未匹配／待复核”及理由。界面显示候选与匹配项的逐项差异，人工结论须说明依据。
- **输出／规则**：匹配成功复用真实 risk_id；风险源或触发事件不同不必另建风险；名称相同不能覆盖核心范围差异；检索无结果仍须经过准入。匹配到关闭风险转恢复审核，不能直接重新开一个同义风险。
- **异常**：召回失败、多个候选部分覆盖或机制冲突均待复核；不存在的 ID 拒绝。两个并发候选可能同一风险时，正式纳管前再次检查。
- **验收**：AC-L1-03-1：不同事件揭示同一风险时只复用一项 MonitoredRisk；AC-L1-03-2：同名不同范围不能自动复用；AC-L1-03-3：关闭风险可被召回且不会自动恢复；AC-L1-03-4：检索故障不作为新建依据。

### FR-L1-04 新风险准入与正式纳管

- **来源／角色／触发**：A+N+D；S1 §2.2.3—2.2.4、4.3；研究员提交，审核员确认；关联 D-05。
- **输入／前置**：未匹配候选、明确风险问题／潜在损害、四类宏观观察对象之一、范围、机制、有效事件依据，以及可执行观察条件。
- **操作与处理**：纳管预览核对全部候选内容→列出缺失条件与相似风险→审核员选择“纳管／退回／暂缓”并说明理由→提交前重查同一性与引用→一致创建风险、初始变量关系和初始事件关系→交付 L2。
- **输出／规则**：系统生成 risk_id、admitted_at，初始 observing。本版建议至少有1项已确认变量关系且有可用指标映射或可定位事件观察路径；数量只是可执行性的最低门槛，不代表证据充分，也不强制四种角色各1项。缺损害对象可在明确机制及不确定性后由审核员决定，不编造对象。
- **异常**：全部变量均待审核、缺原文、引用无效或宏观范围不合格时不能纳管；审批期间发现已纳管同项风险，返回复用路径；任一初始关系保存失败不出现半完成正式风险。
- **验收**：AC-L1-04-1：纳管成功后 risk_id、变量关系、事件关系和 admitted_at 同时可查；AC-L1-04-2：两人同时纳管同一候选，最多创建一个正式风险；AC-L1-04-3：关键条件缺失时列明原因，候选仍保留且不进入今日新增。

### FR-L1-05 风险定义与长期变量配置维护

- **来源／角色／触发**：A+N+D；S1 §2.2.3、4.3—4.4、4.6，S2 §3.2 BR-L2-03；研究员因事件或 L2 反馈提出，审核员确认；关联 D-08。
- **输入／前置**：现行风险定义、候选改动、证据、影响说明；变量配置需风险源身份、variable_id、角色及作用机制。
- **操作与处理**：风险详情“观察配置”→复制为变更草稿→逐项增改停用→预览范围、机制及引用影响→审核。仅措辞澄清可保留风险身份；核心问题或观察范围改变须重新执行同一性审查，可能转新风险，不得作为普通编辑覆盖。
- **输出／规则**：保留版本与生效时间。四种变量角色为 risk_driver、risk_transmission、risk_buffer、damage_verification。正式关系不存当次数值；同变量可在不同源／角色下有独立说明，但完全相同配置不重复建立。历史快照继续解析旧关系和机制。
- **异常**：新变量无真实 ID 转候选审核；同变量多角色存在矛盾时复核；配置停用导致无可执行观察条件时列入阻断清单，不能静默继续。
- **验收**：AC-L1-05-1：修改机制后新观察使用新版，旧快照仍展示旧版；AC-L1-05-2：修改范围不能绕过身份复核；AC-L1-05-3：两种角色引用同一证据时不产生两份重复压力计量。

### FR-L1-06 风险与事件关联维护

- **来源／角色／触发**：A+N；S1 §4.5；匹配／纳管结果形成，或研究员提出关联纠正。
- **输入／前置**：正式 risk_id、event_id、关联原因、可选首次 event_update_id。
- **操作与处理**：验证风险与事件身份→验证更新属于该事件→建立或复用有效关系→展示关联理由与首次依据。后续进展沿 event_id 查找，不覆盖首次 event_update_id；关联失效／恢复由审核员确认原因，保留操作历史。
- **输出／规则**：使用既有八字段 monitored_risk_event_relation；业务上不重复建立同一有效关联，物理唯一键设计另定。失效关系停止作为新增自动观察入口，旧快照证据仍可追溯。is_active 不代表风险方向。
- **异常**：候选 risk_id、跨事件 update_id、空理由被拒绝；重复请求返回原关联；恢复同一关联优先复用既有关系身份并追加审计，不重置首次依据。
- **验收**：AC-L1-06-1：事件后续更新两次，关联的首次 update_id 不变且 L2 能取到后续更新；AC-L1-06-2：错误 update_id 所属事件被拒绝；AC-L1-06-3：重复关联只产生一项有效业务关系。

### FR-L1-07 跟踪状态变更、暂停与恢复

- **来源／角色／触发**：A+N；S1 §1.4、3.1；研究员申请、审核员按第4.4节执行。
- **输入／前置**：目标风险、当前版本、拟变更状态、原因及必要证据；恢复须核验定义、变量和计划。
- **操作与处理**：风险详情选择状态动作→查看在途任务和后续计划影响→填写理由→审核→改变状态→同步调度和产品读取。paused／closed 的人工回溯分析需审核员明确许可，并标记用途；不能借人工观察偷偷恢复自动跟踪。
- **输出／规则**：状态历史、恢复记录、调度变更；已关闭风险恢复保留 risk_id 和首次 admitted_at。“今日恢复”与“今日新增”分别统计。关闭不删除报告和快照。
- **异常**：版本冲突要求重新确认；在途任务已完成计算但尚未正式提交时，重新检查状态，暂停提交并交审核员；已正式保存结果保留，按结果管理流程决定可消费性。
- **验收**：AC-L1-07-1：暂停后不新建自动观察任务；AC-L1-07-2：关闭后恢复复用原 ID 且不进入今日新增；AC-L1-07-3：L2 发现风险减弱不能直接关闭风险。

### FR-L1-08 纳管结果交付与变更通知

- **来源／角色／触发**：A+N；S1 §5.2—5.3；正式纳管、有效事件关联、定义配置生效或跟踪状态变化后执行。
- **输入／前置**：已保存风险定义版本、变量关系版本、关联事件及本次变化。
- **操作与处理**：验证正式身份和初始配置完整→形成交付记录→区分新风险、事件关联、配置变更和跟踪状态变化→通知 L2。用户可查看“已保存／待交付／已交付／下游待处理”的独立状态。
- **输出／规则**：交付包含观察对象、范围、damage_targets、机制、变量角色和作用说明、事件更新集合与追溯定位。配置变更为本版新增业务交付语义，不预设消息名称；不能仅发送标题导致机制丢失。
- **异常**：交付失败仅补发已保存版本；L2 暂停不回滚 L1；已纳管但缺初始关联的半完成对象不得交付。重复通知不重复启动同一观察。
- **验收**：AC-L1-08-1：下游能从交付信息还原本轮适用定义与变量配置；AC-L1-08-2：重发不会新增风险或重复首次观察；AC-L1-08-3：下游不可用时正式纳管记录保留且显示待交付。

## 9. L2 风险态势分析功能

### FR-L2-01 观察发起、截止时间与基准选择

- **来源／角色／触发**：A+N+D；S2 §2.2.1、3.2 BR-L2-01／02／12；新纳管、有效事件／指标更新、定期或人工观察；关联 D-03、D-06。
- **输入／前置**：正式 risk_id、适用定义与配置、snapshot_time、触发来源、可选比较快照。
- **操作与处理**：用户在风险详情选择“发起观察”→指定截止时间→查看数据覆盖和默认历史基准→必要时更换基准并说明原因→提交。系统默认选择截止时间更早、同风险、已批准且未撤回、口径可比的最近快照；不存在则无基准。自动触发使用计划中的截止规则。
- **输出／规则**：固定本轮风险、证据可用边界与配置版本。新纳管可立即进行首次观察；paused／closed 按 FR-L1-07 控制。周期无新数据仍可复核已知条件并生成一次周期观察，但必须标记证据未更新，不能自动填写 stable。
- **异常**：基准属于其他风险或时间晚于本轮时拒绝；范围变化导致不可比时保留当前观察，变化待判断；重复触发返回已有运行，主动重算另记原因。
- **验收**：AC-L2-01-1：首次观察不要求伪造历史快照；AC-L2-01-2：未来快照和其他风险快照不能选为基准；AC-L2-01-3：周期无新数据不会直接输出风险维持。

### FR-L2-02 指标与事件证据准备

- **来源／角色／触发**：A+N+D；S2 §2.2.1、3.2 BR-L2-02／04；系统准备，研究员补充或核验；关联 D-03。
- **输入／前置**：本风险有效变量关系、指标映射、截止时间、相关事件及更新、历史数据。
- **操作与处理**：逐变量读取定义与机制→获取适用指标及历史窗口→按范围、单位、时间和版本校验→补充必要事件→标注缺失、过期、冲突与反证→形成证据清单。通过 event_id 取截止时间内相关后续更新，不局限于首次关联更新。
- **输出／规则**：每个值有单位、统计对象、观测期、发布时间、来源版本及取得时间；事件有状态及原文定位。指标充分时不强制补事件。研究员补证据必须经同样时间与来源校验，不能直接粘贴无出处结论。
- **异常**：部分缺失可进入受限分析；风险身份无效、全部依据不可用或引用无法定位时待补齐。冲突证据都保留，选用哪项须解释；不能混用不同季调／非季调口径。
- **验收**：AC-L2-02-1：首次关联之后的第三条相关更新可进入本轮证据；AC-L2-02-2：截止时间后才取得的修订数据不能混入普通历史观察；AC-L2-02-3：缺指标显示缺失，不以0填充。

### FR-L2-03 关键变量当前状态与风险作用分析

- **来源／角色／触发**：A+N+D；S2 §2.2.2、3.2 BR-L2-03／05、4.4.1；AI 共用分析任务执行，研究员复核；关联 D-02。
- **输入／前置**：relation_id、变量定义、角色、作用机制及本轮证据。
- **操作与处理**：归纳 observed_state→引用 evidence_content／source_refs→核对作用机制的条件→判断 risk_effect→记录 interpretation、uncertainty。页面并列显示“观测事实”“当前状态”“对风险作用”“依据与限制”。
- **输出／规则**：risk_snapshot_variable_analysis 明细；relation_id 必须属于本轮风险。候选作用值 pressure、relief、neutral、undetermined 采用本版工作语义，正式编码按 D-02 定版；角色不能自动决定实际作用。
- **异常**：有数值变化但作用条件不足时状态可确定、作用待判断；neutral 须有“未显示明确作用”的证据，不能代表缺数据；模型未返回某项变量必须列为漏项，不直接丢弃。
- **验收**：AC-L2-03-1：驱动变量下降但机制条件不明，不自动判为 relief；AC-L2-03-2：当前变量状态与作用可以分别确定和待判断；AC-L2-03-3：其他风险的 relation_id 被拒绝。

### FR-L2-04 风险来源与传导压力分析

- **来源／角色／触发**：A+N；S2 §2.2.2 的2.1、6.1 AI-L2-01；证据准备完成后执行。
- **输入／前置**：risk_driver、risk_transmission 变量明细、风险源分类、L1 整体机制。
- **操作与处理**：按风险源组织变量→判断推动力量当前水平→检验传导条件是否出现及进展→说明压力作用环节→汇总关键依据和缺口。用户可从来源摘要展开到变量及原文。
- **输出／规则**：当前来源压力和传导条件说明，进入 status_summary 与变量明细；不新增独立“来源评分表”。相同观测值跨角色引用只解释不同作用，不重复相加。
- **异常**：只能确认来源变化但传导未获证据时分别说明，不能声称损害已兑现；分类或机制缺失向 L1 反馈，不临时制造新风险源身份。
- **验收**：AC-L2-04-1：存在压力但传导条件未证实时，摘要明确区分两者；AC-L2-04-2：同一证据被两个变量引用，结果不按两项独立冲击计量。

### FR-L2-05 应对措施、缓冲条件与效果分析

- **来源／角色／触发**：A+N；S2 §2.2.2 的2.2、6.1 AI-L2-02；证据准备完成后执行。
- **输入／前置**：risk_buffer 变量、治理事件、措施实施记录、效果指标及当前约束。
- **操作与处理**：列出措施与缓冲条件→分别判断已宣布、已实施、效果是否可见→指出对象、覆盖范围和时滞→记录仍需验证条件。用户能看到各判断对应的证据。
- **输出／规则**：措施规模与有效程度分别表述；已宣布措施可进入持续性条件展望，不能按规模直接抵减当前风险。未见效果不等于已证无效。
- **异常**：缺实施证据标记未证实；效果指标与政策时间不匹配时不能认定因果；反证并列保留，不能只选缓解证据。
- **验收**：AC-L2-05-1：仅有救助公告时不产生“缓冲已生效”结论；AC-L2-05-2：部分对象获得支持只能说明该范围效果；AC-L2-05-3：实施但观察窗口不足时显示效果待验证。

### FR-L2-06 当前两股力量比较

- **来源／角色／触发**：A+N+D；S2 §2.2.2 的2.3、3.2 BR-L2-06、AI-L2-03；来源和应对分析完成后执行；关联 D-02。
- **输入／前置**：来源压力、已体现的缓解作用、关键传导和损害证据。
- **操作与处理**：对照压力与缓冲的对象、范围和时间→识别主要约束→形成“来源占优势／应对占优势／大致均衡／无法判断”的定性说明→列出支持和反向依据。
- **输出／规则**：当前力量比较进入 status_summary；不能用压力变量条数减缓冲变量条数，不设未批准的抵减公式。当前来源占优势不自动代表风险较上次加剧。
- **异常**：任一侧关键证据不足可判无法比较；不把未实施措施当成已生效对冲；双方都有重大压力但不同作用对象时必须解释不可直接相抵。
- **验收**：AC-L2-06-1：本轮来源占优势、较上轮压力下降时，允许后续 trend 为 easing；AC-L2-06-2：两侧各有三项变量不能据数量相同自动判均衡。

### FR-L2-07 实际影响范围与损害兑现分析

- **来源／角色／触发**：A+N；S2 §1.5、2.2.2 的2.4、3.2 BR-L2-07、AI-L2-04；风险状态分析时执行。
- **输入／前置**：L1 definition、damage_targets、mechanism_summary、损害验证变量及主体证据。
- **操作与处理**：引用潜在损害对象→检查暴露与传导证据→识别实际受压力影响主体→逐项核验是否已发生所定义损害→说明局部与整体边界→保留未证实部分。发现新的潜在损害对象可作为本轮分析补充并向 L1 反馈，不直接改正式集合。
- **输出／规则**：实际主体及环节写入 affected_scope；损害兑现和限制写入 status_summary。无证据时写“尚未证实”，不能写“确定未发生”。观察对象不自动视为全部受损。
- **异常**：证据仅覆盖个别主体时不得扩大到整个系统；只出现价格下跌不能直接认定基本面损害；损害定义不清退回 L1 维护。
- **验收**：AC-L2-07-1：两家机构受损的证据不产生“全金融系统已损害”的结论；AC-L2-07-2：结果保留损害说明但没有独立 realization_degree；AC-L2-07-3：损害待证不被转为低风险。

### FR-L2-08 当前风险快照与持续性展望

- **来源／角色／触发**：A+N+D；S2 §2.2.2 的2.5、3.2 BR-L2-08—11、4.3、AI-L2-05；汇总当前分析；关联 D-02。
- **输入／前置**：来源、应对、力量比较、影响损害、变量明细与适用评级规则。
- **操作与处理**：综合形成 risk_level、risk_stage、affected_scope、persistence_outlook、status_summary→检查范围与时间一致→在当前状态页展示依据与限制。持续性说明支撑条件、可估时间／窗口、改变条件；不能估时间时保留条件性展望。
- **输出／规则**：RiskSnapshot 的分析内容；正式 ID 由程序在保存流程中提供。risk_level 无适用规则则待判断；阶段积累／传导／兑现／修复需事实支持，可说明混合状态。trend 和 persistence_change 不属于本步骤。
- **异常**：字段缺依据时保留待判断及原因，不强制完整赋值；缺主分析结果则不伪装为有效快照；来源与应对叙述矛盾时转复核。
- **验收**：AC-L2-08-1：可形成“等级待判断、阶段传导、范围有依据、持续性为条件描述”的受限快照；AC-L2-08-2：没有日期依据时不输出精确结束日；AC-L2-08-3：快照当前状态只有四维，趋势在附属分析中。

### FR-L2-09 可比性检查与方向变化分析

- **来源／角色／触发**：A+N+D；S2 §2.2.3 的3.1、BR-L2-12、AI-L2-06；当前结果形成后执行；关联 D-06。
- **输入／前置**：当前快照、候选历史基准、前后定义及配置版本、相关变量依据。
- **操作与处理**：确认同风险与时间先后→比较对象、范围、方法和证据口径→明确可比／部分可比／不可比→比较程度、阶段、实际范围、来源与应对→生成 trend 和方向变化理由。用户查看左右对照与基准选择理由。
- **输出／规则**：comparison_snapshot_id、aggravating／stable／easing／undetermined 及 change_reason。同等级可加剧或减弱；有证据支持没有实质变化才可 stable。部分可比需界定结论覆盖范围，不能用局部可比替代整体方向。
- **异常**：无基准或不可比时方向待判断，不阻塞首次当前状态；基准已撤回则重新选择或待判断并显示影响；技术执行失败记录失败，不当成业务待判断。
- **验收**：AC-L2-09-1：首轮方向为待判断而不是 stable；AC-L2-09-2：等级未变、压力有可比改善时允许 easing；AC-L2-09-3：观察范围实质扩大时不无说明地产生加剧结论。

### FR-L2-10 持续性变化分析

- **来源／角色／触发**：A+N；S2 §2.2.3 的3.2、BR-L2-13、AI-L2-07；与方向分析共享基准执行。
- **输入／前置**：前后 persistence_outlook、预计结束窗口、持续条件、改变条件及证据。
- **操作与处理**：分离日历自然推进与预期修订→比较时间窗口和条件变化→形成延长／缩短／无实质变化／待判断→把修订依据写入 change_reason。时间型与条件型展望可分别解释，不强迫换算天数。
- **输出／规则**：persistence_change 为 lengthening、shortening、unchanged、undetermined；允许方向 easing 而持续性 lengthening。无法把条件改变换成时长变化时保留条件说明并待判断。
- **异常**：两次展望期限口径不同，或支撑条件冲突无法定论时不强行比较；没有新证据且原结束日期相同不能仅凭剩余天数减少判缩短。
- **验收**：AC-L2-10-1：两次都预计12月底结束，即使相隔一个月，也不据此输出 shortening；AC-L2-10-2：当前压力下降但延长性条件出现，可同时输出 easing 与 lengthening；AC-L2-10-3：纯条件展望不能被编造为明确天数。

### FR-L2-11 减弱节点候选、验证与失效

- **来源／角色／触发**：A+N+D；S2 §2.2.3 的3.3、BR-L2-14、4.4.2、AI-L2-08；变化分析后执行；关联 D-04。
- **输入／前置**：方向与持续性变化、驱动条件、缓冲实际效果、支持／反向证据及先前候选说明。
- **操作与处理**：检查减弱证据是否涉及关键条件→提出候选及可验证条件→后续观察定位原候选→核对规则要求→保持候选、确认、说明失效或保留待判断。用户可查看原判断、后续证据与处理理由。
- **输出／规则**：weakening_node_status 使用 none／candidate／confirmed／undetermined 候选口径；“失效”首先作为对既有候选的处理说明和历史引用，不擅自新增正式枚举。无确认规则时只能候选或待判断，不能靠人工强填 confirmed 绕过方法门槛。
- **异常**：单次 easing、仅措施宣布、没有可比基准均不足以确认；先前候选无法定位时要求补齐；反向证据出现不删除原候选而形成后续解释。
- **验收**：AC-L2-11-1：单次 easing 不自动确认节点；AC-L2-11-2：规则未定时 confirmed 操作被阻止；AC-L2-11-3：候选被反证否定后，原候选和新失效说明均可查；AC-L2-11-4：节点确认不触发风险自动关闭。

### FR-L2-12 结果保存、审核、修订与交付

- **来源／角色／触发**：A+N+D；S2 §2.2.4、BR-L2-15、4.5；系统保存草稿，研究员提交、审核员确认；关联 D-08。
- **输入／前置**：当前快照、变量明细、附属变化结果、输入与版本引用、必要限制说明。
- **操作与处理**：一致性校验→保存本轮草稿及明细→提交审核→审核员对照证据→批准或退回→批准后交付产品。后续纠正新建修订，记录被修订结果、原因和当时／事后证据标识；不能原地改已批准内容。
- **输出／规则**：一轮快照与其明细、附属分析引用一致；首次没有历史基准属于有效“变化待判断”。本版建议变化分析技术失败时保留当前状态草稿并重试，默认不批准为完整新结果；产品继续显示上次有效结果及更新失败提示。
- **异常**：跨风险明细、未来证据、基准错误阻止批准；业务上可表达缺口可由审核员批准受限结果，但结构缺陷／技术缺项不能当成普通缺口放行。运行期间定义或跟踪状态改变，批准前展示版本差异并要求重新核验。
- **验收**：AC-L2-12-1：保存中断不产生只有主表没有必要明细的可消费快照；AC-L2-12-2：变化任务崩溃时不产生 stable 或新的公开当前状态；AC-L2-12-3：修订后旧版本仍能复原原判断；AC-L2-12-4：重复批准／交付不产生第二份同版本结果。

### FR-L2-13 后续观察重点与 L1 维护反馈

- **来源／角色／触发**：A+N；S2 §2.2.4 的4.5、BR-L2-16；分析发现条件待验证或观察机制需要变更。
- **输入／前置**：next_observation、证据缺口、建议补充的变量／事件／条件，相关风险和快照。
- **操作与处理**：分析结果展示后续重点→研究员选择创建补证据或配置维护事项→填写责任人和可选到期时间→L1 接收并复用 FR-L1-05 审核→结果回写处理状态。时间未知只建待办，不编造完成日期。
- **输出／规则**：可追溯的观察待办与 L1 反馈记录；“待接收／处理中／已处理／暂不采纳”各有理由。反馈不直接改变 risk_id、scope_boundary、变量或 tracking_status；是否改计划由有权限人员明确操作。
- **异常**：重复反馈指向同一事项并补充新证据；对象已关闭仍保留反馈但不自动恢复；负责人不可用进入未分配队列。
- **验收**：AC-L2-13-1：L2 提出新增变量建议时 L1 正式配置不立即改变；AC-L2-13-2：L1 完成维护后反馈可查到新版本及决定理由；AC-L2-13-3：观察重点不包含自动交易或持仓操作。

## 10. 风险产品与发布功能

### FR-PUB-01 完整风险目录与多维检索

- **来源／角色／触发**：A+N；S3 §1.3、3.3 C，S1 §5.4；所有获授权用户访问风险目录。
- **输入／前置**：关键词、市场／对象、风险源、风险维度、跟踪状态、风险等级、纳管日期及分页参数；仅在授权范围内查询。
- **操作与处理**：打开目录→筛选／排序→查看条数→翻页→打开详情。默认完整目录包含 observing、monitoring、paused、closed 及尚无快照项；关键词搜索标题和定义，筛选条件组合按“不同维度取交集、同维多选取并集”。
- **输出／规则**：每风险一条，展示身份、观察对象、跟踪状态、最新有效快照时间和等级、是否待评估／陈旧。默认 admitted_at 倒序、risk_id 稳定补序。未映射市场归“未分类”，不从标题自动猜测。零结果显示可清除的条件。
- **异常**：部分数据不可用显示加载失败而非“无风险”；无快照项显示未评估；分页期间数据更新显示列表查询时点并提供刷新，避免同次查询重复漏项。
- **验收**：AC-PUB-01-1：无快照及 closed 对象在完整目录可查；AC-PUB-01-2：状态和风险源组合筛选准确且可清除；AC-PUB-01-3：查询失败不会展示空目录成功态。

### FR-PUB-02 最新风险与今日新增风险

- **来源／角色／触发**：A+N；S3 §3.3 A，S1 §5.4；用户查看总览。
- **输入／前置**：正式风险、已批准未撤回的快照、查询时点、时区及跟踪状态筛选。
- **操作与处理**：每风险先选择最新有效快照→按 snapshot_time 倒序→同时间以 risk_id 稳定补序。今日新增卡片独立按 admitted_at 所在业务日筛选，点击进入相同筛选的目录。
- **输出／规则**：“最新”指评估截止时间，不按记录创建时间或风险首次发现时间排序。无快照风险不进入最新列表；今日新增可无快照。默认最新列表展示活动跟踪状态；暂停／关闭可切换包含并标明。旧截止时间的追溯重算不挤到最前。
- **异常**：当最新快照被撤回且无可用后续结果时标记“最新结果已撤回／待评估”；如展示前一有效结果，必须标明沿用历史及原时间，不能冒充刚更新。
- **验收**：AC-PUB-02-1：今日只新增快照的旧风险不进入今日新增；AC-PUB-02-2：今日纳管未评估风险进入今日新增但不进入最新风险；AC-PUB-02-3：昨日风险今日重算上月快照不因 created_at 新而排首位。

### FR-PUB-03 最严重风险排序与不可比较项

- **来源／角色／触发**：A+N+D；S3 §2.3、3.3 B；用户查看严重度列表；关联 D-02、D-03。
- **输入／前置**：每风险最新有效快照、活动跟踪状态、RiskLevelConfig 严重度顺序、规则可比较关系与时效配置。
- **操作与处理**：先按风险选最新有效快照→判定等级有效、可比较且时效明确→按严重度降序、snapshot_time 倒序、risk_id 补序。等级空、不可比、过期／时效未配置分别进入旁列集合，并提供明细原因。
- **输出／规则**：默认只纳入 observing、monitoring。先选最新快照再取等级；最新等级待判断时不得回溯挑旧高等级参榜。D6 不重算分数，不按 M 排序。本版建议陈旧项在独立历史观察区展示而非当前严重度主榜。
- **异常**：统一严重度口径未定则该分组暂停排名，显示风险目录与未排名原因；过期不等于低风险，不能涂成安全状态。
- **验收**：AC-PUB-03-1：同级按截止时间与 ID 稳定排序；AC-PUB-03-2：不同且未映射的规则等级不混排；AC-PUB-03-3：最新等级为空时不取旧高等级参榜；AC-PUB-03-4：陈旧高风险保留标识但不伪装成当前判断。

### FR-PUB-04 风险详情、证据下钻与 Timeline

- **来源／角色／触发**：A+N；S2 §5.4，S3 §3.1；用户从列表、报告或检索打开风险。
- **输入／前置**：risk_id、可选 snapshot_id／版本、用户阅读权限。
- **操作与处理**：详情页分区显示风险定义与观察范围、潜在损害对象、四维当前状态、两项历史变化、减弱节点、变量依据、事件及 Timeline。点击变量查看观测值和机制，点击依据查看当时原文版本；时间线按 snapshot_time 排列，显示修订标识及比较基准。
- **输出／规则**：当前状态取同一快照，变化取其附属结果，不能混用不同快照的“最新字段”。Timeline 是派生视图，不在展示端重新分析演化。报告进入的历史快照应保持选中，不能自动跳到当前结果。
- **异常**：未评估、变化待判断、节点未确认各自展示原因；证据无阅读权限时显示“无权限查看原文”及允许公开的来源说明，不泄露正文；外部链接失效仍可读库内版本。
- **验收**：AC-PUB-04-1：从报告进入旧快照能看到当时定义与依据；AC-PUB-04-2：四维状态和附属变化同属一条快照；AC-PUB-04-3：历史版本及候选节点后续失效说明可沿 Timeline 查到。

### FR-PUB-05 日报、周报、月报编制

- **来源／角色／触发**：A+N+D；S3 §1.3、2.3、3.1；研究员手工或已启用计划生成草稿；关联 D-10。
- **输入／前置**：报告类型、周期、时区、dataCutoffAt、范围和栏目模板；仅使用截止时已批准可消费的风险结果。
- **操作与处理**：选择类型及周期→预览候选条目与不足→生成草稿→查看风险列表和纳入理由。默认日报为业务日00:00至次日00:00；周报周一00:00至次周一00:00；月报月初至次月月初，均左闭右开。报告截止不得早于周期结束，期中报告须明确标“截至当前的未完结周期”。
- **输出／规则**：日报包含期内新纳管、完成有效观察／修订、已确认状态变化及应关注的期末严重风险；周／月报按周期内快照与变化归纳起末状态、关键节点及反复，不只复制日报标题。风险条目按 risk_id 去重，多次关键变化可在同一条目内列出；保留每项引用版本与纳入理由。
- **异常**：无可用快照仍可生成明确的“本期暂无可用评估结果”草稿，不能声称市场无风险；部分风险数据未更新需列出覆盖缺口；周期重复生成转新草稿版本，不创建不可区分的同一期刊物。
- **验收**：AC-PUB-05-1：分别能生成日、周、月三种草稿，跨日边界不重复纳入；AC-PUB-05-2：同一风险周期内三次变化归入一项并保留关键引用；AC-PUB-05-3：周报能表达先加剧后减弱，不机械平均 trend；AC-PUB-05-4：无结果期报告明确不足。

### FR-PUB-06 报告编辑、引用与一致性校验

- **来源／角色／触发**：A+N；S3 §2.5、3.1；研究员编辑、审核员复核。
- **输入／前置**：报告草稿、栏目、ReportRiskItem、固定快照与变化结果、上游限制说明。
- **操作与处理**：编辑标题、总述、栏目顺序和条目摘要→添加／移除允许范围内的条目并写理由→查看引用→运行校验→提交审核。AI 可组织文字，但等级、方向、范围、持续性和节点状态来自上游；编辑这些结论须回到 L2 修订。
- **输出／规则**：每条保留 riskId、snapshotId、comparisonSnapshotId（可空）、纳入原因及摘要；关键数字、状态与证据一一对应。摘要不得删除足以改变结论的时间条件、未知状态或适用限制。
- **异常**：引用不存在、超截止时间、同一条拼接不同快照字段或文字与结构化结论冲突时阻止提交；被引用快照撤回时标记报告受影响，转复核；草稿并发编辑按版本冲突处理。
- **验收**：AC-PUB-06-1：上游 trend=easing，报告写“风险加剧”触发冲突复核且不能直接发布；AC-PUB-06-2：一条无快照的新增观察可列为“新纳管、待评估”，不能虚构等级；AC-PUB-06-3：每个正式判断均可定位到对应快照版本。

### FR-PUB-07 报告审核、发布、撤回与修订

- **来源／角色／触发**：A+N；S3 §3.2—3.3；审核员操作，采用第4.5节状态机。
- **输入／前置**：通过结构和引用校验的报告草稿、审核说明；发布时重新检查所引用结果是否仍有效。
- **操作与处理**：研究员提交→审核员查看内容及引用差异→批准发布或退回→系统使该版本进入授权读者范围。撤回须填写理由并停止公开入口和下载；修订从既有版本复制新草稿，重新审核后发布，旧版本明确标为已被修订。
- **输出／规则**：同一报告周期／范围／类型有稳定 reportId，各版独立。已发布内容不因后续上游更新自动改写；有影响的证据纠正先标“需复核”，发现依据失效或关键错误则撤回相应版本，由审核员决定修订。禁止无痕替换已发布字节内容。
- **异常**：权限不足、引用已失效、已撤回或版本冲突时拒绝相应动作并说明；发布响应丢失后重试返回已发布版本，不重复出刊；撤回失败显示未完成并重试，不能先宣称全端完成。
- **验收**：AC-PUB-07-1：重复点击发布只产生一次该版本发布；AC-PUB-07-2：撤回后列表、直达地址及下载均不再提供该版正文；AC-PUB-07-3：发布修订版后仍可由有权限人员查到旧版、差异和理由；AC-PUB-07-4：研究员无发布权限时请求被服务端拒绝。

### FR-PUB-08 报告阅读、历史版本与导出

- **来源／角色／触发**：A+N；S3 §1.4、3.1；获授权读者查看报告，研究员可查看草稿预览。
- **输入／前置**：报告类型、周期、关键词、reportId／version 及阅读权限。
- **操作与处理**：报告中心筛选→打开指定版本→浏览总述及栏目→点击风险与快照依据→查看版本信息→主动下载。首版提供与页面同内容的 Markdown 和可打印 HTML 导出；PDF 作为打印结果，不要求单独 PDF 生成服务。
- **输出／规则**：阅读页与导出包含标题、周期、截止时间、状态、版本、风险判断及引用标识；内部草稿预览带草稿标记且不对阅读者开放。已下载文件无法被远程收回，故文件必须携带报告 ID、版本和状态核验入口。
- **异常**：撤回直达链接显示撤回时间与理由，不显示旧正文；导出失败可重试，不影响已发布记录；无权限请求不能通过导出绕过限制。
- **验收**：AC-PUB-08-1：页面与两种导出中的风险、等级、截止时间和版本一致；AC-PUB-08-2：下载不包含用户无权读取的内部原文或审计数据；AC-PUB-08-3：撤回报告旧链接可见撤回说明但无法重新下载正文。

## 11. 运行管理与横向功能

### FR-OPS-01 身份、角色与访问控制

- **来源／角色／触发**：N；管理员配置，所有业务请求生效；授权边界见第3章。
- **输入／前置**：用户身份、有效角色、数据范围、启停状态；认证方式由技术设计选择。
- **操作与处理**：管理员分配或撤销权限→用户界面按权限显示入口→服务端逐次校验读取、变更、导出和发布。后台任务继承经批准的业务权限范围，记录系统执行者。
- **输出／规则**：权限变更与拒绝操作可审计；默认无匿名敏感数据入口；凭据通过安全配置引用，页面和日志不显示秘密值。
- **异常**：会话失效提示重新登录且保留未提交草稿提示；权限被撤销后后续请求拒绝，已排队任务提交前重新校验授权。
- **验收**：AC-OPS-01-1：阅读者直接请求修改、批准或下载内部原文均被拒绝；AC-OPS-01-2：撤权后旧会话不能继续发布；AC-OPS-01-3：管理员没有审核角色时不能批准风险判断。

### FR-OPS-02 任务状态、重试、重算与取消

- **来源／角色／触发**：A+N；各层横向追溯要求；研究员管理业务任务，管理员处理技术故障。
- **输入／前置**：请求身份、对象／输入版本、任务类型、规则集合和处理记录。
- **操作与处理**：运行中心按状态筛选→查看阶段、子任务、已保存结果和交付状态→对可重试故障重试→必要时取消。重试复用业务请求，重算另记运行身份、原因及新版本；批处理只重试未完成子项。
- **输出／规则**：采用第4.3节状态；本版建议瞬时故障自动重试最多2次，等待30秒、120秒，可配置并展示；校验错误、授权失败、待业务判断不自动循环重试。取消在阶段安全边界生效，已提交业务数据保留。
- **异常**：响应未知时先查询是否已保存／发布，再决定重试；执行中断从最后可验证阶段恢复，不重复生成正式实体；上游已变更时不得用旧请求偷偷消费新版输入。
- **验收**：AC-OPS-02-1：响应丢失后重试不新增同一快照或报告版本；AC-OPS-02-2：校验错误不无限调用 AI；AC-OPS-02-3：取消多项任务后已成功项保留，其余不继续正式提交。

### FR-OPS-03 人工复核中心

- **来源／角色／触发**：A+N；S0—S2 复核边界；系统生成待办，研究员处理，审核员决策。
- **输入／前置**：所属层、关联对象／任务、触发原因、原文／数据、AI 建议、冲突差异和可选动作。
- **操作与处理**：待办列表→认领→查看上下文与前后对照→修改草稿／补资料／确认／驳回／退回→填写理由→系统重跑必要校验→恢复关联流程。可以转派，禁止以删除待办表示已解决。
- **输出／规则**：复核记录含执行者、决定、依据、时间和后续任务。无法判断可保留待复核，必需规则未配置不能靠点击“通过”绕过。一个子项待复核不锁住独立子项。
- **异常**：两人同时提交只接受仍匹配当前版本的决定；输入已变更提示重新查看；超期仅提醒，不自动批准。
- **验收**：AC-OPS-03-1：UNRESOLVED 事件复核通过后从归组阶段继续，无需重复采集；AC-OPS-03-2：无规则的节点不能被强制确认；AC-OPS-03-3：后提交的过期复核决定被拒绝且不覆盖前一决定。

### FR-OPS-04 证据追溯、版本审计与历史重放

- **来源／角色／触发**：A+N；S0 §5.2、S1 横向职责、S2 BR-L2-15；授权人员查看分析依据或排查问题。
- **输入／前置**：业务对象／运行／版本标识、查询时间范围。
- **操作与处理**：从结果打开追溯视图→定位当时风险定义、变量关系、指标／原文版本、规则／Prompt／模型→查看操作前后值及批准记录。历史重放先固定输入包；重新调用 AI 产生新运行，不能把文字完全相同作为可复现承诺。
- **输出／规则**：形成“报告→快照→变量分析→配置及指标／事件→原文版本”链。人工修改保留原始 AI 输出与修改理由。审计不可由普通业务编辑覆盖，敏感凭据不得写入。
- **异常**：历史引用缺失标记受影响对象并转修复，不用当前数据填补成旧依据；访问无权资料只显示授权范围内元数据。
- **验收**：AC-OPS-04-1：任取已发布报告条目可完整回到当时依据；AC-OPS-04-2：新配置发布后旧结果追溯不变；AC-OPS-04-3：重放会产生新运行且不覆盖旧结论。

### FR-OPS-05 采集、观察和出刊计划

- **来源／角色／触发**：A+N；各层触发能力与 S3 周期报告；管理员配置调度，研究员／审核员确认业务范围。
- **输入／前置**：任务类型、来源／风险范围、周期、时区、执行时间、截止时间规则、启停状态；观察需有效变量配置，出刊需模板。
- **操作与处理**：计划管理→新建→预览下次执行时间及范围→保存为停用→显式启用。到期检查重复、权限与对象跟踪状态后创建任务；暂停计划停止新增任务。定时报表默认只生成草稿。
- **输出／规则**：每个计划时段有可查执行记录。采集／观察频率按业务配置，不硬编码统一日报节奏；系统恢复后列出错过时段，由管理员选择补跑，本版不无界自动补跑历史。
- **异常**：时区／周期非法阻止启用；暂停风险不参与自动观察；执行时依赖缺失记录跳过／待补齐并提示，不能悄悄消失；同计划前次仍运行时新周期记录等待或合并原因。
- **验收**：AC-OPS-05-1：同一时段重复触发只创建一次业务请求；AC-OPS-05-2：计划停用后不再生成新任务；AC-OPS-05-3：恢复服务后可看到漏跑窗口及补跑结果；AC-OPS-05-4：定时生成报告不会未经审核直接发布。

### FR-OPS-06 运行异常、数据陈旧与恢复验证

- **来源／角色／触发**：N；管理员和任务负责人处理任务失败、待办积压、来源中断、结果陈旧及交付失败。
- **输入／前置**：任务状态、配置的时效与提醒条件、责任人；不增加用户行为分析或外部遥测。
- **操作与处理**：系统在运行中心产生异常事项→按对象和故障类型聚合同一问题→负责人确认接手→修复／补齐／重试→以重新校验和成功交付验证恢复→关闭事项。提醒只在系统内，外部渠道需另行需求。
- **输出／规则**：显示首次发生、最近发生、影响对象、最近成功时间、待处理数和恢复证据。数据时效未配置显示“未配置”，不伪装正常。业务待判断与服务不可用分开统计。
- **异常**：重复故障更新同一事项，不刷屏；有部分下游仍失败不能标记全部恢复；告警确认不等于故障已解决。
- **验收**：AC-OPS-06-1：同来源连续失败聚合一项可追踪故障；AC-OPS-06-2：任务恢复但交付未恢复时事项仍显示残留影响；AC-OPS-06-3：待判断风险不会被统计为 AI 技术故障。

### 12.2 跨层交付契约

| 交接 | 生产方交付内容 | 消费方必须检查 | 完成与失败处理 |
| --- | --- | --- | --- |
| L0 → L1 | 事件身份／版本、本次更新集合、增量类别、阶段时间、对象、直接变量、来源、可选评级 | 已保存、引用有效、是否重复、是否需要完整识别 | 记录接收／跳过／待补齐／已处理；不能只“发出即完成” |
| L1 → L2 | 正式风险及适用定义版本、变量关系与机制版本、损害对象说明、相关事件、跟踪状态及变化 | 已纳管、范围有效、观察可执行、跟踪权限、当前关系 | 首次、持续、配置变更、暂停分别处理；失败可补交付 |
| 指标接入 → L2 | 指标身份、口径、观测值与期间、发布时间、取得时间、来源和修订版本 | 单位／范围一致、截止内可用、无重复、映射有效 | 不合格数据保留失败明细，不冒充已更新 |

| L2 → L1 | 需维护的问题、建议、证据、关联快照和影响范围 | 确认所属风险及是否已有反馈 | L1 决策后返回处理状态，不自动改定义 |
| 发布模块 → 阅读／导出 | 已发布报告或可消费动态列表、固定版本及读取权限 | 发布状态、用户权限、报告引用有效性 | 撤回统一生效；缓存不能绕过状态检查 |

统一交接元数据至少表达：请求／变更唯一标识、生产方、对象与版本、生成时间、关联运行、变更类型、处理状态。正式英文键名及序列化 Schema 留给接口设计；技术实现须提供与上述语义逐项对应的契约测试。

### 12.3 幂等、并发与版本规则

1. **资料**：同来源同资料同内容版本只产生一次有效接入；内容修订是新版本，不是重复。
2. **事件更新**：同一事件、同一来源版本引起的同一业务增量只保存一次；来源增加不伪造进展。
3. **风险纳管**：正式提交前再次检查候选是否已被处理、风险同一性及引用；并发请求复用已产生结果或进入冲突复核。
4. **风险—事件关系**：业务上同一有效关系不重复；这不预设原八字段表必须增加哪个复合唯一键。
5. **观察运行**：同一业务请求的重试只恢复原运行；主动重算须有新运行与理由。两个合法不同截止时间的定期观察可以产生两份相似结果，不以文本相同删除。
6. **结果修订**：同一截止时间存在多个修订时明确前后关系；产品选用最新已批准、未撤回的有效修订，历史版本仍可读。修订版本编号不能代替 snapshot_time 排序。
7. **报告**：类型＋周期＋时区＋范围定义同一期产品；重算生成可辨识版本，发布动作对同一版本幂等。
8. **并发编辑**：所有草稿确认、审核和状态变更必须校验用户读取版本；冲突返回最新差异，不自动覆盖他人修改。
9. **消费一致性**：禁止快照主记录来自新版本而变量明细或变化结果来自另一运行。保存成功与交付成功分别显示，可恢复。

### 12.4 当前有效结果选择算法（N）

给定查询时点，先限制批准／发布时间不晚于查询时点，再排除撤回、引用失效和无完整业务结果的版本；同一风险先按 snapshot_time 取最新观察，再按该观察的已批准修订选择有效版本。草稿、待审核、技术失败运行均不替代产品当前状态。

若最新观察已获批准但 risk_level 待判断，该观察仍为最新结果，严重度榜进入待评估集合，不能从旧版抽取等级。若最新观察被撤回，详情可显示上一有效观察，但必须注明回退原因与历史时间；没有可用记录时显示待评估。陈旧阈值独立决定是否可参加当前严重度排序，不改变历史记录有效性。

以下为业务错误标识建议 N，不预设接口错误码数值。所有异常提示应包含：哪个对象／步骤、什么原因、哪些内容已经保存、下一步可执行动作及任务标识。不得把内部调用栈或凭据直接显示给用户。

| EX-01 来源未准入／停用 | “来源当前不可用于采集或分析” | 历史材料保留 | 管理员修接入，审核员确认准入 | AC-L0-01-1 |

| EX-08 缺失、陈旧或冲突证据 | 显示覆盖和冲突，结论受限 | 原值、各版本与反证保留 | 研究员补证据或提交受限结果审核 | AC-L2-02-3、AC-PUB-03-4 |
| EX-09 无历史／不可比 | 变化待判断及原因 | 当前状态允许独立形成有效首轮业务结果 | 准备基准或等待后续观察 | AC-L2-09-1、AC-L2-09-3 |
| EX-10 规则未定 | 明确“未配置适用规则” | 保留文字分析及待判断 | 业务负责人完成 D 项；不自动填阈值 | AC-CFG-05-1、AC-L2-11-2 |
| EX-11 保存失败 | 本对象提交失败 | 不产生半套可消费结果 | 管理员恢复后同请求重试 | AC-L0-10-1、AC-L2-12-1 |
| EX-12 交付失败／下游不可用 | “结果已保存，待交付” | 已保存对象保持 | 仅补交付，不再生成对象 | AC-L0-10-2、AC-L1-08-3 |
| EX-13 并发编辑／状态改变 | 版本冲突、请核对差异 | 已生效决定不覆盖 | 用户刷新并重新提交 | AC-OPS-03-3 |
| EX-14 原文／数据后续纠正 | “当前依据被修订，相关结果需复核” | 旧快照／报告保持原版 | 定位影响对象，重算修订／必要撤回 | AC-CFG-04-3、AC-L2-12-3 |
| EX-15 权限不足／会话失效 | 无权限或重新登录提示 | 未授权操作不生效 | 管理员授权；用户重新登录 | AC-OPS-01-1、AC-OPS-01-2 |
| EX-16 变化分析技术失败 | 当前分析草稿已保存、变化失败 | 上次已批准结果继续可读，显示失败时间 | 重试变化步骤，默认阻止新整轮批准 | AC-L2-12-2 |
| EX-17 上游快照撤回 | 报告／页面依据失效提示 | 固定历史版本保留内部审计 | 相关报告停止正常发布资格、审核撤回／修订 | AC-PUB-06-3、AC-PUB-07-2 |
| EX-18 计划漏跑／服务重启 | 展示缺失周期与受影响范围 | 已完成周期不重复 | 管理员明确选择补跑，逐项校验 | AC-OPS-05-3 |

**恢复完成标准**：原失败原因消除、同一业务请求未产生重复、完整数据已经校验、需要的下游消费已确认、用户可查看恢复结果；点击“已读”或任务进程退出不能作为恢复完成依据。

| 复核中心 | 原因、关联对象、证据、建议、责任人和处理历史 | 认领、补充、批准、驳回、转派 | FR-OPS-03 |
| 运行中心 | 计划、任务及子项、阶段、失败、交付、最近成功、异常事项 | 重试、取消、补跑、查看审计 | FR-OPS-02、04—06 |

### 14.2 表单与提交行为

1. 所有必填字段、条件必填项、示例及空值含义在操作前显示；校验错误定位到具体字段并保留用户已输入内容。
2. 用户点击提交后立即显示“已受理／执行中”，返回可查任务；提交成功、业务处理完成、正式批准／发布分别提示。
3. 长任务允许离开页面后返回查看；前端重复点击不重复受理相同业务请求。刷新页面不会重新执行原操作。
4. 未保存编辑离开页面时提示；草稿保存成功须有明确反馈。系统不得用“保存草稿”悄悄批准或发布。
5. 纳管、合并／拆分、正式配置生效、暂停／关闭／恢复、报告发布／撤回显示对象与影响预览并要求理由；这属于系统内业务操作设计，不是本次文档生成的审批要求。
6. 关键状态不能只用颜色区分，必须提供文字；空列表、无权限、加载失败、待评估、过期数据是不同界面状态。
7. 筛选、返回列表和分页保留当前条件；查询结果显示总数、时间与可清除条件。下载遵循当前报告版本和权限。
8. AI 原建议与人工修订可对照；人工说明不得隐藏反证。资料正文中的指令文字作为待分析内容，不得取得系统任务控制权。

## 15. 非功能性验收约束

以下指标为本次提出的首版验收目标 N，不是现有系统实测性能。性能测试必须登记硬件、数据库、网络、数据量、并发及版本；环境基线由开发与测试在联调前固定，见 D-11。业务完整性不能以性能优化为由降低。

| 编号 | 要求与度量 | 验收办法 |
| --- | --- | --- |
| NFR-01 可追溯性 | 100%已发布判断具有固定风险／快照／依据版本；不存在引用别的风险明细 | 对验收样本全量检查引用并人工穿透至少10条（不足10条则全查） |
| NFR-02 幂等与恢复 | 同一请求重复3次、并发重复2次，正式业务效果均只有一次 | 对采集、纳管、观察、发布和补交付分别注入重复与中断 |
| NFR-03 查询响应 | 参考数据量：10万资料版本、1万事件、1000风险、10万快照、100万变量明细；20并发读者下列表 P95≤2秒、详情 P95≤3秒 | 固定索引与查询条件，持续10分钟，含过滤及翻页；不把模型计算计入只读响应 |
| NFR-04 长任务可见 | 任务受理 P95≤2秒返回任务标识；任务状态改变后10秒内在运行中心可见 | 用可控延迟模拟分析；离开／返回／刷新仍能查到状态 |
| NFR-05 超时与有界重试 | 单阶段超时、重试次数和等待策略可配置；默认分析阶段超时建议180秒；不无限运行或重试 | 注入超时与限流，检查次数、状态及恢复入口；阈值调整需留记录 |
| NFR-06 历史与备份 | 已发布结果、原始依据与审批记录在 V1 无自动删除；备份目标建议 RPO≤24小时、RTO≤4小时 | 上线前完成一次隔离环境恢复演练，核对引用、版本和发布状态；未演练不宣称通过 |
| NFR-07 权限 | 页面、直接请求、导出、后台提交遵守相同授权，越权成功数为0 | 按第3.2节逐类角色做正反向验证 |
| NFR-08 内容与安全 | 外部正文不改变系统指令；页面脚本不能由原文执行；日志／导出无秘密凭据 | 构造含指令、脚本片段与假 ID 的材料，验证被当内容处理或拒绝，不提升权限 |
| NFR-09 撤回一致性 | 撤回操作成功后，所有受支持的读取和下载入口都拒绝正常正文访问 | 查询缓存命中、直达URL、列表、导出逐一检查；无法统一完成则显示撤回处理中而非成功 |
| NFR-10 时间与编码 | 中文 UTF-8 完整，时区和日期精度不丢失；0、负值、空值、百分数与基点区分 | 用中文长标题、跨日时点、季度数据、空值／零值与单位转换样本验证 |
| NFR-11 AI 业务质量 | 已定业务禁则测试全部通过；风险定义／因果解释由标注样本评审，不能只检查 JSON 合法 | 形成含正常、无结果、冲突、首次、不可比及反证的评测集，记录每次版本结果 |
| NFR-12 自动化启用 | 自动归组／自动纳管／自动确认节点的准确性门槛须先经业务负责人批准 | 门槛与评测集未定时保留人工复核模式，不声称自动决策已验收；关联 D-12 |

## 16. 端到端验收与完成定义

### 16.1 验收样本约定

下列数据均为**假设测试数据，不代表真实宏观事件或投资判断**。测试环境预置：

- 信源 S-A 已准入、S-B 已准入、S-X 未准入；资料 I-A 为某经济体政策公告，I-B 为同事件另一来源，I-A-v2 修订关键数字。
- 事件 E-A：同一政策从 announced 到 effective；E-B：同机构另一次独立决定；资料 I-C 同时包含两项独立决定。
- 风险 R-A：“某宏观融资市场续接压力风险”，对象为金融市场，范围明确；风险 R-B 同名但对象／范围不同；R-C 已 closed。
- 变量含驱动、传导、缓冲、损害验证四类；至少一个未知变量候选、一个指标缺失项、一组单位／口径冲突项。
- 快照 T1、T2 同属 R-A，时间先后明确；T3 为范围改变后的不可比样本；T4 无历史。风险等级测试使用显式标注“仅验收”的已批准测试规则，不把测试权重当生产方法。
- 报告 D1／W1／M1 覆盖日、周、月；分别含正常条目、无快照新纳管、待判断及陈旧项。权限用户覆盖四类角色。

测试人员为每个用例保存输入版本、执行人、期望与实际结果、相关对象数量、页面截图或机器回执、缺陷编号。AI 输出可以使用受控样本验证业务流程，但还须对真实模型执行 NFR-11 的业务质量评测，不能用桩结果代替模型验收。

### 16.3 单项功能完成定义

一项 FR 只有同时满足以下条件，才可标记“开发完成”：

1. 页面／操作入口、授权校验及后台行为已经实现，用户能够完成正常路径。
2. 本项所有 AC 与引用的全局规则通过；至少一个无效输入或异常恢复路径有可重演记录。
3. 实际输入、输出、状态、空值和字段含义与本说明书一致；存在技术映射时有清晰对照。
4. 写入具有幂等、版本和审计；跨层交付可查结果，技术失败不会伪装业务成功。
5. 人工待办具备可操作恢复路径，不能只写一条日志后永久停住。
6. 未决 D 项有明确开关／降级并通过相应测试；被关闭的自动功能必须标“未启用”，不能填写“已全部验收”。

### 16.4 系统验收与发布判定

- **功能验收**：51项 FR 的逐项 AC 全部执行；32个 E2E 全部执行；通过项目须有证据，失败项归到具体 FR。
- **业务正确性**：关键禁则零违反，包括假 ID、未来信息污染、无基准判稳定、公告直接当效果、M 当风险等级、无痕改历史、越权发布。
- **可运行性**：首个有效信源、变量与指标映射、风险分类、模板、角色、任务计划和人工复核责任已配置；不能只在代码中存在页面而没有业务可用配置。
- **完整性与恢复**：重复、并发、保存失败、通知失败、重启、修订、撤回及备份恢复验证通过；没有未解释的半完成对象。
- **质量门槛**：NFR全部有结论，任何豁免必须记录原因、范围、风险和责任人。阻断正确业务结果、造成历史损坏、越权或重复发布的缺陷不可豁免。
- **两种结论分别记录**：可在明确待判断和人工流程下验收首版业务闭环；量化评分、跨风险严重度比较、节点自动确认、自动纳管／发布按各自 D 项单独启用验收。方法未定时不宣称这些能力已验证。

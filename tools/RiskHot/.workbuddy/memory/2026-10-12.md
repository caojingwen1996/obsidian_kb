## BMAD 技能接入 WorkBuddy（整目录挂载）

**背景**：项目根目录已由 BMAD-METHOD 铺下 29 个技能到 `.agents/skills/`，但 WorkBuddy 只从
`~/.workbuddy/skills/` 与 `{workspace}/.workbuddy/skills/` 加载技能，因此这些技能对当前会话不可见。
推荐技能市场搜索 `bmad` / `bmad-prd` 均为 0 条结果，确认非市场技能。

**安全审查结论：P2（安全）**
- 无 `curl|sh` / `wget|bash` 远程管道下载
- 无 `eval` / `exec` / `os.system` / `shell=True`；`subprocess.run` 仅本地调用 `git`、`uv`
- 无网络请求库（仅 `urllib.parse.urlparse`，不做网络 I/O）
- 无凭据/敏感路径访问；`token` 命中均为 LLM token、design token、auth token 等文档术语
- `shutil.rmtree` 仅作用于临时 staging 目录；`os.unlink` 为原子写临时文件
- 外部域名仅 w3.org（SVG 命名空间）、github.com、docs.bmad-method.org 等文档链接

**执行**：
```bash
cd /Users/cjw/dev/Obsidian/wiki/tools/RiskHot
mkdir -p .workbuddy
ln -s ../.agents/skills .workbuddy/skills   # 相对软链，29 个技能一次接入
```
验证：软链可穿越读取，`bmad-prd/SKILL.md`、`customize.toml`、`assets/`、`references/` 均可达。

**环境**：`uv 0.11.5` 已装于 `/Users/cjw/.local/bin/uv`（BMAD 技能依赖 `uv run _bmad/scripts/*.py`）。

**已知权衡**：`.workbuddy/skills` 是指向 `.agents/skills` 的软链，若后续从技能市场安装新技能，
文件会落进 `.agents/skills/`，与 BMAD 目录混在一起。如需隔离，可改为「真实目录 + 逐个软链」。

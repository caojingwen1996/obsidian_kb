## 3. Temporal 验证证据

1. 人工模式任务进入等待输入；重复启动事件只产生一次执行登记；关闭并重启 Worker 后任务状态保留；取消由 PostgreSQL 资格门禁与 Workflow 协同生效。
2. 注入明确标记的模型测试适配器，产生待审建议及来源元数据；重复完成事件幂等处理。
3. 批准快照事件检查数据库资格后完成任务；重复批准通知不重复完成。
4. 真实 Temporal Schedule 触发，生成一份报告草稿；同一窗口重复触发不重复出稿，不自动发布。

本轮“重启”是 Worker 优雅关闭和重新启动，不是主机断电、Temporal 集群故障、数据库恢复或历史版本 replay 演练。

## 4. 测试发现并修复的问题

| 问题 | 修复与复验 |
| --- | --- |
| 候选可携带其他事件的更新 ID | 纳管前验证增量归属；SC-014 |
| 同身份并发纳管 | 短业务事务协调与重复身份校验；SC-015 |
| 取消、暂停、定义变化及发起人撤权后的迟到结果 | 提交前复查资格与领域状态；SC-021—023 |
| 审批与任务取消竞态 | 正式快照与任务完成在同一事务写入 |
| 来源补充未进入证据包 | 纳入事件来源引用并按可知时间过滤；SC-041 |
| 审核决定只记日志、未推进业务状态 | 应用层原子组合领域退回/驳回及审核记录；SC-042 |
| 隐藏原文参与搜索造成检索侧信道 | 在权限过滤后的可见数据上匹配；SC-043 |
| 撤回后旧请求回执仍包含报告正文 | 返回当前撤回元数据；SC-044 |
| 迟到批准的历史快照被用作截止前基准 | 比较基准同时检查批准可知时间；SC-045 |
| 技术失败任务仍能批准完整草稿 | 终态资格校验；SC-046 |
| 初始化成功仍停在表单 | 保留会话查询订阅，清理其他业务缓存；B-01 / B-02 |
| 模板异步返回覆盖编辑内容 | 模板加载期间禁用编辑与提交；B-01 |
| 手机卡片内容被裁切 | 最小宽度与网格约束，加入内部溢出断言；B-01 / B-02 |
| Temporal 开发脚本启动后退出 | 显式维持进程并在退出时关闭服务；真实 Worker 场景通过 |

## 5. 复现

```bash
pnpm infra:up
pnpm report:scenarios
pnpm build
pnpm verify:boundaries
pnpm test:e2e
# 先在另一终端启动 pnpm dev:temporal，或使用已运行的 pnpm dev
pnpm test:temporal
```

完整开发环境启动：`pnpm dev`；入口 <http://127.0.0.1:4311>。运行说明见 [README](../README.md)。`pnpm db:seed` 可在用户创建管理员后幂等准备明确标记的虚构演示资料。

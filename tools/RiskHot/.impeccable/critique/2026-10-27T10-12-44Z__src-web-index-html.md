# M1 页面层级审查

结论：建议由三个一级入口收为“信源目录”和“信息接入”两个。将自动计划作为信源的接入设置，同时保留全量自动接入表；执行历史统一归入信息接入。仅在原三个页面外再套一层页签不会真正减少层级。本记录是待确认建议，不替代现行设计。

## 现状与建议

当前：目录包含八项筛选、四种视图、最多三级分类和档案/技术/关系/历史；任务页包含累计统计、日期概览、执行记录和本轮统计；计划页同时承担周期配置、运行历史及结果阅读。

建议：目录在同一信源集合下提供档案浏览、自动接入表格；单信源包含档案、接入设置、关联资料和历史。信息接入提供全局开启、当前任务、执行记录、每轮状态统计；累计统计保留但减少首屏占位。资料与候选使用统一阅读器，配置入口可定位对应执行记录。正式事件仍归F02。

## 优先问题

1. P1 操作范围：单源详情里的开启任务运行全部启用源，视觉归属容易误导。移至全局信息接入工具栏，明确范围，保持点击直接开启。
2. P2 重复职责：计划表和任务表分别维护运行历史与不同结果入口。计划归配置、历史归执行，跨页面保留定位快捷入口。
3. P2 无效分类：桌面实测40个信源连续落在三级待补充分组。默认平铺，无区分价值的单分组层压平，次要筛选折叠。
4. P2 阅读链和首屏负担：接入结果仅作资料/候选中转；结束任务横幅跨工作区占位。统一内容阅读器，结束态压缩为摘要；每轮结果仍只含状态及统计，不增加按信源明细。

待处理诊断可由独立的异常处理入口承接，不能为了诊断擅自恢复用户已取消的整轮信源明细。此入口目前仅建议，尚未实现。

## 优点与产品特性

业务资格和技术状态独立，资料、Fact、Event统计有可追溯口径；目录主从布局和行内展开适合操作型工作台。保留真实状态及渐进展开。

## 启发式暂评

| 项目 | 0–4分 | 依据与限制 |
| --- | --- | --- |
| 状态可见 | 3 | 真实状态清楚，结束态占位过重 |
| 用户语言 | 2 | 关系与全局操作范围含混 |
| 用户控制 | 3 | 返回关闭存在；未实测编辑保护 |

| 合计 | 21/40 | 桌面观察与源码暂评，不是全面验收 |

认知负担：重复入口、无效分类、首屏竞争及跨页记忆是主要负担。新用户易误解单源启动；熟练用户受重复检索和阅读中转影响。真实状态建立信任，但需处理数量没有顺畅通往诊断的路径。

轻微问题：关系可改名关联资料；来源监测偏好、计划周期与任务暂停需要持续区分。单dialog替换内容，不应误报为多个模态框叠加。

待确认：采用两入口加目录自动接入表，还是保留三入口仅去重？调整范围仅导航/重复路径，还是同时压平无效分组和首屏信息？

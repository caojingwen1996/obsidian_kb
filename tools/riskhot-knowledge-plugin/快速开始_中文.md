# RiskHot Knowledge Plugin 使用说明

这是一套可用于 RiskHot 本地 Markdown 设计仓库的**只读 MCP 插件起步工程**。目前是项目骨架，尚未读取你 Mac 上的实际资料，也尚未与你的 ChatGPT 账户建立连接。

## 1. 本地启动

将压缩包解压到 Mac 任意目录（建议放在 RiskHot 项目之外），然后在终端执行：

```bash
cd riskhot-knowledge-plugin/server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export RISK_HOT_ROOT='/Users/cjw/dev/Obsidian/wiki/tools/RiskHot'
python server.py
```

服务器默认只监听 `127.0.0.1:8765`，MCP 地址为 `http://127.0.0.1:8765/mcp`。

## 2. 验证读取功能

另开一个终端：

```bash
npx @modelcontextprotocol/inspector@latest
```

在 Inspector 中选择 Streamable HTTP，填写 `http://127.0.0.1:8765/mcp`，检查 `project_manifest`、`search_project`、`read_project_file` 等工具。

## 3. 与 ChatGPT 连接

ChatGPT 网页无法直接访问你的本地端口。建议按 OpenAI 的官方 Secure MCP Tunnel 文档建立私有通道：

https://developers.openai.com/api/docs/guides/secure-mcp-tunnels

然后进入 ChatGPT Plugins → `+` → Add custom MCP server → Tunnel，选择已配置的通道，完成插件创建和安装。在支持插件的 ChatGPT 聊天/Work 界面中调用。

这个 Starter 不带认证服务器，所以**禁止把本地 8765 端口直接通过无认证的公网转发开放**。


### RiskHot Tunnel 一键启动脚本

《riskhot-tunnel.command》

脚本将自动完成：
① 检查 RiskHot MCP Server
如果服务已启动，直接复用


② 自动启动 MCP Server（如有需要）
检查 Python → 创建虚拟环境 → 安装依赖 → 运行 server.py


③ 初始化并连接 Secure MCP Tunnel
读取 Tunnel 配置，输入 API Key，执行诊断和启动


④ 自动检测服务状态并打开管理页面
检查 8765 MCP 服务与 8080 Tunnel 状态

操作	命令
一键启动全部服务	bash riskhot-tunnel.command
检查全部服务状态	bash riskhot-tunnel.command --check
重新配置 Tunnel	bash riskhot-tunnel.command --reset
启动但不打开浏览器	bash riskhot-tunnel.command --no-open
停止本次启动的服务	Ctrl + C


## 4. 能读取什么

当前可以遍历项目目录、统计全部普通文件的元信息；可以读取和全文检索 Markdown、TXT、JSON、YAML、Mermaid、PlantUML 及常见源代码文件；可以提取 Markdown 大纲并列出指定时间后的变更文件。

PDF、DOCX、图片等二进制附件在这一版只有文件清单和大小等元数据，需要后续增加解析器。隐藏文件、`.env`、版本库元数据、依赖目录和符号链接默认排除；超过 1 MiB 的文本也默认不读取。

MCP 服务在提问时按需读取最新文件；不会一次性把整个项目资料全部装入 GPT 的上下文窗口。

## 5. 工程中各文件的用途

`server/catalog.py` 负责受控文件访问、搜索和路径安全；`server/server.py` 提供 MCP 工具接口；`skills/riskhot-context/SKILL.md` 告诉 AI 如何检索设计资料并用行号标明来源；`plugin.json` 是可移植插件描述文件；`mcp.json.example` 是未来有**受认证**远程 HTTPS 地址时使用的连接配置示例。

目前 `plugin.json` 尚未绑定 ChatGPT 注册的远程 MCP 应用标识。完成服务器连接后，可按官方 plugin-creator 工作流封装为完整的可安装插件：

https://developers.openai.com/plugins/build/plugins


# RiskHot Tunnel 凭据文件说明

这次更新实现了一次配置、反复读取 Tunnel ID 与 Runtime API Key。原有脚本仍负责启动 RiskHot MCP Server、初始化与启动 Tunnel、健康检查以及进程清理。

## 文件位置

更新后的启动脚本仍放在 `riskhot-knowledge-plugin/riskhot-tunnel.command`，与 `server/` 同级。

凭据文件默认存放于 Mac 当前用户目录：

`~/.config/riskhot/tunnel.env`

示例内容：

```ini
TUNNEL_ID=tunnel_此处填写实际ID
API_KEY=此处填写实际RuntimeAPIKey
```

脚本读取纯 `KEY=VALUE`，不会执行文件中的 Shell 命令。API Key 以明文形式保存，但设置文件权限 `600`、配置目录权限 `700`，因此仅当前 Mac 用户能够访问。不要把实际配置文件放进 Git 仓库或分享给其他人。

## 首次配置

先把新版 `riskhot-tunnel.command` 替换旧版，然后在项目目录执行：

```bash
bash riskhot-tunnel.command --configure
```

根据提示分别输入 `tunnel_...` 和 Runtime API Key。API Key 输入时不回显。脚本自动创建配置目录和文件。

## 后续启动

```bash
bash riskhot-tunnel.command
```

将直接读取保存的 ID 和 Key，不再逐次询问。原有 MCP Server 自动启动与 Tunnel 健康检查功能保留。

## 修改凭据

```bash
bash riskhot-tunnel.command --configure
```

如果只更新 API Key，可直接重新启动。如果修改 Tunnel ID，更新凭据后执行：

```bash
bash riskhot-tunnel.command --reset
```

`--reset` 会备份旧的 Tunnel Client 连接配置并重新初始化，以使用新的 Tunnel ID。

## 查看或手工编辑配置

```bash
nano ~/.config/riskhot/tunnel.env
```

编辑完成后确保文件权限：

```bash
chmod 600 ~/.config/riskhot/tunnel.env
```

不要把实际 Key 粘贴到聊天中。

## 其他选项

```bash
bash riskhot-tunnel.command --check       # 仅检查连接状态
bash riskhot-tunnel.command --no-open     # 启动后不弹出管理页面
```

如果希望另存位置，可以先在终端设置 `RISK_HOT_TUNNEL_CONFIG_FILE=/其他路径/tunnel.env`，然后再运行 `--configure` 与日常启动命令；该变量需在每次运行时保持相同值。

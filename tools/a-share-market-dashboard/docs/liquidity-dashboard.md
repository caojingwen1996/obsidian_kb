# 资金面日报

## 入口与操作

2026-11-05 根据用户提供的《资金面日报（Liquidity Dashboard）》需求接入现有面板。市场总览第四个快捷卡位展示A股和美股资金面状态，点击进入同一面板内的详情页；右上角“刷新”重新读取公开数据，左侧返回市场总览。详情页的位置随既有导航保存，重新加载仍可回到该页。

页面阅读顺序：宏观风险提醒 → A股／美股切换 → 各路资金动向与市场涨跌分布（仅A股）→ 评分指标表 → 所选指标的历史走势和历史数值 → 评分说明 → 数据来源。点击指标名称切换图表；资金卡片展开“查看口径与历史”核对观测。手机端单列显示，历史图允许局部横向滚动。

## 需求与实际接入

默认使用Tushare Python、Yahoo及已有其他非Wind来源；Wind MCP和ETF每日任务已停用。请求仍为 `/api/liquidity`，手动刷新 `/api/liquidity?refresh=1` 也不调用Wind。当前以 [[tools/a-share-market-dashboard/docs/wind-disabled|Wind停用与当前来源规则]] 为准，下方旧Wind章节保留作历史实现记录。

当前默认Tushare Python覆盖7条基础序列：美债10Y/2Y、SPX、融资余额、融资净买入、Shibor及沪深300。旧公开源模式仍可通过显式配置free使用；默认模式不在这些序列请求失败后自动改用旧源。原来源缓存只作为标注stale的历史值保留，不计分。其余覆盖缺口维持既有源，详见 [[tools/a-share-market-dashboard/docs/tushare-migration|迁移记录]]。RRP规则与评分留空。

评分市场分别独立：≥3宽松，1至2偏松，0中性，−2至−1偏紧，≤−3紧张。A股4个评分项，美股当前6个；RRP待定，不占有效评分分母，DXY盘中报价和南向为参考项。部分可用时展示“部分指标”和覆盖数量，不归一化；全缺失时显示“数据不足”，不显示中性。宏观提醒仅由有效的VIX、利差和MA200触发，缺项时明确无法排除风险。当前倒挂不依赖20日历史即可提醒。

## 缓存与时间

缓存位于 `data/资金面日报/cache/`，按序列保存，已加入Git忽略。公开源成功数据缓存1小时；失败结果短缓存60秒，避免频繁重试。ETF单独采用每日09:00定时更新，不因普通读取缓存而启动取数。页面刷新绕过序列缓存；3秒内重复刷新会合并复用。单次请求超时8秒，数据源并行执行；本机首轮实测约11秒，不能保证所有网络下5–10秒。有效缓存命中后可快速返回。

新鲜度基于观测日期：日度最多7个自然日，WALCL周度最多14日。刷新失败保留上次有效序列和来源，同时标记旧数据、不计分；后续成功取数重新写入。检查时间单独显示为北京时间，不冒充观测日期。重复日去重，非数值与未来日期剔除；美元与人民币金额按表中单位统一。

MA使用最新收盘序列计算；按当地时区剔除收盘前的当日日线，并预留15分钟更新缓冲（A股15:15、港股16:15、美股纽约16:15、DXY纽约17:15）；主力与南向每日净额同样处理。DXY明确为盘中参考。图表保留最多260个观测值，按有效观测顺序展示，水平虚线仅代表最新均线参考值，不是历史均线曲线。

## 历史Wind数据读取（已停用）

配置在 `scripts/liquidity_config.py`：`WIND_ETF_ENABLED = True` 已让ETF申赎单项通过Wind MCP取数，与其余指标的提供方独立；详情见下方“ETF申赎实时接入”。其余指标如需切换导入模式，将默认 `DATA_PROVIDER="tushare"` 改为 `"wind"` 后重启本地面板服务。`scripts/liquidity_data.py` 中的 `wind_fetch_all()` 读取 `cache/wind/` 的标准化序列；这是其余指标的缓存导入接口；ETF单项另走MCP采集模块。

通过Wind MCP取数后，按对应数据定义导出下列结构。示例仅说明字段，不代表真实观测：

```json
{
  "id": "us_DGS10",
  "unit": "%",
  "source": "Wind · 美国10年期国债收益率",
  "sourceUrl": "https://www.wind.com.cn/",
  "points": [{"date": "2026-11-04", "value": 4.9}]
}
```

文件名为 `us_DGS10.json`，id与单位须匹配 `SERIES_UNITS`。所有序列ID与标准单位以 `scripts/liquidity_data.py` 为准；WALCL统一十亿美元，FRED原始百万美元需除1000；纽约联储RRP原始美元除10亿；融资余额元除1亿；东财南向百万元除100。不得把现价、融券合计、单通道或不同美元指数历史写入不匹配的序列。Wind输入同样接受日期、新鲜度和历史长度检查，缺失时不退回免费源冒充Wind。

### 历史ETF申赎接入（2026-11-05，现已停用）

已验证Wind MCP的 `fund_get_listed_historical_price` 提供 `f_mf_netsubamt`（申赎净流入额，元）。与 `f_mf_netinflow` 二级市场净流入、成交额是不同字段。使用该申赎字段直接合计，不用份额变化或成交额替代。

采集代码为 `scripts/wind_etf.py`。名单由Wind `fund_screener` 分别查询“全部上海证券交易所上市的股票型ETF”和“全部深圳证券交易所上市的股票型ETF”，避免全市场查询超过1000条展示上限。解析时严格核对返回总数、明细数量、交易所代码及重复代码。此口径采用Wind股票型分类，含该分类下的港股通产品，不能解读为完全纯A股资金。当天名单按日期缓存，历史保留当时名单覆盖信息。

每批最多50只、最多2批并发。先确定实际交易日，再让其余批次读取同日；Wind明确返回“均无行情数据”时，最多向前找15个自然日。各批次实际日期必须一致。空字段仍视为缺失；仅当 `fund_get_basic_info` 的上市日期证明该基金在观测日尚未上市，才从当日统计范围排除，并显示筛选总数、排除数及有效覆盖。其他任何缺项、批次失败或名单截断都不发布部分合计，也不填零。日期过旧仍受既有7天新鲜度限制。

首次补入最新和前一交易日，之后随实际刷新累积观测；不拿当前名单倒填完整60日历史。初始前次使用同一筛选名单并排除当时未上市基金，名单筛选日期记录在覆盖信息中；60日分位需要60个有效观测才显示。

ETF改为每天北京时间09:00由本机Codex定时任务执行一次。定时命令为 `python3 scripts/wind_etf.py --scheduled`（工作目录为本工具目录），按上海日期记录每日尝试，成功或失败都不在同日重复自动执行；遇到另一个正在取数的任务则跳过，避免重叠。本机Codex需处于可执行任务的状态，面板网页和本地HTTP服务无需保持打开。普通读取不再按1小时缓存期限自动触发Wind取数；右上角手动刷新仍可启动更新。

定时进程与手动刷新共用文件锁；手动刷新不会抹掉当天自动执行记录。页面空闲时每60秒读取只读的 `/api/liquidity/etf`，更新中每5秒读取进度；这两种查询都不访问Wind，也不触发其他公开源取数。连续检查失败3次暂停，回到页面或手动刷新可恢复。临时上游错误最多尝试3次，失败任务保留分批检查点1小时；完成后清除，下一次取数可获得数据修订。

ETF卡片和底部来源表明确区分：**数据日期**为Wind返回的实际交易日；**更新时间**为本机最近一次成功获取完整日度合计并写入缓存的时间，以北京时间显示。Wind尚未发布新交易日数据时，数据日期可能不变；成功重新核验后更新时间可前进。失败或仅打开页面不会改写最近成功时间。

复用已有凭证：优先读取进程环境变量 `WIND_API_KEY`，否则读取用户现有 `~/.codex/config.toml` 中 `mcp_servers.wind-tools` 的Bearer配置。没有另写密钥文件，密钥不进入前端、业务缓存和错误日志。Python 3.11及以上使用标准库TOML解析；当前macOS Python 3.9使用已安装pip随附的TOML解析器。HTTP仅访问固定Wind MCP地址、拒绝重定向，支持JSON/SSE响应；错误输出仅含固定分类，不保留鉴权响应或异常原文。

缓存位置：`data/资金面日报/cache/wind-etf/series.json`保存完整日度合计和覆盖信息；`universe.json`保存名单；`constituents-日期.json`保存逐基金申赎值（元）以便复核；`status.json`保存更新进度。上述目录沿用资金面缓存的Git忽略规则。

关闭 `WIND_ETF_ENABLED` 后，原有 `cache/imports/cn_etf_flow.json` 标准化导入仍可用：要求id为cn_etf_flow、unit为亿元、scope为沪深股票型ETF、basis为net_creation_redemption，并有真实来源、HTTPS链接和日期数值。关闭自动MCP不等于用其他资金流字段替代申赎。
